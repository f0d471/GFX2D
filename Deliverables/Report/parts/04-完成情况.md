# 第三部分　完成情况及性能参数

## 3.1 整体介绍

本作品的实物由 Ti60F225 开发板、HDMI 显示器及供电和输入连线构成。程序在板上的 RISC-V 软核执行，像素由 FPGA 引擎绘制后直接输出到显示器；上位机通过板载 USB 串口转发输入和采集日志。图 16 为系统实物：开发板经 HDMI 线连接显示器，屏上运行弹幕游戏，HUD 显示硬件渲染 60 FPS。

当前成果包含二维分桶与三维光栅两种配置。前者用于比较二维执行路径及数量极限，后者用于三维场景；两者使用同一开发板，功能组合和资源占用分别列示。

## 3.2 工程成果

### 3.2.1 电路成果

硬件交付包括可执行命令表的绘图引擎、DDR 帧缓冲到 HDMI 的扫描链路，以及对应的软件控制接口。二维构型保留直通、片上纹理、条带和硬件分桶，可切换执行方法；三维构型保留片上纹理与条带，配置三维光栅和深度处理。表 3 给出整机编译结果，统计对象包含软核、存储接口、显示和引擎，所列建立与保持余量均为正。

TC|两种整机构型的资源和时序

| 资源 | 二维构型 | 三维构型 |
| --- | ---: | ---: |
| XLR | 60,064（98.8%） | 59,623（98.06%） |
| 片上 RAM | 172（67.2%） | 187（73.0%） |
| DSP | 23（14.4%） | 26（16.3%） |
| 内核时钟 建立 / 保持 | +0.104 / +0.022 ns | +0.762 / +0.026 ns |

XLR 表示逻辑资源，片上 RAM 以块计，DSP 用于乘法等运算；其中 12 个 DSP 对应基础像素通路的 4 像素×RGB 三通道，其余承担相应构型的地址计算或光栅工作。两种构型均接近逻辑容量上限，DSP 使用比例仍较低，资源取舍主要受整机逻辑与存储组织约束。

两种构型目前均由 JTAG 装载运行。Flash 应用写入、回读与断电自启动已在开发过程中单独验证，但尚未把两种构型都固化为上电自启动，演示按 JTAG 装载进行。

### 3.2.2 软件成果

软件交付包括板上 C 驱动、PC 与板上双目标应用、素材打包工具以及游戏机前端。驱动负责提交与呈现；前端以菜单组织四个应用，弹幕游戏提供移动、射击场景、炸弹和关卡变化，HUD 同屏显示当前后端与帧率。用户可在菜单与应用内切换场景，具备对应能力时再切换渲染路径。

四个应用分别是基础演示、弹幕游戏、压力测试与三维走廊轨道射击：弹幕游戏包含半透明弹幕、色键角色与首领战，压力测试调节发射密度并自动搜索活动 Sprite 极限。图 17 至图 19 为三个应用在 PC 上的界面，展示同一前端下的画面与交互；板上实际运行见图 16、图 21，三维性能见 3.3.4 节。

## 3.3 特性成果

本节按优化顺序报告结果：基础加速与负载极限、片上纹理与条带、硬件分桶，最后是三维扩展。N_max 表示指定尺寸 Sprite 在真实游戏中保持稳定 60 FPS 的活动数量极限；K 是负载旋钮，N_max 是实际存量，成对结果依次对应 16×16 与 8×8。

### 3.3.1 基础加速与负载极限

基础直通版本使用相同游戏与绘制语义，在 CPU 软件执行和 FPGA 硬件执行之间切换。普通游戏短测中，硬件首秒预热后达到 60 FPS，纯软件约 2.5 FPS，约加速 24 倍。CPU 提交绘图任务后不再逐像素搬运和混合，因而能够维持实时游戏显示，图 20 左侧给出这一对比。

压力档约有 2030 颗活动弹，硬件 60 秒呈现 1839 帧，约 30.6 FPS，说明更高密度仍会超过单场预算。软件路径此时无法维持同一更新节拍，场上活动弹存量下降，图中右侧用于展示过载行为，不据此计算同规模加速比。图 21 的 61 FPS 是 HUD 瞬时显示，统计结论仍采用场数与交换数。

FIG|../Assert/figures/report/rep_fps.png|普通游戏与过载表现

FIG|../Assert/photos/board_myriad_hw61_20261005_crop.jpg|板上运行局部屏摄|14.5

基础直通版本的 N_max 为 1014（16×16，K896）和 1365（8×8，K1216），各完成 3600 场稳定确认，搜索轨迹见图 22。较小 Sprite 的像素面积减少，数量极限随之提高，但没有按面积同比例增长，说明每对象的取指、访存和调度等成本也影响整机能力；这一现象本身不能单独定位 CPU 或 DDR 瓶颈。

独立 K896 固定负载运行中，帧时间约为 16.3 ms，首秒建立流水，其后 59 个逐秒窗口均为 60/60，见图 23。该结果描述基础版本的持续负载能力。后续构型改变了访存和命令路径，采用各自同条件对照，不直接用历史成绩差值归因。

### 3.3.2 片上纹理与条带对照

片上纹理让圆弹等热素材从片上反复读取，直通路径仍按对象顺序访问目的帧缓冲；条带路径进一步把同一区域的合成留在片上。表 4 在同一版本内比较直通片上纹理与条带两种执行，并在条带程序内比较 CPU 数据缓存的容量与路数。

4 KB 缓存下，直通片上纹理的 N_max 为 1891 / 2237，条带为 424 / 505。条带虽然减少了目的数据反复进出 DDR，CPU 还要为每条带求交、调整坐标并复制命令。分段测得 CPU 逻辑与组帧约需 13 ms、引擎约需 6 ms，CPU 侧成为主要成本。两者是局部分段，提交和同步等仍占帧预算，最终是否达标以实际呈现为准。

TC|片上纹理、条带及缓存容量对照

| 构型与后端 | 16×16 N_max / K | 8×8 N_max / K |
| --- | --- | --- |
| 4 KB，直通片上纹理 | 1891 / 1648 | 2237 / 1984 |
| 4 KB，条带 | 424 / 384 | 505 / 464 |
| 16 KB 候选，条带 | 479 / 432 | 597 / 544 |

将 CPU 数据缓存由 4 KB / 1 路改为 16 KB / 4 路候选后，条带 N_max 提高约 13% / 18%。这是容量和路数共同变化的构型差距，仍未消除组帧成本。该阶段的结果使优化目标从目的写回转向命令构造：保留条带的局部合成方式，把 CPU 反复进行的分桶与复制交给硬件。

### 3.3.3 硬件分桶的同程序收益

二维构型将分桶计算和保序引用构建移入引擎，CPU 发布原始绘制与实例数组，随后由硬件组织各条带任务。对照程序同时携带直通片上纹理与硬件分桶两条路径，在同一比特流、素材及负载定义下运行时切换，以减少程序版本差异。

表 5 采用开发定稿记录：16×16 的 N_max 由 1872 提升到 2189，8×8 由 1947 提升到 2187，分别提高 16.9% 和 12.3%，各完成 3600 场稳定确认。该结果表明，减少 CPU 任务构造后，条带组织能够在这组真实负载中获得整机收益。

TC|同一比特流、同一程序的后端对照（开发定稿记录）

| 后端 | 16×16 N_max / K | 8×8 N_max / K |
| --- | --- | --- |
| 直通片上纹理 | 1872 / 1632 | 1947 / 1728 |
| 硬件分桶 | 2189 / 1904 | 2187 / 1936 |

总线流量另取同一程序的独立复现记录，在各自确认档上比较。两路 16×16 极限档中，分桶承载更多活动弹，每帧读突发均值仍由直通约 32,493 次减至 9863 次，写突发由约 39,835 次减至 3286 次，分别减少约 70% 和 92%。引用表比跨桶复制的完整命令紧凑，任务取用与目的合成共同降低事务数量；这些流量属于各自确认档，不是固定活动数量的独立带宽测试。

按 N_max×Sprite 面积×60 换算，分桶两档的等效混合吞吐约为 33.62 / 8.40 Mpix/s，包含游戏状态、调度与访存条件。像素阵列理论 400 Mpix/s 则假设流水持续供数，两类指标描述不同层次，分别报告。

图 24 汇集各阶段的绝对成绩，用于观察不同组织方式的负载能力。表 4 的直通 2237 与表 5 的直通 1947 属于不同程序，后者还携带分桶发布和缓冲管理路径。因此，图中历史柱形不能直接连接成单项优化的增长率，硬件分桶收益以表 5 的同程序结果为准。

### 3.3.4 三维渲染表现

三维应用沿用二维的条带执行方式，把区域内的处理对象换成三角形。三维构型在三维走廊轨道射击中透视绘制连续门框、敌机和弹幕，物体随相机与输入改变位置和远近，深度通路处理前后遮挡，二维通路叠加 HUD。

该场景支持交互移动和炸弹输入，连续推进时敌机与门框由远及近穿过视野。CPU 完成几何准备，FPGA 承担条带内光栅与深度工作，具体分工见 2.2.2.5 节。

走廊场景分别以自动驾驶和脚本移动、炸弹输入连续测量 1800 帧，两组均记录 3600 场与 1800 次交换，保持每两场呈现一帧。表 6 同时列出典型帧和较慢帧：自动驾驶的 p50 为 25.96 ms、最大 30.96 ms；脚本输入的 p50 为 27.26 ms、最大 32.34 ms。两组最大值均低于 33.3 ms 预算，迟到为 0，说明所测连续窗口能够保持 30 FPS。该连续性能结论针对走廊场景。

TC|三维走廊轨道射击的连续帧时间

| 输入 | p50 / ms | p99 / ms | 最大 / ms |
| --- | ---: | ---: | ---: |
| 自动驾驶 | 25.96 | 30.15 | 30.96 |
| 脚本移动与炸弹 | 27.26 | 31.30 | 32.34 |

三维构型的二维直通片上纹理 N_max 另测得 1870 / 1969，说明同一三维构型仍保留二维应用能力。由于该构型未启用硬件分桶，该组成绩与二维构型分属不同构型，分别报告。三维扩展的意义在于沿已有条带调度、纹理和搬运基础增加新的图元处理通路，所需逻辑、RAM 和 DSP 已在表 3 单列。
