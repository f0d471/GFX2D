#TITLE|GFX2D：基于 RISC-V 与 FPGA 异构架构的 2D 图形渲染加速引擎

#ABSTRACT
二维图形渲染是嵌入式人机界面的基础负载。若完全由 CPU 逐像素搬运与混合，像素运算会占满处理器，帧率随画面元素数量骤降。本作品在 Ti60F225 FPGA 上实现了一套由 RISC-V 软件驱动的 2D 图形渲染加速系统：Sapphire 软核处理器运行自研弹幕射击游戏 MYRIAD，只负责游戏逻辑与生成 32 字节渲染命令表；自研 BitBlt 渲染引擎作为 AXI4 主机直接访问 DDR3，按命令完成图像块拷贝、纯色填充、硬件 Alpha 混合（12 个 DSP 混合核，每周期 4 像素）与颜色键控去背；扫描输出模块以双缓冲方式从帧缓冲取数，经 HDMI 以 640×480@60 Hz 显示。软件执行器与硬件流水线按同一份逐像素规格实现，板上同帧 CRC 对比证明两者逐像素等价。实测结果：普通游戏短测中硬件后端稳定 60 FPS，同命令表的纯软件渲染约 2.5 FPS，加速约 24 倍；在开启 Alpha 混合与色键的条件下，自动搜索测得稳定 60 FPS 下同屏活动精灵数极限 N_max：直通（片上纹理）后端 16×16 弹型 1891 颗、8×8 弹型 2237 颗；条带后端同帧语义通过验证，但 CPU 分桶成本使其降至 424/505；据此新增硬件空间分桶后端，CPU 只发布一份原始绘制、由硬件建立按条带组织的紧凑引用表（参数缓冲），同一比特流同轮对照下两弹型 N_max 提高至 2189/2187 颗（+16.9%/+12.3%），各档均以 3600 场（60 秒）确认零掉帧；整机占用 60064 个 XLR（98.8%）、172 块片上 RAM（67.2%）、23 个 DSP（14.4%），核心时钟 setup/hold 余量 +0.104/+0.022 ns，无时序违例。
#END
