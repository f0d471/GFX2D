# 第四部分　总结

## 4.1 可扩展之处

混合方程表、tint 与 INDEX8 字段为效果扩展保留了接口。提高分辨率需要同步修改扫描时序、帧缓存布局和条带宽高，并重新核算带宽与场预算，不能只更换像素时钟。TEX 与条带模式已经接入；下一阶段优先分解 CPU 的裁剪、分桶、记录复制和桶写入成本，比较连续桶写入与当前散写路径。16KB/4 路对条带 N_max 的收益约 13%/18%，继续保留候选，采用结论由完整游戏与扫描实测决定。

## 4.2 心得体会

事务探针让架构取舍有了可复测的依据，但单层模型不能替代整机结果。P1 的瓶颈主要是 DDR 事务固定开销；条带将源与目的的像素访问搬到片上后，CPU 构造成本成为限制，原预测因此被推翻。后续优化必须同时报告 CPU 与引擎分段，以及逐场呈现结果。

同规格软硬实现、独立像素金标准与变异测试共同支撑正确性；当前构型的串口日志、产物身份和综合报告支撑交付结论。缓存路数、生成配置或代码改变后，需要验证相关假设并更新证据，历史日志只能证明对应版本。
