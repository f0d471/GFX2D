# 第四部分　总结

## 4.1 可扩展之处

混合方程表、tint 与 INDEX8 字段为效果扩展保留了接口。提高分辨率需同步修改扫描时序、帧缓存布局与条带宽高，并重新核算带宽与场预算——这是分辨率提升的正确做法，而非只更换像素时钟。下一阶段的主攻方向已经锁定：引擎执行与 CPU 状态生成；条带搬运重叠（双条带缓冲的装载/写回与执行重叠）与 CPU 侧描述符化组帧是首选候选。16 KB/4 路对条带 N_max 的收益约 13%/18%，作为候选保留，采用与否由完整游戏与扫描实测决定。

## 4.2 心得体会

事务探针把架构取舍变成可复测的工程动作。三种后端各自消解一类瓶颈：直通消除重复读事务、条带消除随机写、分桶消除 CPU 构造，瓶颈因此逐级转移，最终落在引擎执行与 CPU 状态生成。这条链路本身就是本作品的方法论——先量瓶颈，再改结构，最后用同一比特流对照验证。

正确性由三条独立证据支撑：同规格软硬双实现、独立像素金标准、以及变异测试。每条交付结论都绑定串口日志、产物指纹与综合报告，可回溯到具体版本。
