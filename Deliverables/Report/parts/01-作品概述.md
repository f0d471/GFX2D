# 第一部分　作品概述

## 1.1 功能与特性

本作品是一套完整的 2D 渲染加速系统，包含硬件渲染引擎、显示输出链路、板上软件平台和一个真实可玩的弹幕射击游戏。

每帧的渲染流程为：RISC-V 处理器运行游戏逻辑，把绘制需求编码为 32 字节渲染命令写入 DDR3 命令表，写 DOORBELL 寄存器触发引擎取指；引擎以每周期 4 像素的吞吐完成像素搬运、Alpha 混合与色键去背，结果写入帧缓冲；扫描输出按场同步取数，经双缓冲与 TMDS 编码后以 HDMI 输出画面。

引擎保留直通、条带与硬件分桶三种执行模式，可在同一比特流上运行时切换：直通以 16 KiB 片上纹理承接高频小素材的读，条带以片上行缓冲把弹幕的随机写合并为条带连续写，硬件分桶把命令整理与分桶计算搬进硬件，CPU 每帧只发布一份原始绘制清单，各条带的紧凑引用表（即参数缓冲）由引擎生成，跨条带精灵不再复制命令（见 2.2.5 节）。

三个演示模式覆盖赛题全部要求：基础演示（方块运动与大图切换，屏幕同屏显示软/硬件两路帧率）、可玩游戏（默认开启 Alpha 混合与色键）、压力测试（自动搜索稳定 60 FPS 下的同屏精灵数量极限并显示结果）。

## 1.2 应用领域

本系统面向以图层合成为主的 2D 嵌入式图形场景：仪表与设备的图形界面、图标与半透明面板的叠加显示，以及精灵类 2D 游戏。这些场景由块拷贝、纯色填充、Alpha 混合与色键等基本操作构成，不需要 3D 变换与抗锯齿。渲染引擎的命令接口带版本号与能力寄存器，混合方程以表格方式扩展；引擎对外仅暴露寄存器与命令表两类接口，也可作为图形子系统集成进更大的 SoC 方案。

## 1.4 创新功能

本作品的创新分两部分：四个传统 2D 引擎没有的硬件与架构功能，以及一个贯穿全程的设计方法。

（1）硬件分桶渲染（构造方向）。把分桶计算与跨条带记录复制从处理器移入引擎：CPU 每帧只发布一份原始绘制与实例数组，引擎以两次遍历建立各条带的保序引用表，跨条带精灵不再复制命令；同比特流同轮对照的收益见表 5（机制见 2.2.5 节）。

（2）片上纹理（读方向）。16 KiB 片上纹理承接高频小素材，使这类命令的 DDR3 读事务降为零，直通模式的小源读瓶颈由此消解（见 2.2.5 节）。

（3）条带缓冲（写方向）。把散落帧面的随机小写合并为整条带连续写，弹幕写入的 DDR3 随机访问由此收敛（见 2.2.5 节）。

（4）命令 ABI 与十步错误模型。命令只携带表面号与坐标，硬件统一完成裁剪、越界与重叠检查；错误码与出错记录索引锁存上报，可定位到具体命令与字段，驱动无需信任输入（见 2.2.4 节）。

（5）以实测反推架构。开工前先用探针实测 DDR3 控制器的事务模型，得到“瓶颈在事务次数而非带宽”的结论；数据布局与访问形态据此而定，是三种执行模式与像素通路共同的设计输入（见 2.2.2 节）。

## 1.5 相关工作与本作品的定位

2D 图形的硬件加速有两条主线。第一条是合成语义：Porter 与 Duff 把 Alpha 合成抽象为一组算子 [8]，此后硬件混合单元的语义基本建立在这套代数上，本作品的六种混合方程与预乘主路径正是它的直接实现。第二条是固定功能 2D 引擎：面向 MCU 的 DMA2D 类加速器以寄存器级命令完成块拷贝、格式转换与两图层混合 [10]；FPGA 上也有面向精灵的专用引擎，例如用高层次综合与片上存储实现多精灵处理的硬件引擎 [13]，以及 2D 图形系统的软硬协同设计 [14]。这类工作把逐像素搬运与混合从处理器移入硬件，命令通常由处理器逐条写入、执行模式单一。

当像素通路不再是最紧的瓶颈，限制随之转移到访存。Rixner 等人的访存调度研究表明，行缓冲命中与突发组织对有效带宽的影响可以超过峰值带宽本身 [12]；Molnar 等人的排序分类则指出，按空间局部性重排访问可以把随机访问转成连续访问 [11]，移动端的图块化渲染沿用了同一思路 [16]。1.4 节前三项创新功能正是把这两条结论落到 2D 弹幕负载上的结果。

与上述工作相比，本作品的定位在三点：命令以 32 字节定长表提交、由引擎自取，业界引擎的命令通常由处理器逐条写入；同一比特流上提供直通、条带与硬件分桶三种执行模式，可按负载切换并同板对照，业界引擎执行模式单一；为读、写、构造三个方向各建一级片上缓冲（16 KiB 片上纹理、640×16 行条带缓冲与参数缓冲），传统 2D 引擎没有这一存储层级。
