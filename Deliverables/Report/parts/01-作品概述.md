# 第一部分　作品概述

## 1.1 功能与特性

本作品是一套完整的 2D 渲染加速系统，包含硬件渲染引擎、显示输出链路、板上软件平台和一个真实可玩的弹幕射击游戏。赛题规定的 7 项基础要求与 3 项高阶要求全部在真实板卡上实现，每一条都有可对账的实测证据（见表 1 与表 6）；在此之上，本作品给出六项超出赛题要求的创新（见 1.5 节）。RISC-V 处理器运行游戏逻辑，将每帧的绘制需求编码为 32 字节渲染命令（块拷贝 BLIT、纯色填充 FILL、裁剪 SET_CLIP），写入 DDR3 命令表并写入 DOORBELL 寄存器触发引擎取指。FPGA 端的 2D 渲染引擎取指执行，以每周期 4 像素的吞吐完成像素搬运、12 通道 DSP Alpha 混合与色键去背，结果写入 DDR3 帧缓冲。扫描输出模块按场同步从帧缓冲取数，经双缓冲切换与 TMDS（Transition-Minimized Differential Signaling）编码后输出 HDMI。引擎保留直通、条带与硬件分桶三种执行模式并可在同一比特流上运行时切换：直通模式以 16 KiB 片上纹理承载高频小素材，条带模式以 640×16 行片上缓冲把弹幕的随机写合并为条带连续写，硬件分桶模式由引擎两次遍历输入建立按条带组织的紧凑引用表（参数缓冲），CPU 不再为跨带元素复制命令（见第二部分 2.2.5）。三个演示模式覆盖赛题全部要求：基础演示（大量方块随机移动、多张大图快速切换，屏幕同屏显示软/硬件两路帧率）、可玩游戏（默认开启 Alpha 与色键）、压力测试（自动搜索稳定 60 FPS 下的同屏精灵数量极限并显示结果）。

## 1.2 应用领域

本系统面向 CPU 逐像素渲染难以胜任、又无需 3D 管线的各类嵌入式图形场景。典型应用包括：高密度信息显示与仪表叠加（半透明面板、文字图层）、工业与医疗设备的图形化人机界面、游戏机与街机风格的娱乐终端、以及车载液晶仪表的图层合成。渲染引擎的命令接口带版本号与能力寄存器，混合方程以表格方式扩展，可在不改动流水线结构的前提下增加效果种类；配合上位机经串口转发输入，也可作为图形子系统集成进更大的 SoC 方案。赛题演示所用的弹幕游戏对渲染吞吐的要求高于多数仪表界面，因此本系统的性能余量可以平移到上述场景。

## 1.3 主要技术特点

第一，预算驱动的设计方法。开工前先用板上探针实测 DDR3 控制器的事务模型（突发上限 256 拍，读事务固定开销 27.4 周期、写 7.3 周期），得出“瓶颈在事务次数而非带宽”的结论，再据此定出帧缓冲行跨 4096 字节（行不跨 4 KB 边界）、4 像素并行、长突发优先的像素通路。第二，软硬同规格双实现。软件执行器与硬件流水线实现同一份逐像素规格（六种混合方程、除以 255 舍入、裁剪与色键语义全部定稿），软件侧既是 PC 开发平台，也是硬件的金标准参照。第三，全链路自研闭环。从 PNG 素材打包、Flash 镜像合成、bootloader 引导、素材装载，到游戏逻辑、碰撞检测、命令生成、统计埋点，均为团队自行实现，整链在真实板卡上运行。第四，可观测性贯穿始终。硬件性能计数器（命令数、像素数、色键跳过数、读写突发与 beat 数、等待周期）与软件统计按同一统计定义设计，板上可直接对账。

## 1.5 超越赛题要求的创新点

赛题要求的是“指令解析、块拷贝与填充、HDMI 输出、总线直访、C 驱动、双缓冲、软硬同屏对比”七项基础能力与“Alpha 混合、Color Keying、高负载 Demo 冲极限”三项高阶能力。以下六项是在这些要求之上本作品额外给出的工程创新。

（1）赛题要求“总线直接访问内存 + 突发 + FIFO”，本作品进一步把 DDR3 事务模型实测成设计输入：识别出固定事务开销（读约为写的 3.8 倍）才是并发瓶颈，用数据布局（行跨 4096 字节）与访问形态（长突发、读改写合并）直接消解，而非堆砌带宽。

（2）赛题要求“硬件 Alpha 混合与 Color Keying”，本作品进一步用同一份逐像素规格驱动软件与硬件两个实现，配以全定义域穷举校验（ALPHA 预乘路径 8,421,376 组逐值一致）与板上同帧 CRC 对比，使“加速不改画”成为可验证的性质。

（3）赛题要求“稳定 60 FPS 下冲同屏精灵极限”，本作品进一步把这条要求做成可执行判据：倍增到首次失败再二分收敛，候选档以 3600 场确认，在真实游戏负载上自动搜索并记录，极限值因此可复测、可复核，而非一次性演示读数。

（4）赛题只要求“解析渲染指令”，本作品进一步把命令 ABI 做成表面表间接寻址，并内建裁剪、越界、重叠检查与十步错误模型，错误码、错误定位与首错副作用语义完整，驱动无需信任输入。

（5）赛题未要求多执行模式，本作品在同一比特流上给出直通、条带与硬件分桶三种模式：片上存储（16 KiB 源纹理、640×16 行条带缓冲）使高频小素材与弹幕写入脱离 DDR3 随机访问；条带语义经万张级构造差分、真实游戏整帧对拍与 9,208 帧板上回放验证与直通逐像素一致。

（6）赛题未要求消除 CPU 构造开销，本作品的硬件空间分桶（参数缓冲）后端把分桶计算与跨带记录复制移入硬件：CPU 每帧只发布一份原始绘制与实例数组，引擎以两次遍历建立按条带组织的保序引用表，执行阶段逐桶取用；同一比特流同轮对照下两种弹型 N_max 提高 16.9%/12.3%，每帧读突发减少 70%、写突发减少 92%，并以 9,208 帧板上回放验证逐帧一致。

## 1.6 设计流程

开发先打通下载、内存、显示和启动四条板级通路，再用探针实测 DDR3 事务与多主机仲裁，据此实现计算、搬运、几何、阵列和控制层。软件侧同步实现同规格执行器与游戏，最后以整帧 CRC、性能计数器和真实 N_max 搜索完成整机联调。各层先写判据，再实现和验证；正常用例通过后，注入代表性错误并要求判据报错，以检查验证本身的有效性。

## 1.7 相关工作与本作品的定位

2D 图形的硬件加速有两条主线。第一条是合成语义：Porter 与 Duff 把 Alpha 合成抽象为一组算子 [8]，此后硬件混合单元的语义基本建立在这套代数上，本作品的六种混合方程与预乘主路径正是它的直接实现。第二条是固定功能 2D 引擎：面向 MCU 的 DMA2D 类加速器以寄存器级命令完成块拷贝、格式转换与两图层混合 [10]；FPGA 上也有面向精灵的专用引擎，例如用高层次综合与片上存储实现多精灵处理的硬件引擎 [13]，以及 2D 图形系统的软硬协同设计 [14]。这类工作把逐像素搬运与混合从处理器移入硬件，命令通常由处理器逐条写入、执行模式单一。

当像素通路不再是最紧的瓶颈，限制随之转移到访存。Rixner 等人的访存调度研究表明，行缓冲命中与突发组织对有效带宽的影响可以超过峰值带宽本身 [12]；Molnar 等人的排序分类则指出，按空间局部性重排访问可以把随机访问转成连续访问 [11]，移动端的图块化渲染沿用了同一思路 [16]。本作品把这两条结论落到 2D 弹幕负载上：以板上实测的事务模型定 4 KB 行跨与长突发，用 16 KiB 片上纹理消除重复读事务，用 640×16 行条带缓冲把随机小写合并为连续写，再用参数缓冲把跨带记录复制移入硬件。

正确性方面，差分测试以同一输入驱动两个独立实现、用输出差异判定缺陷，是成熟的等价性判据 [15]。本作品把它工程化为同规格软硬双实现：软件执行器作为金标准，与硬件流水线共用一份逐像素规格，并以全定义域穷举、同帧 CRC 与 9,208 帧回放逐层收敛。

与上述工作相比，本作品的定位在三点：命令以 32 字节定长表提交、由引擎自取，处理器每帧只发布一份原始绘制与实例数组；同一比特流上提供直通、条带与硬件分桶三种执行模式，可按负载切换并同板对照；把“稳定 60 FPS 下的同屏精灵极限”做成可复现判据（倍增到首次失败、二分收敛、3600 场确认），使性能结论可复核。
