# 第一部分　作品概述

## 1.1 功能与特性

本作品实现了一套能在 FPGA 开发板上运行弹幕游戏、直接向 HDMI 显示器输出画面的 2D 图形加速系统。自研部分包括硬件 2D 位块传输（BitBlt）引擎、显示链路、C 驱动、软件执行器和游戏机前端，覆盖赛题要求 [1]。

FIG|../Assert/photos/board_system_20261101.jpg|本作品运行实拍|12

RISC-V 处理器承担输入、运动与碰撞计算，并将本帧所需的背景、角色与弹幕整理为绘制任务；FPGA 引擎据此完成图像块拷贝、纯色填充、Alpha 混合与颜色键控去背，结果写入显存后由显示通路输出至 HDMI。双缓冲使绘制与显示各占用一块缓冲，避免画面撕裂。针对同屏小图块数量大、复用率高且相互重叠的特点，引擎将常用贴图驻留片上反复取用，按屏幕横条就地合成后整条写回，各横条所需的绘制内容亦由硬件统计与排序。前端提供基础演示、弹幕游戏、压力测试与三维走廊轨道射击四个应用，可在菜单间切换并实时显示帧率与绘制数量；在开启 Alpha 混合与颜色键控去背时，同屏 2187 颗 8×8 弹幕仍维持 60 FPS。

## 1.2 应用领域

从早期 2D 游戏机到当代嵌入式图形界面，画面的生成长期依赖处理器逐像素搬运与混合。这类重复操作占用了大量处理器时间，帧率随图层与绘制元素增加而下降。图形界面的共性在于素材高度复用、图层相互遮盖，绘制数量又随状态起伏；通用处理器并不擅长此类逐像素工作，异构计算与软硬件协同因而成为主流做法。

FIG|../Assert/third-party/app_ui_samples.jpg|医疗与车载界面 [9]|14.4

本系统适用于工业控制、医疗监护、车载仪表、智能家居与游戏娱乐等二维界面。这些界面的绘制任务以搬运、填充和图层叠加为主，对稳定的帧率与较低的主控成本有共同诉求。由专用硬件承担像素级操作、处理器专注于业务逻辑，可在不改变上层界面结构的前提下提升整体表现。

## 1.3 主要技术特点

系统以命令驱动方式组织绘制：处理器只更新状态并提交一组绘图任务，之后由引擎自主取指、访问内存并完成像素运算。基础流水线在连续供数时每周期处理 4 个像素，4 个像素的 RGB 三通道由 12 个 DSP 并行完成混合。

针对源读取、目的写回与命令构造的三项手段，收敛为直通、条带和分桶三种执行路径。三者共用同一套二维操作语义，同一应用可在其间切换，不同实现因而能在相同负载下对照。

软件在 PC 与板上双目标构建，画面先在 PC 上验证再上板运行。硬件按目标负载分为二维与三维两种构型，分别在逻辑与存储资源之间取舍。

## 1.5 主要创新点

赛题高阶要求是开启硬件加速（Alpha 混合 + Color Keying）时保持 60 FPS，挑战同屏活动元素（Sprite）数量极限。本作品从源读取、目的写回与命令构造三处逼近，并扩展到三维，形成四项创新：

（1）片上纹理：高频素材驻留片上，不再读 DDR3。

（2）条带缓冲：同一区域片上合成，整带写回。

（3）硬件分桶：FPGA 生成保序引用，替代 CPU 分桶复制。

（4）三维扩展：条带框架加三角形光栅与深度缓冲。

## 1.6 设计流程

设计流程由赛题要求与游戏负载共同确定软硬件分工。首先定义命令接口与表面登记方式，完成基础绘图、双缓冲和显示链路，使分工可运行、可对照；随后按帧分段测量，把一帧的时间拆到源读取、目的写回与命令构造三处，据此依次优化，每一步都用同一负载做前后对照；最后扩展三维通路，两种构型分别综合、上板测量并回归既有功能。
