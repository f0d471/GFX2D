# Deliverables

对外交付物：技术报告、讲解用的幻灯片，以及两者共用的图片与图片源码。

工程本体在 [`../Main/`](../Main/)，开发过程在 [`../Engineering/`](../Engineering/)。
本目录不产生新结论，只把那两处已有的结论讲给别人听。

## 数字从哪里取

报告和幻灯片里的每个数字都要能在仓库里找到出处，优先级如下：

1. `../Engineering/TechReports/` 里的实测章节，例如 platform 第 03 章的突发预算。
2. `../Main/doc/赛题二总体设计.md` 里注明了实测日期的数字。
3. 同一文件里的估算。引用时必须在页面或正文上标「估算」。

没有出处的数字不写。其他项目里测过的数字不能当作本工程的实测，
设计文档 3.1 节已经因为这个订正过一次。

实测被后续实验推翻时，`TechReports/` 会在原章订正。
交付物引用过的数字要跟着改，所以每份交付物的 README 里登记它引用了哪些数字、出自哪一节。

## 共同约定

- **不写绝对路径**，与仓库其他部分一致。
- **不用 emoji**，状态用文字表示。
- **不用 AI 生成的插画。** 配图只有三种来源：自己画的结构图与数据图（源码放 `Assert/`）、
  板上实拍与录屏、带出处的第三方图（出处登记在 `Assert/` 的台账里）。
- **行文直接陈述事实。** 不用破折号插入语，不写「不是 A 而是 B」式对比，
  不写「唯一」「彻底」这类绝对化用词，不写排比。
- **实测与估算分开标。** 估算的数字在页面上注明「估算」；还没有做的部分在结构图里画灰色虚线。
