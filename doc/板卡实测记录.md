# 板卡实测记录

2026-09-16，开发板用板载 Type-C 线接入本机后的实测结果。只从资料推出、没有实际测到的内容单独标注。

## 1. USB 枚举

| 项 | 实测 |
| --- | --- |
| 芯片 | FTDI FT4232H，VID `0403`，PID `6011` |
| USB 描述串 | `Quad RS232-HS`，是 FTDI 出厂默认值，EEPROM 里没有写板名 |
| 序列号 | 设备实例路径为 `5&2C0399E&0&9`，是按接入位置生成的，说明 EEPROM 里没有序列号 |
| 接入位置 | 根集线器 Port_#0009 |
| 驱动 | 四个接口都是 FTDI VCP 2.12.36.20（服务 `FTDIBUS`） |

本机没有 COM8。四个接口与串口号的对应关系，由设备管理器中接口与串口设备的父子关系查出；板上用途取自原理图（设计说明第 13 页，U5 FT4232HL）：

| 接口 | FT4232 通道 | 串口号 | 板上用途 | 驱动 |
| --- | --- | --- | --- | --- |
| Interface 0 | A（ADBUS0~7） | COM9 | 未连接，8 个脚全部悬空 | 不用动 |
| Interface 1 | B（BDBUS0~3） | COM10 | JTAG：TCK、TDI、TDO、TMS，各串 33Ω | 要换成 libusbK，Efinity Programmer 和 OpenOCD 才能访问 |
| Interface 2 | C（CDBUS0/1） | COM11 | UART：CDBUS0 接 `UART_TX_3V3`，CDBUS1 接 `UART_RX_3V3`，两根线上各有一个指示灯（D15、D16） | 保持 FTDI 驱动，作串口用 |
| Interface 3 | D（DDBUS0~7） | COM12 | 未连接 | 不用动 |

由此得到三点：

- 板上没有单独的 SPI 下载通道。Efinix 官方 Ti60F225 开发套件用 Interface 0 烧 Flash，这块板不一样，Flash 只能在 Programmer 里选 `SPI Active using JTAG Bridge` 烧写，设计说明第 85~86 页也是这样做的。
- 资料目录 `02_.../驱动安装及说明/` 下的 `XL_YLS_DL_*` 驱动包是外接下载器 YLS_DL 用的，写的是 FT2232 的 PID `6010`，与板载 FT4232H 的 `6011` 不符，不要装。那个目录里的 `zadig-2.8.exe` 可以用。
- 设计说明第 87 页让 OpenOCD 配置写 `ftdi channel 0`，但原理图上通道 A 是悬空的，两者矛盾。以原理图和本仓 `sdk/bsp/efinix/EfxSapphireSoc/openocd/ftdi_ti.cfg` 的 `channel 1` 为准；上板时如果 OpenOCD 连不上，再核对这一点。

## 2. 串口

- FPGA 侧：`system_uart_0_io_rxd` 在 GPIOL_02（R4），`system_uart_0_io_txd` 在 GPIOR_28（R14），3.3V LVCMOS。`fpga/ddr_demo_ti60/ddr_demo_ti60.peri.xml` 与设计说明第 34 页一致。
- 实测：COM9~COM12 同时以 115200、8N1 打开，DTR/RTS 不置位，只收不发，监听 8 秒，四个口都收到 0 字节。
- 这只能说明这 8 秒内板子没有往串口输出。板上 Flash 里现在是什么设计、SoC 是否在运行，都还不知道。官方示例只在启动时打印，要在按复位或重新上电的同时监听 COM11 才能判断。

## 3. JTAG 与 OpenOCD 配置

- `ftdi_ti.cfg` 中 `vid_pid 0x0403 0x6011`、`channel 1`，与上表的 JTAG 通道一致。
- 新版 IDE 使用的配置分支里 `ftdi device_desc` 一行是注释掉的，不按描述串匹配，所以 EEPROM 保持默认的 `Quad RS232-HS` 也不影响。旧版 IDE 分支里仍写着 `ftdi_device_desc "Titanium Ti60F225 Development Kit"`，用不上。
