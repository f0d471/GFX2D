# doc：文档

| 文件 | 内容 | 什么时候看 |
| --- | --- | --- |
| `开工前准备情况.md` | 当前工程的资源占用、可裁剪项、接入准备的完成情况与下一步清单 | 接手先看这份 |
| `赛题二总体设计.md` | 方案：指标口径、资源划分、加速器结构、软件分层、待测实验、里程碑 | 做具体模块前看对应章节 |
| `板卡实测记录.md` | 流水账：USB 枚举、串口、JTAG、命令行上板流程、比特流与时序对照、Flash 读写 | 要具体命令或历史结论时查 |

## 分工

- **设计文档**写的是打算怎么做，以及为什么这么选。数字带「估算」两个字的都还没有实测。
- **实测记录**写的是实际做了什么、命令是什么、结果是什么、踩了哪些坑。只记已经发生的事。
- **准备情况**是一份清单，回答「现在能不能开工、还差什么」。

各目录的 README 负责说明该目录下的文件，不重复这三份文档的内容：

- `rtl/README.md`：源码分层与各文件来源
- `fpga/README.md`：Efinity 工程、PLL、管脚、编译
- `sdk/README.md`：BSP 与官方示例，以及我们改过的地方
- `sw/README.md`：自己写的程序与编译方法
- `sim/README.md`：仿真与注错规则
- `bit/README.md`：比特流与 Flash 备份
- `tools/README.md`：辅助脚本

## 约定

- 结论要带出处：文件路径加行号，或者报告名加章节。
- 没有实测的数字必须标明是估算或推测。
- 上板类结论要写清判据和对照组，例如「注错见红」这一组是否做过。
