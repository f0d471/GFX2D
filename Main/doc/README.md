# doc：方案与手册

本目录只放两类文档：这个工程打算怎么做，以及在一台机器上怎么把它跑起来。
各文件都描述当前状态，不记录过程。

| 文件 | 内容 | 什么时候看 |
| --- | --- | --- |
| `赛题二总体设计.md` | 方案：指标口径、资源划分、加速器结构、软件分层、待测实验、里程碑 | 做具体模块前看对应章节 |
| `验证流程.md` | 按影响选择检查、quick / acceptance / release 档、缺项状态与证据复用的唯一规则 | 开工选择范围、提交与验收之前 |
| `三维数值契约.md` | Q16.16、视空间裁剪、Q12.4、128B setup ABI、参考光栅与舍入规则 | R1 软件、R2 硬件与 R3 对拍 |
| `开发环境.md` | 第 0 节是标准工作流程（写 RTL、仿真、编译比特流、编译软件、上板、提交各步的顺序与判据）；其余是工具链清单与获取方式，编译、加载、调试、烧写、仿真的命令 | 每次动手改工程前看第 0 节；换机器、装工具、忘了某条命令时看其余各节 |

设计决策的依据与实测数据写在 `赛题二总体设计.md` 对应章节，就地写全；
硬件各模块的职责、编码表与协议见 `../rtl/README.md` 与 `../rtl/engine/engine-manual.md`；
软件分层与构建见 `../sw/README.md`；当前整机资源与时序登记在 `../README.md`「现在的状态」。

## 各目录的登记

每个目录的 README 说明该目录下的文件从哪来、能不能改、有没有被工程引用，
不重复本目录文档的内容：

- [`../rtl/README.md`](../rtl/README.md)：源码分层与各文件来源
- [`../fpga/README.md`](../fpga/README.md)：Efinity 工程、PLL、管脚
- [`../sdk/README.md`](../sdk/README.md)：BSP 与官方示例，以及改过的地方
- [`../sw/README.md`](../sw/README.md)：本项目编写的程序
- [`../sim/README.md`](../sim/README.md)：仿真与注错规则
- [`../bit/README.md`](../bit/README.md)：比特流与 Flash 备份
- [`../tools/README.md`](../tools/README.md)：辅助脚本

## 约定

- 结论要带出处：文件路径加行号，或者文档名加节号。
- 没有实测的数字必须标明是估算或推测。
- 上板类结论要写清判据和对照组，例如「注错见红」这一组是否做过。
- 不写绝对路径。需要指工具安装位置时用 `开发环境.md` 第 1 节的占位符，
  实际取值只出现在该文件第 11 节。

- [平台软件接口](平台软件接口.md)：公开 SDK、职责边界、资源所有权与生命周期。
- [应用与输入契约](应用与输入契约.md)：console、UART 线协议、调度和固件状态。

应用玩法、美术、HUD 和手感不在本目录立长期规格。
