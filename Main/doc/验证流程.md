# 验证流程

本文件是检查范围、通过状态和证据复用的唯一规则。操作命令见
[开发环境](开发环境.md)，可执行的检查清单由 `tools/check/validate.py --list` 给出。
模块 README 说明专项判据，不再各自规定提交前全量回归。

## 维护范围

正式工作点覆盖硬件、驱动、共享接口、参考模型、配套框架和验证工具。
应用玩法、美术和手感按效果迭代，做对应构建/冒烟即可，不自动建立 spec、TechReport
或待试玩任务。修改 ABI、资源所有权、参考结果或声明硬件性能时，仍选择实际受影响判据。
game、stats、flight、sh 等应用专项按需要显式选择；固定硬件测试负载继续保留。
生产流水所有权有独立 `pipeline` 项，不以玩法或截图检查替代。

## 1 按改动选择范围

开工时登记改动文件、受影响的消费者、检查项、档位与板测需求。检查的是本次声明的行为；
未影响的历史结果继续保留其原版本边界。完成检查后再次核对源码未变。

| 改动 | 默认验证 | 何时扩大 |
| --- | --- | --- |
| 文档、索引 | 路径与引用；图片或排版变动补目检 | 不触发仿真、综合或板测 |
| 检查脚本、解析器、编排 | 流程行为测试、既有日志的正反例、受影响的真实检查 | 改部署／串口控制时补代表性板测 |
| 普通应用局部逻辑 | 相关单测、该应用构建与场景 | 改库、BSP、构建或共享接口时加入消费者 |
| 绘制语义、命令构造、renderer | 独立模型、受影响的 RTL 集成、相关回放 | 新候选采用／默认后端切换前完成候选完整回放与板测 |
| RTL 内部 | 模块正常用例、[外部变异活动](../sim/mutation/README.md)（`run_mutation.py --run`）、直接消费者和相关帧级检查；整机综合、时序 | 改共享控制、复位、总线或公共 AXI 模型时扩展至全部消费者 |
| 顶层、PLL、DDR、SoC IP、约束 | 相关平台与引擎回归、完整构建、部署与功能板测 | 变更启动／Flash 布局时加入启动判据；性能结论变化时测对应负载 |
| 正式交付／采用候选 | 冻结输入与构建参数，完整执行已选定的正式判据 | 全仓回归由全局依赖变化或明确的交付范围触发 |

“模块 + 消费者”按真实依赖选择。共享 AXI 从机模型改变时覆盖所有使用者；
HDMI 独立编码模块不因修改游戏文字而重跑。新增功能不因旧清单没有登记而免检。
`--changed` 只生成建议，执行前按工作点复核；未知依赖保留显式待定范围。
未映射的代码改动必须显式选择 `--checks`，不能只运行路径检查后宣称功能通过。
各检查的输入模式登记在唯一清单中，是保守依赖范围；补充或收窄时同步维护消费者。

## 2 档位与状态

| 档位 | 用途 | 边界 |
| --- | --- | --- |
| quick | 日常局部验证 | 正常／定向变异仍保留；Demo 每段每遍 120 帧，实例完整引擎采用 25 个代表用例、分桶采用 64 张 RTL；不做录像重搜、生产模式完整 N_max 双进程搜索与十分钟日志长跑 |
| acceptance | 工作点正式验收 | 选定项使用全量参数；实例 144 组、分桶 10000 张；选中游戏／统计专项时包含重搜／长跑 |
| release | 冻结交付范围的复现 | 全量参数与 acceptance 相同；按交付清单补齐平台、当前候选回放、部署与相关板测，人工观察单独登记 |

档位不代表检查了所有功能。结果必须同时写明档位、实际检查项及未覆盖范围。
快速通过不能代替候选的完整验收；宿主回放不能代替硬件回放；JTAG 装载不能代替 Flash 启动。

| 状态 | 意义 | 进程结果 |
| --- | --- | --- |
| PASS | 本轮选定范围的必需判据全部通过 | 0 |
| FAIL | 判据失败、输入改变或证据不一致 | 1 |
| INCOMPLETE | 必需项因工具链／设备／显式跳过而未执行 | 3 |
| NOT_APPLICABLE | 按声明范围不适用，必须附原因 | 不阻塞该范围 |

`SW7_SKIP_SEARCH=1`、`SW8_SKIP_LONG=1` 是显式缺项，返回 INCOMPLETE；
quick 档依规则排除这两项时记录 NOT_APPLICABLE。缺交叉工具链始终属于必需构建未完成。
素材检查在 quick 档缺目标镜像时仅覆盖素材；正式档缺镜像输入属于 INCOMPLETE。
上层必须消费状态／退出码，不能仅凭日志中的 `fail 0` 宣称完整通过。

## 3 执行与同轮去重

WSL 中从仓库根运行，交叉工具链按开发环境第 11 节设置：

```sh
python3 Main/tools/check/validate.py --list
python3 Main/tools/check/validate.py --changed Main/doc/验证流程.md
python3 Main/tools/check/validate.py --checks workflow pipeline --profile quick
python3 Main/tools/check/validate.py --checks workflow pipeline --profile quick --run
python3 Main/tools/check/validate.py --checks instances bin --profile acceptance --run
```

默认只打印计划，`--run` 才执行。每轮打印 RUN 相对路径，后续用
`--run-dir Main/sim/build/check-runs/<运行号>` 与相同档位、参数和检查范围续跑。
同轮已有通过项自动复用；输入或参数改变则拒绝续跑，必须开始新轮。
物理板测每次实际执行，不自动复用设备状态；原始输出缺失属于未完成，不能汇总通过。

库与应用正常 64/32 位测试在同轮各编跑一次，游戏／统计专项读取相同结果；
专项的输出断言与不同变异保持独立。实例的 `--legacy` 包含 v2，重复选择只执行一次；
分桶的 `--platform` 包含 `--platform-hw`，重复选择只执行一次。

生产源码、ABI、参数、工具链或输入变化后重新验证受影响项。研究原型与冻结取样仅在
研究工具／语义／输入改变或正式复现需要时执行，不默认绑在日常提交中。
混合全定义域穷举保留在 blend 项，只有混合核／方程／位宽／相关判据改变或交付范围包含它时运行。

## 4 运行与归档证据

新检查输出进入已有忽略目录 `Main/sim/build/check-runs/<运行号>/`：

- `plan.json`：选择范围、档位和实际命令。
- `run.json`：源码与输入身份、参数、各项状态及产物登记；同轮未变文件复用已登记摘要。
- `logs/`：本轮原始输出；`build/` 与 `shared/`：本轮中间产物和公共测试结果。
- `result.json`：本轮所选检查项的汇总，包含范围；无此结果不视为完整通过。

实例／分桶、条带数据面／控制／整机和前端复现工具接受公共 `--run-dir`、`--profile` 参数。
未指定运行目录时建立新轮，不写回历史 `sim/**/logs/`。
输入与产物的身份缓存位于同一忽略目录的 cache/，未变文件跨轮复用；内容／大小／时间戳变化时重新登记。
发生保留时间戳的复制或外部改写时，用 `--fresh-inputs` 强制复核。检测到变化的运行永久失效，必须开始新轮。
实例的 `--collect` 仅汇总本轮正式宿主／RTL，不代表板测或综合通过；旧完整归档使用
`--review-archive --archive-dir <仓内历史日志目录>` 只读复核，结果写入新轮 archive-review。
分桶的完整 `--collect` 消费同轮正式软件／RTL组，DDR 日志诊断由显式 `--ddr-log` 产生。
quick 档拒绝生成正式完整汇总。
已有归档日志保留为原版本证据；检查历史日志属于“历史复核”，不表示当前产物已重跑。

汇总／归档需要本轮通过状态与未变化的输入，不接受只复制进来的 PASS 文本：

```sh
python3 Main/tools/check/validate.py --run-dir Main/sim/build/check-runs/<运行号> --profile quick --collect
python3 Main/tools/check/validate.py --run-dir Main/sim/build/check-runs/<运行号> --profile quick --archive <新的仓内证据目录>
python3 Main/tools/check/validate.py --run-dir Main/sim/build/check-runs/<运行号> --snapshot --archive <新的历史快照目录>
```

归档只复制清单与原始输出，复制后验证字节身份，目标存在时拒绝覆盖；构建目录不入库。
保留一份完整身份清单，正文引用它，不多处抄录长摘要。
--snapshot 只保留运行当时的状态、输入与缺项，不重判当前源码，也不生成新的通过结论；
可用于保存已完成的失败诊断。归档元数据的本机路径替换为占位符，原始日志字节保持不变。

## 5 综合与板测边界

RTL 排版也可能改变 Synplify 映射，仍需整机综合确认资源、告警与 setup/hold。
不能以 token 等价代替综合，也不能只比较 RAM/DSP 和 slack 就宣称位流相同。
只有部署对象及依赖已确认未变、原板测范围仍适用时才复用板测；新位流按影响选择板测范围。
普通脚本／文档修改不重建位流。性能只在性能路径改变、报告新数字或正式采用候选时测量。

Windows 的 Efinity Python 下执行代表性部署与引擎功能检查：

```text
python Main/tools/check/validate.py --checks board --profile quick --run
```

该入口自动从 FT4232H C 接口定位当前 UART，也可设 `GFX_CHECK_PORT`；
先扫描 JTAG、检查当前位流与时序，再部署、两次调试连接、重建并加载 engineTest、
检查部署字节数、完整结束行与引擎功能。独占 COM/JTAG，不写 Flash、不生成新性能结论。
设备缺失或 B 接口驱动未恢复时记录 INCOMPLETE；历史 COM 号不能视为当前事实。

完整板测工具继续承担候选 CRC/PERF/padding、同 BIN 对照和硬件回放。
新运行目录下的板测与综合身份清单跟随该轮保存。HDMI 现象和实体按键等人工观察保留独立状态。
