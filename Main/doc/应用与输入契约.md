# 产品应用与输入契约

## 入口与应用

PC 和 Ti60 产品运行同一份 `sw/apps/console`：默认进入菜单，应用管理器、菜单、
游戏内容和导航规则一致。PC 由宿主事件循环驱动，Ti60 由 FreeRTOS runner 驱动。
组合入口在`sw/firmware/console`，通用管理器在`sw/runtime`；平台与内容接线分别在
`sw/ports/host|ti60`与`sw/ports/myriad`。新应用的公开边界见[平台软件接口](平台软件接口.md)。
`gfx2dGame` 保留为明确的开发/判据入口，不作为产品默认菜单实现。

| ID | 内容 | 全局快捷键 |
|---|---|---|
| 0 | 系统菜单 | Esc / Backspace |
| 1 | 基础 2D 演示，方块与大图切换 | 1 |
| 2 | 弹幕游戏 | 2 |
| 3 | 压力测试 | 3 |
| 4 | 三维走廊与茶杯 | 4 |
| 5 | 系统信息 | 在菜单选择 |

菜单不出现在可启动内容列表中。应用 ID 与注册顺序无关，重复启动当前应用不重开；
需要重开游戏时先返回菜单再进入。PC 开发者可显式用 `--app <ID>` 跳过菜单，
`--frames`、`--input-script frame:keys,...` 用于定向自动化。

## 系统与应用输入

- Enter / Space：菜单确认。系统信息页再次确认或 Space 返回菜单。
- Esc / Backspace：全局返回菜单，按下沿生效，不按渲染帧数计时。
- 数字 1/2/3/4：全局启动固定 ID，不随页面改变含义。
- C：三维场景切换；基础演示中切 A/B 场景。
- Tab：应用内切绘制后端；Shift：三维 L1/L2 阶梯，弹幕慢速移动。
  PC产品仅提供CPU绘制；旧开发/判据入口保留硬件模型模拟，PC耗时不作为板上性能。
- 方向 / WASD：移动；Space：游戏炸弹；射击与无输入自动演示沿用原内容规则。

框架先消费系统启动/返回命令，应用不处理 MODE 位。切换边界消费仍按住的启动、
确认和应用热键直到松开，方向保持可继承；三维内部重进同样保留热键的按住状态，
一次按下只切换一次。菜单返回后保留上一次菜单选择。

板载 KEY0～3 正常映射左/下/上/右。仅产品前端启用物理键组合：左右同按确认，
上下同按返回；游戏中的确认可使用炸弹。PC 方向键组合不再触发导航或后端切换。
旧裸机判据未启用产品映射，保留原输入语义。

Windows 转发支持 Enter、Esc/Backspace、C。XInput：A 炸弹、LB 慢速、Start 确认、
Back 返回、RB 场景、B 切后端。面板 F8 暂停/恢复转发，Esc 保留为返回操作。
PC 产品端用 F11/Alt+Enter 切全屏；Alt+Enter 不同时产生确认动作，Esc 返回菜单时
保留产品端的全屏状态。旧窗口判据入口保持原 Esc 退出全屏行为。

## UART 快照

接收仍保留短按上升沿；300ms 无有效更新会释放远程按键。上游持续转发每 100ms
至少发送一次快照，长按脚本也必须重发。校验失败不改变有效按键和超时锚点。

旧 10bit 包保持不变：`header=80h|(keys&7fh)`，
`data=(check4<<3)|(keys>>7)`，`check4=(keys^(keys>>4)^(keys>>8))&0fh`。

扩展 14bit 包为 `ff 7f lo7 hi7 crc7`，CRC多项式为`x^7+x^3+1`、初值0，
按lo7、hi7顺序逐字段高位先行。`ff 7f` 是校验无效的旧包，旧接收端不会把它
作为有效按键。扩展位 10=确认、11=返回、12=场景；位 13 保留。
发射器对 0..1023 继续发旧包，存在扩展位时发新包，禁止越界后静默截断。

## 生命周期、资源与故障

应用声明稳定 ID、名称、描述和 enter/frame/leave 回调。enter 成功后才提交活动状态；
frame返回0表示本次步骤成功生成/提交了新绘制，1表示内部切换/无新帧，负值表示失败。
异步路径的回调完成数可领先实际完成/呈现一帧；设备完成由票据确认，呈现量由交换计数确认。leave的
排空结果必须检查。旧应用排空失败时不得配置下一应用的表面、TEX 或帧缓冲。

发生进入、绘制或退出失败时，框架先使活动应用失效，再确认引擎复位/物理排空，
完成部分初始化的清理，恢复菜单。排空/清理失败则保持故障状态，不继续绘制；
返回命令可重试恢复。错误累计与日志丢弃可观察，不通过新应用初始化将它们清零。
应用切换保留全局双缓冲状态，只有完成呈现的缓冲才被登记为前景。

产品与旧入口共用 `ports/myriad/stg_runtime` 的启动、表面登记、TEX 热集、后端覆盖
和三维钩子。覆盖层显式接收应用模式，保留旧 INJECT_TEX_CRC 与 G1/G4 影子对拍能力。
压力测试更换后端会重新开始搜索，避免同一搜索混用两种执行负载。

## 时间与构建策略

Ti60 使用标准 RISC-V FreeRTOS CLINT 端口，内核 tick=1kHz。CLINT 地址来自
`bsp/include/board_clock.h`，BSP 对生成的 SoC 地址做静态断言。显示中断只派发显示
与引擎事件，不推进内核时间；比较寄存器读回为零不能用来判定 timer 不可用。
显示与引擎分别使用独立的计数事件；各自等待使用带1ms超时的阻塞钩子，runner 每次迭代也让出 CPU；输入、后台监控和 idle
都必须有进展证据。

产品构建的 `PIPELINE` 决定引擎流水，`DIAGNOSTIC` 决定逐帧 CRC/诊断，`PERF` 保留
产物与旧统计档位。默认 `PIPELINE=1 DIAGNOSTIC=0`；逐帧对拍显式选择
`PIPELINE=0 DIAGNOSTIC=1`，仍可使用同步硬件执行。禁止异步写帧期间读取该帧 CRC。
旧判据没有显式设置时，保留原编译参数对应的策略。
应用私有包含路径放在`APP_CPPFLAGS`，不扩散到lib/BSP编译；内核/端口显式接收其可信
配置头路径。所有影响编译的配置进入构建stamp，改变后清理整个OBJDIR。
跨目录源码的父路径在对象名中编码为`__up__`，对象和依赖文件始终位于本次OBJDIR内，
不直接把`../../`拼接到对象路径；分层检查以host/target的A/B/A不同参数构建验证隔离。

## 状态协议与验证

启动声明 `console protocol 2 tick_hz 1000`，进入行只在进入成功后输出。
`console complete app ... id ... frames ... presents ... errors ...` 给出离开前的真实完成量。
`console status` 使用键值字段，包含版本、应用、后端、`fps_milli`、完成帧/呈现、错误、
丢日志、场景/阶梯、毫秒 tick、显示中断、堆/任务数、idle/monitor。FPS 按实际窗口
毫秒数归一；系统页的 UPTIME MS 与这个时钟一致。面板解析产品状态并兼容旧 CSV/R4 日志。

验证入口：`validate.py --checks console` 覆盖真实框架故障、64/32 位、sanitizer、
协议穷举、实际宿主菜单/四应用和反例；Windows 的 `console-board` 每轮调用 make，
绑定本轮 bit/BIN，检查全部应用的真实出帧、独立时钟、后台任务和零错误状态。
使用 `board_run.py --precise-boundary` 将加载与运行分开，在 CPU 停止时清掉旧串口
数据后才运行。历史日志需同时提供身份清单，不能代替当前板卡状态。

JTAG 验证与 Flash 固化分开；新产品程序未写入 Flash 时，断电启动仍由原固件决定。
