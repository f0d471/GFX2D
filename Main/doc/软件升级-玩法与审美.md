# 软件升级：玩法与审美（2026-10-25）

状态：**实施中**。范围由老师五点要求收敛而来：只做**画面审美**与**玩法**两个维度；
音频、外设交互、RTOS、摄像头、AI 一律不做。**B7 位流保持冻结**，全部改动在软件与素材层。

权威口径：本文与代码注释一致时以代码为准；判据的权威在 `tools/check/check_sw7_game.sh`。

## 1. 约束（为什么这样做）

游戏有一条确定性契约（`stg_game.h` 头注释）：`stg_game_step` 的逐帧结果被三样东西消费——
两遍运行逐字节相同的判据日志（G10/G15）、自动驾驶与按键脚本、**通关录像
`replay/stg_clear.g2dr`**（搜索器重搜必须与入库录像逐字节相同，G16b）。
因此改动分三层对待：

| 层 | 能不能动 | 依据 |
| --- | --- | --- |
| 仿真规则（`stg_pool`/`stg_emit`/`stg_collide`/`stg_game` 的规则步） | **不动** | G4/G5/G7/G8/G12/G17 全部冻结在其上；规则改动会作废通关录像 |
| 关卡常量（`stg_stage`） | 经典路线**不动**；EX 路线**新增**（见 §4） | G13 对经典关卡表断言；G16 录音只覆盖经典路线 |
| 绘制层（`stg_draw`/`sw6_hud`）与素材 | **放开改** | 判据不比对金标准帧 CRC，只比对"两遍相同 + 计数恒等式"；恒等式见 §3 |

3D 模式（R4 茶杯）**不做视觉改动**：`check_r4_board.py` 的三场景 CRC 与 R4 验收证据绑定，
收益配不上重跑全部 R 系判据的成本。

## 2. 素材升级（`tools/assets/gen_stg_neon.py`）

12 张既有 PNG **几何全部冻结**（格子尺寸、行数、帧数、文件名不变，游戏代码零改动），
只升级每格内部的画法；另新增 4 张背景/特效图。全部仍是按坐标算出的确定性图案，
`--check` 与新基线逐像素比。清单：

| 项 | 改动 |
| --- | --- |
| `bul16/bul8/rice20` | 弹芯白心更亮，光晕分内环/外环两层，米弹加运动方向拖尾渐隐 |
| `pshot` | 芯更亮、两侧羽化 |
| `spark` | 4 帧从"闪烁"改为"爆-散-暗-灭" |
| `ships` | 线框改为填充+深色描边（剪影可读），自机加引擎光点 |
| `boss` | 六边形/六芒星改渐变填充+亮缘+内部纹样 |
| `title` | 加装饰框、底光与副标题线 |
| `stars/icons/digits/font_cyan` | 配色并入统一色板 |
| **新增** `bg_layers.png`（512x608，槽 15） | 背景合图：天空 400x480（三段渐变+两团星云+三条极光带）+ 远景剪影带 512x56 + 城市剪影带 512x72。表面 ID 在命令记录里是 4 位（上限 16 张），一张合图占最后一个空槽；合图宽取 512 使 stride 恰为 2 的幂，素材包 4 085 504 字节 < 4 MiB Flash 分区上限 |

擦弹特效不新增资产：复用火花图（ADD 方程四粒，计入 `fx_graze`），避免占用已满的表面槽。

色板沿用并收紧：底 `#02040A`、青 `#35F2FF`、品红 `#FF4FD8`、琥珀 `#FFB23E`、
绿 `#8DFF6A`、自机 `#A8FBFF`；背景新增深蓝过渡带 `#041022→#0B2A4A`。

## 3. 绘制层（`stg_draw.h`/`stg_draw.c`）

命令表形状的恒等式（V2 断言）扩展为（类别恒等式保持可断言）：

```
by_eq[ADD]   == pbullet + particle                 （不变）
by_eq[ALPHA] == ebullet + boss + title + fx_graze  （加擦弹环一类）
by_eq[CONST] == flash                              （不变；受击帧颜色改红，数量不变）
背景          = sky BLIT(COPY) + 恒定数条 FILL + 剪影/星 BLIT(COPY)，条数导出常量 STG_BG_FILLS
活动元素 K1   五类口径不变，背景/特效不算
```

逐项：

1. **新背景**：天空底图两笔 200 宽列切片 BLIT 打底（HW/TEX 条带流水线的源切片窗口 16KiB 限单笔源宽 ≤256，见 techreport sw/12 §4.4）；横线/竖线/星点机制原样保留（亮暗改新色板）；
   `bg_far`/`bg_city` 两条剪影带以 `g->frame` 派生的相位横向循环（纯绘制层数学，不改仿真）。
2. **震屏**：状态两拍（幅度、衰减）放进 `stg_game`，第 7 步从 `ev` 位派生
   （受击/炸弹给幅度，逐帧衰减；偏移量 = 幅度与帧号的确定性函数，不消耗随机数）。
   组帧时游戏区所有元素加同一偏移，HUD 不动。
3. **受击红闪**：`STG_EV_LOST` 帧的闪白改红（CONST 一条，数量口径不变）。
4. **Boss 血条**：HUD 段名下加血条（外框+内芯 FILL，颜色按剩余比例从绿→琥珀→品红），
   数据读 `g->boss.hp` 与当前符卡满血常量，只读仿真。
5. **擦弹环**：上一帧擦弹数 > 0 时在自机周围画 `ring.png`（ALPHA，计入 `fx_graze`）。
6. **CLEAR 画面**：维持单词级 "CLEAR"（域内逐字文本量有悬崖，板上实测 38 字提示行把标题帧拖到 282ms，提示语已烘进标题图资产；见 techreport sw/12 §4.3），本局得分看 HUD。
7. **标题画面**：保留两张 title 图（V3 的 `title==2` 不变），提示行
   "ALL ARROWS = EX STAGE" 烘在 title.png 资产里（不占每帧域内文字预算）。

## 4. 玩法：EX 关卡（经典路线逐字节不变的附加路线）

- **入口**：标题→开局切换帧上，**四个方向键同按**（`STG_KEY_UP|DOWN|LEFT|RIGHT` 全 1）；另有编译钩子 `-DGFX2D_START_EX=1` 供演示与截帧直接走 EX。
  判据按键脚本与通关录像搜索器永远不产生这种输入（四向同按=原地不动，无搜索价值），
  因此经典路线的仿真、判据、录像全部不受影响。标题画面有提示行。
- **内容**：EX 复用同一套发射原语与机种，只换常量表——
  EX 杂兵事件表（波次更密、排布不同）、EX 移动表补充、**4 张重构符卡**
  （LOTUS ROTATION 旋转对称六向螺旋 / TWIN FAN 双侧扇形夹击 / STORM RAIN+AIM 混合雨 /
  FINAL OVERLOAD EX 终符超载）。符卡结构（血量/超时/发射器数上限）与经典完全同构，
  `stg_game` 里只是表指针在进入 EX 时切换。
- **确定性**：EX 分支只由按键位决定，两遍运行逐字节相同；新 L 组判据覆盖（E 前缀已被发射器组占用）
  （触发、表指针、段推进、与经典路线的前缀一致性）。
- **不做**：难度选择、武器升级、连击系统——都会触碰规则层与录像契约，留给下一轮。
