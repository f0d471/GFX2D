# Bugs

未修复的在产缺陷。一个缺陷一个文件。

## 收录范围

- 收：代码已经在仓库里、尚未修复、可能已经上过板的问题。
- 已修复的缺陷从「当前条目」移除，结论写入 [`../TechReports/`](../TechReports/) 对应系列。
  为保留第一现场而留下原文件时，文件头必须标明已结案，并只列入「结案索引」。
- 不收：未开工的改进、开工前的 spec、开发过程中的日志，进 [`../Todo/`](../Todo/)。
- 不收：风格与规范问题，进 [`../Todo/`](../Todo/)。

## 单条要求

按以下七节组织，节序固定。

| 节 | 内容 |
| --- | --- |
| 1 症状 | 观测到什么。贴串口原文、编译日志或 OpenOCD 输出的原始内容 |
| 2 复现 | 最小复现步骤或激励，写明用的是哪个比特流、哪个程序 |
| 3 影响面 | 哪些构型和程序受影响，板上是否跑过 |
| 4 定位过程 | 排除了什么、依据是什么 |
| 5 根因 | |
| 6 修法与验证判据 | 修法有多种写法时，写明选择依据 |
| 7 判据缺口 | 现有判据为什么没有覆盖到它。每条缺陷都要回答 |

文件开头一行状态，写明是否已修、影响范围、是否阻塞其他工作。

这块板上的三类问题特别容易漏进来，写条目时对照一下：
厂商加密 RTL 整机无法仿真，问题只能在板上暴露；
Interface Designer 与顶层端口对不上时不报错；
改动扰动布局之后 hold 余量可能被挤成负数，而功能仿真不会变红。

条目已按「不收未采用方案」的口径删除；触发条件、定位过程与两处对照实验
记在 [`../TechReports/platform/04-SoC构型对比与资源归因.md`](../TechReports/platform/04-SoC构型对比与资源归因.md) 第 4.4 节，
如果将来又要启用统一时钟，先看那一节。

技术报告 platform 系列第 01 章第六节留了一条未验证项：`apb_probe` 读未映射地址时会置
PSLVERROR，但 OpenOCD 的读命令仍然正常返回 0。错误响应有没有传到调试通路还没有查过，
在查清之前驱动不要依赖它。这一条还不构成缺陷，写驱动时如果发现它确实被吞掉，再转成本目录的条目。

**2026-10-02（引擎 P1 B6）更新**：`apb_probe` 已按 D21 从顶层撤下，未映射页由顶层常量应答
（`PSLVERR=1`、读回 0）。OpenOCD `mdw 0xf8108008` 照常返回 0，错误响应是否传到调试通路
仍未查——但引擎驱动不依赖它（`gfx_engine` 靠读寄存器值判别，不靠 PSLVERR），本条按原状
保留为「未验证、不依赖」。
