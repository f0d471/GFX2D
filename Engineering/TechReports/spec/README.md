# spec 系列

像素与命令的规格：软硬件两边必须实现成一样的那部分约定。

这个系列记录的不是某一个模块怎么实现，而是**实现之间必须一致的接口与数值**。
它存在的理由是：软件执行器与硬件流水线是同一份规格的两个实现，
规格里任何一处歧义都会表现为「两边算出来的像素不同」，
到那时无法判断是谁错。所以这一系列的每一章都要把话说到没有第二种读法，
能用代码穷举的给出穷举结论，不能穷举的给出与设计前提对齐的理由。

## 规格的定稿位置

正式文本在设计文档 [`Main/doc/赛题二总体设计.md`](../../../Main/doc/赛题二总体设计.md)：
3.4 节是命令 ABI，3.5 节是逐像素规格。spec 章节记录的是**定稿过程、完整伪代码与依据**，
两处内容重叠属于正常：设计文档写结论，本系列写结论是怎么来的。

穷举工具在主机上跑、不依赖板子：

| 文件 | 用途 |
| --- | --- |
| `Main/tools/check/check_round255.c` | 定稿方程的逐方程校验，按方程表的 `Fs`、`Fd` 直接代入；另校预乘与非预乘两条路径相对实数定义的量化误差 |
| `Main/tools/check/check_cmd_semantics.py` | 命令语义的结构校验与 159 条一致性向量（ABI 1）：字段矩阵、检查优先级、错误码、方程/格式匹配表，带六项注错自检 |

## 当前的规格状态

七项已定稿并经用户确认（2026-09-18；`Todo/hw/E7` 本条整体不验收，规格这一阶段无异议），
其中三项有穷举数据支撑（除以 255 的舍入、中间量位宽、定序的适用范围）。
定稿过程中有三处实质结论被订正，过程见第 01 章第四节：

- 需要定序的是 CONST 与非预乘 ALPHA 两档（各 4121020 / 16777216，24.56%），预乘 ALPHA 与顺序无关（4.1 节）；
- 中间量不能模截断到 16 位（64643 处不符），17 位或把 `t` 饱和到 16 位都正确（4.3、4.7 节）；
- 预乘比非预乘多量化一次，相对非预乘源色最大偏差 254/255（4.8 节）。

命令语义于 2026-09-20 定稿并经用户确认：v1 只做 DDR 直通与 XRGB 目的，不实现 tint；
新增 ARGB8888_STRAIGHT；同一表面重叠 BLIT 返回错误；COUNT/END、字段矩阵、错误优先级和
失败副作用见第 02 章。

第 02 章的前期研究同日做完：规范条款 §7 的九组落成 **159 条**带字面期望值的一致性向量（ABI 1），
由 `check_cmd_semantics.py` 逐条校验并带六项注错自检，全部通过。做这批向量的过程里补了四处
正文没写死的地方（描述符的地址公式与控制字保留位、零面积是否仍做 space/format 检查、
`space` 与 `format` 两步各覆盖哪些表面、`FETCH` 时的 `ERROR_TAG`），并订正了两处重复副本的
过期措辞（`SET_CLIP` 的「其余字忽略」、设计文档 3.4 节缺 `stride_log2` 范围）。
用户授权按审核推荐把一项新判定与四项澄清全部定案；复核还修正了多命令表导出边界、
`FETCH` 的有界来源接口、控制字保留位掩码和重复文本中的标签冲突。
研究过程、问题现场、原始输出与交接清单已经归档在第 02 章第三至第五节。
