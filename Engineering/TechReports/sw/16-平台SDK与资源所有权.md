# 16 平台SDK与资源所有权

2026-10-29的软件接口实现与验证。对象为公开`Main/sw/api/`、`runtime/`、`services/`、
`ports/`和固件组合根；公开接口以实际消费者和资源所有权约束验证。
接口现状见 [平台软件接口](../../../Main/doc/平台软件接口.md)。

## 1 问题与可检验边界

早期管理器公开stg_runtime，renderer依赖游戏头，系统适配留在console main，板级头混入产品动作。
仅禁止包含soc.h不足以证明可替换：独立pixels/bounce消费者只见公开头、不链接旧游戏，
PUBLIC_APP实际编译逐项拒绝五类私有头；低层诊断保留明确的可信接口，不作为新应用模板。

## 2 职责与所有权

| 编号 | 原问题 | 实现方向与判据 |
|---|---|---|
| A01 | 管理器绑定stg/R4 | runtime/appfw公开不透明user，注入配置；独立ID42与失败路径 |
| A02 | 通用renderer在游戏目录 | services/gfx共同消费，无游戏头依赖 |
| A03 | 应用上下文公开硬件资源 | 新api/platform采用代次帧句柄；低层判据为独立可信消费者 |
| A04 | 公共启动混合内容资源 | 通用资源窗口进入服务；myriad端口保留具体素材/槽位/热集描述 |
| A05 | 无独立接入证明 | pixels与bounce仅含公开头，分别构建/运行，不链接旧游戏 |
| A06 | 引擎完成忙轮询 | 等待中接入调度协作，PC编译实际驱动/端口验证 |
| A07 | 循环次数冒充一秒 | 驱动使用board_cycles差值，包含回绕和可控MMIO反例 |
| A08 | 输入临界区包含解码 | 采集/解码在外，临界区仅发布快照；每次最多64字节 |
| A09 | 动作混入板级事实 | 公共输入动作头、独立映射服务与旧接口兼容层 |
| A10 | 隐含全局资源 | 声明单所有者，内容状态不再成为通用框架结构 |
| A11 | 调度适配留在内容入口 | firmware/console配置/启动，ports/host和ti60提供系统服务 |
| A12 | void等待吞掉结果 | 新SDK显式返回忙/无效/超时/退出/IO等；旧包装仅兼容 |
| A13 | 产品和旧判据重复机制 | 共用renderer和资源服务，保留原CRC/录像，不更新golden掩盖差异 |
| A14 | 构建允许新应用看私有层 | PUBLIC_APP真实编译只给api；五类私有头逐个拒绝 |

公开应用只依赖api/标准C；服务连接api、纯库和BSP，固件组合根连接应用与系统。
纯库不见BSP/SDL/OS，具体内容资源由myriad端口描述，通用renderer不能包含游戏头。
一个固件只有一个图形/显示所有者；代次句柄拒绝过期访问。帧经map/unmap/present/wait转移所有权，
完成未知时进入fault，不用清零标志假装回收。该SDK不能承诺任意SDL/OpenGL游戏无需适配运行。

## 3 真实边界修正

- 初版负向构建使用make不支持的绝对APP_SRCS，失败在找源文件而不是头隔离；改为合法相对路径，要求明确因私有头不可见而失败。
- 输入映射只搬文件仍留下BSP调用服务的反向依赖；最终BSP返回分开的物理/远程样本，由输入服务组合，SDL后端不查询产品状态。
- IRQ独立编译暴露task声明依赖间接包含，补显式task.h。
- 等待以board_cycles差值计时并处理回绕，不把循环次数当一秒；PC测试实际编译驱动与调度端口。
- 清理前先确认物理排空；API返回忙、无效、超时、退出、IO错误，旧void包装仅为兼容。

独立持久化、健康与镜像模块分别见 [双槽记录](18-双槽持久化记录.md)、

## 5 板端公开消费者

使用冻结B7，SHA256 `4703e94ccd6746eb0fb774f4b1bf005fbeb9b2ee783e751b98c4fd40291d38b9`、CAPS 0xd46f。
`sw16-board-20261029-final2`中pixels/bounce分别呈现16/24帧；独立Python期望与DDR完整CRC
8590b256/6a04e790一致，并核对显示ID、扫描面地址、交换计数和JTAG六点像素。
示例仍受公开头约束，可信探针`apps/probe/sdkBoardTest`不因此让示例获得BSP可见性。

第一次检查误用默认B0特性头，修正为强制预包含对应B7头；读取整幅DDR的JTAG dump超时后，
采用程序全帧CRC加JTAG抽样，像素期望和交换判据未放宽。五应用、1kHz、后台进展及双故障恢复
属于同次系统回归，数值/呈现节拍另按各自模块和负载解释。

收尾轮另在主仓完成lib/pack/console/r4。历史结果不代表当前源码重新复跑，未写Flash，
不声称Flash boot、硬件watchdog、最坏关中断时间和人工实体输入已验收。
