# 23 PC中文输入法与真实键盘

2026-11-05，用户反馈凝时“鼠标能转视角，但WASD不移动”。读取正在运行的游戏坐标：
玩家仍在出生点(0,2.59999)，视角有变化，敌人没有与玩家重叠，排除移动被场景碰撞阻挡。
只读检查该窗口键盘布局为0x08040804，属于当前中文输入环境。

## 1 复现与原因

原输入路径是SDL键盘状态→BSP位图→appfw→sh_world_tick。中文输入法组合输入可以先
消费字母键，导致Windows物理键已按下、SDL键盘状态仍为0。独立原生探针包含实际BSP
与实际sh世界层，以SendInput向自己的已获前台窗口发送真实扫描码，再调用生产输入和tick。
修复前数据：

```text
layout=0000000008040804 text_active=1
KEY W bits=0 native=-32767 position=0,170393
KEY A bits=32772 native=-32767 position=-32766,170393
KEY S bits=0 native=-32768 position=0,170393
KEY D bits=0 native=-32767 position=0,170393
```

位置以Q16.16输出。W/S/D没有位移，A偶尔收到，符合用户观察。
先只调用SDL_StopTextInput，普通窗口检查通过，但探针重新主动开启IME后W/S仍然丢失。
因此不能只以SDL文字输入标志为0宣称输入已修复。

## 2 修复

`bsp/host/board.c`的游戏窗口不接受编辑文字，初始化时停用文字输入；Windows读取动作
按键时改用GetAsyncKeyState高位判断物理按下，保留原有“本窗口必须是前台”的检查。
松键以原生按键状态为准，失焦立即返回0，不受文字组合或SDL丢弃KEYDOWN影响。
Linux仍从SDL扫描码读取，动作位图与游戏规则没有改变；不切换系统键盘布局。

`test_window.c`补充中文IME主动开启时的原生W/A/S/D及松键检查，继续验证失焦释放。
测试链接的imm32仅用于控制测试窗口的IME状态。正式输入不依赖测试注入，
也不需要用户切换到英文输入法。

## 3 验证与交付

选定范围为acceptance的pc-window，加同一实际BSP→sh世界层原生位移探针；
未改变纯sh规则、RAST、素材和板端，不重复无关全仓检查。
最终原生窗口轮 `20261105-070300-b5a1c0bd` PASS，包含真实WASD、松键、
鼠标、失焦、全屏、缩放和显示恢复。注意此前 `070003-aa5f8d77` 仅有停用文字输入，
不作为最终修复结论。

最终探针在IME主动开启时：

```text
layout=0000000008040804 text_active=0
KEY W bits=1 native=-32768 position=0,137627
KEY A bits=32772 native=-32768 position=-32766,170393
KEY S bits=2 native=-32768 position=0,203159
KEY D bits=65544 native=-32768 position=32766,170393
```

四个方向各推进6个生产tick、约0.5米，且不需要模拟按键位图绕过BSP。
正式日志中失焦例还记录SDL_W=0、native_W=-32768、pressed=1，说明物理输入确实绕开
了SDL被IME抑制的状态。Linux分支另通过-Wall/-Wextra/-Werror语法编译。

原始前后探针、正式窗口证据与新版程序身份在
`evidence/23-pc-ime-20261105/`。新版仍使用原生凝时入口，保留无敌、无限补员和材质；
当前旧窗口已关闭，更新程序后重新进入sh供用户复验。

## 4 覆盖缺口

此前sh移动测试和实际绘制回放通过输入脚本送入动作位图，验证了规则和渲染，
没有证明中文输入法开启时真实字母键能够到达游戏。既有原生窗口检查只测一枚W键和
一次普通焦点状态，也没有强制组合输入。这次补的是实际物理输入边界，
不能再用帧率正常或errors 0替代交互验收。
