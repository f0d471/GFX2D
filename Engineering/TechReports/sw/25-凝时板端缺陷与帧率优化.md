# 凝时板端缺陷与帧率优化

2026-11-05，接续第24章。用户已把凝时运行在板子上，本轮重新读取当前源码、实际固件、
串口和面板状态，检查缺陷并优化CPU热路径。不修改RTL、记录ABI和Flash。

修复后的完整人形参考构建约1.4 FPS；采用下述数学、缓存和远景LOD后，B7两组各至少
1800帧的固定视角与移动射击窗口，平均分别为7.69与11.71 FPS。功能检查通过，
稳定30Hz目标尚未达到；硬件贴墙遮枪缺陷保留在Bugs，HDMI外观和真实按键待用户试玩。
这些数字包含LOD与时间推进的变化，不能解释为相同逐像素工作量的纯算术加速比。

## 1 起点与两处错误结论

起点提交为`0f96b281795412badd74e0ca3c2af329b1dda958`，入口为快捷键6、目录ID7、
内部场景3。保留用户已有Flash备份和host-sh-cap/host-sh-dbg探针；先保存原固件、
构建身份与面板状态，再释放COM11用于本轮JTAG和串口测试。

`sh_normalize`原式：

```c
const int32_t inv=(int32_t)(INT64_C(1)<<42/(int64_t)len);
```

除法先于移位，实际是`1 << (42 / len)`，大多数输入得到1，法线和环截面基向量接近零，
连续人体坍缩。原注释所谓倒数总能放入int32也不成立，极小向量需要另行处理。
新增单位轴、极小值、3-4-5、对角线和符号判据，使原实现稳定见红。第24章的3.53 FPS
日志只含约162条记录，不能作为完整人形的性能基线。

第二处是计时解释：`R4TIME`的`cyc_submit`包含等待硬件，`rast_cycles`在该阶段内，
二者不能相加。旧报告用约17.7ms+15.5ms推出30Hz无望，重复计时；第24章已订正。
重新测量完整参考版本，约1253条记录，geometry约660ms，submit约18.9ms，
其中raster约16.7ms；瓶颈首先是CPU几何/材质/setup。

## 2 采用的改动

`sh_scene.c`只优化本场景，不改变共享`fixmath.c`与光栅记录格式。

| 改动 | 机制与限制 |
| --- | --- |
| 归一化 | 先把最大分量缩放到14位，再用32位平方根与倒数；支持零和极小向量，判据容许16个Q16末位误差。保留`SH_REFERENCE_MATH`慢参考开关 |
| 雾与材质 | 雾距离以Q8计算，距离量化小于1/256米；权重约去公共1000因子，使用32位除法；相机空间武器直接跳过世界雾 |
| 顶点复用 | 按可见三角形惰性计算共享顶点的材质和投影；相机变换利用稀疏项，保留R1逐项舍入；倒数投影用余数校正，50000组与原除法完全一致；近远裁剪仍走原路径 |
| 远景LOD | 2米内保持完整头/躯干/肢体采样与插值材质；更远保留头肩腰肘膝轮廓，减少中间环和截面边数，采用细三角常量分面色；完全在视锥外的人形按保守包围球拒绝 |
| 完全相同记录缓存 | 房间按相机位置、朝向、投影和viewport失效；各敌人按位置/姿态和相机版本失效；32槽武器姿态缓存独立于世界相机。命中时复制原记录，缓存开关对照逐字节一致 |
| 缓存内存 | 从共享池offset 1MiB租用1.5MiB，退出归还；避免静态BSS增加约213KiB。主表2048条/256KiB，分桶128KiB，深度32KiB，均在2D arena之前，静态断言与运行容量检查防重叠 |

近景保留完整轮廓，因此人物靠近、转动视角使缓存失效时仍可能慢。没有将所有敌人
替换为块状人或精灵，也没有降低世界深度精度。LOD属于实际外观取舍，仍需用户目检。

游戏逻辑原先每绘制一帧只推进一次，低FPS使移动、装填和补员随之变慢。板端现在用
实际毫秒累计固定30Hz步长，单次最多补1秒；确定性回放仍按原单步。以20×50ms与
60×16/17/17ms分组验证同一总时间的步数和位移相同。迟到帧仍记录真实迟到，再恢复
下一次截止点，避免永久追赶旧截止时间。不会把丢失的绘制帧算成30FPS。

敌人碰到家具时，原先没有位移也持续摆腿；现在只在实际移动时推进步态，并尝试沿
掩体切向绕行，保持与玩家的碰撞间距。修复板端没有HUD的问题：弹药、击杀、时间条、
无敌状态和准星通过已有2D条带阶段绘制，板端软件参考执行同一组命令。

## 3 实验与撤回

| 阶段 | 板端取样 | 解释 |
| --- | --- | --- |
| 修好数学的完整参考 | 约1.41–1.43 FPS，约1253条 | 有效外观参考，短窗口诊断 |
| 快速数学/共享顶点 | 约2.12 FPS，geometry约433ms | 仍保留完整人形采样 |
| 增加远景LOD | 约3.87 FPS，约640条 | 实际改变远景工作量 |
| 房间缓存/按实时时间推进/HUD | 早期约5.45 FPS | 敌人仍在移动 |
| 武器姿态缓存 | 后期约12 FPS | 敌人逐渐停下，取样时刻不同，不能据此单独归因速度倍数 |
| 远景常量分面色 | 早期约6.56–6.67 FPS，geometry约112ms | 减少每三角RGB梯度除法；最终长窗口见第4节 |

临时`SH_PROFILE`计数显示，完整模型的projection和setup明显重于normalize；各计时有
嵌套，loft包含内部阶段，不能相加。生产构建关闭该探针。

尝试过通用64/32除法、记录对齐字写和全局`-Os`。除法随机对照50万组通过但无明确
板端净收益，字写也无收益；全局`-Os`可减小固件但帧率相近。三者均未采用，
共享数学、光栅头文件及全局编译选项恢复原状。相应原始短测与候选源码保留在证据中。

## 5 剩余问题与交付

[硬件武器共用场景深度](../../Bugs/凝时硬件武器共用场景深度.md)尚未修复。
同ABI模型在靠墙位姿得到共享深度0、独立深度4104个枪身暗像素；PC/板端软件参考
清理武器深度，B7硬件仍单次世界深度。出生点两帧像素对照不能发现它。
后续应以已有2D阶段叠加烘焙枪姿态，或设计有独立资源/时序判据的武器深度阶段；
本轮没有压缩世界Z精度规避该问题。硬件专项画面复现、HDMI外观与真实按键仍待试玩。

本机保留摘要绑定的`Main/bit/board_release_sh_optimized_20261105`试玩包，使用本章同一
B7/BIN；恢复仅通过JTAG，面板继续连接。恢复后实时状态为ID7/scene3/backend=hw、
connected=true、errors=0，约7FPS；这只是当时的实时快照，长窗口性能以上表为准。
包摘要与Windows PowerShell 5.1/7的CheckOnly均通过。断电仍回到原Flash内容；包内入口可以重新加载。
工作树改动待用户审阅，SW21 Todo保留，稳定30Hz与上述缺陷不作已完成声明。
