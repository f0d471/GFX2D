## 已经就位、开工时要接着用的结论

下面两条来自已完成的实验，**它们的原始条目会在验收后删除**，所以在此登记接棒点：

**一、共享区的一致性规则（来自 platform 第 05 章）。**
CPU 的数据缓存会遮蔽外部主机写入 DDR 的结果，硬件没有缓存一致性机制。
驱动规则是「**读回共享区之前必须失效一次**」：

```c
data_cache_invalidate_all();                  /* 或 data_cache_invalidate_address(a) */
```

三条使用条件：

1. 失效必须在引擎对这一区域的写入**完成之后**，读回期间引擎不再写这一区域。
   先失效、再读、再让外部主机写，读到的仍是旧值（机理实验 T5）。
2. 失效调用包一层带 `"memory"` clobber 的函数，不要直接排在条件分支之后：
   紧跟在跳走的分支之后的失效指令即使没执行也会清缓存（T10），结果正确但白付装行代价。
3. 读一次会把整行（64 字节）装进缓存，只写不装行（T2）；本构型没有写缓冲，写返回即已落到 DDR。

代价：失效指令本身全清约 67 个周期、单地址约 4 个周期；失效之后每一行第一次访问重新装入约 69 个周期。
命令表读回校验、素材复核、调试时读帧缓冲都在读之前失效即可，不需要维持「只写不读回」的单向约定。

**二、软硬件同帧 CRC 对比的判据（来自 platform 第 05 章与设计文档 3.8 节）。**
判据成立，前置条件三条：算 CRC 前全清一次，不管上一轮是谁写的；
失效必须在引擎渲染完成之后（`IRQ_STAT.list_done` → `SWAP_REQ` → 场消隐切换之后）；
加一条注错：跳过这次失效时 CRC 必须不一致，否则说明这一步是空转。
整帧 640×480 读回仅装行就约 132 万个周期（约 13 ms，按 T11 单行代价外推的估算），适合逐帧调试时开启。

这条判据证明的是**硬件与软件执行器逐像素等价**，证明不了规格本身对不对；
规格的算术由 [`spec 第 01 章`](../spec/01-逐像素规格.md) 的穷举与软件执行器的逐方程注错分别覆盖。
