## 2 时间基准的订正

原 `vPortSetupTimerInterrupt` 读 `0x0f8bbff8`，而生成的 CLINT 基址与 TIME offset
得到 `0xf8b0bff8`。反汇编和同次 JTAG 读值确认进入实际代码的是错误地址。
比较寄存器读回为 0，被早期调试误认为 timer 不工作。

修复前独立诊断用正确地址：100Hz档两秒199次中断，1kHz档两秒1998次，异常均0；
cmp读回仍为0。因而不需要先重生成 SoC 才能推进毫秒级软件移植。
本轮删除覆盖函数，让标准 FreeRTOS RISC-V 端口用 BSP 同源地址初始化与更新 cmp。
显示 ISR 只派发 PLIC/帧通知，内核 API 的启动窗口门控保留。

开发轮新RTOS程序中，菜单fps_milli=60000，tick_ms每秒增长1000、irqA增长60，
idle与优先级1的monitor持续增长。runner优先级2，inputd优先级3；不再靠把monitor
提高到输入任务级别掩盖忙轮询。完整正式证据在第6节按冻结运行登记。

## 3 应用模型与输入

`appfw.c` 不再包含 FreeRTOS/SDL。`main.c` 是目标调度端口，`main_host.c` 是宿主端口，
两者驱动相同的初始化、step和shutdown。注册表只枚举可启动内容；菜单是独立系统页。
ID 1/2/3/4稳定，不随注册表位置变化；系统信息为ID5，从菜单进入。

系统动作先于业务输入：全局启动、BACK被框架消费；启动/确认等控制键按住时不会
成为新应用的第一条热键，方向可继承。Esc返回，C切三维场景；保持C期间三维重进
不会再次触发。物理四键组合仅在产品模式启用，因此旧判据与旧四键契约保留。

扩展包 `ff 7f lo7 hi7 crc7` 承载确认/返回/场景，CRC7覆盖全部14位，旧10bit包不变；前缀对旧协议
校验无效，不会误作为旧按键。实际 Python 发射器与 C 接收器穷举16384快照对照。
新面板使用协议2状态，不再从旧CSV猜菜单；应用进入后先清掉旧后端/FPS再等状态。
F8暂停转发，Esc交给返回；Alt+Enter切全屏不同时确认，产品Esc不退出全屏。

旧入口保留开发/判据用途。默认原生PC构建选择console；`--legacy`才构建旧入口。
冻结打包器核对PC与板端是否同一前端，加载器按包声明等待菜单或旧R4启动反馈。

## 4 失败处理与共享能力

进入失败后不调用失败应用的frame。旧应用leave必须先成功排空；否则引擎确认复位/
物理排空后才清理并恢复菜单。排空/清理失败时保持fault、不绘制新表面，可显式返回重试。
帧回调区分完成、内部切换和错误；菜单/系统页不再丢弃bad，不显示失败帧。
错误、丢日志、实际完成帧和呈现计数进入统一状态协议。

公共运行时吸收旧main的启动、三套表面、TEX覆盖、三维钩子，并保留INJECT_TEX_CRC、
G1/G4影子和mode感知。旧main改为显式`s_runtime`成员，不再维护同名boot/tex/backend段。
纯旧Demo的预合成仍由内容适配负责，因为它是单独应用的资源准备。

产品的PIPELINE控制执行策略，DIAGNOSTIC控制逐帧CRC；异步写帧与同步逐帧CRC的组合
被构建拒绝，诊断可显式使用同步硬件。PERF不再决定产品是否能走引擎流水。
旧消费者没有显式新配置时保持原参数语义。
合并时另发现旧对象路径直接拼接`../../`会越出OBJDIR。构建器现按源文件生成规则，
把父路径编码为`__up__`，所有对象/依赖都留在本次目录；host/target的A/B/A构建检查
实际参数不混用，软浮点扫描也改为递归覆盖对象。中止的第一轮不作为本次验收证据。
三维检查曾将外部生成的R4RP头放进OBJDIR，整目录清理会删掉输入；现将它移到独立
的本轮输入目录，由host与target显式引用同一份并登记身份，不靠保留旧对象目录复用。
面板的后端待确认请求在跨应用时取消，避免遗留Tab命令作用到新应用；显示按键名称的合并
不修改原始keys遥测，两项都有实际方法调用的回归检查。

包身份行，再让旧独立日志检查器逐行比较：490行与1236行分别相同（按原规则去cyc）。

字段保留旧值。旧期望和本轮完整输出一并归档，不用重录图像掩盖绘制差异。

新增console专项覆盖实际管理器、错误回退/排空、按键隔离、默认菜单/系统页、64/32位、
ASan/UBSan、线协议和旧缺陷变异；也执行真实产品程序的四应用与持续场景键。
console-board要求每个应用实际完成并呈现，连续时钟/任务/堆/后台进展和零错误/丢日志。

与正常零错误流程分别判定，不把预期故障混成正常通过。

`--precise-boundary` 分离load与resume：CPU停止时清掉旧串口数据、建立采集边界再运行。
禁止只因BIN存在就跳过make，运行绑定源码、bit、BIN、字节数和原始串口；历史复核需身份文件。
