# 21 凝时 PC 战斗与交互修复

2026-11-05，SW21 的 SH2 原生 Windows 试玩版本审查。用户要求检查快捷键6的游戏，
按 SUPERHOT 的动作时间机制改进并打开 PC 试玩。实现沿用项目三维平涂通路，
不是把先前网页原型作为本轮交付。

## 1 审查定位

继承工作区已有未提交 SW21 代码；本轮开始时备份实际相关文件到忽略构建目录，
保留既有目录、构建和输入接线。原有目录元数据中 sh 的稳定 ID 为7、shortcut为6，
about 的 ID 为6。本轮不交换目录身份；独立游戏名仍为 HALTTIME。

官方对原作的核心表述为“时间随动作流动”，参考
[SUPERHOT 官方产品页](https://superhotgame.com/superhot)。本轮采用这一交互原则，
没有引入原作代码、模型或素材。SH1 网页轮的审美研究与既往试错继续保留于 SW21 Todo，
本章只记录本次原生 PC 改动，不据此关闭整个 SW21。

| 问题 | 机制与修复 |
| --- | --- |
| 两侧敌人消失、场面空 | 出生点把32个十分之一米写成32米；改为房间内的固定入口，并检查家具、其他敌人与玩家距离 |
| 开火似乎随便命中或不命中 | 原锥角比较将 tan 权重放反，而且12度自动锁敌代替了瞄准；改为随视角发射实体弹，按实际飞行段判定最先碰撞 |
| 几乎无法中弹 | HIT2 定点平方少乘 ONE；改用三维线段对玩家体积的连续碰撞，避免高速弹穿透 |
| 穿家具、隔柱射击 | 玩家与敌人使用家具包围盒滑动限位，枪线和弹丸使用相同位置、尺寸与高度的掩体 |
| 时间机制前后不一致 | 出生计时、冷却和碎片寿命曾混用普通整数与Q16时间；统一为世界时间，重力与旋转也随同一缩放 |
| 静止时按住开火能一直加速 | 按成功击发触发时间加速，单发枪使用按下边沿；空枪或冷却期间不会仅因按住鼠标推进全速世界 |
| 左右移动其实是转身 | sh 捕获输入时 A/D额外标记为横移，方向键保留转向；其他应用的映射保持原样 |
| 无鼠标视角、无枪口反馈 | BSP提供可选相对指针服务，场景消费BAM视角；加入俯仰、相机空间三维枪、后坐力和枪口闪光 |
| 敌人积木状、手臂不随目标转 | 以玩家方向构造局部基，棱台连接髋、膝、踝和肩肘关节，枪朝玩家；隐藏面先剔除，控制记录量 |
| 无死亡、清场与资源循环 | 一击死亡，R重试，敌人掉枪可E拾取补至6发，3敌/4敌房间清场后确认继续；重试回到本房间分数基线和随机种子 |
| 画面缺少可操作提示 | PC软件路径在世界完成后显示准星、弹药、时间条、清场和死亡反馈，并显示键位 |
| 偶发组帧超容量 | 限定最多3敌、16弹、32碎片；装饰碎片为枪与战斗几何保留64条记录，仍更新其逻辑，不省略活弹和敌人 |
| 几何计算异常慢 | 雾的平方根由逐次加一换成有界二进制算法，每面只算一次雾色 |
| 从凝时返回4号仍是凝时 | 恢复 app_r4 每次进入都选择走廊；去掉已被独立应用替代的C键临时桥 |
| 新快捷键导致检查报错 | 目录生成器已允许6，采集验证器仍只允许0到5；同步到0到6，保留历史无目录日志的旧ID回退 |

## 2 当前接口与玩法

世界逻辑和几何在 `Main/sw/apps/game/gfx2dGame/src/sh_scene.c`，适配在
`Main/sw/ports/myriad/app_sh.c`；共享 R4 执行器只在场景3调用它。
相对鼠标读取与捕获留在 BSP；目标端接口返回零位移，目前不声称板端键鼠可用。

世界采用30Hz、Q16.16时间，静止下限约0.025倍；玩家按固定真实步长移动，
对角线速度归一。移动被墙完全挡住时，不仅因按住移动键而全速推进世界。
子弹采用扫过线段与最早命中体积的比较，掩体先到就阻挡；击发后的弹仍随世界时间，
玩家需移动推进弹程，也可停下观察敌弹。

当前只在PC软件执行器接入HUD；几何继续走L1定点记录。硬件HUD、目标端鼠标、
声音、投掷武器与完整原作关卡不属于本次已实现范围。操作入口见
[Main中的玩法文档](../../../Main/doc/凝时PC玩法.md)。

## 3 验证与交付

新增唯一清单中的 `sh` 检查：直接覆盖生产场景状态与正式setup函数，
验证出生、时间、横移、瞄准、弹程、掩体、连续命中、死亡重试、拾枪和碎片。
64位运行ASan/UBSan、32位逐字对照，重复仿真核对记录字节一致，
覆盖640/854/1792宽、贴墙、俯仰、满特效池、输出容量和HUD行尾保护。
把出生坐标重新改成32米，测试必须报 `SH FAIL`，作为定向变异预期失败证据。
实际console执行 sh→走廊→sh，检查出帧和零错误，单独测试生命周期与输入消费者。

初次验证执行期间补充测试文件导致输入身份变化，编排正确拒绝通过；这些轮次保留为诊断，
不作为最终验收。压力检查曾真实触发512条溢出，调整池上限与装饰保留后重测。
补充1200组满池随机位置、朝向和俯仰诊断，峰值477条，sanitizer通过。

最终冻结轮 `20261105-054720-7eb00635`，**acceptance：pack、sh、console、workflow
全部PASS**。sh记录峰值478/512，64/32位重复序列摘要相同；console覆盖16384种
输入快照、两档PERF和生命周期故障；workflow的28个流程测试通过。
Windows轮 `20261105-054332-74a5aa9d` 的 **acceptance：pc-window PASS**，
包含相对指针消费一次、失焦与离开释放、全屏、比例、缩放、显示恢复和实际键盘失焦。

证据按正式编排分别归档在
[软件验收](evidence/21-halttime-20261105/software/result.json)和
[原生窗口验收](evidence/21-halttime-20261105/windows/result.json)，
输入身份和原始输出随同各轮保存。本轮补充原生150帧移动/死亡场景：150次present、
errors 0，画面与键位提示目检通过；不据此声明FPGA性能。
试玩程序、源码摘要和启动参数见
[PC交付身份](evidence/21-halttime-20261105/review.json)。

原生试玩入口为 `Main/sw/apps/console/build_windows_sh_review/Play-Halttime.cmd`，
直接使用 `--app sh`。已启动并确认存在可见窗口，运行状态为sh、软件后端、30fps、errors 0。
