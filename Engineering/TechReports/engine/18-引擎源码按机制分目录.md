# 引擎源码按机制分目录（2026-11-12）

`Main/rtl/engine/` 原来是 18 个 `.v` 加 4 份生成头平铺。本文记录把它按特性宏边界
分成 `core/`、`buffer/`、`frontend/`、`rast/` 四个子目录的做法、改动面与验证结果。
全过程只动路径与注释，RTL 内容一字未改。

## 一、分组与依据

| 子目录 | 文件 | 文件数 | 依据 |
| --- | --- | --- | ---: |
| `core/` | `engine_cmd.v`、`engine_regs.v`、`engine_mover.v`、`engine_geom.v`、`engine_pix.v`、`engine_blend.v` | 6 | 任何构型都编进来，对应技术报告的控制层、事务层、几何层、计算阵列四章 |
| `buffer/` | `engine_tex.v`、`engine_band.v` | 2 | 片上存储数据面，分别由 `GFX_HAS_TEX` 与 `GFX_HAS_BAND_HW` 整块开关 |
| `frontend/` | `engine_inst.v`、`engine_pb.v`、`engine_pb_dma.v`、`engine_bin.v`、`engine_bounds.v`、`engine_packet_check.v` | 6 | 绘制前端，由 `GFX_HAS_INST` 与 `GFX_HAS_PB` 控制；`engine_bin` 例化 `inst`/`bounds`/`packet_check`，拆开就断 |
| `rast/` | `engine_r3.v`、`engine_rlst.v`、`engine_rast.v` | 3 | 三维，由 `GFX_HAS_RAST`/`GFX_HAS_RAST_TEX` 控制；`r3` 例化 `rlst` 与 `rast` |
| 根 | `engine_top.v` 与四份生成头 | 5 | 顶层看全部子模块；生成头是宏的唯一定义处，不复制到各子目录 |

分组用的是特性宏边界而不是功能相似度：一个子目录里的模块要么整体在构型里、
要么整体不在，这样 `feature_config.FEATURE_SOURCES` 的子目录前缀与目录结构一一对应。

## 二、`include` 怎么解决

`.v` 与生成头不再同目录。沿用原约定（头是唯一定义处、不做多份副本），
改为给综合工程加 include 搜索路径：

- 主工程 `fpga/gfx2d_ti60/gfx2d_ti60.xml` 的 `<efx:synthesis>` 里加
  `<efx:param name="include" value="../../rtl/engine" value_type="e_string" />`。
  `efx_run.py` 第 760~761 行把这个参数翻成 `efx_map` 的 `I=`，实测 map 命令行里出现
  `I=../../rtl/engine`，四步 PASS。
- 六份独立综合工程补同一参数：`sim/engine/ctrl/syn/engine_top_syn.xml`、
  `frontend/syn_bin/engine_bin_syn.xml`、`frontend/syn_inst/engine_inst_syn.xml`、
  `geom/syn/engine_geom_syn.xml`、`pix/syn/engine_pix_syn.xml`、`pix/syn/probe_pix_syn.xml`。
- `check_r2_synthesis.py` 与 `research_engine_features.py` 会拿 `engine_bin_syn.xml` 当模板、
  在别处生成平铺的源码副本，这两个脚本在写 XML 前删掉继承来的 `include` 参数，否则相对路径不成立。
- 仿真侧的 `iverilog -I rtl/engine` 本来就在，一处未改。

## 三、改动面

`Main/` 下有 71 个文件出现 `engine_*.v` 路径。处理分三类：

1. 含 `engine/engine_x.v` 字面量的 44 个文件按映射批量改写，改写后全仓扫描残留 0 处。
2. 用变量拼路径的 14 处逐个手改，包括 `check_r2.py`（`E+f'engine_{x}.v'`）、
   `check_g2_band.py` 与 `check_g3_stripctl.py`（`MAIN/'rtl/engine'/p` 的元组）、
   `check_r3.py`（变异目标路径）、`inject_baseline.py`（`os.path.join`）、
   `probe_cut.sh`/`probe_strip.sh`（`cd` 进源树后按裸文件名预处理）、
   `elab_tree.sh`/`elab_verbose.sh`/`contract_all.sh`（按 `rtl/engine/$extra.v` 探测可选模块，
   不改会静默漏掉 tex/band/pb/rast 这些模块，elaboration 直接失败）。
3. 6 处按目录枚举源码的 `glob('*.v')` 改为 `glob('**/*.v')`：`check_f4_instances.py`（两处）、
   `check_f5_bin.py`、`check_g4_integration.py`、`check_r3.py`、`check_feature_function.py`、
   `run_f5_board.py`（位流与 RTL 时间戳比较）。

工程文件里的源文件顺序逐条比对过，与改前完全一致：顺序影响厂商映射，所以只换路径不换次序。
`Engineering/` 的历史证据与技术报告正文不改，本系列 README 的路径表随新布局更新。

## 四、验证

| 项 | 结果 |
| --- | --- |
| `feature-caps` | PASS |
| `feature-elab`（八代表档 + 22 合法 / 106 非法结构组合的配置穷举） | PASS |
| `ctrl`、`frame`、`geom`、`pix`、`mover`、`blend`、`band`、`stripctl`、`frontend`、`rlst`、`rast-ports` | 全部 PASS（quick 档，各自含定向变异） |
| `tex` | `run.sh` 直接执行，6 项 PASS |
| B0 整机四步（map/interface/pnr/pgm） | PASS |
| XLR / RAM / DSP | 35925 / 105 / 16，与 `bit/snapshots/B0/manifest.json` 逐项相同 |
| `core_clk` setup / hold | +1.047 / +0.027 ns，与 manifest 相同 |
| 位流 SHA256 | 与 B0 快照不同（`3AB211F2…` 对 `86138E9B…`），未做字节一致要求 |

未覆盖的部分：本次没有重做板测——纯路径移动、资源与时序与冻结档逐项相同，且没有替换任何快照；
B3/B5/B7 的整机四步未重跑，四档快照仍是 2026-10-29 的产物。

## 五、留给后人的两条

- 第 00~17 章正文写于分目录之前，里面的 `rtl/engine/engine_xxx.v` 按文件名对应到新目录即可；
  本文第二节的映射表就是对照依据。
- 以后再往下分层时，要同步两处：工程 XML 里的 `include` 参数，以及
  `tools/check/feature_config.py` 与 `feature_build.py` 里的路径表。只改一处会在构型构建时
  报找不到源文件，或者在综合时找不到 `engine_feature.vh`。
