# 18 软硬件同构验证

2026-10-24 完成选定acceptance，2026-10-29用户验收。对象是相同数值与工作量下的CPU/FPGA
参考和硬件渲染路径，不新增RTL，也不规定应用玩法、模型美术或战斗反馈。

## 1 固定输入与可比性

茶杯负载为207顶点、396面。CPU与FPGA使用相同Q16.16变换、近远裁剪、320×240居中视口、
128B记录和16位z；视口外背景保持相同，逐帧/主表CRC核对。旧cup3d的S3L/8位压缩z不是同一负载，
不能用于软硬件加速比。另有L1平涂、L2纹理生产帧，测量绑定当时bit/BIN和输入版本。

录像R4RP为32B头（魔数/版本、30Hz tick、seed、场景、阶梯、素材版本）加小端u32输入流；
历史场景身份0x52344333、素材版本2。逻辑按固定tick推进，不从墙钟取位置；不同身份拒绝混用。

封闭实体按同一背面剔除规则构造几何；薄片双面复用已投影顶点并反转绕序。
两个后端消费相同几何集合，不能把减少绘制工作量当作算术加速。

## 2 资源与完成边界

固定硬件帧为640×480、30条带。历史SHARED区含64KiB主表、32KiB子表和32KiB软件条带z；
3D使用16KiB TEX，四个32×32区块按64词行距交错发布，装载后核对CRC。
进入/退出时表面与TEX热集重新登记；源、目的、显示前缓冲不能重叠写，错误帧不呈现。
几何/除法快路和缓存的等价证明见 [定点数学](15-定点三维数学与参考光栅器.md)，
异步提交与代际所有权见 [提交运行时](../sw/27-记录缓存与生产流水所有权.md)。

## 3 对拍中的问题与修正

原型已有子视口和L1/L2通路，但PC、板上SW、板上HW的整帧CRC不一致。对拍中修正以下问题：

| 问题 | 处理 |
| --- | --- |
| PC/板上SW/板上HW 整帧 CRC 不同 | HUD 的 FPS 与路径文字在功能构建标为 TEST；修后 L1 60 帧全图 CRC 一致，L2 图像与 128B 主表随之一致 |
| 约 260ms 被当作引擎耗时 | 区间混入 1.9MB 缓存失效和逐帧 CRC，RAST 实际约 1.5ms；诊断移出渲染计时，性能构建关 CRC |
| 宿主 frame0 截图全黑 | 第一次 present 是建立安全扫描面，不是逻辑帧 0；截帧按真实呈现序号对账 |
| 板上 JTAG 读样点不可比 | 旧入口先 reset halt 且场景继续推进；判据改为程序在帧边界取 CRC 与记录身份 |
| 首帧锚点偏差 | 先清非扫描面并 present，确认后再清旧前缓冲，预热后才锚定 F0 |
| 纹理边缘串区块 | atlas 局部 UV 端点为 31 texel；全 0 ARGB 为共同透明色，透明片元同时跳过颜色与 z |
| 预算处静默截记录 | 取消硬截断，按完整物体选最近门框；构造错误与容量不足显式拒绝，不 present 失败帧 |
| 二维 Demo 背景被覆盖 | 改用尾部独立 2MiB，原三个 2MiB 槽保持；切换检查逐次核对这 6MiB 的 CRC |
| 软件条带 z 残留 | 颜色与深度共用 1024 元素行跨，必须清 16×1024 个 z，不能只清 640×16 |
| 子视口八顶点极值 | 近远裁剪可把 8 点扩成 10 点；内部路径接受 10 点，公开入口仍 3~8 点，补凸八边形跨双深度面回归 |

## 5 结论边界

JTAG装载不等于Flash启动；本轮未改默认B0或写Flash。原生参考图不作为HDMI实拍。
功能对拍与性能构建分开：计时不混入整帧CRC或无关缓存失效，submit包含硬件等待时不与raster相加。
历史数据不代表当前源码/固件已经复验，固定输入可继续用于硬件回归。
