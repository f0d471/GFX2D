# 00 P1 路线与层间契约

本章归档引擎 P1 拆成 B1～B6 时跨批次的取舍。各层内部的研究、实现和验收见第 01～06 章；
本章只记录路线、分层、接口及它们改变的原因。B6 已于 2026-10-02 完成整机上板，
真实游戏的整帧帧率和 `N_max` 仍归 SW9。

## 一、为什么拆成六批

原计划把所有层的规格和研究写在同一个条目里，但早期十个研究问题中有四个集中在 AXI 搬运层，
计算核心和几何层当时尚无同等深度的实验。2026-09-28 改为先约定层间接口，再按
计算核心 B1、AXI 事务层 B2、几何层 B3、计算阵列与片上缓存 B4、控制层 B5、
SoC 集成与上板 B6 的顺序推进。B1～B4 先接通数据通路，B5 再接 APB、取数与检查，
B6 才将引擎接入真实 SoC。各批至少阅读两个本层实现或论文并做一个有数字的实验，
仿真注错须见红，单独综合须记录资源与时序；最终整机证据由 B6 给出。

## 二、路线与系统边界

**D1 路线。** P1 是直通 BitBlt：完整执行 ABI v1 的 NOP、FILL、BLIT、SET_CLIP、END；
源表面支持三种格式，目的表面为 XRGB8888，地址空间为 DDR。P2 在 P1 上增加片上纹理，
只缓存 SW7 的标准圆弹、小圆弹与火花（合计不足 16 KiB），约 100 KiB 的米弹和约 432 KiB
的 Boss 仍从 DDR 读。P3 条带模式以 P1 在十月中旬前上板为排期条件，实施时与 ABI v2 的
实例列表一起做；`gfx_blit_run()` 的调用侧保持“目的坐标与源帧”输入。P4 弹幕运动卸载
不进本路线，E8 的阶段性数据是 N=2000 时运动占一帧的 5.6%。P2、P3 与 P4 的最终工作范围
仍须以各自开工时的实测与决策为准。

**D2 分层。** 控制层负责 APB、命令取数、十步检查、错误、中断和计数；几何层把目的矩形、
游戏区、裁剪框、目的表面和源表面五者求交并拆成行描述符；搬运层把描述符变成 AXI 事务；
计算阵列用两组乒乓行缓冲和像素旋转器组成每拍四像素通路；计算核心完成单通道混合。
FILL 没有源表面，只交前四者。源越界的 BLIT 像素在矩形级裁掉，不交给像素阵列逐点判断。
命令缓冲归控制层，因为取数和检查都在这里；`engine_top.v` 也归控制层，因为 APB 入口在这里。
像素接口是流，跳过写入由 X 字节最高位带内标记表示，不能依赖写核中间拍不采纳的 `tkeep`。

P1 所依赖的平台边界是：引擎占 Axi_Mux S1；读方向要等前一笔 `rlast` 握手才可发下一笔
`arvalid`，写方向要等 `bvalid` 握手才可发下一笔 `awvalid`；地址有效区间为
`0x0000_1000～0x0FFF_FFFF`，AXI ID 截为四位，突发最多 256 拍。两帧缓冲基址为
`0x0200_0000` 和 `0x0240_0000`，行跨 4096 字节；缓冲切换只归 display。
CPU 读回引擎写过的共享区之前须在写完成后失效缓存。各层在 100 MHz `core_clk` 同域。
引擎前的片上 RAM 基线是 4KB/1 路缓存 71 块，16KB/4 路候选 89 块，器件总共 256 块；
`core_clk` 的历史 hold 余量仅 +0.026 ns。
这些边界的板上来源分别见 platform 第 02、03、05、06、10 章及 spec 第 01、02 章。

路线顺序来自上板事务预算：16×16 ALPHA 在目的行不对齐时每行约五拍，源读与目的读
各约 `27.41+1.086×5=32.8` 拍周期，写可与下一行的读重叠。16 行加取数和流水线约
1100 周期/颗；每帧 166.7 万周期扣掉约 9.8 万清屏与约 11.3 万扫描占用，
硬件侧粗估约 1300 颗。B2 的校准模型给出 1092～1124 周期/颗，B6 的板上测试给出
1183.5 周期/颗。固定读事务开销是这组负载的主要部分，所以 P2 优先考虑消掉“读源”
那一笔。以上是合成负载估计；CPU 构造命令和真实游戏整帧争用尚未计入，须由 SW9 测 `N_max`。

## 三、跨层接口的最终契约

各接口均在 `core_clk` 下以 valid/ready 握手。原先的草案在 B1～B5 中逐项细化，
以下记录验收后的契约；字段最终以 RTL 端口为准。

| 编号 | 方向 | 约定 |
| --- | --- | --- |
| I1 | 控制 → 几何 | 十步检查通过的 FILL/BLIT 携带操作、方程、色键、常量、表面、坐标、裁剪框和命令索引；NOP、SET_CLIP、END 不下发。零面积命令仍交给几何层，几何层不发描述符而回 `cmd_done` 与索引；非空命令由最后一行写状态报告完成。D52 规定一次只提交一条语义命令，预取可以继续。 |
| I2 | 几何 → 搬运 | 读写描述符各含 16 字节对齐地址、拍数和命令索引，恰好一笔突发、不跨 4KB、不超过 `AXI_MAX_BURST_LEN`。写描述符的 `wr_last_row` 只在本命令最后一行的最后一段置位。`rd_buf={源/目的, 行号最低位}`。边带先发，再发源读、目的读、目的写；一行最多两段、161 拍（对 640 种宽度与四种相位穷举），beat 宽度或行宽改变须重算。 |
| I3 | 搬运 → 计算阵列 | 128 位读流带 `tlast` 与目标缓冲号；消费者恒 ready。读事务完成要同时捕获状态脉冲并握手该流的 `tlast`，仅看到 AXI 状态不足以释放在途门控。 |
| I4 | 计算阵列 → 搬运 | 128 位写流每拍四像素，X 字节最高位为 1 表示不写。阵列不提供 `tlast`；搬运层按当前写描述符剩余拍数打末拍（D48）。写核首拍与 FIFO 半满时会拉低 `tready`，阵列按 `tready` 停整条流水并保持 `tvalid`（D47）。 |
| I5 | 几何 → 计算阵列 | 每行边带含 `npx`、总写拍数 `beats`、源/目的行首地址的拍内相位 `lead=(row & 15)>>2`、方程、色键、常量、源格式等。`lead` 来自地址低位，不可只用 x 坐标取模。反向的 `row_free[1:0]` 每半一位，每行包括新命令第 0 行都要先等该半空闲；半号按命令内行号低位选。FILL 的 alpha 取 `w4[31:24]`，不看源格式。 |
| I6 | 计算阵列 → 混合核心 | 每通道源、目的、alpha、常量各 8 位，方程 3 位；每拍四像素共 12 个实例。固定延迟 `L=3`，流水停顿由 `en` 统一控制。五个输入必须由寄存器直接驱动，以保留 B1 第一级实测的时序余量。 |
| I7 | 控制 ↔ 搬运 | 命令取数描述符/状态、排空请求电平与完成脉冲、超时事件；复位超时门限 `T=4096`。一次排空请求只完成一次，撤下后再举才是新请求。读写状态以描述符上下文带出命令索引，写状态还带 `wr_last_row`。批量取数跨 4KB 可拆两笔并拼回，任一笔失败则整批丢弃、从批首回退。低四位 `fd_cidx/fs_cidx` 仅供一致性监视，完整 `ERROR_INDEX` 由控制层重建。 |
| I8 | 各层 → 控制 | `PERF_*` 统计命令、求交后的像素、色键跳过、读写突发与拍数、DDR 等待和忙周期。像素数与软件 `pixel_total-src_oob` 对账；色键以握手的写拍四槽计；突发/拍数计实际总线事务，含命令取数。 |

引擎不设 `FRAME_DROP` 计数：缓冲交换和场计数属于 display，SW8/SW9 以场数减交换数计算掉帧。
`PERF_*` 不做场同步快照，等命令表完成后读并按帧做差。

完成顺序还有两个不能忽略的边界。空命令的 `cmd_done` 可能早于上一条非空命令的
最后一笔写状态，所以整表完成按“完成数等于已下发的 FILL/BLIT 数”判断；不能按脉冲
到达顺序推断。跨命令写后读由控制层在上一条末行写状态到达前挡住下一条的语义提交，
否则下一条 BLIT 可能读到旧像素；只挡提交，下一批命令取数预取仍可继续，且后一条的检查错误
不得抢成首错。B4 的真通路测试和 B5 的 D52 给出了这一选择的判据。

## 四、验证流程与借鉴来源

**D13 验证流程。** 仿真沿用 Verilog 测试台与每目录 `run.sh`。公共 AXI RAM 从机
`sim/axi_probe/axi_ram_model.v` 在 B2 补到 4 MiB、支持 `wstrb`、地址窗口 `SLVERR`、
以及校准定时模式 `RD_LAT=23`、`RD_BUB=12`、`WR_BUB=6`、`B_LAT=1`；新增参数默认值
保持已有探针仿真行为。各层注错应让相应判据见红，再做单独综合；B6 再用整帧仿真、
整机编译和板上 CRC/缓存/扫描压力完成集成验收。

| 来源 | 借鉴的形态 | 本工程取舍 |
| --- | --- | --- |
| [CAVE CV1000 blitter](https://wiki.arcadeotaku.com/w/Cave_SH-3)（MAME 行为模型，BSD-3） | CPU 写内存命令表，按序执行 draw、clip、upload、end；源与目的各有混合参数 | 借鉴命令流和 D8，不照搬专用显存 |
| [ORGFX](https://opencores.org/projects/orsoc_graphics_accelerator)（Verilog，LGPL-3） | 裁剪、片元、混合、写回分层，多个读方经仲裁汇成一个读主机 | 借鉴 D2/D8 分层，不照搬 Wishbone 与逐像素实现 |
| [iDMA](https://github.com/pulp-platform/iDMA)（SystemVerilog，SHL-0.51） | 前端、中端、后端分工，多维请求在中端拆成一维 | 借鉴几何与协议搬运的职责边界，不移植其跨仓代码 |

## 五、结果

B1～B5 的单元与单独综合结果依次收在第 01～05 章。B6 的整帧仿真 16/16、
整机四步 PASS、36009 XLR / 105 RAM / 16 DSP、`core_clk` setup/hold +1.067/+0.026 ns，
以及固定负载的板上 CRC、缓存一致性和扫描压力结果收在[第 06 章](06-顶层集成与上板.md)。
这组证据证明 P1 引擎已接入整机并完成固定负载验收；板上 16 颗 ALPHA 的平均周期
约 1184，与早期每颗约 1100 的手算同量级。它不等于真实游戏 60 FPS 的验收数字。

## 六、还欠什么

P2 片上纹理、P3 条带与 ABI v2、显示端每场 CRC/OSD、摄像头均不属于 B1～B6。
真实游戏的中断驱动、软硬件切换、完整帧率、扫描压力与 `N_max` 归
[SW9 板上移植](../../Todo/sw/SW9-板上移植.md)。16KB/4 路缓存仍是候选，
采用条件见 platform 第 10 章第六节；不能把 B6 4KB/1 路的结果当作候选构型的结果。
