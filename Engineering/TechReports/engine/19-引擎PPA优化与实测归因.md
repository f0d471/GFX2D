## 3 映射归因与失效的估算

### 3.1 输入不同的运行不能证明随机噪声

本次回查两轮七档记录 `20261016-183103-ffccd7f1` 与 `20261016-190653-29876126`。
它们的 revision 都为 `0f16896`，但输入清单中 65 个共同相关 RTL/工程输入里，
`Main/rtl/engine/engine_top.v` 的 SHA 不同；实际构建副本的 diff 包含：

- PB 分支的 `band_mode && !pb_active` 改为 `band_mode && !bin_mode`；
- 无 PB 分支的 `preserve_clip(1'b1)` 改为 `preserve_clip(1'b0)`。

这是实际 RTL 变化。前一轮还复用了较早构建，后一轮为新构建。因此这对记录不能证明
“全部输入不变、固定参数重复综合仍有 2～3% 随机变化”。排版/路径/算法启发式敏感性
可以存在，但需要与真实设计变化分开。早期候选估算把观察到的差异上升成通用“噪声底”，
证据不足；不能据此豁免 300 XLR 以下候选的归因，也不能把所有增长归为不可解释波动。

`engine_top.v` 在两轮输入清单中的 SHA256：

| 运行号 | SHA256 |
| --- | --- |
| 20261016-183103-ffccd7f1 | 461514e1c68ba366e93435c1e518efdd7ca142af63030b85083d5b11e91dc68e |
| 20261016-190653-29876126 | 746cb13f8ebba4fdcbf12899adb15a10f0c39b34edcfea3da718beab1ab9b58c |

后续先冻结实际输入摘要、工具、参数与目录条件，做不改设计的重复对照；再做单候选 A/B。
若要比较布置种子，A 与 B 使用相同的种子集合分别报告，不混入设计修改后称为重复噪声。
结果必须同时列 map、层级估计、Routing 与时序；“同一轮”本身不足以证明只有一个变量。

还有一个立项目标本身错误：该批版本 `settings.json` 为 `SOC_MODE=0`（Standard），
`soc.h` 已声明 M 扩展，map 也已显示 CPU 四路 DSP。厂商生成器的关闭条件是
`{SOC_MODE}==1 and {MULDIV_EXT}==0`；IP 参数界面也只在 Lite 时显示该选项。
[平台第 04 章 3.2](../platform/04-SoC构型对比与资源归因.md)早已记录 Standard
下该参数不生效。因此“给该批版本 B7 腾资源再开 MULDIV_EXT=1 的单周期乘法器”不能继续作为
候选收益目标。M 扩展也不等于任何位宽乘除都一周期；RV32 的宽除法成本须按实际指令和
库函数测量。此项由该批版本配置、原生成器条件与既有平台报告交叉确认，没有生成新 IP。

厂商资料另有明确的 `syn_use_dsp` 和 `operator-sharing` 选项，研究时应先查实际映射与
选项，再决定是否使用属性/原语/显式共享结构；单纯改源码外观不能代替映射证据。
来源：[Efinity Synthesis User Guide v4.7，p.27、38](https://www.efinixinc.com/docs/efinity-synthesis-v4.7.pdf)。

## 4 构型成本与优化对象

### 4.1 B3 控制与表面对象

B3 该批版本构型为 TEX+BAND_HW+STRIP+INST，保留基础像素能力。它的主链是：

```text
平台驱动发布命令/实例 → cmd 取数/检查/条带调度 → geom 裁剪/逐行描述符
                                               ↓
DDR/TEX/BAND ← mover 事务/流路由 ↔ pix 行缓冲/四像素混合
```

整机 43519 XLR 包含平台，不能全算引擎。该批版本层级估计中引擎 22189 XLR；SoC 8703.5、
DDR 5296.5、display 3358，其余是顶层、互连、HDMI 等，最终另有 1297 Routing XLR。

| B3 引擎子树 | XLR 估计 | RAM | DSP | 解释 |
| --- | ---: | ---: | ---: | --- |
| cmd | 7222 | 15 | 3 | 包取数、实例、检查、预取、条带生命周期 |
| regs | 5662.5 | 0 | 0 | 表面表、多路读回、计数和状态 |
| geom | 2419 | 0 | 0 | 求交、地址、拆段 |
| mover，含 BAND | 3285 | 51 | 0 | BAND 36 RAM，两个 AXI DMA 合计 15 RAM |
| pix，含 12 个 blend | 3503.5 | 12 | 12 | 四像素/拍、行缓冲、对齐与混合 |
| TEX | 70 | 16 | 0 | 显式片上 scratchpad |
| engine 自身连接 | 27 | 0 | 0 | 父层自持归属 |

cmd+regs 为 12884.5，占引擎估计 58.07%。12 个 blend 合计 1712，占 pix 48.87%；
早期静态估算把混合核估成 pix 的六到八成、regs 估 1500～2500、geom 估 900～1100，都不能继续
当优先级依据。资源画像必须更新到真实子树，不能把父层预算再当叶子预算。

相对本批 B0，B3 增 7594 XLR、60 RAM、3 DSP；RAM 增量可对到 BAND 36、TEX 16、
cmd 8。它确实用存储和控制成本换取局部访问能力，不能把条带/实例当成免费前置。

### 4.2 B3 控制和存储接口的代价

**B3-A：小容量表面表使用昂贵的组合多读口。** 三组 16×32 位数组共 192B，执行侧两路
96 位组合读，另有 APB 读回和复位/valid 更新。map 明确报 `surf_w0/w1/w2w` 因读口非同步
而映成 logic memory；regs 的 0 RAM 与大 LUT 占用相互印证。源码锚点是
[engine_regs](../../../Main/rtl/engine/core/engine_regs.v) 的 SURF 存储、读回和软复位部分。
不能把 regs 的全部 5662.5 都归给这 192B，但这是有直接映射证据的重点对象。

替代方案比较：同步表+该批版本命令源/目的快照；配置阶段验证后形成紧凑执行描述符；对忙时
修改使用明确的影子/活动代际。代价是读延迟、端口仲裁、复位有效位及读回协议。旧 R-1 的
“复制三份 BRAM、直接省 1000～1500”没有试综合支持，不能沿用；多读口的时序需求应先
重设，再选存储组织。B3 的 SURF 写保护还与 PB 不同，不能直接套用 PB 的整帧冻结前提。

**B3-B：命令层混合了多种工作粒度和兼容入口。** cmd 同时处理 32B 包、批次预取/回退、
v1/v2 条带、实例取数、错误身份和全帧调度。接口宽度和所有权分派成本真实存在。
改成 task/拆文件只能改善源码组织；硬件共享要明确选输入、共用哪一个运算器/缓存、何时
锁存上下文。建议重审“帧调度→规范化命令→行描述符→数据通路”的单向接口，保留首错
顺序、预取错误抑制和排空责任。能否把旧入口作为可裁剪兼容配置，需要单独定义产品需求。

**B3-C：通用软件 ABI 直接影响硬件验证网络。** 16 位尺寸、32 位地址/列表/读回契约、
变量 stride、空间与格式检查决定了移位器/比较器宽度。B3 并不是所有维度都只支持小值。
平台驱动可以生成受约束的执行描述符，应用继续使用平台 API；若要收窄硬件契约，应给出
版本和范围，不能仅因屏幕 640×480 就截断源表面、地址或错误字段。PC1 已说明未经证明的
校验前移会破坏语义。

**B3-D：一笔在途与多种小事务限制实际吞吐。** 这是该批版本 Axi_Mux 实时性设计的一部分，
不是删除门控就能修掉的低效代码。[平台第 06 章](../platform/06-Axi_Mux三端口仲裁与SoC防饿死保护.md)
记录了扫描/CPU 防饿死与该约束的关系。若增并发，需要连同 owner/tag、返回顺序、取消和
扫描最坏等待重做。该批版本两个 DMA 的 XLR 合计约 963，并非 B3 最大逻辑块；优先重写厂商
DMA 缺少成本依据。

### 4.3 像素与局部存储的适用边界

四像素通路匹配 128 位总线，行缓冲/掩码处理非对齐，TEX 保存热纹理，BAND 保存局部目的
像素，这些方向可保留。TEX 该批版本是固定 scratchpad，CPU 装载纪律与容量是其成本边界；
不应直接追加标签/替换逻辑把它升级成通用纹理 cache。

单 BAND 每帧完整 LOAD+FLUSH 仍有 2457600B，60Hz 时为 147456000B/s；单缓冲三相执行
也不自动重叠。条带只减少带内反复访问，并不消除这份背景/呈现流量。
[engine 第 10 章](10-整机与Nmax实测.md)已记录过条带引擎忙周期下降、
CPU 组帧却成为关键路径的反例。因此“少 DDR 字节必然提高整帧帧率”属于已被推翻的选型
依据。F6 双 BAND 保持条件启动合理，增加 36 RAM 不保证解决 CPU 主导的场景。

RAM 账也须订正：一条带是 `640×16×32 bit=327680 bit`，理论容量下界 32 个 10K RAM，
实际 36。早期“640×16×128b”的公式多算了四倍。TEX 的理论下界为 13，实际 16；容量
下界不能证明带 lane 写使能和多消费者的结构能达到该下界。TEX 的空闲期 RMW 与 BAND 的
持续像素提交也有不同吞吐条件，不应合并成“同一个 lane-WE 技巧、零代价”的承诺。

**B3 裁决：保留数据通路与局部存储路线，重审控制/表面对象接口。** 该批版本证据支持组织成本
偏重，不支持“整个 blitter 分层选错了”或“砍一半像素算力即可解决”的结论。

### 4.4 B5 构建与引用回放的成本

B5=B3+PB。该批版本 PB 子树 10708.5 XLR/7 RAM/4 DSP，其中 bin 6086.5 已包含实例读取、
求交、检查和桶 RAM；两者不能相加。其余还带动 regs、mover 和物理布线变化。

```text
原始包/实例 → COUNT+clip快照+64B metadata写出 → PREFIX
          → SCATTER再次遍历/写引用/写目录/发布READY
          → 按桶LOAD → 引用→metadata→坐标→还原32B命令→旧cmd/geom/pix → FLUSH
```

该批版本跨档最终差 17273 XLR，包含 Routing 差 4693；本批 B5 的绝对 Routing 是 5990，
已占器件 XLR 的 9.85%。跨档模式不同，不能把这些差额全部当成 PB 的逻辑原语数，但它们
确实构成该成品构型的成本。该批版本 60792/60800 与 core setup +0.099ns 的结果只说明这一次
构建刚好满足门槛，缺乏继续扩展的余量；PPA 以前的超容已经证明这种边缘状态会造成维护成本。

### 4.5 B5 中间表示与共享服务

**B5-A：通用输入的完整语义在多个阶段重复消费。** 空间求交、clip 快照、表面/别名验证、
实例数组、metadata 身份、引用回放和旧执行器都保留各自逻辑。早期“源码同名谓词可删”
没有核对它们验证的对象、时刻及先后副作用。应先给每条规则指定唯一责任者和可复用证明
结果；结构有效性可按被冻结的 surface id 缓存，包字段和地址别名仍按实际包检查。

**B5-B：中间表示完全物化到 DDR，再恢复旧命令。** 64B metadata 包含原 32B 包、8B clip、
4B 索引和填充；8B 引用恢复完整包/实例身份。它保留顺序、支持稀疏散布，也带来两遍读、
随机小写、回放 gather 和桥接控制。只缓存最近一个 metadata、单拍引用/坐标，命中率受
绘制顺序约束，不能任意排序提高命中而破坏透明混合顺序。

可以研究新版本紧凑引用、规范化执行描述符、受约束实例批输入，或继续使用平台 CPU
分桶/旧直通。每一种都要同时算 CPU 发布、PB 构建读写、回放读取、容量失败和整帧延迟。
默认 DRAW_CAP=1024/REF_CAP=8192 不会自动裁掉编码上限 32768/131072 的可变参数逻辑；
若产品只需较小上限，必须通过明确构型/ABI 限制进行综合裁剪。

**B5-C：互斥工作仍保留重复读取器。** cmd 和 bin 各一份 engine_inst，分别约 1017 与
1014.5 XLR/2 RAM。可研究共享读取服务，但要保存调用者、取消与状态上下文，不能只接
valid/ready 二选一。该批版本两个实例的面积是机会的上界，不是合并后的净节省保证。

**B5-D：面积投入的价值依赖负载。**
[F5 历史同位流实测](13-硬件分桶与引用列表.md)中两型 Nmax 提升
17.78%/12.22%；空场的执行时间增加 80.63%，另一小像素场景增加 5.21%。构建约 1.22ms，
PB 相关读取约 198.8KiB、写约 55.8KiB；这些是对应冻结输入的历史测量，不能改称该批版本
固件结果。它证明 PB 有适用负载，也证明通用固定成本真实存在。该批版本 renderer 的
`GFX_FRONTEND_BIN` 缺省仍为 0，硬件存在不能等同生产软件在使用它。

**B5 裁决：先修复 PC1 语义，再决定保留多大的前端。** 追求大实例 2D 吞吐时可保留该方向；
以长期产品余量为目标时，应优先评估窄化的批绘制前端或不带 PB 的 B3。继续靠位宽/排版
修补满容量 B5，不能替代功能范围和中间表示的选择。PB 与 RAST 互斥也不只是一个宏限制：
现有 PB 操作的是 2D 包和实例，不能直接作为三角形 tiler 复用。

### 4.6 B7 局部光栅与存储成本

B7=B3+RAST+RAST_TEX，不含 PB，保留 INST。早期候选表中“B7 不编译 inst”的描述错误。
该批版本三维子树 13922.5 XLR，其中 rast 11620/20 RAM/7 DSP，rlst 1465/1 RAM，父层自持
837.5。相对 B3 总 RAM 增 22，其中三维子树 21、mover 净增 1；这是该批版本报告的归属口径。

光栅核含三路 s32 边缘、六路属性及其行首值、初始化部分积/归并、两份 128B 参数槽、
八项返回队列、深度和提交控制。初始化用四个 DSP 分八拍发射乘积；扫描最多一候选点/拍。
它用时间复用控制乘法器数量，同时以并行累加支持扫描吞吐，面积有实际功能来源。

全帧 16 位深度需要 614400B，已超过 Ti60 全部 256 个 10K RAM 的 327680B；
全帧 32 位颜色还需 1228800B。局部条带是合理选择：每带颜色 40KiB、深度 20KiB。
四 bank 深度占 20 RAM，除单点访问外还支持四点清零；合并 bank 可能增加初始化成本，
不能只看容量利用率。该批版本颜色/z 同一提交、三角形间排空解决真实 RAW 依赖，这些责任应保留。

### 4.7 B7 setup、引用与候选扫描

**B7-A：CPU/setup 预算曾被严重低估。** 该批版本为 RV32IM、4KiB/1 路 I/D cache，已具备整数
M 扩展。[R3 测量](17-B7三维控制与集成对拍.md)中 1100 条通用 view→setup
约 504.453ms、分桶 48.318ms，合计 552.771ms；该批版本凝时报告的完整人形参考构建又出现
geometry 约 660ms、submit 18.9ms（含 raster 16.7ms）。这些是不同版本/负载的诊断记录，
不能互算加速比，但都反驳了“旧 CPU 已能廉价供给大规模动态三角形”的假设。

`rast_setup.c::gradient` 的非常量路径每属性计算两个宽除法，六属性最多十二个；已有
常量属性快路，不可重新当作未做项。共享倒数/校正、固定场景缓存、紧凑顶点/材质路径或
专用 setup 加速都值得研究；必须保持符号、逐项舍入、裁剪与溢出拒绝。新增 FPU 或切换
MULDIV_EXT 不能直接解决该批版本固定点宽除法。专用 setup 单元应先做成本/精确性原型，不能
继续沿用“无除法器、一拍初始化”的旧错误假设。

**B7-B：每个 strip 引用重新取 128B 记录并初始化。** 两槽只覆盖该批版本/预取记录，不是跨带
参数 cache。1100 条都跨 30 带时可有 33000 引用，记录读取 4224000B，另有索引/目录流量。
大三角形重复较多；大量微三角形则取数/初始化/排空占比高。跨带参数缓存、预变换静态
记录或按活跃工作集保留参数均属候选，需要记录命中率、引用重复度和实际带宽；不能只用
“主表只有 140800B”代表整帧取数。

**B7-C：包围盒扫描的成本按候选点增长。** `fire0` 推进扫描，覆盖外点也要推进边/属性
和退休；只在 coverage 真时读 z/发纹理。故 1px/cycle 指候选点上限，薄斜三角形、重叠和
小三角形均会降低有效吞吐。粗块边缘剔除、扫描跨度或更细 tile 是可比较方案；小 tile
同时增加目录、引用与调度成本，必须用真实 bbox/覆盖比测量后选择。

**B7-D：运行期可选功能仍保留全部硬件。** 纹理/顶点颜色的 runtime flag 允许同帧混用，
不会让 B7 的六属性硬件在平涂场景消失。可以增加用途明确的平涂/常量材质构型，或让不使用
的字段在新记录契约中省略；代价是兼容、配置矩阵、取数解码与验证成本。该批版本仿射 TEX 和
固定 64×64 图集是演示用取舍；要支持更通用的 3D，需要重新核算采样/存储/数值目标。

**B7-E：精度和存储的固定约束不能只靠口号冻结。** 48 位内部累计是保守实现，不代表任何
寄存器都数学上必须 48 位。按该批版本 640×480、origin 与 gradient 校验范围，包含末行更新的
一次 y=480 值，|dx|≤14335、|dy|≤11776、|g|≤2^30−1，可得活动 acc/ar 的保守绝对界
`65535×65536 + ceil(((2^30−1)×26111+8)/16) = 1756574448033 < 2^41`。
因此可进一步证明 42 位活动累计的可行性；初始化部分积/归并发生在右移之前，不能一起
截到 42 位。仅 acc/ar 十二组各减 6 位也只减少 72 个状态位，不能重新包装成千级 XLR
收益。边界、舍入、停顿和不可见末行更新仍需验证。这是低优先级的数值证明候选。

### 4.8 后续实验的边界

CPU setup + 定点增量光栅 + 条带颜色/z，适合有限动态几何的固定功能演示；原本拒绝把
硬件除法/setup 草案直接落地有合理性。已经错误的是用不完整的 CPU/引用/bbox 成本模型
承诺规模和帧率，随后又用错误 CPU 参数目标规划面积。

对于动态复杂场景，后续先按实际独占阶段计时决定 CPU/setup、记录复用或光栅工作量的
优先级。submit 包含 raster，不能相加；不同 LOD、相机、缓存和场景的 FPS 也不能当等
工作量加速比。计时和生产流水的边界见[配套运行时记录](../sw/27-记录缓存与生产流水所有权.md)；
应用帧率目标已撤销，不作为硬件 PPA 工作的固定验收负载。

Standard SoC 的保留也有历史实测依据：Lite 曾有调试/板端问题，不能为了 RAM 余量直接
换回。缓存、setup 单元、参数 cache 和表面表 RAM 化会竞争剩余资源，应放在同一产品预算
中比较。该批版本 XLR 接近满、DSP/RAM 尚有余量，只能说明值得研究资源互换，不保证任意
运算搬到 DSP 都有净收益。
