# 20. 计算阵列可读性重构（engine_pix.v）

状态：**已验收（2026-10-29 用户验收；2026-10-26 授权修改，2026-10-29 统一验证成轮）**。
Todo 条目已于验收后删除，内容以本章为准。验证原始日志见
[evidence/20-pix-refactor-quick](evidence/20-pix-refactor-quick/)（quick 档功能轮）与
[evidence/20-pix-refactor-syn](evidence/20-pix-refactor-syn/)（整机综合）。

## 1 要解决什么

现有 `engine_pix.v` 混用资源管理、RAM 对象与流水阶段三种排列方式；
行控制器位于文件末尾，数据与对应 valid 分散在不同段，逐行阅读需要频繁跳转。

本次保持端口、逐拍采样、复位/保持、行内拍数、七拍通路、八次推进排空、
特性宏与注错分支含义，调整源码组织和内部命名，并简化等价的组合表达式。
不要求综合网表相同。

## 2 怎么切分

1. 行资源的声明、接收事件与状态更新收拢；开行/行完成作为显式跨段事件。
2. 当前行参数快照独立于执行状态机，调度器提前到 RAM 读地址之前。
3. 数据、拍号、valid 按 S1 至 S7 的事务阶段命名与归组。
4. 四槽旋转改成一次 128 位固定切片选择；保留原条件选择及异常值兜底。
5. 保留 RAM 同步读写模板、接收端独立推进、计数与占用位的同沿优先级。

主要改动为 `Main/rtl/engine/engine_pix.v`；当前机制说明同步到
`Main/rtl/engine/engine-manual.md` 和 `Main/rtl/README.md`。
原 B4 历史报告、既有仿真/综合/板测证据不重写，也不作为新源码的通过证据。

## 3 判据与验证边界

- 静态核对每个旧寄存器的新归属、位宽、复位值/条件、更新条件、沿前右值和优先级。
- 位宽截断、首/末 mask 优先级、完整 32 位色键、FILL alpha 与带内不写标记保持。
- `INJ_ROT_OFF`、`INJ_SKIP_KEY`、`INJ_DROP_MASK`、`INJ_EN_NOTREADY`、
  `INJ_CORE_NOEN` 的定义及 GFX_KEY 开/关分支保持；不顺带补充复位或删减延迟级。
- 后续统一轮按实际合并改动选择 `pix`、`ctrl`、`frame`、`band`、`stripctl`、
  `feature-elab`、`feature-probe` 等直接消费者和构型检查；整机综合按验证流程执行。
  正式检查前再核对当时的清单、档位和影响范围，板测按部署变化决定。
