# 11 外部变异验证机制

本章记录测试有效性检查的实现：生产 RTL/C 只保留正常逻辑，在独立源树中施加一条缺陷，
由不知道变异开关的普通测试检出。源码隔离、基线、判定与迁移核对属于同一机制。
2026-10-08 的条件编译版本和 2026-11-14 的试点、全量迁移是该机制的历史阶段。
当前执行入口和清单格式见 [外部变异测试](../../../Main/sim/mutation/README.md)。

## 1 问题与边界

早期生产源码使用 INJECT 参数，随后改用 INJ_* 条件编译。Verilog parameter 是 elaboration 时
确定的常量，不是运行期输入；常量传播与预处理删除的边界不同，但条件编译并不是唯一可用方案。
旧方案仍把故意写错的逻辑放在生产文件内，也允许测试台根据同一个开关改变激励或期望值。

最终目标为：正式源码不含故意错误；同一普通检查先通过正常基线，再检出登记的错误版本。
事务级错误响应、研究探针的诊断开关有各自对象，不与这里的源码变异混用。

## 2 实现与接口

- `Main/sim/mutation/mutants.yaml` 登记目标、缺陷、规格出处、替换规则、普通命令及具体检查器。
- `run_mutation.py` 冻结 Git 登记的真实输入，保留实际字节摘要和工具身份，在本轮影子树运行。
  不复制旧 build/logs，素材和向量在隔离树生成；复制树使用自己的显式源清单。
- 全部未变异基线先通过。单条多站点规则同时施加，退出或异常立即恢复所有被改变的源文件。
  不同命令独占运行目录，不用前一条输出或外层仓库身份冒充本条输入。
- 规则默认逐字匹配；五条 blend 规则按 Verilog token 精确匹配，忽略注释和排版，
  保留运算符和字符串差异。两种方式都要求唯一命中。
- `verify_migration.py` 比较 B0/B3/B5/B7 下的生产展开；有历史宏的规则还需反演一致，
  每条规则至少在一个构型中实际改变代码。迁移剥离脚本已退役。

## 3 结果判定

| 状态 | 判据 |
| --- | --- |
| KILLED | 普通消费者非零退出，命中预先登记的具体检查器，且不是准备或编译失败 |
| SURVIVED | 消费者成功，未检出错误 |
| KILLED-WEAK | 只有超时、总看门狗或没有命中具体检查器 |
| PARTIAL | 多个发现者只有部分检出 |
| INVALID | 规则、输入、编译或基础设施不成立 |

只有选定规则全部 KILLED 才通过。失败不能反过来自动修改期望标签；不同版本、输入和变异的
结果不合成一轮。完整输出和身份在本地运行保存，必要结果直接记录在本章。
公共 Session、范围选择和结果复用见 [验证调度与结果判定](12-验证调度与结果判定.md)。

## 4 实现中修正的问题

| 问题 | 原因与最终约束 |
| --- | --- |
| 旧用例看开关切换流程 | 迁移中发现一些所谓注错用例与正常用例激励完全相同，只把期望写成 FAIL；改为普通测试加外部错误版本 |
| 嵌套、多站点规则漏迁 | 一个宏可改变多处，INJ_BAND_RAW_MASK 还嵌在 INJ_MASK_BYPASS 中；规则作为整体施加，迁移由内向外核对 |
| 删除 endif 行尾代码 | engine_top 的 endif 后仍有布尔表达式；只删除预处理指令，保留有效代码 |
| ifndef 语义反了 | exec_sw 的未定义分支才是正常排空；反演曾抓到错误删除四行正常代码 |
| 跨文件残留错误 | 初版只恢复当前目标，使下一条失败不能唯一归因；进入前核对干净状态，退出/异常恢复并拒绝未登记改动 |
| 空输入身份 | 初版复制树向上借用外层 Git，得到空 inputs；改为复制树显式清单，空或缺失输入直接失败 |
| 存活或弱证据退出成功 | 初版只对 INVALID 返回非零；最终所有非强检出均阻塞通过，旧委托入口必须真正执行 |
| 文件路径被截断 | 影子树令 F5/R2 向量路径达到 160～177 字节，128字节 plusarg 读失败；改用 SV string，不复制旧 build 绕过问题 |
| 当前素材超过夹具容量 | G4/F5 旧夹具只读3MiB，实际包4134720字节；素材区独立4MiB，F5实例区移到0x780000并保持读所有者对账 |
| 普通检查器不足 | mover 末拍原来只靠总看门狗；检查器改从请求字节数独立计算剩余拍数，逐拍核对 tlast，不读取 DUT 内部剩余数 |

### 4.2 试点与全量迁移

2026-11-14 先迁 blend/pix 两文件10条规则；随后迁其余12个RTL和3个C文件的65条规则。
批量阶段删除320行故意错误/预处理分支，旧结果为17文件正向、75条历史反演一致。
两阶段使用同一套跑器和等价检查；后来补入寄存器和PB四条缺陷，形成79条集合。
试点当时为生产正向2/2、历史反演10/10、KILLED 10/10；这些结果只覆盖当时的两模块十条规则。

首轮旧跑器的75条结果为 INVALID 40、KILLED 10、KILLED-WEAK 23、SURVIVED 2，
基线17/21通过。该结果存在隔离缺陷，保留失败，不用它证明最终覆盖。

## 5 2026-11-14 验证结果与版本边界

以下是该日期冻结运行的历史记录，不表示后续源码重新完成同一验收，也不表示板测通过。

### 5.1 79 条逐项覆盖及版本边界

全量 acceptance `20261114-180849-ceb7cfd2` 的 28 条普通基线全部通过，实际执行全部 79 条：
76 KILLED、3 KILLED-WEAK，无 SURVIVED/INVALID。该轮保留 FAIL，不能改写历史汇总。

三条弱证据分别处理：

- `geom.band_clip` 已触发普通 BAND 范围拒绝 `BAND_ERROR code=2`，清单原标签未覆盖该检查器。
- `rast.rast_partial_commit` 已触发原有 `atomic color/z commit` 断言，清单漏登记该精确标签。
- `mover.no_tlast` 原来只有总看门狗。新普通检查器从请求字节数独立计算剩余拍数，
  在 DMA 输入握手时逐拍核对 tlast，报 `WRITE-LAST-MISMATCH`；不读取 DUT 的剩余拍数，
  也不判断是否施加了变异。

新增检查器只影响 `tb_engine_mover.v` 的消费者；源码引用审查确认唯一入口为 mover/run.sh。
将其涉及的 7 条变异以及两条精确标签变异共 9 条重新进行 acceptance：
`20261114-204813-938e9729`，5/5 基线通过、9/9 KILLED，整轮 PASS。

最终覆盖矩阵是 **70 条未受影响的冻结证据 + 9 条定向重验 = 79 条强检出证据**，
不宣称存在一轮新的单轮 79/79 PASS。审查逐项核对规则、命令、档位、变异源码摘要与原始输出；
工具链一致，规范文档不变；YAML 的执行字段完全不变，只有三个观察标签更新。
未受影响行不消费变更测试台；不同变异、输入或参数的输出没有拼成同一条结果。
