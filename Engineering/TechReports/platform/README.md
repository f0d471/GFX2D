# platform 系列

在一块钛金 Ti60F225 开发板上搭出一条端到端可观测的硬件基线，供后面的 2D 渲染引擎挂靠。

平台为易灵思 Ti60F225（60K 逻辑单元，256 块片上 RAM，160 个 DSP），
板上有 256MB 的 16 位 DDR3、8MB SPI Flash、HDMI 发送口和一颗板载 FT4232H 下载器。
片内跑的是易灵思提供的 Sapphire SoC，核心是一个 VexRiscv RV32 处理器，主频 100MHz。

这个系列记录的是引擎之外的部分：工具链、下载链路、启动链路、顶层工程的组织方式，
以及每次改动之后要跑什么才算没退化。它不加速任何东西，收益全在后续工作的可观测性上。

## 实测结果

2026-09-16 的编译与上板：Efinity 2026.1 四步 PASS，用时 77 秒，
XLR 14517（23.9%）、片上 RAM 65 块（25.4%）、DSP 4 个，约束告警 0 条，无负 slack。
板上通过的判据有五项：JTAG 链路、memTest、HDMI 八色竖条、512KB bootloader 从 Flash 引导、
APB 探针寄存器读写。命令见 [`../../../Main/doc/开发环境.md`](../../../Main/doc/开发环境.md)，原始输出见本系列第 01 章。

2026-09-17 接入 `Axi_Mux` 与测量主机之后：XLR 16151（26.6%）、片上 RAM 65 块、DSP 4 个，无负 slack，
`core_clk` 最快 142.7MHz。第 01 章的回归判据与第 02 章的 `ddrAliasTest` 复跑通过，HDMI 竖条经肉眼复核，数据见第 03 章。

2026-09-17 构型对比之后：**保留 Standard 构型。**
Lite + 统一内存时钟实测省 19 块片上 RAM（65 → 46）与 2936 个 XLR，`core_clk` 时序还变好，
但该构型的调试通路不可用（读 CPU 寄存器与 `resume` 都会挂住），
而可用的三个构型资源完全相同，所以换 Lite 不带来可用的收益。
Standard 的 CoreMark 是 `Iterations/Sec 178.63`、`Correct operation validated`。数据见第 04 章。

2026-09-19 端口重分配与防饿死保护之后（第 06 章）：`Axi_Mux` 改 X3，S0 扫描替身、S1 探针、S2 SoC，
永久模块 `axi_mux_guard`（`0xF810_F000`，VERSION 2）。XLR 21753（35.8%）、片上 RAM 65 块、DSP 4 个，
`core_clk` setup 3.780 / hold 0.026 ns。三方并发时 CPU 拷贝是单独运行的 1.70 倍（探针读）与 1.92 倍（探针写），
扫描替身一行最坏 529 个周期、没有跳行；仿真 `axi_mux_guard` 17/17，回归表与 HDMI 竖条全过，前三节已验收。

2026-09-19 SoC IP 定型之后（第 07 章）：efx_soc 3.4.0 经 IP Manager 的 Python API 重新生成，
开 GPIO1 接 KEY0~3、开用户中断 A/B/C、保留 I2C0 给摄像头、关 `axiA` 与 `io_ddrMasters_0`；工具链换成 gcc 13.4.0。
XLR 21653（35.6%）、片上 RAM 65 块、DSP 4 个，`core_clk` setup 3.405 / hold 0.026 ns。
调试通路、回归表、`bootSizeTest`（含对照组）与 gfx2dGame 的 60 帧 CRC 全过；HDMI 八色竖条与按键（`keyTest`）经用户确认。

## 这条线的当前位置

三条通路（下载、内存、显示）和两个接入点（程序空间、控制寄存器）都已经上板验证。
DDR 的地址规则已经查清（第 02 章）：`0x0000_1000`~`0x0FFF_FFFF` 内 CPU 地址即控制器地址，
以上按 256MB 回绕；SoC 发出的 AXI ID 恒为 0，顶层截断安全。
DDR3 上已经有第二个 AXI 主机的位置（第 03 章）：`u_axi_mux` 常驻在 SoC 与控制器之间，
暂由测量主机 `u_axi_probe` 占用；控制器突发上限 256 拍，读事务固定开销约 27 个周期、写约 7 个，
持续吞吐每周期 0.85~0.92 拍。
引擎本体、帧缓冲扫描输出、双缓冲都还没有开始，显示通路上跑的仍是硬件内部的彩条发生器。
第 06 章之后 `Axi_Mux` 是三端口，S0 与 S1 上是替身（`u_scanout`、`u_axi_probe`），
扫描输出与引擎接入时替换它们；引擎必须遵守「读、写各一笔在途」的契约，写方向没有 guard 兜底。

2026-09-18 缓存一致性实测之后（第 05 章）：CPU 的数据缓存会遮蔽第二个主机的写入，
**单向约定放宽为「读回前必须失效」**，条件是失效晚于外部写入完成。
判据在 `-Og` 与 `-O0` 两种编译档下结果相同，注错版四行变红、注错自检版 `fail 4`。
本构型没有写缓冲；紧跟在跳走的条件分支之后的失效指令即使没执行也会清缓存。
失效指令本身全清约 67 个周期、单地址约 4 个周期；失效之后每一行重新装入约 69 个周期。
