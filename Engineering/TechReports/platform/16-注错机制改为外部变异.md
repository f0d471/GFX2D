# 16 注错机制改为外部变异（试点）

2026-11-14。第 11 章把注错从 `parameter` 改成条件编译，解决的是「功能代码与注错代码同一行」
的问题；这次要解决的是它留下的第二层问题：**生产源码里仍然住着 70 处故意写错的逻辑**，
而且「判据是否真的在检查」只做到「报 FAIL」，没做到「红在哪儿」。

本轮是试点，只迁 `engine_blend` 与 `engine_pix` 两个文件、10 条变异，把机制、工具与
等价证明先立起来。

## 一、动机

第 11 章的机制在 9 个 RTL 文件里放了 39 处 `` `ifdef INJ_* ``；到这次清点是 **70 处、14 个文件**
（另有 10 个测试台侧 `INJECT_*`、7 个研究探针的 `INJECT` 参数）。它有三个后果：

1. **读生产代码要同时读故意写错的分支。** 改一处算法要同步维护它的错误版本。
2. **判据强度没有统一强制。** 70 条里约 30 条登记了见红位置（Python 表驱动的 band/stripctl/
   inst/bin/g4 和 tex 的 case 映射），其余约 40 条只要求打印 `RESULT: FAIL`——判据顺带抓到
   别的错也算「通过」。
3. **正式构建要保证绝不误开 `INJ_*`。** 这件事目前靠约定，不靠机制。

外部触发是一次方案审查，结论是把它做成独立活动：生产 RTL 不含注错分支，变异体在隔离工作
目录里生成，用原有测试台跑，输出可追溯的分类报告。审查同时提了 MCY/Yosys 这条工具路线，
本轮**没有采用**：SoC 与 DDR 控制器是加密网表、EFX 原语与 `Axi_Mux` 只认 Efinity，
Yosys 化不了整机；而叶子模块（混合核）已有更强的等价证据（六方程全定义域穷举）。

## 二、为什么是这几步

| 步 | 解决什么 | 为什么不能省 |
| --- | --- | --- |
| 1 清点与规则化 | 摸清 70 条的分布与强度 | 不做就只能按印象估工作量；规则化让剩下的 60 条可机械生成，不靠手抄 |
| 2 跑器 | 在隔离树里施加一条变异并分类 | 必须先有跑器再迁移：迁移后旧开关消失，没有跑器就无法确认变异体仍被抓到 |
| 3 迁移两个文件 | 生产 RTL 变干净 | 试点必须动真代码，否则机制没被验证过 |
| 4 等价证明 | 证明迁移没改生产逻辑 | 「生产 RTL 零变化」是这次能一次改 42 行的唯一依据 |
| 5 判据强度归位 | 每条变异登记见红位置 | 这是迁移最大的收益；只搬代码不补这一项，等于白搬 |

## 三、每一步做了什么

### 3.1 清点

`git grep` 全仓：95 个 `INJ_*` 宏名、417 处引用；其中 **70 个宏在 14 个生产 `.v` 文件里**
（`engine/` 12 个文件 63 个、`display/` 2 个文件 7 个），24 个 `sim/` 文件引用 47 个宏，
15 个 `run.sh` 与 10 个 Python 检查引用其余。按模块分布：mover 11、cmd 7、rast 7、bin 6、
geom 6、blend 5、pix 5、band 5、tex 4、rlst 4、display_out 3、inst 2、display_fetch 4、top 1。

另外还查出 18 个 `.v` 一个变异都没有，其中 `engine_regs`（434 行）与 `engine_pb`（600 行）
是最可能错又没人用变异证明判据在查的两个模块。

### 3.2 规则抽取

`Main/sim/mutation/migrate_ifdef.py`：解析 `` `ifdef INJ_* `` / `` `else `` / `` `endif ``（支持
嵌套别的 `ifdef`），`ifdef` 分支是变异体、`else` 分支是生产逻辑。删除整块只留生产分支，
再为每个变异体生成一条「原文 → 变异后」的字面替换。

规则必须在新文件里**唯一匹配**。做法是从生产分支所在的窗口开始，优先向上扩行（上一行通常
是注释或 `3'd0: begin` 这样的标号），直到唯一。两个文件的 10 条里，5 条需要 1~2 行上下文
才唯一（例如 CONST 的两行与 default 分支的前两行完全相同）。

写回时保持原文件行尾：`engine_blend.v` 是 LF，`engine_pix.v` 是 CRLF，混用会直接报错。

### 3.3 跑器

`Main/sim/mutation/run_mutation.py`：

- **影子树**：把 `Main/rtl`、`Main/tools/check`、`Main/sw/lib`、`Main/sim/axi_probe` 与本次
  涉及的套件按原相对布局复制到运行目录。套件里的 `../../../rtl` 与 `cd $(dirname $0)`
  照旧成立，所以 **15 个 `run.sh` 一行都不用改**。
- **单例模式**：每个 `run.sh` 新增 `--case <用例名>`，只构建并运行那一个用例、只打印
  `RESULT:`，**不自己判定**；判定权归清单里每条用例的 `evidence` 正则。
- **基线**：同一棵影子树先跑一遍无变异用例，基线不过直接 `INVALID`，不产生任何 KILLED。
- **分类**：`KILLED`（FAIL 且见红位置匹配）、`KILLED-WEAK`（FAIL 但红在别处或只靠超时）、
  `SURVIVED`、`PARTIAL`（多用例时部分抓到）、`INVALID`（规则不唯一/编译失败/基线不过）。
- **报告**：`mutation-report.json/md`，含每条用例的 `RESULT`、见红原文、耗时与归档日志。

清单 `mutants.yaml` 一条记录带缺陷模型、规格出处（文档 + 章节标题，审计会去文档里找）、
规则、应发现它的用例与见红位置。

### 3.4 迁移两个文件

`engine_blend.v` 153 → 132 行，`engine_pix.v` 555 → 534 行，合计删除 42 行，全部是
`ifdef`/`else`/`endif` 与变异分支，生产行一行未改（见 3.5 的证明）。

同时把「测试台知道有变异」的开关拆了：`tb_engine_pix.v`、`tb_engine_pix_pipe.v`、
`tb_engine_path.v`、`tb_engine_blend.v` 里的 `INJ_VAL` / `INJECT_VAL` 只用于打印
「inject N as expected」，删掉后测试台按普通期望判 PASS/FAIL。

**一个意外发现**：迁移后 `run_formal.sh` 的 8 个 `*_inj_*` 用例与 blend 的 5 个 `inject_*`
用例全都与原正常用例**激励完全相同**，区别只有期望值（写死 FAIL）。也就是说它们不是
「另一组测试」，只是「同一个测试再跑一遍并要求它红」。迁移后它们与正常用例重复，所以
直接删除，改由清单指向原有的 `unit_stall`、`pipe_burst`、`path_golden` 与 blend 的
`narrow_*`（后四条是压到单方程的快速用例，保留）。

### 3.5 等价证明

`Main/sim/mutation/verify_migration.py`，两个方向都用 `iverilog -E`：

| 方向 | 比什么 | 结果 |
| --- | --- | --- |
| 正向 | 迁移前（`551c2029`）不定义任何 `INJ_*` 的展开 vs 迁移后当前文件 | `engine_pix.v` 465 行逐行相同；`engine_blend.v` 98 行，代码相同（本轮改了文件头两行说明） |
| 反演 | 把规则应用回当前文件的展开 vs 迁移前带 `-D<原宏名>` 的展开 | 10/10 词法相同 |

两条规范化的理由都是实测出来的：`-E` 会给被删掉的指令行与未取分支各留一个空行，所以正向
只忽略空行；`` `ifdef `` 行尾的注错注释会作为注释残留在 `-E` 输出里，而迁移后的文件按约定
不留痕迹，所以反演只比到 token 层（去注释与空白）。

### 3.6 判据强度

10 条全部登记见红位置，按检查器归类：blend 的 5 条红在逐向量比对的 `MISMATCH #N: eq=…`；
pix 的分三类——`PIX_MISMATCH`（逐槽像素）、`MASK_MISMATCH`（「不写」掩码，色键与首拍掩码
两类缺陷都落在这一项）、`BEATS_OR_GAP` / `MEM_MISMATCH`（拍数对账与整片内存比对）。
正则写到标签级，不写死数值；数值一改就会退回 `KILLED-WEAK`，逼着重新核对，而不是静默通过。

## 四、遇到的问题

**① 规则全部匹配 0 次。** 第一版 `build_rule` 用 `"\n".join(lines)` 拼窗口，而行本身已带换行，
于是每行之间多出一个空行，`new_text.count(find)` 恒为 0，10 条规则全部失败。改成空串拼接
（行自带换行）后通过。判据是「规则必须唯一匹配」，它先于任何仿真把这类错误挡住了。

**② 正向比对不能逐字节。** `-E` 对删掉的指令行输出空行，迁移后文件少 3~4 行，所以字节数
必然不同（166 vs 145 行）。改成「只忽略空行、其余逐行相同」后，两个文件都是 98/98、465/465。

**③ 反演不能逐行。** 带 `-DINJ_COPY_DST` 的展开里残留一行 ` // 注错：抄了 ADD 行，COPY 用到了 dst`，
迁移后的文件没有这一行，逐行比对 10 条全 FAIL。这不是迁移的错，是 `-E` 保留了 `ifdef` 行尾
注释。改成词法比对（去注释与空白）后 10/10 通过；同时证明「注释不同、代码相同」。

**④ 伪·八条用例。** 见 3.4。原以为 pix 有「五个注错用例」，实际是同一个 `-DSTALL` 用例
换了个期望值，跑五遍。这类用例在旧机制下看不出问题，迁移时才暴露：它把「判据有效」的证据
和「激励设计」混成了一件东西。

**⑤ 基线比变异体贵。** `narrow_unreg` 与 `narrow_const` 的基线各 137 s 与 158 s：`ONLY_EQ`
只过滤比较、不减循环，所以「收窄」对通过的基线不起作用，只对 FAILFAST 的变异体有用。
整轮 10 条约 5.5 分钟，其中 5 分钟是这 8 条基线。

**⑥ 测试台仍可能知道变异。** mover/geom/tex 等 7 个套件的测试台里有 `INJ_VAL`/`ANY_INJECT`，
后者用来「有注错时跳过一段正常流程」。本轮只清了 blend 与 pix；其余模块迁移时必须一起清，
否则变异体会被测试台当作正常流程的一部分，红得没有意义。已经写进 `Main/sim/mutation/README.md`。

## 五、结果

迁移与等价证明：

| 项 | 结果 |
| --- | --- |
| 生产 RTL 里的 `INJ_*` 宏 | 70 → 60（blend 5、pix 5 迁出） |
| 删除行数 | 42（全部是指令与变异分支） |
| 正向等价 | 2/2 文件：pix 逐行相同、blend 代码相同（只改了文件头说明） |
| 反演等价 | 10/10 条词法相同 |
| 规则唯一性审计 | 10/10 |
| TB 侧注错耦合 | 删掉 4 个测试台的 `INJ_VAL`/`INJECT_VAL` |

变异活动（运行目录 `Main/sim/build/check-runs/mutation-20261114-012027`）：

| 变异 | 缺陷模型 | 用例 | 见红位置 |
| --- | --- | --- | --- |
| `blend.copy_dst` | 输入依赖 | `narrow_copy` | `MISMATCH #0: eq=0` |
| `blend.wrong_eq` | 运算恒等 | `narrow_const` | `MISMATCH #1: eq=3` |
| `blend.unreg_c` | 流水对齐 | `narrow_unreg` | `MISMATCH #65791: eq=1` |
| `blend.x_no_en` | 停顿时序 | `stall` | `MISMATCH #1: eq=0`（`exhaustive` 上 PASS） |
| `blend.trunc16` | 位宽截断 | `narrow_trunc` | `MISMATCH #767: eq=2` |
| `pix.en_notready` | 握手反压 | `unit_stall` / `pipe_burst` | `BEATS_OR_GAP` / `PIX_MISMATCH beat=` |
| `pix.core_noen` | 停顿时序 | `unit_stall` / `pipe_burst` | `PIX_MISMATCH n=` / `PIX_MISMATCH beat=` |
| `pix.rot_off` | 像素相位 | `unit_stall` | `PIX_MISMATCH n=` |
| `pix.skip_key` | 条件判断 | `unit_stall` / `path_golden` | `MASK_MISMATCH n=` / `MEM_MISMATCH addr=` |
| `pix.drop_mask` | 掩码边界 | `unit_stall` | `MASK_MISMATCH n=1 ls=0 ld=0 beat=0 slot=1` |

**KILLED 10/10，KILLED-WEAK 0，SURVIVED 0，PARTIAL 0，INVALID 0；基线 8/8 PASS。**
单条变异耗时 0.4~24 s（唯一的两条 4 分半以上是基线）。

套件回归（迁移后原样跑全套）：

```text
engine/blend   SIM OK: 7/7 cases as expected
               （exhaustive 全量穷举、golden、stall，加四条 narrow_*）
engine/pix     SIM OK: 8/8 RTL checks as expected
               SIM OK: 17/17 checks as expected（研究探针 9 + 入库 RTL 8）
```

本轮未综合、未上板：生产 RTL 的变化已由预处理逐行证明为零，但按仓库规则，
改动 RTL 仍需一次整机综合对账（资源、告警、setup/hold），这一项没做，记在第六节。

## 六、还欠什么

1. **剩余 12 个文件、60 条变异。** 其中 band、stripctl、instances、bin、g4 五个套件由 Python
   表驱动，要先改成吃影子树；这五处是剩余工作量的主要部分。
2. **`run_mutation.py` 还没注册成 `validate.py` 的检查项。** 当前它输出的是本轮证据，
   不受档位与证据复用规则约束；注册之后才能进 quick/acceptance。
3. **7 个测试台的 `INJ_VAL`/`ANY_INJECT`** 待随各模块迁移一起删。
4. **一次整机综合对账**：本轮的 RTL 删除应不影响网表，但没有实测。
5. **`EQUIVALENT` 状态还没有实例**：机制要求给出已跑过的等价论证（`proof` 字段），
   本轮 10 条全都直接 KILLED，没有用到这一档。
6. **零变异模块**：`engine_regs`（434 行）与 `engine_pb`（600 行）没有一条变异，
   用户已同意迁移完成后立刻补这两个模块的缺陷类覆盖。
