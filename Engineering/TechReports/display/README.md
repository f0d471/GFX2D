# display 系列

把 DDR3 里的帧缓冲逐行读出来送 HDMI，并让「场」成为全设计的同步基准。

平台为易灵思 Ti60F225（60K 逻辑单元，256 块片上 RAM），板上有 256MB 的 16 位 DDR3、
8MB SPI Flash 与一个 HDMI 发送口，片内 Sapphire SoC 的 VexRiscv 核跑 100MHz。
扫描输出接在 `Axi_Mux` 的 S0 上，只读、每个方向在途一笔（第 06 章定的契约）。

这个系列记录的是显示一侧：从 DDR3 取数、跨 100MHz 到 25.2MHz 的异步 FIFO、
像素侧的对齐与拆像素、双缓冲与场同步，以及每次改动之后要跑什么才算没退化。

## 实测结果

2026-09-21 三处修复之后重编译：四步 PASS，`Missing Interface Pins` 仍是已知 6 项，
XLR 21807（35.87%，比 2026-09-19 的 21653 多 154）、片上 RAM 71 块（比 65 多 6 块，正好是异步 FIFO
推断出来的块数，在 7 块预算内）、DSP 4 个、自写代码没有位宽截断告警；
`core_clk` setup 3.898 / hold 0.026 ns（最紧的一条没有被挤薄），`hdmi_tx_slow_clk` setup 33.807 / hold 0.071 ns。
`sim/display` 正常 9 项全 PASS（含像素时钟 ±0.5% 两组与整帧 640×480）、注错 7 项全部 FAIL 在对应判据上，
`sim/hdmi` 在 `hdmi_tx` 改造后仍 3/3。

2026-09-21 上板第一轮：烧 SRAM（不动 Flash），`0xF810_E000` 读回 `"DISP"`、VERSION 1，
`FRAME_COUNT` 每秒 +60，`ddrAliasTest` 打 `fail 0`，`ddrBurstProbe` 的扫描行
`beat = txn × 160`、`skip=0`、`resperr=0` 全部成立（当时该程序的 ID 判断还是 `"SCAN"`，一行 FAIL；
2026-09-21 已改成 `"DISP"` 并复跑两轮 `fail 0`，见第一章第六节）。
屏幕留在彩条状态交给用户确认。

2026-09-21 上板第二轮：往帧缓冲灌四条横向色带、切 `SRC=1`，
`FRAME_BEATS` 读回 `0x12C00`（恰好 480 × 160）、`SNAP_END_LEVEL` 0、`SNAP_MIN_LEVEL` 347 拍、
`FIFO_ZERO_HITS` 与 `FIFO_UNDERFLOW_BEATS` 0 / 0、`RESPERR` 与 `SKIP` 0 / 0；屏幕上从上到下红、绿、蓝、白，
由用户确认——这是「扫描输出接帧缓冲不需要字节重排」这条推导的端到端证据。
双缓冲同轮验证：`SWAP_REQ` 置位后 `SWAP_COUNT` 0 → 1、请求位被硬件自清、
`FRONT_BASE` 从 `0x0200_0000` 变成 `0x0240_0000`，屏幕色带反序且没有上下两半不一样的帧。

2026-09-21 上板第三轮（三处修复之后）：判据全套复现，`MAX_FULL_TXN` 239 个周期（占行周期 7.5%，
第 1 节预算 7.4%）；缺陷三的修复在硬件上验证——故意写 `CTRL=0x2` 造欠载，300 毫秒读出
`FIFO_UNDERFLOW_BEATS = 1305600 = 17 × 76800`，再写 `SRC=0` 与 `CTRL.CLEAR`，两个计数器都读回 0；
`ddrAliasTest` 回归 `fail 0`。

## 这条线的当前位置

显示通路上跑的已经是扫描输出自己的通路：`display_fetch` 按水位发一行 160 拍的读，
经 `display_fifo`（128 位 × 512 深）跨到像素时钟，`display_out` 拆像素、对齐、按 `SRC` 选彩条或帧缓冲，
再交给纯编码封装的 `hdmi_tx` 出 TMDS。上电默认 `EN=0`、`SRC=0`，屏幕上是彩条，不依赖软件。
帧缓冲模式与双缓冲已经在板上验证过。

留给软件的两个接口还没接：`sw/bsp/ti60/board.c` 的 `board_present` 与 `board_wait_frame`
仍是 SW1 留下的空实现，SW9 的后半要用 `FRAME_COUNT` 或场同步中断把板上的帧节拍接起来。
引擎接入时替换的是 S1 上的 `u_axi_probe`，S0 与它的契约不变。
