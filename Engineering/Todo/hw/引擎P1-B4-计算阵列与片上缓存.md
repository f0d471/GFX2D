## 1 要解决什么

**这一层做什么。** 把搬运层读回的源行、目的行放进片上，按几何层给的每行边带（I5）逐拍算出 4 个像素，
每拍一拍地喂给写核（I4）：

1. **行缓冲**：源、目的各一块 128 位 RAM，每块放两行乒乓（D23）。读流从搬运层来（I3），消费者恒 ready。
2. **像素旋转器**：源与目的的行首地址拍内相位 `lead`（I5，D36）不同时，用两拍窗口、4 个位置的旋转把源拍对齐到目的拍（D15）。
   `lead = (行首地址 & 15) >> 2`，表面基址按 16 字节对齐时就是 x 对 4 的余数，基址只按 4 字节对齐时不是。
3. **像素通路**：每拍 4 像素、12 个 B1 的混合核；色键比较源的原始存储字（spec 第 01 章 3.5 节）；
   XRGB 源的 `a` 取 255；FILL 的源是常量 `w4`。
4. **「不写」标记**：色键命中、行首行尾不属于本行的像素，X 字节最高位置 1（D16），由 B2 清掉对应的 `wstrb`。

**现在是什么样。** `engine_pix.v` 已实现并通过第 3 节判据，待验收。
前期研究的综合探针曾放过深 256 与深 512 的 128 位行缓冲、4 个位置的像素旋转与色键比较（第 4 节第 3、4 问），
入库实现进一步将目的缓冲压为 96 位并接通了 B1～B4 的真实通路。

**不做会怎样。** 高阶要求 2 的色键在这一层；每拍喂不上一拍时，写核会把 W 通道挂在 S1 上，扫描输出与 SoC 跟着等（D23）。

## 2 怎么切分

### 2.1 已定的取舍

**D15 对齐方式：`ENABLE_UNALIGNED = 0`，像素通路自带旋转器。** 首稿取 1，前期研究量到三处代价：
一行跨 4KB 拆成两个描述符时，第二段的流又从 0 号通道开始，两段在像素位置上接不上，像素通路仍要按像素重排；
起始地址的低 4 位原样发上总线（随机用例 800 笔突发里 578 笔非 16 字节对齐），而 E4 的探针只发过对齐地址，
控制器对这种地址的行为没有数据；两个核的字节移位器让搬运层从 1515 XLR 涨到 3198 XLR，周期数不变。

定案：描述符一律按 16 字节对齐的覆盖区间发，总线地址恒对齐；行首、行尾拍里不属于本行的像素按 D16 不写；
源与目的的行首地址拍内相位不同时（首稿写「x 对 4 的余数」，B3 前期研究按 D36 订正），像素通路用一个两拍窗口、4 个位置的像素旋转器把源拍对齐到目的拍；
4KB 边界本身是 16 字节的整数倍，拆开的两段按拍直接拼接。
没有采用：维持 1 并另加 4KB 拆分时的像素重排与一条控制器接收非对齐地址的上板验证。

**D16 的像素一侧**：本层按边带与色键打「不写」标记，清 `wstrb` 的一半在 B2（原文见 [engine 第 02 章](../../TechReports/engine/02-AXI事务层.md) 3.9 节）。

**D23 行缓冲：源、目的各一块，不设输出行缓冲。** 128 位宽的存储深 256 与深 512 都是 7 块（6 块 512×20 加 1 块 1024×8），
一行 161 拍的缓冲与两行乒乓的缓冲一样贵；原条目 2.2 节第 3 问原先估的「各 3 块」不成立。
写核只在第一笔突发的流数据到了之后才拉起 `awvalid`（`axi_dma_wr.v` 第 509 行），之后流一断 W 通道就挂在总线上，
所以要保证的是「写一开始就能每拍给一拍」。

定案：源、目的各一块 128 位 RAM，每块放两行乒乓；源、目的两行都在片上之后，像素流水线每拍出 1 拍直接喂写核，
写核自带的 32 深 FIFO 吸收总线反压（这个 FIFO 半满节流、对上游只开放 16 拍，每个写描述符的首拍写核也要停一拍，
所以像素流水线仍要按写流的 `tready` 整条停住，见 D47）。读描述符只在目标缓冲那一半空出来之后发，读流的消费者恒 ready，
S1 的 `rready` 不会因为引擎自己拉低（`Axi_Mux` 按读地址顺序回数据，S1 一停，扫描输出与 SoC 的读数据跟着停）。
片上 RAM 合计：行缓冲 14 块、两个核 16 块、D18 的命令缓冲 7 块，共 37 块；加上现行 71 块（4KB 缓存）是 108 块，
加上 89 块（16KB 缓存）是 126 块，总共 256 块。D46 之后行缓冲是 12 块（目的块只存 96 位），合计 35 块，
加现行 71 块是 106 块，16KB 缓存构型 124 块。
没有采用：首稿的三个行缓冲（21 块），写描述符等输出行整行算完再发。

**D42~D49（2026-10-01 前期研究与复核之后按推荐全部定案）。** 依据、数据与没有采用的做法在第 4 节开发日志的定案表，
这里只列结论：

| 编号 | 定案 |
| --- | --- |
| D42 | 旋转器放在行缓冲读出之后（数据级，4 个 32 位 4:1 选择）；两拍窗口，`off = (ls ≥ ld)`、`st = (ls − ld) mod 4`、`px[t] = 窗口[st + t]`；`off = 1` 的行首先走一拍预热（把地址 0 压进读口） |
| D43 | 首末拍掩码按目的拍在旋转之后打：槽有效 ⟺ `0 ≤ 4k + t − ld < npx`；边带级预算出首拍、末拍两个 4 位掩码，按拍号二选一，中间拍满拍 |
| D44 | 流水 7 拍：地址 → 行缓冲读出 → 数据级 → 旋转、色键、a 选择 → 混合核三级（`L = 3`）→ 标记合并；下游 ready 时行内无气泡；色键与掩码标记、拍号、valid 三条延迟像逐级贴着数据链 |
| D45 | `row_free[h]` 在第 h 半的边带握手之后拉低，该半的写流末拍被写核收走那一拍拉高；`rd_buf = {源/目的, 行号最低位}` 照 B3 的 D41。I3 的读流按 `rs_buf` 写进对应块的对应半，每半的写地址在该半的边带握手时清零、一行的两段读之间不清（边带先于本行的读发出，I2 的发出顺序） |
| D46 | 目的行缓冲读、写口都只用 96 位（每个像素的 X 字节不存）：512×96 是 5 块（`efx_map_ramest`，area、speed 两种模式相同），行缓冲合计源 7 块 + 目的 5 块 = 12 块 |
| D47 | 写流反压下整条流水停住：一个时钟使能 `en = ws_tready \|\| !ws_tvalid`，行缓冲读使能、各级寄存器、12 个核的 `en`、行状态机都挂它，停顿时 `tvalid` 保持 |
| D48 | 写流的 `tlast` 由搬运层按写描述符拍数打（`engine_mover` 里 `tlast = (wr_beats_left == 1)`，正常写流与排空哑拍同一个式子）；计算阵列不出 `tlast`，按边带的 `sb_beats` 出拍 |
| D49 | 半号不跨命令翻转（维持 B3 现状），每条命令的第 0 行都用第 0 半；奇数行命令边界多等的拍数在 B6 用真实命令表实测 |

### 2.2 开工前要补的研究

第 4 节的前期研究回答了 RAM 块数与 `tkeep` 的对应关系，这一批补下面几项，结果写进 TechReports `engine/` 第 04 章。

1. **旋转器与首末拍。** 读 Amiga blitter 的桶形移位与首尾字掩码（硬件手册第 6 章），定出两拍窗口的写法、
   旋转放在行缓冲读出之后还是写入之前、首末拍有效像素与旋转的先后。
2. **行缓冲的乒乓与空闲握手。** Efinity 上 128 位简单双口 RAM 的推断写法与读延迟；
   「这一半空出来」由谁告诉谁（本层 → B3 或 B2），怎么保证读描述符只在有整行空间时发（D23），回写总览 2.4 节。
   B3 已按 D41 留好接口：`row_free[1:0]` 每一半一位，几何层在每一行（含每条命令的第 0 行）发边带之前查它那一半，
   约定本层只在第 h 半的边带握手之后才拉低 `row_free[h]`；B3 测试台里有一个行缓冲替身（engine 第 03 章 3.7 节）可作参照。
   半号要不要跨命令连续翻转（单行、奇数行命令能交替用两半）也在这里一起定（engine 第 03 章第四节）。
3. **流水线的拍对齐。** 源拍、目的拍、边带、色键结果与 B1 的延迟 `L` 怎么对齐，出口怎么保证每拍一拍；
   设计文档 3.5 节画的五级流水与这里的实际级数对照。
4. **开源实现。** 至少读两份：STM32 DMA2D 的前景、背景两路输入（AN4943，总览原借鉴表）；
   ORGFX 的片元与写回模块；有现成的 FPGA 精灵行缓冲实现（例如街机核心）时一并看。
5. **实验。** 单独综合行缓冲、旋转器与一条 4 像素通路（带 12 个 B1 的核），RAM 与 D23 的 14 块对账，
   看「行缓冲读出 → 旋转 → 色键 → 混合 → 写核」这条路径在 100MHz 下的余量
   （前期研究 `ENABLE_UNALIGNED = 1` 那份的最差路径就是它的前半段，3.648 ns）。

研究之后要定的（编号 D42 起；本节首稿写「D24 起」，拆批时 D24~D28 已归 B1，D29~D32 归 B2、D33~D41 归 B3，顺延至此）：
旋转器的位置、乒乓的空闲握手、流水级数；复核又加了三项：写流反压下的停顿、写流两段的段界从哪来、半号要不要跨命令翻转。
2026-10-01 全部定案，结论见 2.1 节末的表。

### 2.4 仿真

新目录 `sim/engine/pix/`。

1. **数据通路逐像素**：B1~B4 连起来（写流经 `engine_mover`，`tlast` 由它打，D48），从机是补齐之后的 `axi_ram_model.v`（随机反压），测试台按 I1 直接喂解码后的命令。
   engine 第 03 章 3.4 节的几何定向用例（行跨 4KB、余数 4×4、宽度余数 4 种、源越界）逐像素与软件执行器相同。
   期望值由 `tools/check/` 新写的一个链接 `sw/lib/gfx` 的主机小程序导出（第 4 节第 9 问的整帧导出，本批先写，B6 复用）。
2. **色键与首末拍**：目的行首相位 `lead` 为 1、2、3 的窄矩形（含基址只按 4 字节对齐的表面；首末拍的部分掩码）与色键棋盘（中间拍按像素跳过的稀疏掩码），逐像素正确。
3. **每拍一拍**：源、目的两行都在片上之后，写流不断拍（`tvalid` 从首拍到末拍握手不落；写核不 ready 时整条流水停住，D47）；
   读数据阶段 S1 的 `rready` 恒为 1。写流下游必须是真写核 `axi_dma_wr`（经搬运层），不能用恒 ready 的替身。
4. **注错**：跳过色键、旋转错一个位置、不看写流 `tready`、混合核不随流水停，各自必须见红。

### 本批不做

命令的取数与检查（B5）；十一个整帧用例的整帧 CRC（B6，要经 APB 提交整张命令表）。

## 4 开发日志

### 2026-10-01 验收复核

在仓库的干净克隆里复现实现阶段的全部数字（`run.sh` 18/18、常规九个套件全部 `SIM OK`），再审 RTL 与测试台，改了下面几处。
研究过程、数据与解释都写进了 engine 第 04 章（第四节的前三个问题、3.8~3.11 节），这里只记流水。

### 2026-09-26 前期研究（原条目 2.2 节第 3、4、9 问）

原来的问题：

3. 行缓冲的深度与片上 RAM：源行、目的行、输出行各最多 161 拍 × 128 位，估算各 3 块、合计约 9~10 块；
   输出行要整行缓冲完再发写描述符，写核拿不到数据时会把 W 通道挂在总线上，占住 S1。
4. 读侧最后一拍的 `tkeep` 与行内像素的对应关系；宽度不是 4 的倍数时，像素通路怎么丢弃多余像素。

#### 第 3 问：行缓冲与片上 RAM

综合探针里深 256 与深 512 的两个 128 位行缓冲各占 7 块（6 块 512×20 加 1 块 1024×8，14 块合计，见 engine 第 02 章 3.1 节 30 块的拆分：
两个核 16 块、两个行缓冲 14 块）。原先「各 3 块」的估算按 10 Kbit 一块折算，没有考虑位宽：Ti60 的 RAM 块在这里最宽只取到 20 位，
128 位就要 7 块并排，深 512 以内不再增加。

写核只在第一笔突发的流数据 `tvalid` 到了之后才拉起 `awvalid`（`axi_dma_wr.v` 第 509 行），之后流一断，W 通道就挂在总线上。
所以要保证的是「写一开始就能每拍给一拍」，不一定要整行输出缓冲：源、目的两行都已在片上时，像素流水线是定长流水，
每拍出一拍，写核自带的 32 深 FIFO 吸收总线反压。输出行缓冲可以省掉，见 D23。

#### 第 4 问：`tkeep` 与宽度不是 4 的倍数

- `ENABLE_UNALIGNED = 1`：读流第一个像素在 0 号通道，最后一拍 `tkeep` 恰好是低 `len mod 16` 个字节（测试台逐个操作核对过）；
  写核只在最后一拍看 `tkeep`。宽度不是 4 的倍数时，最后一拍多余的通道由 `tkeep` 截掉。
- `ENABLE_UNALIGNED = 0`：每拍 `tkeep` 全 1，拍内像素位置与地址一致；几何层知道 `x0 mod 4` 与宽度，
  像素通路按拍号算出哪几个通道属于本行，其余通道打「不写」标记。测试台里这一步按下标换算，相当于像素通路的旋转器，两个种子都过。
- 拆行：一行跨 4KB 时几何层要拆成两个描述符。`= 1` 时第二段的流又从 0 号通道开始，
  第一段最后一拍只有 `(len1 / 4) mod 4` 个像素，两段要按像素重新拼；`= 0` 时 4KB 边界是 16 字节的整数倍，两段按拍直接接上。

#### 第 9 问：期望值怎么进 Verilog


- 转换脚本：把标签文本展开成定长的十六进制记录，每条记录前面一个类型字（向量头、表面、表、命令、内存初值、期望），

  64 KiB 的从机存储够用；命令表放在向量不用的地址（例如 `0xE000`），`reads` 之后的地址回 `SLVERR`。

#### 第 1 项：旋转器与首末拍

**Amiga blitter（node011F~node012A，amigadev.elowar.com 镜像）。** 与本设计的对照按
「word ↔ 128 位拍、桶形移位器 ↔ 像素旋转器、node0127 的流水寄存器 ↔ 两拍窗口」映射：

| 手册原文（节点） | 结论 | 对本设计的含义 |
| --- | --- | --- |
| node011F：A、B 通道各一个 0~15 位桶形移位器；移位量写在 BLTCON0/1，不是硬件从地址差算的；「a shift of 100 bits would require the destination pointer to be advanced 6 words, and a right shift of the remaining 4 bits」 | 移位量 = 相位差，超出字宽的部分并入指针 | 本设计 4 像素/拍，相位差 `ls−ld` 落在 0~3，**全部在旋转器内**，没有指针修正这一层 |
| node011F：首字/尾字掩码「anded with the source data, **before** any shifts are applied」；node0121 的例子里掩码由目的相位与宽度算出 | 掩码在移位前、按源字边界打（1bpp 位平面格式的产物） | 本设计掩码单位是 32 位整像素，**按目的拍在旋转后打**更优：只依赖 `ld` 与 `npx`，不依赖 `ls`，且每行重置窗口，天然没有手册里「行尾移出的位串进下一行首字」的跨行污染 |
| node0127（Pipeline Register）：「the first two sets of sources are fetched before the first destination is written」 | 两字窗口：目的的第一个字由源的头两个字拼出 | 两拍窗口 `{前拍, 当前拍}` 的依据；每行的窗口都重置，前拍在行首没有合法数据（→ 预热拍，见下） |
| node011F：右移时「the second word will be the second word fetched from A, shifted right, with the least significant four bits of the first word shifted in」；零从另一侧移入 | 窗口拼接方向与移位方向绑定（常规右移、降序左移） | 本设计两种窗口都要：`off=1`（`ls≥ld`）窗口 `{beat k, beat k+1}`，`off=0`（`ls<ld`）窗口 `{beat k−1, beat k}`——方向由 `off` 选择，Amiga 只有单向是因为它的降序模式另有硬件 |
| node011F：掩码为 0 处经 C 通道写回旧目的（cookie-cut，「Destination does not change where mask is 0」） | 超界位不写新数据、旧值保持 | 与 D16 的带内标记等价：行外像素的写使能清掉，目的原值不动 |
| node012A：一次 copy 周期 A+D 四拍、B+D 六拍、B+C+D 八拍；移位零开销 | 吞吐按数据通道数计费 | 本设计每拍一次混合、无逐通道计费的问题 |

**逐像素公式（探针 `probe_pix_rot`/`probe_pix_mask` 实现并全组合验证）。**
目的拍 k（0 起）槽 t（0~3）的像素号 `j = 4k + t − ld`，属于本行 ⟺ `0 ≤ j < npx`；
行外槽打「不写」（D16）。源像素 j 在源行缓冲的 beat `(ls+j)/4`、槽 `(ls+j) mod 4`。
旋转器读地址超前量与窗口起始槽：

| 相位关系 | off（读地址超前） | st（窗口起始槽） | 窗口 | 拼接 |
| --- | --- | --- | --- | --- |
| `ls ≥ ld` | 1 | `ls − ld`（0~3） | `{beat k, beat k+1}` | `px[t] = 窗口[st+t]`：`st+t<4` 取前拍（beat k），否则取当前拍（beat k+1） |
| `ls < ld` | 0 | `ls − ld + 4`（1~3） | `{beat k−1, beat k}` | 同式：`st+t<4` 取前拍（只喂行外槽），否则取当前拍 |

`off=1` 时第 0 拍的「前拍」也要真数据（`st>0` 的槽是行内像素），所以行首要一拍**预热**：
状态机先走一拍 `PS_PRE` 把地址 0 压进读口，再进 `PS_RUN` 连发 `dst_beats = ceil((ld+npx)/4)` 拍。
`off=0` 不用预热：第 0 拍的前拍只喂 `j<0` 的行外槽（掩码掉），读到旧数据无妨。
行尾多读的一拍尾巴（off=1 时地址 `k+1` 最多到 `dst_beats`）落在 256 深的半内，越界槽全行外。
这条预热规则是本轮研究新发现的设计约束，**入库实现必须遵守**（探针漏掉它时 `ls≥ld` 且 `st>0`
的行首像素直接错，见下面踩坑记录）。

掩码在边带级预计算成首拍/末拍两个 4 位常量、按拍号二选一即可（首拍只有头部行外、
末拍只有尾部行外，中间拍恒满拍）；探针里逐槽比较是为可读性，两者等价，定案时选预计算。

#### 第 2 项：行缓冲的乒乓与空闲握手

**Efinity 2026.1 的 RAM 推断规则**（`Efinix/03_.../03_芯片数据手册/efinity-synthesis.pdf`「RAM」章，原样摘录）：
读写口都是寄存的、不支持异步读；Titanium 映射为 `EFX_RAM10`（简单双口）/`EFX_DPRAM10`（真双口）；
宽度档位 512×16、1024×8、2048×4、4096×2、8192×1、512×20、1024×10、2048×5；
Byte Enable 只在写宽度 16/20 时可用（WE[1:0] 各管半字）；同钟读写同地址时可选
READ_FIRST（默认）/WRITE_FIRST/READ_UNKNOWN。行缓冲用最普通的推断写法
（读写分立 always、非阻塞、同步读），读延迟恒 1 拍，探针实测推断出 13 块 `EFX_RAM10`（见第 5 项）。
乒乓两半谁也不会同地址读写，WRITE 模式对本设计无差别。

**深度与块数。** `efx_map_ramest --family Titanium --mode area`（Efinity 2026.1.132）：
512×128、256×128、162×128 都是 **7 块**——深度在 512 以内不花钱，位宽才花钱。
D23 的「一行 161 拍的缓冲与两行乒乓的缓冲一样贵」成立。取深 512（位 [8] 选半，半内 256 拍；
一行最多 162 拍含 off 尾拍，深 256 也够且省一位地址，取哪个留给定案）。

**row_free（D41）的确认与释放时机。** 探针按 `half` 参数对两半各跑了一半用例（sweep 的
`half = (n+ls+ld) mod 2` 交替），两半对称可用；`rd_buf = {源/目的, 半}` 的编码与几何层的
发射一致。半的生命周期定为：**边带握手占用 → 读流写入该半 → 像素通路消费 → 该半的写流
末拍离开像素通路释放**。B3 测试台的行缓冲替身（握手占上、写拍数收齐后过 `drain` 拍放掉）
与这个模型一致；入库实现里 `row_free[h]` 在写流末拍被写核收走的那一拍拉高。
半号**不**跨命令翻转：几何层的半号是**本命令内**行号的最低位（`engine_geom.v` 里 `row_i` 每条命令从 0 起，

下一条的第 0 行要等第 0 半放出来；D41 保证的是这时不会读进占着的那一半（正确性），不是两半交替。

#### 第 3 项：流水线的拍对齐

**实际级数（探针实现并逐拍验证，7 拍延迟，行内无气泡）。** 周期编号从「地址寄存器输出
第 0 拍地址」起：

```
周期 0    地址发生器：源 = 半基 + k + off（PS_PRE 时发 0），目的 = 半基 + k
周期 1    两块 RAM 的输出寄存器出数 q_src / q_dst（同步读，1 拍延迟）
周期 2    r_cur ← q_src、r_prev ← 旧 r_cur、r_dst ← q_dst、r_k ← cnt_k（数据级）
周期 3    旋转 {r_prev, r_cur} → 4 像素、色键比较、a 选择（XRGB→255）组合后落寄存器
          r_px/r_a/r_keys/r_maskk；r_dst2 ← r_dst（与 r_px 同拍）
周期 4~6  engine_blend 三级（I6 的 L = 3：判定+乘 → 加 → 舍入饱和）
周期 7    标记合并（色键 | 行外 → X 字节 bit7，D16）与 tlast 落写流寄存器 ws_*
```

与设计文档 3.5 节的五级概念流水对照：级 0 取数 = 周期 0~2（行缓冲读出）、级 1 判定 = 周期 2~3
（色键与选 Fs/Fd，落进 blend 第一级的判定逻辑）、级 2 乘 = 周期 4、级 3 加与舍入 = 周期 5~6、
级 4 写回 = 周期 7。概念图五级落在实际 7 拍上，与 B1 3.3 节「设计文档的级 3 拆成两级」的读法一致。
7 拍延迟无害：B2 3.8 节实测 `PIX_LAT` 4 与 12 每颗弹幕周期数完全相同（被「写与下一行的读并行」盖住）。
I2 注里「写描述符握手到写流首拍的间隔不得长过 T」（4096 拍）：这段间隔是本行余下的读加像素通路，
无争用时最长的一行（读源、读目的各 161 拍）按 E4 公式约 2 × (27.41 + 1.086 × 161) ≈ 405 拍，
再加预热 1 拍、流水 7 拍、写核首拍停 1 拍，约 414 拍，是 T 的十分之一；满负载下的实测归 B6（D30 的同一口径）。

**I6 的两条约定得到综合证据。** blend 的五个输入全部由寄存器直接驱动（`r_px/r_a/r_c/r_eq`
与 `r_dst2` 都过一级寄存）；单独综合的最差路径是 `u_path/r_eq[0]` → blend 核 DSP 的 B 口
（4 级逻辑，slack +4.898 ns；加停顿之前的一版是 +4.560 ns，同一条路径）——正是 B1 第一级的判定选 base/m1/m2 链，与 B1 单独综合的
形态一致，说明旋转器+色键这一段**没有**吃掉第一级的余量。

**延迟链对齐规则（本轮踩出来的，入库实现要照做）。** 与数据链并行的三条延迟像——
色键/掩码标记、拍号 k、valid——必须逐级贴着数据链，**差一级就是提前/落后一拍**。
探针先后踩过两个：拍号链比 valid 链少一级寄存 → 两拍行的 tlast 提前一拍（373 条
TLAST-POS）；掩码吃的是距 cnt_k 一级的拍号而窗口数据距 cnt_k 两级（RAM 输出寄存器多一级）
→ 掩码相对数据提前一拍、只红在 ld≠0 行的首末拍（1922 条 MISMATCH）。都修掉后
逐槽比对 0 处不符（第 5 项）。

**「每拍一拍」判据与写流反压。** 地址发生器行内连发，下游 ready 时写流每拍一拍：
恒 ready 的测试台里 sweep、fill、seg、long 全部 418 行写流一次都没断。
但像素通路**必须看 `ws_tready`**。写核的 `s_axis_write_data_tready` 是寄存器，
在 `STATE_START` 里看到 `tvalid` 才发 AW、下一拍才拉高（`axi_dma_wr.v` 第 509、515 行），每个写描述符的首拍至少停一拍；
输出 FIFO 半满就拉低（`m_axi_wready_int = !out_fifo_half_full_reg`，第 905 行），对上游只开放 16 拍，
总线 W 通道一慢，长行的行中也会停。所以整条流水挂一个时钟使能 `en = ws_tready || !ws_tvalid`：
行缓冲读使能、各级寄存器、12 个核的 `en`（I6 留的口）、行状态机都按它走，停顿时 `tvalid` 保持为 1、不出气泡。
接真写核的停顿数字见第 5 项。读数据阶段 S1 的 `rready` 由搬运层保证（I3 的消费者恒 ready）。FILL 不读源块（源常量 w4 直接进 12 核，DMA2D R2M 的做法），
探针里源地址发生器照转（读的是垃圾、值不进通路），入库实现可以顺手把 FILL 的源读使能关掉。

#### 第 4 项：开源实现

三份的出处、形态与取舍得已补进本条目「借鉴来源」表。要点：

- **STM32 DMA2D**（RM0090 第 11 章、AN4943）：FG/BG 两路输入 FIFO（64 位）+ 各自的像素格式
  转换器统一成 32 位 ARGB 进 blender；**R2M 填充「none of the FIFOs is activated」**——常量源从
  寄存器广播，一次存储器都不读（本设计 FILL 同法）；它没有逐像素「不写」能力（混合结果逐像素
  写出），也没有像素相位重排（每拍 1 像素，无相位问题）——本设计的 D16 带内标记与旋转器都超出它。
- **ORGFX**（DIVA 论文；opencores 的 websvn 仍取不到源码）：每级 1 像素、无行缓冲（blender 经读
  主口现读目的、读仲裁优先级最高），50 MHz 下 5.1 Mpix/s，论文自评瓶颈在带宽。反面对照支撑本设计
  的取舍：E4 实测每行两笔读事务 65.6 周期、固定开销 54.8，行缓冲 + 每拍 4 像素正是绕开
  ORGFX 式「每像素一次总线事务」的手段。色键在片元级比较、命中像素不产生下游写事务，与
  D16 语义同向。
- **jotego jt1942**（街机核心，`jtgng_objpxl.v`）：两块 256×4 单口 RAM 乒乓（逐行翻转）、
  精灵非透明才写（色键跳过落在行缓冲写口使能上）——与本设计「两半乒乓 + 混合前打不写标记」同构。
  它的「读出即清空」技巧本设计不需要：帧缓冲在 DDR、写核整行覆写，行缓冲无需清零。

`ceil((ld+npx)/4)`、首个 valid 到末拍握手之间 `tvalid` 不落、tlast 只在段末、tkeep 恒 FFFF。

`-DREALWR` 的接法：写流接 `rtl/vendor/verilog-axi/axi_dma_wr.v`（参数与 `engine_mover` 例化的相同），

测试台按段发写描述符，拆段的行让段 1 结束在 4KB 边界上。逐行的停顿：

| 行 | 拍数 | 段首停 | 段中停 | 首拍到末拍握手 |
| --- | --: | --: | --: | --: |
| sweep 与 FILL（406 行，各一个描述符） | 1~8 | 每行 1 | 0 | 拍数 + 1 |
| 拆段 4 行（各两个描述符） | 6~8 | 每行 3（段 1 首拍 1、段 2 首拍 2） | 0 | 拍数 + 3 |
| 253 像素（4 行） | 64 | 1 | 0 | 65 |
| 640 像素（4 行） | 160~161 | 1 | **9** | 170~171 |

段首停顿合计 406 + 12 + 8 = 426 拍、段中 4 × 9 = 36 拍，与汇总行对得上。
每个写描述符的首拍都至少停 1 拍（写核 `STATE_START`；段 2 多停一拍，写核收完段 1 的末拍之后才接下一个描述符），
行长了之后，输出 FIFO 被 W 通道的气泡（定时从机每 6 拍空 1 拍）积到半满，行中开始停：
64 拍的行还没积满，160 拍的行停了 9 拍。两种停顿像素通路都得接住：
不看 `tready` 的注错丢掉 9388 处，只让混合核照走的注错 3380 处；同样两处错在恒 ready 下都不红。
复核之前的 4/4 就是这样过的。

**RAM 对账（对 D23 的订正）。** D23 写「行缓冲 14 块」（2×7，按 128 位全宽折算）。实测：
源块 7 块（128 位全用——色键比较整字含 alpha、a 取高字节）；**目的块 6 块——目的像素的
X 字节（每拍 4×8 位）不参与混合也不写回（输出 X 字节恒 0 或标记位），读侧只有 96 位有效**，
Efinity 把 32 个死位折叠后少映射 1 块（map 网表里 `u_lbs` 7 个、`u_lbd` 6 个 `EFX_RAM10`，
逐实例查过 READ_WIDTH 与 RDATA 位段）。探针的写口仍是 128 位，所以是 6 块不是 5 块。
入库实现把目的行缓冲**写口**也收成 96 位（丢掉 4 个 X 字节再写）：`efx_map_ramest --family Titanium`
给 512×96 是 **5 块**（area、speed 两种模式相同；512×128 是 7 块、512×120 是 6 块），不花逻辑，定为 D46。
片上 RAM 总账：行缓冲 12（源 7 + 目的 5）+ 两个核 16（B2 实测）+ 命令缓冲 7（B5）= 35 块，D23 原估 37；
加现用 71 块是 106 块（16KB 缓存构型 124 块），256 块内。

**工具链的坑（都有复现命令，写下来免得再踩）。**

- iverilog 拼接截断：预填地址 `{half, m[8:0]}` 是 11 位赋给 9 位口，`half` 被静默截掉，
  半 1 的行全写到半 0——**先怀疑它错了三轮**，其实真正错因在下面两条；
- iverilog 调度竞态：preload 任务在 posedge 唤醒的同一时刻改写 `lb_src_sel/lb_wdata`，
  RAM 的 `always @(posedge)` 采样到「旧 sel + 新数据」，目的数据写进源缓冲
  （检查点打印证明：源写完时 `lbs[256]` 正确，目的写完后变成目的数据）。
  激励一律 negedge 设置、posedge 被采样后消失（geom 的测试台已经这么写，本探针首版没跟）；
- Efinity verilog_2k 不认 SystemVerilog 的 `8'(expr)` 截断语法（map 直接 FAIL，VERI-1137），
  改成普通条件表达式；位宽截断告警 3 条（`r_half` 2 位进拼接、`dst_beats` 中间量过宽），
  中间量按最大位宽算、取位用显式切片后清零。

#### 定案（D42~D49，2026-10-01 按推荐全部定案）

| 编号 | 定案 | 依据 |
| --- | --- | --- |
| D42 | 旋转器放行缓冲读出之后（数据级、组合 4:1 mux×4），两拍窗口与 off/st 公式；`off=1` 行首加一拍预热（`PS_PRE` 发地址 0） | 第 1 项的推导与探针全部 418 行（两种下游）；预热缺失即错（踩坑实证） |
| D43 | 首末拍掩码按目的拍在旋转后打：`0 ≤ 4k+t−ld < npx`；边带级预计算首/末拍两个 4 位掩码、按拍号二选一 | 第 1 项；掩码只依赖 `ld` 与 `npx`，与 `ls` 解耦 |
| D44 | 流水 7 拍（地址→RAM→数据级→旋转/色键→blend L=3→标记合并），下游 ready 时行内无气泡；标记/拍号/valid 三条延迟链逐级贴数据链，`r_k2` 一类的二级拍号寄存要有 | 第 3 项；差一级的两个 bug 实证 |
| D45 | `row_free[h]` 的释放时机 = 该半写流末拍离开像素通路（写核收走末拍那一拍）；占用 = 该半边带握手 | 第 2 项；与 B3 替身的 drain 模型一致 |
| D46 | 目的行缓冲读、写口都只用 96 位（X 字节不存不读），5 块 | 第 5 项 RAM 对账（6 块 vs 7 块的来源）与 `efx_map_ramest` 的 512×96 = 5 块；写口收窄不花逻辑 |
| D47 | **写流反压下整条流水停住**：一个时钟使能 `en = ws_tready \|\| !ws_tvalid`，行缓冲读使能、各级寄存器、12 个核的 `en`、行状态机都挂它，停顿时 `tvalid` 保持。没有采用：输出端加滑动缓冲、地址发生器按余量发（流水 7 级，要不丢拍就得 8 深以上 × 128 位，约 1000 个 FF 或再占 7 块 RAM） | 第 3 项与第 5 项：写核每个描述符首拍必停（`axi_dma_wr.v` 第 509、515 行）、FIFO 半满就停（第 905 行）；真写核下 422 个描述符段首停 426 拍、640 像素行段中停 9 拍；不看 `tready` 丢 9388 处、核不停 3380 处；`en` 扇出 1256 FF + 13 RAM + 12 DSP，setup +4.898 ns 未变差 |
| D48 | **写流两段的段界由搬运层给**：`engine_mover` 按自己记的描述符拍数打 `tlast`（`ws_core_tlast = (wr_beats_left == 1)`，排空补拍已经这么打），像素通路只管按 `sb_beats` 出拍。没有采用的两个做法：I5 加一个「写方向第一段拍数」字段（B3 已经算出 `seg0`，要改 B3 的 RTL、`geom_model.py` 与测试台）；B4 旁听 I2 的写描述符握手并排队（两层多一组耦合）。定的这个做法改了已验收的 B2（见下面「定案」一节），I4 的「末拍必须带 `tlast`」与 D29 的隐患一起消失 | 复核发现：I5 边带只有 `sb_beats`（两段之和，`engine_geom.v` 第 354 行），探针的段拍数是测试台直接给的；B4 自己算不出段界（要写地址的低 12 位） |
| D49 | **半号不跨命令翻转**（维持 B3 现状）：奇数行命令后面那条命令的第 0 行等第 0 半放出来。估算代价：16 像素宽的行，上一行从读完到写流被收走约 15 拍（预热 1 + 流水 7 + 5 拍 + 首拍停 1 + 握手），每个奇数行命令边界多等约 15 拍，对一颗 16×16 弹幕的 1092 拍约 1.4%，且只有被裁剪框截成奇数行的精灵才有；改成跨命令翻转要动 B3（一位跨命令的翻转寄存器，边带与 `rd_buf` 用它）。B6 用真实命令表实测 | 第 2 项订正；engine 第 03 章第四节「没有采用：半号跨命令连续翻转……等 B4 有了实测再定」 |

### 2026-10-01 复核：前期研究的修正

开发前复核一遍研究结论，对着 `axi_dma_wr.v`、`engine_geom.v` 与登记数据逐条查，改了下面几处。
上面各项里的文字已经直接改成现在的结论，这里记哪里改了、为什么。

1. **写流反压（结论错，影响 RTL 结构）。** 原第 3 项写「地址发生器行内连发、不看下游 ready，
   写核 32 深 FIFO 吸收反压」，测试台 `ws_tready` 恒 1。读写核源码：`tready` 每个描述符首拍必为 0，
   FIFO 半满（16 拍）也拉低。照原写法接真写核，每一行的首拍都会丢。
   修法：探针整条流水挂时钟使能（D47 候选）；测试台加 `-DREALWR`（真写核 + 定时从机）与两个注错；
   重跑仿真 9/9、单独综合四步 PASS。两个新注错在恒 ready 下都不红，`run.sh` 把这一点也当判据留着。
2. **写流两段的段界（接口缺口）。** 探针的 `seg1_beats` 是测试台给的，入库实现拿不到：
   I5 边带只有两段之和 `sb_beats`，段界只在 I2 的写描述符上。三个做法与推荐见 D48 候选，要改已验收的 B2 或 B3，留给定案。
3. **半号跨命令翻转（结论错）。** 原第 2 项写「由几何层按行号最低位自然完成」；`row_i` 是命令内行号，
   每条命令的第 0 行都在第 0 半。已改正文，代价估算与推荐见 D49 候选。
4. **超时门限 T 的余量（数字用错）。** 原第 3 项写「约 28 拍以上的余量」，28 拍是每笔读的固定开销，
   不是余量；按 E4 公式重算，无争用时最长一行约 414 拍，是 T（4096）的十分之一。
5. **板上登记值（措辞）。** 原写「登记值约 347/331/327，write 差 2 拍」；第 08 章登记的 write 组是五轮 327~329，
   本次 329 落在范围内，不是「差 2 拍」。
6. **综合 FF 数（口径）。** 原登记「728 FF」是 `hier_util.rpt` 的 `xlr_ff` 列；FF 总数看 `res.csv`，加停顿之后是 1387。
7. **长行没跑。** 原用例宽度只到 25 像素、161 拍的最长行「由代数一致性覆盖」；补了 253、640 像素各四行，
   640 像素这四行正是真写核下行中停顿的那四行。
8. **综合顶层。** `probe_pix.v` 里的 `probe_pix_top` 输入全接常数（`ls=3`、`ld=1`、`npx=37`，行缓冲写口恒 0），
   注释却写「LFSR 激励」，也没有哪个工程用它（单独综合用的是 `syn/syn_probe_pix.v`，那份是 LFSR 驱动）。B3 验收刚踩过
   「顶层输入接常数，综合把逻辑折掉、余量虚高」，这个模块留着容易被误用，已删除。

### 2026-10-01 D42~D49 定案，搬运层改打 `tlast`

D42~D49 按推荐全部定案，结论列在 2.1 节末，依据在上面的定案表。两项定案前补了数据或落了地：

**D46 补数。** 候选写的是「写口收不收窄按实现代价定」。`efx_map_ramest --family Titanium` 量了四种形状：
512×128 是 7 块、512×120 是 6 块、512×96 与 256×96 都是 5 块，area 与 speed 两种模式相同。
写口收窄只是不接 4 个 X 字节，不花逻辑，所以定成读写口都 96 位，行缓冲合计 12 块，片上 RAM 总账 35 块。

**D48 落地：`rtl/engine/engine_mover.v` 改了三处。**

1. `ws_core_tlast` 从「排空时按剩余拍数、平时直通 `ws_tlast`」改成一律 `wr_beats_left == 1`。
   `wr_beats_total` 在写描述符握手那一拍装入，写核在 `STATE_START` 里至少停一拍才收流的第一拍，
   所以第一拍到来时剩余拍数已经是新描述符的。
2. 去掉 `ws_tlast` 输入口，计算阵列想给也给不进来。
3. 加注错位 5（值 32）：正常写流不打 `tlast`，即「靠计算阵列给、它没给」的情形。

`sim/engine/mover/run.sh` 加一个注错用例和一条判据，**17/17**：

```text
inject_no_tlast: RESULT: FAIL (看门狗：仿真没有自己结束)
inject_no_tlast: FAIL 由写核卡在 DROP_DATA（只有第一笔写上了总线）引起
SIM OK: 17/17 checks as expected
```

`normal` 用例发 4 笔写（`STAT ... aw=4`），注错版只有第一笔上了总线（`aw=1`）：第一笔的拍数用完时流上没有 `tlast`，
写核进 `STATE_DROP_DATA` 一直等，后面的描述符一个也收不进去，这就是 D29 说的后果。
原有的四个正常用例与五个注错照旧；`inject_nodrain` 的收尾从「85 errors」变成看门狗，红的仍是「排空没有完成」
那条判据。原因是这个注错把排空的补拍关了，写流停在半路：原来测试台按自己的拍数在中途送出一个 `tlast`，
写核提前收尾、仿真能结束；现在 `tlast` 只在描述符真的送满时出现，写核一直等。两种都是注错版的坏行为，判据不变。
测试台去掉了 `ws_tlast` 的驱动（写流不送 `tlast`）。

单独综合（仓库外 `.engine-b2-research` 的两个工程直接引用仓里的 RTL，综合顶层只删掉 `ws_tlast` 一处连线）重跑，四步都 PASS，

最差 setup 路径的起点从 `wr_beats_sent` 换成 `wr_beats_total`（主线参数下到写核状态 FIFO 的使能，17 级、4.514 ns），
因为 `tlast` 现在每拍都要看剩余拍数；余量仍有 4.9 ns 以上。读核没改，361 → 353 XLR 是综合与布局的波动。
