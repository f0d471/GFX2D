# 三维光栅总览(R 系列)

状态:**R1~R4 已验收**（R4 于 2026-10-29 用户视觉验收，条目已删）。
CPU setup + FPGA 条带光栅路线保留；1100 tri/6ms 的预算已被本机板测推翻，
R4 固定演示负载下，板上三场景CRC与1800帧
两场节拍全过（p50 25.02ms/max 29.62ms、迟到0），软件12项acceptance通过；
1100条仍为压力/优化目标，不把浏览器预览的模拟TRIS/FPS作为板上指标。
R3证据见 [engine 第16章第七节](../../TechReports/engine/16-三角列表与光栅核.md)；
R4 实现与验证全程见 [engine 第17章](../../TechReports/engine/17-三维演示模式与同构对照.md)。
本文件是三维光栅先行工作点的总览:拍板记录、技术选型与开源调研结论、R1~R5 清单、
阻塞关系与排期。未完成项的 spec 在各 R 条目里,已验收项的过程与数据归 TechReports
(engine 系列续章)。后续按实际硬件工作点立项；应用效果和试玩不形成持续待办。

## 1 背景与拍板记录

嵌赛全赛道统一评选,评委临时接题、非本赛题专家;赛题三优秀作品在演示效果与工作量观感上有
隐藏分。本工作点在不动 2D 主线任何已验收结论的前提下,给作品增加一条 **3D 固定管线**
(总纲 4.6 G3 的嵌赛先行)与 3D 演示模式。硬约束:2D 报告数字、验收证据与可复现性一分
不能丢;3D 全部走增量(新机制宏 + 新预设),任何时点可放弃、回退无损。

2026-10-22 拍板,四项全按调研建议:

| 项 | 定案 |
| --- | --- |
| 做不做 | 做,按降级阶梯 L1(平涂)→L2(TEX 纹理,主目标)走 |
| 基座预设 | **B3**(条带+TEX+INST;归档综合 **43816 XLR/165 RAM/19 DSP**,见 engine 第 14 章);B5 仅剩 736 XLR,排除 |
| 演示形态 | 混合式轨道射击:3D 走廊+世界空间弹幕(全部走 3D 通路,敌弹色键 billboard)+2D HUD;cup3d 硬件版作同分辨率同语义对照 |
| 2D 游戏去留 | MYRIAD 保留为指标演示,3D 是新增模式(菜单切换),不替换 |

核心思路:**3D = 条带模式的推广**,架构属**条带式局部缓冲渲染**(stripe-based local-buffer
rendering;不发「完整 TBDR」的宣称——延迟合成等机制不在本工作点范围)。BAND 条带缓冲即
局部颜色缓冲,旁挂条带 z RAM;每条带内相位化执行(背景装载 → z 清零 → 3D 三角形 → 2D 命令
→ 写回),不与 2D 通路争端口。F5 的引用列表可作理解三角 tiler 的参照，但本版
**CPU 分桶、PB∧RAST 非法**；不能把现有 PB 不加修改就当成三角分桶器。
条带缓冲承担局部颜色存储职责，不据此宣称完整移动 GPU 的 tile memory/调度能力。
cup3d 历史光栅占比只能说明值得加速，CPU 几何/setup、参考语义和整帧时间均须重测，
不能推出硬件接入即满帧。

**静态评审(2026-10-22,外部审阅)主要修订**,已并入各 spec:
三角形 setup 定案由 CPU 完成(硬件梯度归一化需除法,原「无除法器+一拍」矛盾);
R1 数值契约冻结到公式级(采样点/绕序/破平式/guard band 溢出界/舍入表);
S3L 出口前移到视图空间(其屏幕映射整数化、近面默认策略不做正确裁剪,均实证);
BAND/TEX 增设单像素写口与采样口契约(现有口是描述符流,不能直接连线);
整帧生命周期单一化(第 1 页只作参数页,FSM 唯一,TRI_COUNT=0 即绕过);
gfx2d_top 一级页选补进范围;L1/L2 拆 RAST/RAST_TEX 双宏;PB∧RAST 定非法;
synthesis_mode 改显式表;演示判据修正(遮挡分级、30fps 两场节拍、cup3d 同构对照)。
**同日二次修订(用户质询「弹幕怎么还是 2D 的」,成立)**:弹幕全部升为世界空间 billboard
(敌弹色键抠底走 RAST_TEX,L1 纯色方块走 RAST),「2D 阵地」方案废除,2D 层仅剩 HUD;
联动 R1(FLAGS.KEY_EN)/R2(色键跳写)/R3(RAS_KEY)。

## 2 技术选型

### 2.1 开源硬件实现调研(2026-10-22,联网核实)

| 项目 | 许可证 | 架构与现状 | 借用判定 |
| --- | --- | --- | --- |
| [RasterIX](https://github.com/ToNi3141/Rasterix) | **GPL-3.0** | 最成熟:GLES1.1 风格实现,2×TMU,AXI 主口+命令流,100MHz 下 100Mpx/s;顶点在软件,软件侧预计算边缘方程与插值增量;IF 变体=片内分块 framebuffer+驱动切 display list(与条带模式同构);Xilinx 上 4.5k~36k LUT | **参照+对拍对象,禁移植代码**(GPL-3.0 强传染,同 verilog-axi 弃 taxi 先例) |
| [Raster-I](https://github.com/alanjian85/raster-i)([raster-gpu org](https://github.com/raster-gpu)) | **MIT** | TBDR,FPGA(Arty A7),后续版本含 T&L/背面剔除;较年轻 | **可借鉴乃至小段移植**(MIT,入 rtl/vendor 需登记);优先读 tile 遍历与桶结构 |
| [SpinalVoodoo](https://github.com/fayalalebrun/SpinalVoodoo)(3dfx Voodoo1 复刻) | 未核,仅作公开资料 | FBI 完成度高:定点格式表(色 12.12、深 20.12、纹坐标 14.18/2.30)、包围盒+边缘函数、serpentine 扫描、亚像素参数调整 | **只读思路不抄码**;定点位宽与扫描顺序的第一参照 |
| [gplgpu](https://github.com/asicguy/gplgpu) | **GPL-3.0** | 商用 GPU 遗产,`des_smtri.v` 扫描线三角 FSM | 禁移植;扫描线 vs 边缘函数取舍的反例参照 |
| [TinyGPU v2](https://github.com/pongsagon/tt_um_pongsagon_tinygpu_v2) / [tiniest-gpu](https://github.com/pongsagon/tt07-tiniest-gpu)(TinyTapeout) | **Apache-2.0** | 全管线微缩:定点、增量边缘函数、仿射纹理、z-buffer、背面剔除 | 思想参照;规模差 2 个量级,不移植 |
| [SystemVerilog 标量+SIMD 光栅器](https://mummanajagadeesh.github.io/projects/rasterizer/)(Jagadeesh) | 未核 | 结构与本案几乎一致:**屏幕空间参数输入,硬件无 3D 概念**;全定点标量 1px/cycle + SIMD 8px 变体 | 结构参照(CPU 准备参数+硬件增量光栅的先例) |
| [OpenGlory](https://github.com/egorxe/openglory)、[Manticore](https://github.com/thaolt/icculus-manticore)、Columbia/Cornell/[ChaosEngineGPU](https://github.com/Nanousis/ChaosEngineGPU)、[FPGA-Renderer](https://github.com/victoresque/FPGA-Renderer) 等课程/个人项目 | 各异 | 背景:扫描线与 barycentric 两派、SIMD 变体、Zedboard/DE2 先例 | 背景;不深入 |

结论:**光栅核自研**(与 GPU 线「实现自研,外物只作参照与对拍」原则一致),
分工与 RasterIX/Jagadeesh 同构(CPU 准备参数+硬件增量光栅+局部缓冲);
每个设计点都有 2 个以上先例背书,许可红线见 2.5。

### 2.4 设计点定案(评审后)

| 设计点 | 定案 | 背书/出处 |
| --- | --- | --- |
| setup 归属 | **CPU 完成**(边缘系数、梯度、包围盒,128B 记录下发);硬件只做位置求值+增量扫描。跨条带不重复算梯度,硬件免除法器 | RasterIX 软件侧同法;Jagadeesh 反例(硬件 setup 需另行定义除法,工期不容) |
| 光栅算法 | Pineda 边缘函数,Q12.4、整数采样点、32 位增量、内环零乘法;top-left 破平(E+bias≥0) | Pineda'88;D3D 规则;SpinalVoodoo/ryg |
| Guard band | CPU 屏幕空间 S-H 裁到 x∈[−256,896)、y∈[−256,736),边缘 s32、属性 s48 | Main/doc/三维数值契约.md 第 2～4 节 |
| 深度 | 窗口空间线性插值,u16,LESS,z-clear=0xFFFF,条带 z RAM 零 DDR 流量 | Catmull'74;OpenGL 深度变换 |
| UV | 仿射,梯度式,CLAMP;透视校正列 L3 冲刺 | PS1 先例;Heckbert'89 |
| 顶点管线 | CPU:视图空间→近/远面裁剪→除法→映射→guard band→setup→条带分桶 O(N);S3L 只到视图空间为止 | Sutherland–Hodgman；Main/doc/三维数值契约.md |
| 纹理 | TEX 16KiB 定 64×64 atlas，容纳四个 32×32 区块，UV 编码材质选择；四张各 64×64 则需 64KiB，另立预算 | engine 第 16 章 3.4；R4 §2.2 |
| 弹幕 | 敌弹/自机弹=世界空间 billboard:敌弹色键抠底(FLAGS.KEY_EN+RAS_KEY 寄存器),自机弹纵向小条;L1 纯色方块;**2D 层仅剩 HUD** | 评审遮挡论证的延伸(2026-10-22 用户质询成立);2D 引擎色键语义 |
| 扫描组织 | 标量峰值 1 个 bbox 候选点/拍；计入未覆盖点、初始化、取数、排空与 credit 停顿；SIMD 8px 列 L3+ | R2 RTL；R3 复核 |
| 取数 | 索引 FIFO+双缓冲参数组两通道;描述符 4KB 任意边界拆分;FD owner 扩三类;**Axi_Mux 保持 X3** | engine_inst 模式+评审修订 |
| 提交 | z+BAND 单像素原子提交；首版三角形边界排空，解决重叠像素读旧深度；BAND/TEX 新口带响应 credit | engine 第 16 章 3.3/3.4 |
| 生命周期 | 单一参数页+第 0 页门铃；LOAD∥CLEAR_Z 分别锁存完成→RAST→2D→FLUSH；末带撤 ack 后尾检；取消先确认 mover 排空再清读者；TRI_COUNT=0 绕过 | R3 §2.1/2.4/2.6 |
| 分级 | `GFX_HAS_RAST`+`GFX_HAS_RAST_TEX`(依赖 RAST+TEX)；`PB∧RAST` 非法；22 个结构/220 个完整合法构型；旧五位全开或 RAST→speed2 | R3 §2.2 |
