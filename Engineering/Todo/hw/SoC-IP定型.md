## 1 要解决什么

SoC 是 IP 生成器的产物，改它就要重新生成 `ip/soc/` 与软件包 `sdk/`，
然后逐条恢复 `sdk/README.md` 登记的修改，再跑一遍全套回归。这件事做得越晚越危险：
引擎、扫描输出、摄像头接进顶层之后，一次重新生成扰动的布局更多（`core_clk` 的 hold 余量只有 0.026 ns），
回归要覆盖的东西也更多。所以要趁顶层还简单，**把后面所有工作点对 SoC 的需求一次收齐，生成一次，之后不再动**。
唯一允许的例外是 E8 的缓存大小，见 2.1 节第 5 项。

**SoC 的配置是逐项可选的**，不是只能在 Lite 与 Standard 之间二选一。
`ip/soc/settings.json` 里每个外设都有自己的开关（`I2C0`~`I2C2`、`UART0`~`UART2`、`SPI0`~`SPI2`、
`GPIO0`/`GPIO1` 及宽度、`USER_0_INTR`~`USER_7_INTR`、`ICacheSize`/`DCacheSize` 与路数、`FPU` 等）。
被构型绑住的只有 `DDRCLK_DOMAIN` 一项：DDR 统一时钟只有 Lite 能选。

这一次要收齐的需求，出处如下：

| 需求 | 为什么现在做 | 出处 |
| --- | --- | --- |
| 升级 efx_soc 3.3.0 到 3.4.0 | 2026.1 打开工程就提示升级；3.4.0 的软件包模板带 `_zicsr_zifencei`，才能改用 IDE 自带的 gcc 13.4 | 本条原第 1 节 |
| 按键 KEY0~3 接进 SoC | 游戏输入。现在 GPIO0 只有 4 位，接的是 LED0~3 | 设计文档 1.3 节 |
| 用户中断线 | 扫描输出要一条场同步中断，引擎要一条（命令表完成、错误），摄像头以后要一条（帧完成） | 设计文档 1.3 节、[扫描输出.md](扫描输出.md) D5、[摄像头实时图层.md](摄像头实时图层.md) |
| 给摄像头留位置 | 传感器靠 I2C 配置，模组复位要一根输出线；以后再为它生成一次 IP，就是本条要避免的事 | [摄像头实时图层.md](摄像头实时图层.md) 第 1.3 节、第 2 节第一步 |
| 关掉确定不用的 | `axiA` 从口窗口（约 22 XLR）、`io_ddrMasters_0` 外部主机口（已被优化掉，删掉是为了顶层干净） | 本条原第 1 节，platform 第 04 章 5 节 |

**已经去掉风险的部分。** E1 在仓库外的复制工程里用 3.4.0 生成过 Standard 构型：
资源与 3.3.0 逐项相同（16151 XLR、65 块 RAM），调试通路连续三次会话正常
（platform 第 04 章 3.2 节、5.1 节）。生成步骤已经固化成 `Main/tools/gen_soc.py`。
所以本条里真正新的只有 2.1 节表里的几个开关，以及主线上的登记项恢复。

## 2 怎么切分

### 2.1 这一次生成的配置（开工前定稿）

| 项 | 现值 | 定为 | 理由 |
| --- | --- | --- | --- |
| 1 构型 | Standard，`DDRCLK_DOMAIN=1` | 不变 | E1 结论 |
| 2 IP 版本 | efx_soc 3.3.0 | **3.4.0** | 见第 1 节 |
| 3 GPIO0 | 4 位，LED0~3 | 不变 | 已上板在用 |
| 4 GPIO1 | 关 | **开，8 位**：[3:0] KEY0~3（输入），[4] 摄像头复位（输出，预留），[7:5] 备用 | 按键与摄像头复位一次给够；多出来的几位不占 RAM，逻辑可以忽略 |
| 5 缓存 | 指令、数据各 4KB，1 路 | 不变 | E8 的缓存对比要先有测开销的程序，现在没有数据。E8 出结论后若要改，那是**只改一个参数**的一次生成，按本条留下的步骤走，风险可控 |
| 6 I2C0 | 开 | **保留** | 给摄像头配传感器（地址 0x60）。约 370 XLR，不占 RAM；逻辑单元现在用了约 36%（21753 XLR），留得起 |
| 7 用户中断 | 只开 `USER_0_INTR`（16） | **开 0、1、2**：0 扫描输出场同步，1 引擎，2 摄像头 | 一个来源一条线，处理函数不用再分辨来源；没接的线在顶层接 0 |
| 8 `axiA` 从口 | 开 | **关** | 控制寄存器全走 APB Slave 0，引擎、扫描输出、摄像头都一样 |
| 9 `io_ddrMasters_0` | 开，顶层不接时钟 | **关** | 引擎、扫描输出、摄像头都走 `Axi_Mux`，不经 SoC |
| 10 其余 | UART0、SPI0、APB Slave 0、调试模块等 | 不变 | 调试模块不能动，OpenOCD 靠它（E1 的教训） |

中断号以生成后 `soc.h` 里的实际值为准，写进 `sdk/README.md`、`rtl/README.md` 与扫描输出条目的 D5。
摄像头这一条只在 SoC 里预留，**不接管脚、不改 `peri.xml`**：管脚、I2C 的顶层连线与复位线，
都等摄像头工作点自己接，那时不需要重新生成 IP。

### 2.2 生成

1. 生成前：工作区干净，当前提交就是回退点。
2. 按上表改 `settings.json`，用 `Main/tools/gen_soc.py` 以 3.4.0 生成，覆盖 `ip/soc/` 与 `sdk/`。
3. 生成器改了什么先看一遍再动手：`git diff --stat` 与 `soc.v` 的端口表，逐项对照上表，
   多出来或少掉的端口都要有解释。

### 2.3 恢复登记项

按 `sdk/README.md`「已登记的修改」逐条恢复：`USER_SOFTWARE_SIZE` 改回 `0x080000`、
链接脚本程序区 4092K、镜像超限断言、`bootloader_512K.bin/.hex`、`gpioDemo` 路径占位符；
重新编译 bootloader 并同步 8 个片上 RAM 初始文件。

恢复完再看一次 `git diff Main/sdk`：剩下的差异只能是 3.4.0 本身带来的变化与这一次开关带来的变化
（新增的 GPIO1、中断号），**每一处都能说出来源**。说不出来源的，停下来查。

### 2.4 顶层与约束

- `gfx2d_top.v`：删掉 `axiA`、`io_ddrMasters_0` 两段；接上 GPIO1；新增的中断口先接 0；
  I2C0 的输入仍接常量、输出悬空，注释写明留给摄像头。
- `peri.xml`：加 KEY0~3 四个输入管脚（C4、P14、N14、A3，3.3V bank，设计说明第 33 页），
  上下拉按原理图定；顶层与 `peri.xml` 两边同时改（搭车规则第 3 条）。
- `rtl/README.md`、`fpga/README.md` 的端口表同步。

### 2.5 软件

- 改用 IDE 自带的 gcc 13.4：`Main/doc/开发环境.md` 第 2、7 节与 `Main/sw/README.md` 的编译命令一起改，
  写明工具链版本。
- `sw/bsp/ti60/` 登记 GPIO1 的基址与按键位。`board.h` 的 `board_keys()` 板上现在恒为 0，
  KEY0~3 映射到哪几个 `BOARD_KEY_*` 位是 SW9 的事；本条只保证 GPIO1 读得到四个键。
- 新程序 `sw/apps/test/keyTest`：串口打印四个按键的状态变化，末尾 `done`。
- 工具链变了，`bootSizeTest` 的两个 CRC 期望值要重新计算。

### 2.6 本条不做

换构型；缓存大小（E8）；摄像头的管脚与连线；扫描输出与引擎的中断源本身（各自的工作点接）。

## 3 判据

| 项 | 判据 |
| --- | --- |
| 配置 | `settings.json` 与 2.1 节表逐项一致；`soc.v` 的端口增减与表逐项对上 |
| 登记项 | `sdk/README.md` 的表逐条核对；bootloader bin 的 SHA256 与片上 RAM 初始文件一致；`git diff Main/sdk` 剩下的每一处都写明来源 |
| 编译 | 四步 PASS；`Missing Interface Pins` 只剩已知项，新加的 KEY 管脚不在其中；约束告警 0；位宽截断告警仍只有厂商加密文件里那 2 条 |
| 资源 | 与 platform 第 04 章 5.1 节的表逐行对比。片上 RAM 预期仍是 65 块；XLR 的增减要能归到 GPIO1、`axiA`、`io_ddrMasters_0` 与版本差异上 |
| 归因 | 顺手把 platform 第 01 章那约 506 个没有逐项归因的 XLR 用层次报告认领掉，第 04 章 6 节列的 `u_soc` +63.5 与 +263.5 一并拆开 |
| 时序 | `core_clk` 与 `sdram_clk` 的 setup、hold 全为正，hold 与改前逐行对比；变负就停下 |
| 调试通路 | 同一比特流连续三次开 OpenOCD 会话，每次都能读到 `reg pc` 并 `resume`（E1 的教训：这一层以前没有判据） |
| 上板回归 | APB 探针四项、memTest PASS、HDMI 八色竖条、`ddrAliasTest`、`ddrBurstProbe`、E5 guard 板上程序全部 `fail 0` |
| 启动 | `bootSizeTest` 的两个 CRC 与 gcc 13.4 下重新计算的期望值一致；官方 124KB 比特流作对照组仍然不一致 |
| 按键 | `keyTest` 下四个键逐个按下、松开，串口各出现一次对应的变化，**用户按键确认** |
| 中断 | 生成后的中断号写进 `sdk/README.md` 与 `rtl/README.md`；三条新中断线在顶层接 0，使能后不会误触发（上电跑一次程序，不进中断） |

「启动」那一条的对照组不能省。它是唯一能区分「512KB bootloader 生效」与
「程序恰好短到 124KB 也能跑」的判据。
