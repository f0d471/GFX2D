## 1 要解决什么

**这一层做什么。** 一个颜色通道的混合：输入源、目的、`a`、`c` 各 8 位与方程号，输出 8 位（总览 2.4 节 I6）。
六个方程、除以 255 的舍入与饱和已经在 spec 第 01 章 3.3、3.4 节与设计文档 3.5 节定稿，按 V 顺序算：

```
x   = src × Fs + dst × Fd              Fs、Fd 以 255 为满量程
t   = x + 128
out = min(255, (t + (t >> 8)) >> 8)
```

`check_round255.c` 已穷举证明：快速式在 `x = 0..65025` 上与 half-up 精确商逐值一致，
全域 `0..130050` 上先算商再 `min(255, …)` 全部一致；中间量不能模截断到 16 位（全域 64643 处不符），
保留 17 位或把 `t` 饱和到 16 位都对。

**现在是什么样。** 只有 C 的参考（`tools/check/check_round255.c`、`sw/lib/gfx/exec_sw.c`），没有 RTL。
设计文档 3.5 节把像素流水线画成五级，其中「级 2 乘（DSP，输出寄存）、级 3 加与舍入、饱和」两级就是本层；
设计文档 2.4 节按 dual 模式估了每条通路 6~12 块 DSP。

**不做会怎样。** 高阶要求 1「用 DSP 计算 `fg×a + bg×(1−a)`」就是本层；B4 的像素通路没有它拼不起来。

## 2 怎么切分

### 2.1 已定的取舍

**D9 像素通路与乘法器。** 一条通路，每拍 4 像素。六个方程都写成 `x = 基数 × 255 + m1 × m2`
（例如 `src×a + dst×(255−a) = dst×255 + (src−dst)×a`），整数恒等，与 spec 第 01 章的 V 顺序逐位相同，
所以每通道只要一个有符号乘法器，一条通路 12 个。乘法先让综合推断 DSP，时序不够再按厂商原语例化。

### 2.2 开工前要补的研究

D9 只有结论，下面五项补齐它的依据，结果写进 TechReports `engine/` 第 01 章。

1. **代入表与逐位等价。** 把六个方程各自的 `基数`、`m1`、`m2` 列成表（例如 ALPHA 预乘是 `(src+dst)×255 − dst×a`，
   `m1` 取 `−dst`），定出 `m1`、`m2`、`基数` 与 `x` 的位宽和符号；用一个 C 小程序对每个方程的全部输入
   与 V 顺序的精确商逐值比较。D9 的「整数恒等」目前没有穷举过。
2. **Titanium 的 DSP 块。** 读 Ti60 数据手册 DSP Block 一节与 Efinity 的综合手册：各模式的乘法器位宽
   （normal 19×18，dual 11×10 加 8×8）、输入与输出寄存器、块内有没有能吃掉 `基数 × 255` 这一项的加法器、
   什么样的 Verilog 写法会被推断成带寄存器的 DSP、原语名与参数。要回答的是：9 位有符号乘 8 位（或补成 9 位）
   能不能用 dual 模式一块放两个，一条通路是 6 块还是 12 块。
3. **除以 255 与饱和的切法。** `t = x + 128` 与 `(t + (t >> 8)) >> 8` 是两级加法，再加 `min(255, …)`；
   设计文档 3.5 节把乘与舍入分成两级。要定的是流水切点与固定延迟 `L`，以及中间量取 17 位还是饱和到 16 位。
4. **开源实现。** 至少读两份：ORGFX 的混合模块（总览 2.7 节）；Xilinx Video Mixer（PG243）或 Intel VIP 的
   Alpha Blending Mixer 用户手册里的精度与延迟取舍；有 Efinix 官方的 DSP 推断示例时一并看。
5. **实验。** 在仓库外建一个只含本层的 Efinity 2026.1 小工程，单独综合 1 个通道与 12 个通道，
   比较两到三种流水切法的 DSP 块数、XLR 与 100MHz 下的 setup、hold；iverilog 跑一遍穷举，记下耗时。

研究之后要定的（编号 D24 起）：流水级数 `L`；推断还是例化；是否用 dual 模式；中间量的位宽。
**2026-09-29 已定案**：`L = 3`、让综合推断、不用 dual 模式、中间量 17/18 位 —— 见开发日志 D24~D28。

#### 一、代入表与逐位等价（2.2 第 1 项）

新工具 `check_subst.c`（纯整数，主机 `gcc -O2`，已进 `Main/tools/check/`）。
六个方程各自写成 `x = base × 255 + m1 × m2`，**每个方程都跑满自己的全定义域**，
代入表与穷举实测的取值范围：

| 方程 | 名称 | Fs, Fd | base | m1 | m2 | base | m1 | m2 | p = m1×m2 | x |
| --: | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | COPY | 255, 0 | src | 0 | 0 | 0~255 | 0 | 0 | 0 | 0~65025 |
| 1 | ALPHA 预乘 | 255, 255−a | src | dst | 255−a | 0~255 | 0~255 | 0~255 | 0~65025 | **0~130050** |
| 2 | ADD | 255, 255 | src+dst | 0 | 0 | 0~510 | 0 | 0 | 0 | **0~130050** |
| 3 | CONST | c, 255−c | dst | src−dst | c | 0~255 | −255~255 | 0~255 | −65025~65025 | 0~65025 |
| 4 | MUL | dst, 0 | 0 | src | dst | 0 | 0~255 | 0~255 | 0~65025 | 0~65025 |
| 5 | ALPHA 非预乘 | a, 255−a | dst | src−dst | a | 0~255 | −255~255 | 0~255 | −65025~65025 | 0~65025 |

位宽与符号（D9 缺的就是这半句）：`base` 9 位无符号（ADD 要 src+dst，上限 510）；
`m1` 9 位有符号（CONST 与非预乘 ALPHA 要 src−dst）；`m2` **8 位无符号**，
进乘法器前零扩展成 9 位有符号（两个乘数同号才是有符号乘法）；
`p` 17 位有符号（±65025 < 2^16，实现取 18 位）；`base×255` 17 位无符号；
`x` 17 位无符号（130050 < 2^17）；累加器 18 位有符号够，实现取 19 位。

穷举结果：六个方程合计 **50462976 组**输入，
「`base×255 + m1×m2` ≡ `src×Fs + dst×Fd`」**0 处不符**，
「快速式输出 ≡ V 顺序的精确商」**0 处不符**。D9 原先没有穷举过的那个「整数恒等」，这一项成立。

**订正（2026-09-29，复核时发现）：第一版把 ALPHA 预乘限制在 `src_pm ≤ a`，
只跑了 8421376 组，比硬件实际能收到的窄。**
spec 第 01 章的 `src_pm ≤ a` 是素材侧的约束；但 spec 第 02 章只对 ALPHA FILL 的常量做
`BAD_PREMULT` 检查，BLIT 从表面读进来的源像素没有逐个检查（运行时画出来的表面再拿去当源
就是这种情形），软件执行器 `exec_sw.c` 对任意输入都按同一条规则算。
硬件要和它逐位一致，这个范围就必须覆盖到，所以 ALPHA 改成跑满 2^24。
补上的 8355840 组里：代入式与快速式仍然 0 处不符，`x` 上限到 130050——
因为 `a = 0` 时 `Fd = 255`，`x = src × 255 + dst × 255` 和 ADD 一样能到顶。

**由此订正一条判据依据：16 位模截断在 ADD 与 ALPHA 预乘上都会出错。**
这两个方程的 `x` 上限是 130050；其余四个方程（COPY、CONST、MUL、非预乘 ALPHA）上限是 65025，
`t = x + 128 ≤ 65153 < 65536`，**模截断在那四个上是空操作**。全定义域上的错处数：

| 方程 | x 上限 | 16 位模截断的错误处数 |
| --- | --: | --: |
| ALPHA 预乘 | 130050 | **4113532** / 16777216 |
| ADD | 130050 | **32385** / 65536 |
| COPY、CONST、MUL、ALPHA 非预乘 | 65025 | 0 |

所以第 3 节那一行要写成「用 ADD（`src + dst ≥ 257`）或 ALPHA 预乘（`a` 小、`dst` 大）验」——
ADD 足够让注错版见红，理由不是「只有 ADD 能到 130050」，而是「ADD 的输入域最小、
覆盖到顶最容易」。

工具自己也出过一次错：第一版对六个方程都断言「注错版必须见红」，在那四个方程上跑出 FAIL。
那不是被测对象的问题，是断言写错了（正确行为就是不红）。已改成按方程分别给期望值。

#### 二、Titanium 的 DSP 块（2.2 第 2 项）

手册依据：Ti60 数据手册 DSP Block 一节；Quantum Titanium Primitives UG 表 24、27~32；
Efinity Synthesis UG 的 Figure 2~5 与 `syn_use_dsp` 条目；
另核对了安装目录里的 EFX_DSP48 仿真模型（`sim_models/verilog/efx_dsp48.v`）的端口与参数。

**硬件事实。** 一块 DSP 四种模式：NORMAL 一块 19×18 与 48 位加/减；DUAL 一块 11×10 与一块 8×8、
两条 24 位加；QUAD 一块 7×6 与三块 4×4；BFLOAT 一块 BF16 FMA。
三个原语：`EFX_DSP48`（四种模式全支持）、`EFX_DSP24`（DUAL 里的 8×8，一块可放两个）、
`EFX_DSP12`（QUAD 里的 4×4，一块可放四个）。A/B/C/P/OP/W/O 各有一个可选寄存器（`A_REG`…`O_REG`）。
**NORMAL 的 C 口是 18 位**（`C[17:0]`），送进 48 位加法器与乘积累加；
DUAL 把 C 切成 `C[17:8]` 与 `C[7:0]`，11×10 那条只拿得到 10 位。
综合推断按宽度分档：`≤ 4` 推 EFX_DSP12、`≤ 8` 推 EFX_DSP24、`≤ 19,18` 推 EFX_DSP48；
Figure 3 写明 `p = a*b; o = p + c`（c 18 位）**能压进一块 EFX_DSP48**，「因为 C 的宽度放得下 C 口」。

**三个问题的回答。**

1. **9 位有符号乘 8 位能不能用 dual 一块放两个 —— 按现在的代入不能，换代入可以，但不换。**
   DUAL 的 8×8 那条要求两个算子都不超过 8 位。现在 `m1` 是 9 位有符号
   （CONST 与非预乘 ALPHA 要 `src − dst ∈ −255~255`），进不了 8×8；
   11×10 那条能放 9×8，但一块只有一条。所以按现在的代入，一条通路 12 个乘法是 **12 块**；
   实验证实：12 通道的工程一律报 12 个 `EFX_DSP48`（`SIGNED = 1`），没有一块 EFX_DSP24。
   **换一种代入就能进 8×8。** 按 `src` 与 `dst` 谁大来选：
   `src ≥ dst` 时取 `base = dst`、`m1 = src − dst`、`m2 = c`（非预乘 ALPHA 时是 `a`），
   否则取 `base = src`、`m1 = dst − src`、`m2 = 255 − c`（`255 − a`）。
   两个分支上都恒等，且两个乘数都落在 0~255（`check_subst.c` 的全定义域穷举：
   恒等 0 处不符，两个乘数上限都是 255）。这样 12 个乘法能按 `EFX_DSP24` 一块放两个，
   省到 **6 块**。不换的理由见 D26。
2. **块内有没有能吃掉 `base×255` 的加法器 —— 有，在 NORMAL 模式。**
   C 口 18 位，而 `base×255 ≤ 130050 < 2^17` 且恒正，放得下；DUAL 不行（C 只有 10 位）。
   但**默认综合不会用它**，见下一条。
3. **什么样的写法会被推断成带寄存器的 DSP。** 直接写 `p = m1*m2; x = p + c255`：
   综合把乘后寄存器吃进 DSP 的 P 寄存器（DSP 报告的 REGS 列出现 `P`），
   但 O 列是 `(A*B)`——加法器留在 LE 里（每通道约 54 个 EFX_ADD）。
   在加法器输出上标 `(* syn_use_dsp = "yes" *)` 之后，O 列变成 `(A*B)+C`，
   EFX_ADD 从 874 掉到 670、XLR 从 1715 掉到 1549；
   **代价是时序变差**：setup 余量 3.806 → 3.079 ns、Fmax 161.4 → 144.5 MHz，
   关键路径的终点从「r_x 的 D 端」变成「DSP 的 C[17]」，也就是 `base×255` 进 C 口这条路变长了。
   省下的 166 个 XLR 占器件 0.27%，换掉 0.73 ns 余量，不划算（D28）。

#### 三、除以 255 与饱和的切法（2.2 第 3 项）

位宽：`x` 17 位无符号；`t = x + 128` 18 位；`t + (t>>8)` 上限 130686、RTL 里按 19 位写；
`q` 10 位；最后 clamp 到 255。**不用**「把 t 饱和到 16 位」那一条：要多一个饱和加法器，
而且只在 ADD 与 ALPHA 预乘上才有区别。RTL 里按 19 位写是为了消掉综合的
`expression size 19 truncated to fit in target size 18` 告警（数学上 18 位就够）。

四种切法在 **12 通道、100 MHz（Ti60F225，I3 模型）**下实测，工程参数从主线
`gfx2d_ti60.xml` 原样抄：

| 切法 | 级点 | L | XLR | DSP | EFX_ADD | EFX_FF | setup(ns) | hold(ns) | Fmax(MHz) |
| --- | --- | --: | --: | --: | --: | --: | --: | --: | --: |
| PIPE=0 | 只有输出寄存 | 1 | 1798 | 12 | 898 | 215 | 1.724 | 0.098 | 120.8 |
| PIPE=1 | 乘与 base×255 后寄存，加与舍入一级 | 2 | 1752 | 12 | 898 | 212 | 3.930 | 0.110 | 164.7 |
| PIPE=2 | 乘加一体后寄存，舍入与饱和一级 | 2 | 1715 | 12 | 874 | 277 | 3.806 | 0.097 | 161.4 |
| PIPE=3 | 乘 / 加 / 舍入与饱和三级 | 3 | 1748 | 12 | 898 | 428 | **4.461** | 0.104 | **180.5** |
| PIPE=2 + `syn_use_dsp` | 加法进 DSP 的 C 口 | 2 | 1549 | 12 | 670 | 47 | 3.079 | 0.109 | 144.5 |

1 通道的同一张表（照出每通道的底）：XLR 95 / 93 / 90 / 94，都是 1 个 DSP，
setup 4.009 / 5.371 / 6.540 / 7.007 ns。

关键路径：PIPE=0 是 `lfsr → o[8]`，36 级逻辑、7.916 ns；PIPE=1 是 `eqr → r_c[16]`，28 级、5.811 ns；
PIPE=2 是 `lfsr → r_x[17]`，31 级、5.935 ns；PIPE=3 是 `eqr → r_c[16]`，28 级、5.280 ns。
**四者的最长一级都是「判定选 base/m1/m2 + base×255」，不是 DSP 的乘法**。

三条读法：

- 完全不流水的 PIPE=0 在 12 通道下只剩 1.724 ns 余量（Fmax 120.8 MHz）。
  100 MHz 是过得去，但 B4 还要在同一个时钟里放像素旋转器、色键比较与写回选择，余量不够用，
  所以本层必须有流水。
- PIPE=3 的 XLR（1748）比 PIPE=1（1752）还低，setup 余量多 0.53 ns：
  多出来的那一级被 DSP 的 P 寄存器与 XLR 的 adder+FF 单元吸收掉了，**多一级几乎不花钱**。
- PIPE=2 的 XLR 最低（1715），比 PIPE=3 少 33 块，占器件 0.05%，但余量少 0.66 ns。

**草案 RTL 里抓到一个真错，要带进正式实现。**
第一版 PIPE=1/PIPE=3 只寄存乘积，让 `base×255` 仍取当前输入 —— 第二级于是把**两拍**的操作数相加。
iverilog 穷举立刻见红：当时（ALPHA 还是受限范围）42107137 个向量里 **33618694 个不符**，
首个反例 `eq=0 src=0 dst=0 got=1 want=0`。改成把 `base×255` 与乘积一起寄存（新增 `r_c`）之后全过。
结论：本层的流水切点必须保证「同一拍参与加法的两个操作数一起寄存」。
「乘与舍入分两级」这句话最容易漏掉的就是这一半。

#### 五、实验（2.2 第 5 项）

仓库外的研究工作区（不入库）：`ref/`（资料）、`exp/rtl/`（草案 RTL）、
`exp/sim/`（iverilog 穷举）、`exp/proj/`（9 个 Efinity 2026.1 工程）、`board/`（板上自检）。
RTL 与工程都不进仓；`check_subst.c` 已按判据要求放进 `Main/tools/check/`。

**iverilog 穷举。** 六方程全部输入组合加收尾拍，ALPHA 预乘跑满 2^24，共 **50462977 个向量**
（订正前是 42107137）；四种切法各跑一遍，全部 0 处不符。单次墙钟：
PIPE=0 **321.4 s**、PIPE=1 **363.8 s**、PIPE=2 **350.4 s**、PIPE=3 **409.9 s**
（WSL Ubuntu，iverilog 12.0；订正前是 292.5 / 305.8 / 305.6 / 345.6 s，扩到全定义域后涨 10%~19%）。
测试台的期望值用**精确商** `(2x+255)/510` 现算、输入按 Fs/Fd 直接代入，与被测的快速式独立。
这个耗时说明 2.4 节第 1 条「六方程全输入穷举」是跑得动的（一种配置约 6~7 分钟），
不必为了省时间缩域；正式测试台的 ALPHA 循环要从 0 到 255 跑满，
不要沿用草案第一版的 `src_pm ≤ a`。

**单独综合。** 8 个工程（PIPE 0/1/2/3 × 1/12 通道）加 1 个 `syn_use_dsp` 探针，
`efx_run` 四步全 PASS。顶层只有 `clk` 与 8 位输出，宽数据由内部 LFSR 生成、
各通道输出异或回 LFSR 反馈，既不让综合删掉通道，也不给关键路径额外加料。

**板上验证。** 板子已接入本机，JTAG 在线（`ftdi_pgm.bat --scan_usb` 读到
`0x10660A79`、`ir_width 5`）。另做一个自检顶层：128 条宿主侧算好的向量
（COPY 34、ALPHA 28、ADD 19、CONST 12、MUL 17、非预乘 18）逐条比对，
经 GPIOR_28 以 115200 每 1 ms 上报一帧。烧进 Ti60F225 后主机在 COM11 收到：

```
B1 5E NV=128 err_cnt=0 first_err=0        （连续复现）
```

即**这 128 条抽样在硅片上全对**，不只是在行为仿真里对。
这是 D25 选「推断」的加分项：它先把「推断出来的 DSP 会不会在硬件上算错」这个风险排掉了。
自检工程资源：EFX_DSP48 1、EFX_ADD 117、EFX_LUT4 211、EFX_FF 133、EFX_RAM10 3。
烧的是 `.bit`（掉电丢失），没有动 Flash。

#### 六、定案 D24~D28

| 编号 | 定案 | 依据 |
| --- | --- | --- |
| D24 | **流水级数 L = 3**：判定与乘一级（乘后寄存器落进 DSP 的 P 寄存器，`base×255` 同时寄存）→ 加一级 → `t`、÷255 与饱和一级 | 三、的表：PIPE=3 余量最好（4.461 ns、Fmax 180.5 MHz），而 XLR 比 L=2 的 PIPE=1 还低 4 块。多一级几乎不花钱 |
| D25 | **让综合推断，不手写原语** | 12 通道稳定推断出 12 个 EFX_DSP48；128 条抽样在板上全对。手写原语要自己管 A/B/C 的位段与 `C_EXT`/`P_EXT`，收益只有 166 个 XLR |
| D26 | **不用 dual 模式** | 二、1：按现在的代入，m1 是 9 位有符号、进不了 8×8，一块只能放一个乘法，12 个乘法要 12 块。按 `src`/`dst` 大小改代入能把两个乘数压进 8 位、省到 6 块（全定义域穷举验证过恒等成立），但代价是本来就最长的第一级要多一个比较器与选择器；主工程现用 DSP 4/160，加上本层 12 块是 16/160，**余量充足，不换** |
| D27 | **中间量位宽**：`x` 17 位无符号，`t` 与 `t + (t>>8)` 18 位（RTL 按 19 位写以免综合告警），算完商后 clamp 到 255 | 一、的代入表实测；不用 16 位饱和那条 |
| D28 | **`base×255` 的加法留在 LE 里，不加 `syn_use_dsp`** | 二、3：加了省 166 XLR（器件 0.27%），但 setup 余量掉 0.73 ns、Fmax 掉 17 MHz，而且会把流水寄存器吸进 DSP，让「L 拍」的边界变成依赖综合行为 |

**回写总览 2.4 节 I6 三处。**

1. 固定延迟填 **`L = 3`**。
2. 补上 **`en` 时钟使能**，保留。B4 的源、目的行缓冲各由搬运层填，消费侧要等
   「这一行读不读目的」（D7）与缓冲就绪，流水是可能停住的；留着它，B4 不用时接 `1'b1`。
   代价为零：草案顶层就是 `.en(1'b1)`，实验里 PIPE=1/3 的乘后寄存器照样被推断进 DSP 的
   P 寄存器（DSP 报告的 REGS 列出现 `P`）。
3. 补上 **「核心的五个输入（src/dst/a/c/eq）必须由寄存器直接驱动，前面不得有组合逻辑」**。
   PIPE=3 的第一级（选 base/m1/m2 再算 `base×255`）实测 5.280 ns、28 级逻辑，
   起点是测试顶层的寄存器；B4 若把像素旋转器这类组合逻辑直接接在核心前面，
   这一级的余量就被吃掉了。

接口其余字段（每通道 src/dst/a/c 各 8 位、方程 3 位、输出 8 位、一条通路 12 个实例）不变。
设计文档 3.5 节的五级流水图与本节不冲突：级 2「乘（DSP，输出寄存）」就是本层的 `r_p`，
级 3「加与舍入」在本层拆成「加」与「舍入饱和」两级，合起来仍在级 3 之内。
2.3 节的 RTL 文件名与 2.4 节的仿真目录不变。

**留给正式实现的三条。** 一，流水切点必须让同一拍参与加法的两个操作数一起寄存器化（三、的教训）；
二，中间量注错用 ADD 验，ADD 的输入域最小、最容易覆盖到顶（一、的订正）；
三，输入范围跑满全定义域，ALPHA 预乘不要沿用 `src_pm ≤ a`（一、的订正）。

**下一步。** 等确认后按 2.3、2.4 节开工：`rtl/engine/engine_blend.v` 与 `sim/engine/blend/`。
