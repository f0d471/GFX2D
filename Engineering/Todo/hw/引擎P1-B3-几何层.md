# 引擎 P1 · B3：几何层

状态：**未开工**。排在 B2 之后；它定稿总览 2.4 节的 I1、I2、I5 三个接口，B4 要用 I5 的每行边带，B5 要按 I1 下发命令。
路线、层间接口与批次顺序见 [引擎P1总览.md](引擎P1总览.md)。

## 1 要解决什么

**这一层做什么。** 接一条已经通过十步检查的 FILL 或 BLIT（I1），算出这条命令实际要画的矩形，
把它拆成行，每行给搬运层发读源、读目的、写目的的描述符（I2），给计算阵列发这一行的边带（I5）：

1. **五者求交**：目的矩形、游戏区、裁剪框、目的表面、源表面，规则见总览 2.2 节 D2 的第二段；FILL 没有源，只交前四个。
2. **行迭代**：交出的矩形逐行走。
3. **描述符**：每行按 16 字节对齐的覆盖区间发，一行跨 4KB 时拆成两个；每个描述符恰好一笔突发、不跨 4KB、
   不超过 `AXI_MAX_BURST_LEN`（D3 规矩 1，engine 第 02 章 3.9 节）。行首、行尾拍里不属于本行的像素由边带告诉 B4 打「不写」标记。
4. **读写避让**：D7 的三种情形不发读描述符。

**现在是什么样。** 没有 RTL。软件里对应的是 `sw/lib/gfx/exec_sw.c` 的 `dst_window()` 与 `apply_set_clip()`，
SW8 的 `sw/lib/gfx/census.c` 照它另写过一份矩形求交（sw 第 07 章 3.2 节）；规则在 spec 第 01 章 3.6 节（裁剪与坐标的位宽表）
与 spec 第 02 章规范条款 §2（地址公式）。

**不做会怎样。** 求交错一项，画面上就是越界写或该画的没画；描述符跨 4KB 或超长，写核会自己拆成两笔同时在途，
违反在途契约（engine 第 02 章 3.8 节的注错用例量到 9120 个违例周期）。

## 2 怎么切分

### 2.1 已定的取舍

**五者求交**：D2 的第二段（总览 2.2 节），这里不另抄一份，改动只改那一处。

**规矩 1**：D3 的「几何层保证每个描述符按 16 字节对齐、不跨 4KB、不超过 `AXI_MAX_BURST_LEN` 拍」（[engine 第 02 章](../../TechReports/engine/02-AXI事务层.md) 3.9 节）。

**D7 行级调度与读写避让。** 每一行按「读源 → 读目的 → 写目的」走，写目的与下一行的读并行（两个方向各一笔，不违反契约）。
按 spec 第 01 章第 6 条允许的读写避让，只做结果逐像素不变的三种：

| 情况 | 省掉什么 | 依据 |
| --- | --- | --- |
| FILL 且方程为 COPY | 读源、读目的 | 常量源；COPY 不看目的 |
| BLIT 且方程为 COPY（含色键） | 读目的 | COPY 不看目的；色键命中的像素打 W 通道带内标记不写（D16），目的原值不动 |
| FILL 的其余方程 | 读源 | 常量源 |

其余情况（ALPHA、ALPHA_STRAIGHT、ADD、CONST、MUL）都要读目的。SW7 的背景、HUD 底图、机体与文字都落在前两行。
第二行首稿写「用写掩码跳过」，照原样用写核的 `tkeep` 做不到（D3 已核对的写核 `wstrb` 一条），前期研究改成带内标记。

### 2.2 开工前要补的研究

这一层原条目没有做过研究。结果写进 TechReports `engine/` 第 03 章。

1. **产出速率要多快。** engine 第 02 章 3.8 节量到：16×16 ALPHA 每行约 69 周期，16×16 COPY BLIT 每行约 34 周期，
   16×16 FILL COPY 每行只有 15 周期，整屏 FILL 一行 126 周期；命令之间空 0 或 2 拍结果相同。
   要算清几何层每行、每条命令最多能花几拍而不拖慢最快的那种情形，据此在「多拍顺序实现」与「流水实现」之间选。
2. **求交与描述符的算术。** 坐标 16 位有符号、宽高 16 位无符号、中间量 32 位（spec 第 01 章 3.6 节）；
   覆盖区间的起止拍、首末拍的有效像素、源与目的 x 对 4 的余数、4KB 拆分点，逐项写出算式与位宽。
3. **开源实现。** 至少读两份：iDMA 的中端（把多维请求拆成一维的那一段，总览 2.7 节）；ORGFX 的裁剪模块；
   Amiga blitter 的首尾字掩码怎么由移位量算出（与 B4 共用）。
4. **独立模型。** 测试台的期望描述符序列与边带从哪来：写一个不读 RTL 的模型（C 或 Python，放 `tools/check/`），
   按 spec 第 01、02 章的规则从命令算出描述符与边带；定它的输入格式，能直接吃 159 条向量与十一个整帧用例的命令。
5. **实验。** 单独综合求交与行迭代，看 32 位比较与加法链在 100MHz 下的余量。

研究之后要定的（编号 D24 起）：多拍还是流水；独立模型的语言与格式；
与 B5 一起定描述符完成的判定和零面积命令怎么通知控制层（总览 2.4 节末段）。

### 2.4 仿真

新目录 `sim/engine/geom/`。只测本层：测试台按 I1 喂命令，收 I2 的描述符与 I5 的边带，与独立模型逐条比。
逐像素的结果要等计算阵列，在 B4 做。

1. **定向用例**（原条目的几何定向用例，159 条向量与十一个整帧用例都没有覆盖到）：表面基址不按 4KB 对齐、行跨 4KB（拆成两个描述符）；
   源、目的 x 对 4 的余数 4×4 种；宽度对 4 取余 4 种；源矩形越出源表面（五者求交的第五项）。
2. **已有输入**：159 条向量里合法的 FILL、BLIT 与十一个整帧用例的全部命令。
3. **规矩 1 与避让**：每个描述符 16 字节对齐、不跨 4KB、不超过 192 拍；D7 的三种情形没有对应的读描述符。
4. **注错**：漏掉第五项求交、跨 4KB 不拆、ALPHA 误开读目的避让，各自必须见红。
