## 1 要解决什么

**这一层做什么。** 接一条已经通过十步检查的 FILL 或 BLIT（I1），算出这条命令实际要画的矩形，
把它拆成行，每行给搬运层发读源、读目的、写目的的描述符（I2），给计算阵列发这一行的边带（I5）：

1. **五者求交**：目的矩形、游戏区、裁剪框、目的表面、源表面，规则见总览 2.2 节 D2 的第二段；FILL 没有源，只交前四个。
2. **行迭代**：交出的矩形逐行走。
3. **描述符**：每行按 16 字节对齐的覆盖区间发，一行跨 4KB 时拆成两个；每个描述符恰好一笔突发、不跨 4KB、
   不超过 `AXI_MAX_BURST_LEN`（D3 规矩 1，engine 第 02 章 3.9 节）。行首、行尾拍里不属于本行的像素由边带告诉 B4 打「不写」标记。
4. **读写避让**：D7 的三种情形不发读描述符。

**现在是什么样。** `rtl/engine/engine_geom.v` 已实现并单独综合过，`sim/engine/geom/` 的单元仿真
三组输入全过、五个注错各自见红。软件里对应的是 `sw/lib/gfx/exec_sw.c` 的 `dst_window()` 与 `apply_set_clip()`，
SW8 的 `sw/lib/gfx/census.c` 照它另写过一份矩形求交（sw 第 07 章 3.2 节）；规则在 spec 第 01 章 3.6 节（裁剪与坐标的位宽表）
与 spec 第 02 章规范条款 §2（地址公式）。**独立模型 `tools/check/geom_model.py` 是这一层的第二份实现**，
它自己走命令表、并与软件执行器逐像素对照；几何层的 RTL 与它逐条比。

**不做会怎样。** 求交错一项，画面上就是越界写或该画的没画；描述符跨 4KB 或超长，写核会自己拆成两笔同时在途，
违反在途契约（engine 第 02 章 3.8 节的注错用例量到 9120 个违例周期）。

## 2 怎么切分

### 2.1 已定的取舍

**五者求交**：D2 的第二段（总览 2.2 节），这里不另抄一份，改动只改那一处。

**规矩 1**：D3 的「几何层保证每个描述符按 16 字节对齐、不跨 4KB、不超过 `AXI_MAX_BURST_LEN` 拍」（[engine 第 02 章](../../TechReports/engine/02-AXI事务层.md) 3.9 节）。

**D7 行级调度与读写避让。** 每一行按「读源 → 读目的 → 写目的」走，写目的与下一行的读并行（两个方向各一笔，不违反契约）。
按 spec 第 01 章第 6 条允许的读写避让，只做结果逐像素不变的三种：

| 情况 | 省掉什么 | 依据 |
| --- | --- | --- |
| FILL 且方程为 COPY | 读源、读目的 | 常量源；COPY 不看目的 |
| BLIT 且方程为 COPY（含色键） | 读目的 | COPY 不看目的；色键命中的像素打 W 通道带内标记不写（D16），目的原值不动 |
| FILL 的其余方程 | 读源 | 常量源 |

其余情况（ALPHA、ALPHA_STRAIGHT、ADD、CONST、MUL）都要读目的。SW7 的背景、HUD 底图、机体与文字都落在前两行。
第二行首稿写「用写掩码跳过」，照原样用写核的 `tkeep` 做不到（D3 已核对的写核 `wstrb` 一条），前期研究改成带内标记。

### 2.2 开工前要补的研究

**已完成（2026-09-30），过程、数据与解释在 [engine 第 03 章](../../TechReports/engine/03-几何层.md)。**
五项的研究结果按下面的编号收进那一章的对应小节；这里只留一句话的结论。

1. **产出速率要多快。** 已量。多拍顺序的行迭代 5.06~6.06 拍/行；对照搬运层
   15.0（16×16 FILL COPY）/ 34.3（COPY BLIT）/ 68.3（ALPHA BLIT）/ 126.0（整屏 FILL）
   拍/行，余量 2.96× / 6.8× / 11.3× / 25.2×。**结论：多拍够，不做流水**（D33）。
   逐拍数据与探针在 `sim/engine/geom/`，章内 3.1 节。
2. **求交与描述符的算术。** 已写清。五者求交、逐行地址、16 字节覆盖区间、
   4KB 与 192 拍拆段、边带 `lead` 的逐项算式与位宽表在章内 3.2 节；
   其中**「源与目的 x 对 4 的余数」不足以定首末拍**这一处订正回写 I5（D36）。
3. **开源实现。** 已读三份，都读到代码或手册级：iDMA 的 mid-end（不做对齐与切分，
   4KB 与最大拍数在 back-end 是**编译期常量钳位**，每维计数器使能串下游 `ready`）、
   ORGFX 的裁剪（目标边界与 scissor 两级、空结果单拍短路）、
   Amiga blitter 的首末字掩码（**掩码是可编程寄存器，硬件不推导**；
   AND 在移位之前；单字宽时首末取交）。借鉴表见章内 3.3 节与本文件 2.4 节。
4. **独立模型。** 已做，**Python 3**：`Main/tools/check/geom_model.py`（D39）。
   自检 23 项、定向用例 31 条（验收时补到 34 条）、159 条向量与十一整帧用例（经
   `tools/check/geom_cases_dump.c` 链接 `sw/lib/gfx` 导出）。两组真实输入合计
   2064 行、3498 个描述符，规矩 1 与 D7 违例全 0，与软件执行器逐像素对照 76 条命令违例 0
   （**2026-10-01 订正**：原记 2508 行、4018 个描述符是模型走命令表的三个错误算出来的，见第 4 节复核一节）。期望值的记录格式定案 D40
   （`--dump-records`，$readmemh 直读）。章内 3.4 节。
5. **实验。** 已做。`sim/engine/geom/syn/` 是 Efinity 2026.1 的单独综合小工程
   （**入库、路径全相对**，不像 B1/B2 那样建在仓库外），四步 PASS：
   求交 248 XLR、行迭代 638 XLR，块 RAM 0、DSP 0；`clk` 100 MHz 下
   setup slack +1.999 ns（关键路径 8.001 ns，124.984 MHz）、hold +0.097 ns。
   关键路径落在**求交的比较链**上。章内 3.5 节。

研究之后要定的（编号 D24 起的续，实际定了 **D33~D40**）：多拍还是流水（D33）；
独立模型的语言与格式（D39、D40）；与 B5 一起定零面积命令怎么通知控制层（D38）。
八条定案一览见章内 3.6 节。

**研究改动了 I5 的一处措辞**（D36）：边带带的是**行首地址的拍内像素相位**
`lead = (row & 15) >> 2`，不是 x 对 4 的余数。原因是表面结构谓词只要求
`base % 4 == 0`，相位由 `base`、`stride_log2`、`x` 三者共同决定。
真实构图的 base 都是 4KB 对齐、`stride_log2` 都是 12 或 8，把这个差掩掉了，
所以要在定向用例里才有。回写总览 2.4 节 I5。

### 2.4 仿真

目录 `sim/engine/geom/`。只测本层：测试台按 I1 喂命令，收 I2 的描述符与 I5 的边带，与独立模型逐条比。
逐像素的结果要等计算阵列，在 B4 做。**已实现（2026-10-01）**，`run.sh` 一次跑完下面四项。

1. **定向用例**（原条目的几何定向用例，159 条向量与十一个整帧用例都没有覆盖到）：34 条（验收时补了三条 BLIT 跨 4KB 与源基址非 16 对齐），模型给期望值（`--dump-directed`）。
2. **已有输入**：159 条向量里几何层见到的命令（59 条）与十一个整帧用例的全部命令（17 条）。
3. **规矩 1 与避让**：每个描述符 16 字节对齐、不跨 4KB、不超过 192 拍；D7 的读源/读目的有无。
   另加两个握手用例 `+STALL`（三个方向各压反压）与 `+RFSTALL`（B4 行缓冲替身的排空拉长到 23 拍），判据是序列与恒 ready 时相同。
   测试台另有与消费循环无关的握手监视器（多发的描述符、非空命令的 `cmd_done`）与 B4 行缓冲替身（每一行都开在空着的那一半上）。
4. **注错**：漏掉第五项求交（`INJECT=1`）、跨 4KB 不拆（`INJECT=2`）、ALPHA 误开读目的避让（`INJECT=4`）、
   COPY 多发读目的（`INJECT=8`）、行开始不看 `row_free`（`INJECT=16`，配 `+RFSTALL`），
   各自必须见红，而且红在对应的判据上（逐条比对 / `RULE1 ... crosses 4KB` / `sideband read-dst vs D7` / `PROTO handshake count` / `BUFERR`）。
   注错改的是 `engine_geom.v` 里那一段真实逻辑；不能在测试台里另写一个错的表达式去和对的比（恒成立，2026-10-01 复核）。
5. **期望值**：一律由 `geom_model.py --dump-records` / `--dump-directed` 现算。它走命令表的口径与参考实现相同：
   SET_CLIP 取 `w1`、裁剪框跨命令表继承、向量出错时截在出错那一条之前。
   记录格式的字段表在模型里（`REC_CMD`/`REC_SB`/`REC_RD`/`REC_WR`），类型 0 带 I1 的全部字段。
6. **产出速率**：同一批输入下 `engine_geom` 自己的拍数（4.68~6.22 拍/行），与 2.2 节第 1 项的探针数对照。

`run.sh` 传的 `build/cases.txt` 被写到了 `Main/build/`；作者树里 `sim/engine/geom/build/cases.txt` 有一份更早的手工导出、

**2 变异实验：原测试台放过六种错。** 改错七处、每处跑三组输入 × 恒 ready / `+STALL` / `+RFSTALL` 九种组合：

```text
读源第二段地址用目的段长   全绿        读源页余量用目的的        全绿
读目的第二段地址用源段长   全绿        COPY 多发读目的           全绿
非空命令也回 cmd_done      全绿        行推进不看 row_free       全绿
rd_buf 半号恒 0            九种全红
```

原因三类：跨 4KB 的定向用例只有一条 FILL COPY，读源、读目的两套拆段算式没走到；消费循环只看它在等的通道，
另外两个通道 `ready` 恒高，多发的描述符被悄悄收走，非空命令的 `cmd_done` 也没人查；`+RFSTALL` 的判据只有
「序列不变」，不等 `row_free` 序列也不变。

**3 补强。**
- 模型加三条定向用例：`blit-cross-4k-both`、`blit-src-cross-only`、`blit-src-base-mod8`（31 → 34 条，各带自查）。
- 测试台加握手监视器（逐拍数三个通道的握手与 `cmd_done`，每条命令结束时对账，三个 `valid` 互斥，标记 `PROTO`/`DONEERR`）
  与 B4 行缓冲替身（两半各一位占用，边带握手占上、写拍收齐后过 `drain` 拍放掉，`row_free = ~占用`；
  `+RFSTALL` 时 `drain = 23`；标记 `BUFERR`）。规矩 1 的违例原来只计数、不记失败，改成直接记失败；
  结果行「193 of 120 checks failed」改成错误数与检查项数分开写。
- RTL 加注错位 3（COPY 多发读目的）、4（行开始不看 `row_free`），`run.sh` 查它们分别红在 `PROTO`、`BUFERR` 上；
  `+RFSTALL` 加跑 159 条向量；正常构建的反面检查从五份日志扩到八份、标记加 `PROTO`/`BUFERR`。
- 补完之后，前面七种加新写的三种（第 0 行不看 `row_free`、读源覆盖区间长度借目的的、`wr_last_row` 打在每一段上）全部见红。

**4 RTL 隐患：命令边界上第 0 行不看 `row_free`。** 行缓冲替身一上，原版 RTL（`row_free` 一位，按最保守的读法接成
「两半都空」）在定向用例 `+RFSTALL` 下报 17 处 `BUFERR`：行号每条命令从 0 起、半号是行号最低位，
上一条命令行数为奇数时，下一条命令的第 0 行不等就往同一半里读。两组真实输入命令行数恰好都是偶数，所以不报。

没有采用「半号跨命令连续翻转」：要多一位边带、B4 跟着改，留给 B4 有实测时定。

**1 产出速率（章内 3.1 节）。** 先抄参照数：engine 第 02 章 3.8 节量到搬运层四种情形
每行 15.0 / 34.3 / 68.3~70.3 / 126.0 拍，并且 `CMD_GAP` 取 0 与 2 结果相同，
说明几何层的每命令启动开销在几十拍以内看不见。再写探针量自己：
`sim/engine/geom/probe_geom.v` 里一个多拍顺序的行迭代（算覆盖区间、拆段、
按序发读源/读目的/写描述符、发边带），`tb_probe_geom.v` 把消费者接恒 ready，
从 `start` 数到 `done`：

```text
FILL COPY 16x16   命令 81 拍，5.06 拍/行      COPY BLIT 16x16   命令 81 拍，5.06 拍/行
ALPHA BLIT 16x16  命令 97 拍，6.06 拍/行      整屏 FILL 400px    命令 2401 拍，5.00 拍/行
跨 4KB 一行 640px 命令 49 拍，6.12 拍/行      base%16=4 相位     命令 21 拍，5.25 拍/行
```

余量 2.96× / 6.8× / 11.3× / 25.2×，**多拍够，不做流水**（D33）。
首版的行迭代用「先寄存 valid、下一拍再看 ready」的写法，一笔描述符两拍，
每行 12.06 拍——也还在 15.0 以内，但余量只剩 1.24 倍，整机里不敢用；
改成 valid 与数据组合驱动、握手当拍完成之后是 5.06 拍。

**2 求交与描述符的算术（章内 3.2 节）。** 五者求交写成「下界取最大、上界取最小」
两条归约链，中间量与输出一律 32 位有符号，空宽高先判；源表面那一项用
`dst − src` 的偏移在矩形级做完（spec 第 01 章 3.6 节第 5 步「源越界只跳过该像素」
的等价写法）。逐行地址、16 字节覆盖区间、`page_left = 0x1000 − a0[11:0]`、
`seg0 = min(alen, page_left, 192*16)`、边带的算式与位宽表都写清了（D34、D35）。
证明了一行最多两段、最多 161 拍（640 像素 = 2560 字节，取整后最多 2576 < 4096 且 < 3072；
161 是行首非零相位的上界，穷举过 640 种宽度 × 4 种相位）。

**这一项里订正了 I5 的一处措辞**（D36）：条款原文写边带带「源与目的 x 对 4 的余数」，
但拍内相位是**行首地址**的低 4 位除以 4，由 `base`、`stride_log2`、`x` 三者共同决定
（表面结构谓词只要求 `base % 4 == 0`）。真实构图的 base 都是 4KB 对齐、
`stride_log2` 是 12 或 8，把这个差掩掉了；定向用例 `base-mod4-only`
（基址 `0x00100004`、`x0 = 37`，`x0 mod 4 = 1` 而相位是 2）才把它露出来。
改法：边带带 `lead = (row & 15) >> 2`。**已回写总览 2.4 节 I5。**

**3 开源实现（章内 3.3 节）。** 读了三份，都读到代码或手册级：

- **iDMA**（PULP，SHL-0.51）：mid-end 只做 stride 加法，**完全不做对齐与 4KB 切分**
  （`idma_nd_midend.sv` 里连 `PageSize` 都没有）；切分在 back-end legalizer，
  而且 4KB 是**编译期钳位**：`page_addr_width = page_addr_width > 'd12 ? 'd12 : …`
  （`idma_legalizer_page_splitter.sv:40`）、`PageSize = min(max_beats*StrbWidth, page_size)`
  （`idma_legalizer.sv.tpl:100-101`）。另外两条可用：每维计数器使能串下游 `ready`
  （`:124`，天然反压）、末笔标记 `opt.last`（`:205`）。
- **ORGFX**（LGPL-3）：裁剪分「目标物理边界永远生效」与「用户 scissor 可开关」两级；
  空结果单拍短路（`empty_raster`，判据用严格 `>`）；丢弃像素立刻 ack 上游。
  不借鉴它的无符号坐标、每像素一次 Wishbone 事务、空 clip 逐像素空转。
- **Amiga blitter**（AHRM + MAME（BSD-3）+ Minimig（GPL-3））：**纠正了一个想当然的说法**——
  首末字掩码不是硬件从 shift 推导的，`BLTAFWM`/`BLTALWM` 是软件写的寄存器，
  硬件只把它们 AND 到行首/行末字上，**在 barrel shift 之前**，且单字宽时两个掩码同时作用。
  本设计不需要位串掩码（每像素 32 位，掩码天然是 4 位逐像素使能），
  只需要「AND 在拼接之前」与「单拍覆盖时首末取交」这两条。

**订正（2026-10-01）**：这两组数是模型走命令表带三个错误时算的（SET_CLIP 取错字、裁剪框不跨表继承、不在出错处截断），

**两组输入都没有一行跨 4KB**（合计 2508 行），`base % 16 ∈ {4,8,12}` 的合法表面一个都没有，
相位组合远没跑满，192 拍上限在 P1 里不可达（两组输入里最多 160 拍，
P1 的矩形上界是 161 拍）。所以条目 2.4 节第 1 条的

模型的第一版还自己撞出一条要立的判据：`masks()` 里行首地址写成

```text

u_row 行迭代     638 XLR（262 LUT4 + 84 LUT4&FF + 278 加法器）、14 FF
顶层             1916 XLR（含 128 位 LFSR 与 128 位观测寄存器）
```

关键路径落在**求交的比较链**上（`lfsr → 求交 → iy0 → 行首地址加法 → dst_cur`），
不是行迭代的计数器——这从时序一侧也支持 D33 的选择。

**单独综合的顶层踩了两个坑**（章内第四节）：观测拼接 248 位直接异或到 128 位 `obs`
