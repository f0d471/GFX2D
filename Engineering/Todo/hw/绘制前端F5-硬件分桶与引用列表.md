# 绘制前端 F5 硬件分桶与引用列表

状态：**未开工**。前置：[F4](绘制前端F4-通用实例命令.md) 直通实例路径已交付，独立软件分桶模型待建立。
本批将空间分桶放到通用绘制前端，复用现有 BAND/几何/像素路径。
共同顺序、资源与采用门槛见 [总览](../sw/绘制前端总览.md)。

决策依据：engine 第 11 章 D65、D71、D72、D73；空间列表与共享图元参数分离。

## 1 要解决什么

CPU 仍为每个跨带实例计算交集并复制完整命令，M 项 CPU 工作拖慢流水。
目标是 CPU 只发布一份原始绘制与实例数组，硬件建立紧凑、保序的空间引用。
重复几何只保留一份共享描述，引用携带身份，不复制 32 B 完整命令。

工业参照为 PowerVR tiler/Parameter Buffer 与保序软件光栅化阶段；本项目首版
只分 y 条带，保留图元/引用边界以便后续二维 tile 和三角前端接入。CPU 的
运动与游戏状态不进入本模块。

## 2 怎么切分

### 2.1 输入、模式与寄存器

输入为现 v1 平表加 F4 的 v1-I 包，坐标仍是全帧坐标，SET_CLIP 按输入序生效。
PB 帧每次从全屏裁剪开始；需要跨帧恢复裁剪时由输入首条 SET_CLIP 显式表达。
构建使用私有 clip 状态，不改写旧直通路径的跨提交 clip 寄存器。
新增 `CAPS.BIN=bit13`、`CTRL.BIN=bit4`；BIN=1 要求 BAND=1，BAND=1/BIN=0
仍为原 v2 定长表，BAND=0/BIN=0 为直通。其它组合在提交前及硬件门铃检查拒绝。

新增寄存器从 `regs_gen.py` 生成：

| 偏移 | 属性 | 字段 |
| --- | --- | --- |
| 0x03C | RO | ERROR_STAGE：0 旧路径/无错，1 包级，2 实例，3 分桶计数/容量，4 PB 写，5 引用执行，6 BAND |
| 0x140 | RW | PB_BASE，128 B 对齐，按当前门铃锁存 |
| 0x144 | RW | PB_BYTES，完整工作区长度 |
| 0x148 | RW | DRAW_CAP，1..32768 个 64 B metadata 槽 |
| 0x14C | RW | REF_CAP，0..131072 个 8 B 引用 |

写入在 busy 时沿既有拒绝/保护契约；门铃同时锁存输入、表面、背景/目的、条带参数
和 PB 参数。范围用扩位算术检查；PB、输入、实例数组与目标/背景的不可变区域
不得重叠。软件 lease 负责实际分配和跨帧隔离，硬件仍检查可表达的地址/长度回卷。

首版 S≤30，H=8/16/32 且 frame_height=S×H≤480，与当前背景/目的约束相同。
每个桶不沿用 v2 的 1024 上限，受总 REF_CAP 与 32 位计数约束；旧 v2 容量不变。

### 2.2 PB v1 内部布局

PB 是引擎生成的中间对象，不作为 CPU 手工写 v2 桶的替代接口。

```text
PB_BASE + 0                    512 B header / 32 个桶目录
PB_BASE + 512                  DRAW_CAP × 64 B metadata
align128(512 + DRAW_CAP×64)     8×REF_CAP + 16×S B 引用区（含逐桶末拍 padding 预算）
```

header：w0 magic=0x31425046，w1 version=1，w2 status（0 EMPTY/1 BUILDING/
2 READY/3 ERROR），w3=S，w4=实际处理输入包数，w5=M，w6=metadata offset，
w7=reference offset，w8..11=错误 code/index/instance/stage，w12..15=0；
w16..79 是 32 个 `(ref_offset:u32, count:u32)`，offset 相对引用区、单位 B；
w80..127=0。未用桶 count/offset=0；总有效引用≤REF_CAP，目录的实际字节范围
不得越过含 padding 的引用区。每桶首地址 16 B 对齐，尾部补足 16 B。

metadata 第 0..7 字保存原输入包；w8=clip_x0/y0、w9=clip_x1/y1（各 i16），
w10=输入 packet_index，w11..15=0。槽号直接等于输入 packet_index，包含需要
处理的 SET_CLIP/NOP 槽但它们不产生像素引用；输入处理边界沿原 END/LIST_COUNT
规则，尾部不生成无意义 draw。
clip 端点先按原规范以扩位算术求和/饱和，再与屏幕相交后保存；空框规范化为
(0,0,-1,-1)。不能先截成 i16 再处理大宽高的右下端。

引用为 `(packet_index:u32, instance_index:u32)`：标量 FILL/BLIT 的后者为
0xFFFFFFFF，实例包为包内零基索引。只引用受支持的绘制包。完整字段、clip 与
共享状态由 metadata 解析，绝不把纹理内容/弹种编进引用。

最大双 PB 约 2×(512+32768×64+131072×8+16×30)=6.002 MiB；加实例 arena 和计划数据
仍须在共享区内逐项分配并核对。不能把该最大值同时叠加 F3 最大双 workspace 而
默认“10 MiB 够用”；同一后端只租用实际需要的集合，容量写入日志。

### 2.3 硬件构建：两次输入遍历，保序引用

```text
VALIDATE -> COUNT/SNAPSHOT -> META_DRAIN -> PREFIX -> SCATTER -> PB_DRAIN -> PB_READY
    -> 每桶 {LOAD -> 读 refs -> metadata/实例 -> 几何裁到本条带 -> EXEC -> FLUSH}
    -> DRAIN -> DONE
```

COUNT 按输入序执行共享检查和 SET_CLIP，保存 metadata 中的状态快照。
逐实例以扩展有符号算术求原几何层的五者交集；有效 y 覆盖 `[s0,s1]`，只增加
这些桶的 count。裁空不产生引用，但不能跳过应做的包/表面检查；尺寸为零的
实例包可在包检查后直接计零引用。必须读取的实例数组错误在构建阶段报告。

开始构建先写 BUILDING，COUNT 结束等待所有 metadata 写响应，SCATTER 才可读取
快照。PREFIX 对 S 个计数作顺序排他 scan：有效项总和≤REF_CAP；桶跨度为
align16(count×8)，目录使用这些跨度的前缀和；同时检查 LIST_COUNT≤DRAW_CAP
及所有工作区范围。任何容量失败都在目的渲染前结束。COUNT 的 metadata 写可已
发生，但不发布 READY、不修改待呈现 dst。
S≤30 的 scan 由控制器顺序累加完成，不另建前缀和专用协处理器。

SCATTER 按相同输入/实例序重新遍历 snapshot/坐标，只写其覆盖桶的 8 B 引用；
每桶 cursor 自增，天然保持稳定子序列。无需每个桶重扫全表，复杂度 O(U+I+M+S)。
源数组由 lease 保持不变，不能借“两次遍历”容忍中途 CPU 改坐标。

每桶至少持有一个 8 B 待配对引用，两项组成一个完整 128 位写拍；最终奇数尾项
用全零 padding 配成一拍，目录 count 不包含 padding。独立对齐的桶不会共享
末拍，不需要读改写；约 30×8 B 的半拍缓存也计资源。PB 写通路与像素写通路按
owner 仲裁，通用 PB 数据绕过像素 X 字节抑制，不能把引用高位清零。
所有 B 响应收到、总引用和各 cursor 对账后，才写 READY 并进入 LOAD。

原 `engine_mover` 只有像素/FLUSH 写用法，本批需新增通用 metadata/ref 写流端点，
复用已有 axi_dma_wr 与真实字节掩码能力；不新增旁路 AXI 主机，不假定它已存在。

### 2.4 执行与几何边界

执行每桶只遍历自己的引用。引用取数连续，可缓存最后一个 metadata packet；
实例数组取数可按连续实例区间合并，跨包/跨桶不能用错误状态命中。
metadata/实例读取的实际 DDR 字节必须记账，8 B 引用不代表总成本只有 8 B。

I1 增加明确的当前 strip 区间与完整 logical packet/instance 上下文。原几何层
仍用全帧坐标：求交后将目的访问路由到当前 BAND；源裁剪偏移仅按原坐标推导。
不能同时让 CPU、binner 与 geom 各扣一次 strip_y0。bounds helper 与原 geom
在负坐标、65535 宽高及边界进位上通过独立模型对账，内部至少用 18 位有符号端点。

同一桶的引用顺序为输入序×包内实例序；不能按纹理或桶内来源排序。DDR 源与
目的 backing 相交一律沿 v2 拒绝，含不同槽别名；feedback 不能通过保存引用消除。
构建阶段的 SET_CLIP 只影响其后的 snapshot，状态更新不依赖“最后一个恰好被
画到的引用”。PB 成功/失败都不把私有裁剪回写旧直通状态；旧 v1/v2 的状态与
错误语义保持原样，PB 的预检失败明确为渲染前失败。

### 2.5 错误、完成与计数

ERROR_INDEX=输入 packet_index，ERROR_INSTANCE 按 F4，ERROR_TAG=原 packet w7；
ERROR_STAGE 区分前端、PB 与渲染。目录/引用取数坏或非法索引不允许越界读取，
报告 FETCH/BAD_FIELD 及当前引用关联的逻辑上下文；没有可靠关联时 index/tag
按帧级错误规则置 0、instance=0xFFFFFFFF，并保留 stage。

PB_READY 仅为内部阶段，LIST_DONE 仍在全帧 FLUSH 与全部响应排空之后。
构建失败不触发背景/目的渲染；渲染阶段错误可能已写入前缀，但失败帧禁止交换。
软复位覆盖两次遍历、PB 写 FIFO、预取、几何、像素和背景 DMA；下一门铃不得
继承上一帧 count/cursor/metadata cache 的 generation。

旧九项 PERF 不移动。编码包计数保持每输入包一次；PERF_INSTANCE 在 COUNT
接受合法 BLIT_INST 数组元素时计一次，标量 FILL/BLIT 不加、不能在每个桶再加；追加 REF_COUNT、BIN_CYCLES、
PB_RD_BEAT/PB_WR_BEAT，ref 在成功物化时计，bin_cycles 只覆盖构建阶段。
总 RD/WR_BEAT 覆盖所有真实 AXI 数据拍，分类与总计对账，不重复计数。

### 2.6 文件与预算

新增 `engine_bin.v`、`engine_pb.v` 和独立 bounds helper；`engine_cmd.v` 只负责
模式分派和阶段完成，不把三种 ABI 的检查全部塞进同一个无边界状态机。
F4 实例取数模块复用，PB 执行 adapter 复用现 geom/pix/BAND；driver 增加工作区
与模式设置，CPU 侧保留标量/v2 回退及独立 PB 构造模型。
宿主 PB 执行同样使用 F4 的显式只读窗口解析 metadata/ref/实例；共享区工作区
不能通过现素材起始的 `gfx_mem` 隐式访问。普查分别给出编码包、实例、引用和
像素口径，不把内部 PB 直接交给只懂扁平命令的旧 census。

新增片上资源初始预算 ≤8 RAM，加 F4 ≤4 RAM；counts/cursors 可先用寄存器，
不把整帧实例常驻片上。对新计算路径独立综合；整机资源含旧 TEX/BAND、CPU cache
与显示通路重新计数。预算不足时调整缓存/FIFO 或不采用，不缩小为某种纹理专用接口。

## 3 判据

- 独立模型给出精确 counts、offsets、每桶引用和 clip；≥10000 张随机场景与
  RTL 完全一致。像素再对独立标量执行器，两个比较不能互相替代。
- 变更 clip 的跨包序列、透明交叠、跨 3 个以上桶的大图元、空桶、全部裁空、
  不均匀集中分布、REF_CAP−1/等于/超过、DRAW_CAP、4 KiB 与地址回卷全覆盖。
- 至少六个变异：末次 clip 覆盖全表、引用倒序、第二次遍历跳实例、READY 提前、
  PB 写高位被清零、双帧复用 PB；分别在状态/引用/字节/生命周期/像素消费者见红。
- 定时 DDR 模型与随机反压下完整真实游戏帧对拍，旧 v1/TEX/v2 不回退；DMA 错、
  写尾掩码、复位/超时及持有状态均检查。计数分类和 AXI 总量一致。
- 预算包含 COUNT/SCATTER 两次坐标遍历、PB 写、执行再取数与启动尾部，不用
  “CPU 不分桶”直接推导帧率。与 F2/F3 组合单独测，禁止收益相加。
- 采用按总览的双型同轮 TEX、完整硬件回放、3600 场和资源/扫描门槛；若 binner
  或 PB 取数成为新墙，登记新成本与负结果，默认继续已验证后端。
