# R2-三角列表与光栅核(engine_rlst / engine_rast)

状态:**进行中：RTL 主体已落地，全链仿真 bring-up 收敛中**（2026-10-22，进度与停点见 4.12；
五模块×四宏构型零告警，smoke 已打通记录交付→扫描→退休，剩两个收敛问题与 4.9 五步的
注错/关闭态/十万条对拍/独立综合）。R1 的 128B 契约与交换向量已冻结并于 2026-10-22 验收
（独立复现通过），可据此开工。总览见 [三维光栅总览.md](三维光栅总览.md)。

## 1 要解决什么

给引擎增加三角形光栅执行硬件:CPU 交 **setup 完毕**的三角形(R1 的 128B 记录,含边缘系数、
梯度、包围盒),硬件做位置求值、增量扫描、z 测试、TEX 采样与顶点色调制,把像素写进
BAND 条带缓冲。本条目只做单元级(RTL+单元仿真),集成/预设/生命周期归 R3。
分级:**GFX_HAS_RAST**=覆盖+深度+BAND 接入(L1 平涂也在内);
**GFX_HAS_RAST_TEX**=TEX 采样(L2),依赖 RAST 与 TEX;旧 `GFX_HAS_TEX` 两种构型都保留
(L1 不许以关闭 2D 纹理能力为代价)。

## 2 怎么切分

### 2.1 列表 ABI（Main/doc/三维数值契约.md 为唯一规格源，此处只定组织）

- 主表:128B setup 记录连续存放,基址 32B 对齐;记录可跨 4KB 页。
- 子表基址 16B 对齐，逻辑长度 `SUB_BYTES` 显式提供；CPU 为最后物理拍预留补齐到 16B 的空间。
  各段仍无对齐填充，保持 R1 字节 ABI。读取端先做 16B 对齐包络，再去掉首尾无效字节；
  不直接把偶数字节地址送入现有 `ENABLE_UNALIGNED=0` 的 DMA。
- 条带子表:按 strip 顺序连续排放,`[u16 count][u16 rsvd] + count × u16 主表索引`;
  count=0 的条带整体跳过。索引语义:主表记录号,< TRI_COUNT;越界、保留位非 0 归首错
  (BAD_INDEX 拟使用新增值 13，须从 regs_gen 单一真源追加；ERROR_STAGE=7；完整索引与条带/引用序号另行保存，不能截成 FD 的 4 位 tag)。
- TRI_COUNT=0 是合法空帧(R3 的 FSM 据此跳过 RAST 相位,零开销推进)。

### 2.2 engine_rlst(取数)

评审证实不能「仿 engine_inst」一句话带过(一个缓存既装索引又装随机 gather 的记录会互相
覆盖),微架构定案:

- **索引通道**:子表经独立 64 深 u16 FIFO(小 RAM/SRL)顺序流入,与记录通道隔离。
  一拍 128b 数据最多拆成 8 个 u16，采用拍缓存串行写 FIFO；发请求前预留整个逻辑批次空间，
  防止共享 FD 被未完成索引突发占住、记录请求又无法取走 FIFO 的循环等待。
- **记录通道**:独立描述符(按索引生成地址),数据进 **双缓冲参数寄存器组**
  (2×128B=64 词,约 2k FF);三角形 N 被光栅核消费时预取 N+1。
- 描述符拆分：包络的物理起点/长度均为 16B 倍数，受 4KB 页界和 64 拍上限约束；
  逻辑游标可从拍内任意偶数字节开始。记录跨页按实际字节偏移重组，不按完整记录边界截断。
  128B 主表记录可能拆成 32+96、64+64 或 96+32；owner 保持到状态与末拍握手均完成。
- 搬运层 FD owner 编码扩到「命令/实例/光栅表」三选一;光栅表读计入真实 DDR 读(PERF 口径同命令取数)。
- 索引 FIFO 空、记录未就绪时光栅核停等;cancel/错误丢弃在途并回空闲(排空纪律复用)。
- 首版仅在 RAST 相取 FD，不在 BAND LOAD 中抢取；若后续让两者并发，须先修正/验证
  `fd_ready` 的来源门控。当前 mover 的背景描述符优先，`fd_ready` 不能单凭读核 ready 推定 FD 已受理。

### 2.3 engine_rast(光栅核)

流水:三角形装载(参数组切换)→ 位置求值 → 逐像素(1px/cycle)→ 原子提交。

1. **位置求值**（每三角形一次；复用 DSP 分拍求值，含 RGB 的调度与资源在 R2 验证）:E_k(bbox 起点)=C0 + A_px·i0 + B_px·j0;
   z/UV/RGB 从记录的 Q12.4 原点求值，属性累加器用有符号 48 位；RGB 梯度由 CPU 下发。
   提交与初值的两级舍入按 Main/doc/三维数值契约.md，UV 基值乘 4096，深度基值乘 65536。
2. **扫描**:bbox∩条带∩帧内逐行;bias 由 (dx,dy) 符号推导(top ⟺ dy==0&&dx>0,
   left ⟺ dy<0,判内 E+bias≥0);内环只有加法。
3. **z 测试**:z RAM 640×STRIP_H×16b(独立双口:同步读+同步写),逻辑 clear 值 0xFFFF,
   内容不接控制复位；首版 STRIP_H=16。采用四 bank，每 bank 为 2048+512 深的 16b 存储；
   清零每拍写四个深度为 0xFFFF，2560 拍/条带。与 LOAD 并行的起止及双完成屏障由 R3 管理。
4. **采样与调制**(`GFX_HAS_RAST_TEX`):TEX 新采样口(2.4);FLAGS.TEX_EN=0 或 VCOLOR_EN=0
   按位退化;调制按 3.5 节 V 顺序 ÷255。FLAGS.KEY_EN=1 时,采样 texel==RAS_KEY
   (3D 页寄存器)的像素**整像素跳过(色与 z 都不写)**,比较在调制前——色键抠底的
   billboard 弹幕靠它,语义与 2D 引擎色键一致(跳过=该像素完全不变)。
5. **原子提交**：`commit_fire = out_valid && band_ready && !cancel`，色与 z 只在此事件同时写；
   z 失败/色键命中也要退休在途项，但不发写。BAND 反压时输出及其元数据保持。
   **首版在三角形边界排空像素流水**，确认扫描结束且旧三角形在途数为 0 才切换参数或结束本带。
   原“不排空”假设被 4.5 的重叠像素反例推翻；原子写入本身不能解决先读到旧深度的问题。
   下一份记录的取数/验证/位置求值可重叠，不能据此提前发射其像素。取消后不再提交，等待取数/采样在途收尾。

资源仍为预算：z RAM 按分段四 bank 估 20 块，索引 FIFO 约 1 块；参数组本身 2048 FF，
另需初值、扫描与流水寄存器。位置求值拟用 4 个共享 DSP，RGB 调制拟用 3 路乘法；
映射/总 XLR/时序须单独综合验证。100MHz、平涂与纹理稳态 II=1 为目标，不包含取数、位置求值与三角形排空开销。
纹理 L=1/2 时浅流水目标分别在 3/4 拍附近，必须由真实握手实现验证，不能用单笔在途接口直接宣称 II=1。

### 2.4 BAND / TEX 端口契约(评审证实现有口不能直接连线,新增,不改既有口)

- **engine_band 新光栅写口**:`ras_wr_pix(local 线性像素号 [13:0], data[31:0], valid)` +
  `ready`;RAM 写口在 RAST 相位内独占(相位互斥由 R3 的 FSM 保证,本模块不仲裁);
  640×16 最大像素号 10239，通用 BAND 宽度按 `$clog2(WIDTH_PIXELS*STRIP_H)` 推导；
  word=pix>>2、lane=pix[1:0]，仅对应 lane 的写使能有效，高八位强制 0。
  RAST 租约覆盖整个相位，期间 legacy 读写/flush 不受理；退出前所有光栅像素已退休。
- **engine_tex 新采样口**：`samp_valid/ready` 携带 `samp_word[11:0]`，单位为 32b texel 字号；
  16KiB 对应 4096 词，bank=word[1:0]，row=word[11:2]，不能混用字节地址。
  返回 `samp_rvalid/data`，固定 READ_LATENCY=1/2；按序流水，每次发射先预留响应槽，
  响应没有 ready，反压在请求侧实施。请求到返回的延迟与稳态 II 分别验证，最多 L 笔未返回。
  与 APB 装载/legacy 读流互斥，模式交接等待旧请求收尾；停止发射后在途响应仍须接收/丢弃。
- TEX_EN=0 忽略 KEY_EN；无 RAST_TEX 构型提交 TEX_EN=1 报 BAD_FIELD。3D 色键是 RAST_TEX 语义，
  不因 2D 的 GFX_HAS_KEY=0 自动消失。v1 物理窗口不扩容，R3/R4 使用 64×64 atlas 的四个 32×32 区块，选择编码到 UV。
- 两个新口的关闭态(`GFX_HAS_RAST` 无)整块不进编译输入,第 7 章关闭态契约表相应增行。

### 2.5 单元仿真(sim/engine/rast、sim/engine/rlst)

以及 B7 CAPS/机制依赖。具体修法见后续各节，原先评审过程保留在 4.11。

### 4.3 engine_rlst：字节游标、credit 与事务所有权

R1 子表每段长 `4+2*count`。count=1、count=2 后的三个头地址为 0/6/14，
偏移 14 的 u32 头横跨两个 16B 拍。主表 32B 对齐但不保证 128B 对齐；
跨页时需要 96+32、64+64、32+96 三种拼接，不能借命令引擎的记录边界拆分规则。

逻辑请求 `[a,a+n)` 转为物理包络：

```text
p0 = a & ~15
p1 = (a+n+15) & ~15
每次发 min(p1-p, 4096-(p&4095), 1024) 字节
接收后按逻辑 a/n 丢弃前缀与后缀，再解释 u16/u32/128B
```

`SUB_BASE` 16B 对齐；`SUB_BYTES` 是真实逻辑长度，最后分配空间补齐到 16B，
不把 padding 算进逻辑表。R3 增该参数并随门铃锁存。主表和子表起止用 33b 检查，
每次读头/索引先检查逻辑范围；最后一条带结束核对游标，不让异常 count 读进其它数据区。
TRI_COUNT 上界 65535，合法索引 `<TRI_COUNT`；不擅自以 `count<=TRI_COUNT` 禁止重复引用。

研究算例覆盖 20480 个偶数字节起点/长度组合，逐字节重组全部一致；
8192 个主表基址/索引组合覆盖三种跨页形态。64 个 u16 从偏移 14 起取数，
实际包络是 144B，即 9 拍，不能固定成 8 拍。

结构按三条独立现场组织：

```text
字节游标/包络 -> FD kind=HEAD/INDEX -> 拍缓存 -> u16 serializer -> FIFO64
                                                              |
                                                              v
                         FD kind=RECORD -> 参数槽 A / 参数槽 B
                                              |          |
                                              +--> rast <-+
```

FIFO 用同步 RAM 时一拍只写一个 u16；128b 拍先缓存、最多八拍拆出索引。
发索引批次前必须预留整批空间，包括尚未落 FIFO 的数据，不能只检查接收瞬间的空位。
否则 FD 被一笔堵住的索引突发占有，后续记录读拿不到 FD，FIFO 又无法继续消耗，会循环等待。
记录槽则在发第一个描述符前预留，所有片段、拍数、keep/last/tag 与最终状态验证完后才置 valid。

共享 FD 的事务 owner 拟扩为两位 CMD/INST/RAST；内部 HEAD/INDEX/RECORD 类型另存。
owner、完整主表索引、条带号、引用序号在受理时锁存，直到 `status_seen && last_fire_seen`。
4b cidx 只作当前传输 tag，不能当主表索引。对旧 cmd/inst 的兼容转换和所有 mover 实例接线
纳入改动清单，不能让原 cmd 把非 instance 的 raster 数据写进 cbuf。

首版 RAST 相独占这条取数路径，不在 BAND LOAD 中预取。现有 `fd_ready` 没有
显式与 `!rd_pick_bg` 相与，旧协议靠相位排除竞争；新增并发时必须改 ready 来源并回归。
取消已受理事务时继续吞到 last 与状态，丢弃未验证槽；不能立刻改 owner 或启动下一帧。

### 4.4 位置求值：保留两级舍入，给出 DSP 可执行的位宽方案

bbox 使用全帧坐标，与当前条带求交后得到 `(i0,j0)`。边缘按 s32，属性初值和行/列累加
均按 s48；u16 z0 必须先零扩展再左移 16，u/v 先零扩展再左移 12。

`delta_x=16*i0-ox` 在 [-14335,14320] 内，delta_y 在 [-11775,11760] 内，均可用 s15。
合法梯度 `|g|<2^30`，用 s31。分解如下：

```text
g = signed(g[30:16])*65536 + unsigned(g[15:0])
g*delta = high15*delta15*65536 + zero_extend(low16)*delta15
acc0 = base48 + ((gx*delta_x + gy*delta_y + 8) >>> 4)
value = clamp((acc + 32768) >>> 16, 0, limit)
```

low16 要补 0 成 s17，两个部分积均落在单个 19×18 DSP 输入范围。先符号扩展到 48b
再移位/相加，两个方向的乘积求和后只舍入一次；不能分别舍入 x/y 项。
边缘 A/B 已含 ×16，可先取 A/B>>>4（包含 R1 validator 上界时用 s17），
与整像素坐标相乘后再左移 4，避免把整个 s32 边系数映射成大乘法器。

六属性共 12 个完整乘积，即 24 个部分积；三条边另有 6 个乘积，共 30 项。
拟用 4 个共享 DSP，最低需要 8 个发射时钟，再加乘法寄存、归并与初值寄存延迟。
不是“一拍 setup”，不能以 DSP 输出宽 48b 推断输入乘法也能 32×16 单块完成。
下一槽的初值可与当前三角形扫描重叠；当前槽的梯度、原点、颜色、bbox 在全部像素退休前保持。

种子 52323026 的 100000 组部分积/初值与直接整数公式全部相同，CRC=b3d27523；
另测正负极值，观测最大 |acc|=1622550816571，小于契约的 2^41 界。
这证明分解恒等与数值范围，不是 DSP 推断、时序或实际初始化周期的综合结果。

### 4.5 z 流水：原子提交之外还需要三角形屏障

抽象算例取同一个像素，A 深度 100、B 深度 200，写回延迟 3 拍，初始深度 65535。
若 B 在 A 写回前读取，二者均看到 clear，最后 B 错误覆盖 A；即使每次色/z 同拍原子写也仍出错。
READ_FIRST 模式下，B 与 A 同沿读/写还会读到旧值。研究输出为：

```text
A read=0, commit=3
B read=1 -> final_z=200  EXPECTED_RED
B read=3 -> final_z=200  EXPECTED_RED（同沿 READ_FIRST）
B read=4 -> final_z=100  PASS
```

因此首版采用三角形边界排空，不依赖 BRAM WRITE_FIRST 或推测的跨三角形旁路。
切换参数/发 done 的条件为扫描结束且 in_flight=0；退休包含深度拒绝、色键跳过和成功提交。
不以“最后一个像素已发射”“最后一次 BAND 写发生”代替所有在途均退休。

像素稳态拟为：覆盖与属性量化 -> 并行 z/TEX 同步读 -> z/key 判定与 RGB 乘积 -> /255/提交。
TEX L=2 多一个响应延迟级。L=1/2 下争取约 3/4 拍延迟、II=1，但这是实现目标。
RGB 调制仅复用 B1 的整数方程，首版独立三路乘法，不借二维共享实例或依赖 DSP 自动 packing。
平涂分支不发 TEX 请求，关 RAST_TEX 后相关乘法/比较/采样控制应消失。

反压不能只靠全局 en 冻住所有寄存器：已经受理的同步 RAM 读仍会按固定延迟返回。
在 z/TEX 响应汇合处预留 FIFO/skid 槽；请求时扣 credit，响应无 ready 也有位置可存。
算例未执行这条 RTL 流水，实现时必须用 L=1/2、长 BAND 停等和 cancel 逐拍验证。
提交信号只有一个 fire；cancel 优先于新请求与写回，旧采样/DMA 返回接收后丢弃，
直到响应现场清空才允许结束/重启，不能把上一帧响应挂到下一帧参数上。

### 4.6 BAND/TEX：地址单位、时序与租约

640×16 有 10240 个像素，最大地址 10239，必须 14b。11b 只有 2048 个不同地址，
研究穷举看到每五个相隔 2048 的位置发生别名。
BAND 内部是 2560 个 128b 词：`word=pix>>2`、`lane=pix[1:0]`，
新写口只打开一个 lane 的 WE，写 `{8'd0,rgb[23:0]}`，不重写另三个像素。
RAST 租约在整个相位屏蔽 legacy 本地描述符与 flush；不能根据某拍 ras_valid=0 就交回端口。
若旧读/写尚在途，则 ras_ready 保持 0；退出 RAST 前也要排尽 staged 像素。

TEX 物理 16KiB=4096 个 u32，统一用 12b texel word 地址。
bank=word[1:0]、row=word[11:2]；APB 仍是原来的字节地址口，二者在边界明确转换。
L=1/2 时采样 bank 选择与 valid 都延迟 L 拍；不得用当拍 UV 选择先前返回的 RAM 数据。
允许按序流水的固定延迟请求，最多 L 笔未返回；响应缓冲至少覆盖已经预留的全部请求。
旧流、采样流和 APB 的物理读口保持单所有者，模式切换等待在途结束。
APB 运行期不访问纹理的驱动纪律保留，不能靠额外复制 RAM 获得第二个采样口而不记资源。

R1 的 2×2 golden 与四张 32×32 的实际场景分别作为单元配置；R2 核接收尺寸、
以词计的 stride_log2 等只读配置，检查 `(height-1)*stride+width<=4096`，避免窗口截断回绕。
R3 首版将参数固定为 64×64 atlas（stride=64），R4 通过 UV 原点偏移选择四个 32×32 区块。
这不增加记录字段，不动 R1 已验收数学，也不把单张 64×64 误算成 32KiB。

### 4.7 z 存储与清零预算：估算器结果与综合网表分开

本机 Efinity 2026.1.132 的 `efx_map_ramest --family Titanium --mode speed --size ...`
得到以下结果。工具安装路径沿用开发环境占位符，运行环境仅在本次进程中设置。

| 逻辑存储 | 工具估算 RAM10 数 |
| --- | ---: |
| 10240×16 | 20 |
| 8192×16 | 16 |
| 2048×16 | 4 |
| 2560×16 | 8 |
| 512×16 | 1 |
| 64×16 | 1 |

原 16 块只相当于总容量除以 10Kbit，没有结合合法宽深模式。拟用四 bank，
每 bank 2560×16 显式拆成 2048×16+512×16：`4*(4+1)=20` 块。
若直接按四个 2560×16 估，结果是 32 块。单个 10240×16 的工具估计虽也为 20，
但无法据此推定任何 HDL 都映射为 20；已有 BAND 研究证明非二次幂深度的实际推断可偏离预算。

四 bank 每拍可清四个 z：每带 2560 拍，30 带 76800 拍，按 100MHz 纯算术折算 0.768ms。
一像素/拍清零则要 3.072ms/帧。清零起止由 R3 与 LOAD 并行，并等两个完成信号；
不能一边声明串行 LOAD→CLEAR 一边把清零开销全部隐藏。
当局部 count=0 时可不扫描/取记录，但本带头部与已启动清零仍有成本；
全帧 TRI_COUNT=0 才绕过所有 3D 现场。

据 B3 归档 165 RAM，z 20 加 FIFO 约1 得到约 186 RAM 的第一笔加法账；
参数槽、init、扫描/响应寄存器另计。R2 独立综合要检查真实 RAM 形状、DSP 个数和时序，
R3 再用 B7 整机报告替换总账。本轮没有执行 map/interface/pnr/pgm，不产生新的综合通过结论。

### 4.8 R3/R4 联动与错误接口

`feature_config.py:213-215` 当前 B3=0x146F，保留 INST 再置位 14/15 后 B7 应为 **0xD46F**。
原 R3 的 0xC46F 丢了 bit12。`RAST_TEX→TEX` 也必须保留：这是单向依赖，
不意味着 RAST_TEX=0 时关掉旧二维 TEX。R3 同步修正两处规格，生产生成器本轮不改。

R2 需 R3 门铃锁存：TRI_BASE、SUB_BASE、SUB_BYTES、TRI_COUNT、RAS_KEY 和 TEXCFG。
TEXCFG 首版定 64×64 atlas，四个材质的 UV 原点为 (0,0)/(32,0)/(0,32)/(32,32)；
这些坐标的单位是 texel，写 Q12.4 时原点偏移乘 16。每块局部 UV 限于 [0,31]，
再加区块原点，避免把单纹理习惯的端点 32 采到相邻材质；硬件只提供整个 atlas 的 CLAMP。
CPU 装载时按 64 词行距排成图集，不能仍把四张图逐张线性拼接后当 atlas 采样。
切回二维纹理工作集前，R4 等引擎完成后重装，避免两种布局混用。

当前 regs_gen 只有错误码 0..12，没有 BAD_INDEX。拟追加 13，不重排旧值。
坏参数/记录字段走 BAD_FIELD=2，取数/流协议失败走 FETCH=9，超时沿用 12；
全部 ERROR_STAGE=7。ERROR_INDEX 保存完整主表索引；定位还需条带/引用序号。
建议 ERROR_TAG=`{11'd0,strip[4:0],ref_ordinal[15:0]}`，头部错误用无索引哨兵；
数值与 TAG 位域在实现前从公共接口真源统一登记，不能只在 rlst 内自造未公开常量。
发生首错后阻止本带后续提交，已写像素不回滚，取数仍按协议排空。

### 4.9 验证输入、变异与实施顺序

R1 已有的 15 个具名向量、完整记录 hex、初始 color/z 和两套种子复用为金标准。
**当前 JSON 只导出 16 条光栅、20 条几何随机样本**，100000/10000 是生成器的执行规模；
不能重放这几个样本后宣称 RTL 十万条通过。R2 增流式导出器，保持原种子、调用随机数顺序、
纹理、初始深度和记录摘要；逐像素对拍，并核对 100000 条记录实际被 RTL 消费。
C 增量与 ref2、Python 期望仍保留交叉，R2 RTL 比较对象是最终 color/z 及提交掩码。

必须单列以下边界：

- 子表头偏移 14、index 0/65534/65535、保留字段、SUB_BYTES 截断/溢出、30 个空头；
  三种主表跨页、早/晚状态、错误 RRESP、缺/多/错位 last/keep/tag。
- FIFO 空/满、64 条批次 credit、128b 拍八个 u16 的序列化、双参数槽背压、取消每个片段；
  owner 不得根据请求侧当前状态解释旧返回。
- 共享边、跨条带、两个相交三角形覆盖同一像素；第一三角形的最后像素与下一份首像素相同；
  z 相等、近/远覆盖顺序、透明色键像素不占深度、原点在 guard 外侧与负梯度极值。
- BAND 仅单 lane 改写、11b 截断反例、长 ready=0、提交沿 cancel、未排空 flush；
  TEX L=1/2、连续换 bank、响应到达时反压、采样后取消、atlas 四个角与 CLAMP 两端。
- RAST_TEX=0 的纯色/顶点色、非法 TEX_EN 拒绝、KEY_EN 无 TEX 时忽略；
  关闭新机制后旧二维端口与构型行为保持。

计划十三类独立注错：漏 ×16、bias 反、LESS 改错、初值/提交舍入错误、跨页丢片段、
FIFO credit 错、色键恒不命中、状态到即提前释放 owner、子表首字节偏移丢失、
像素号截 11b、色/z 部分提交、移除三角形排空、TEX bank/valid 延迟错误。
每类给指定 witness，另保留基本握手护栏，不能只观察超时或退出码。

实施按以下顺序推进，避免同时调总线和像素方程：

1. 先写流式向量导出器、rlst/rast scoreboard 与端口/时序断言，预先定义预期输出。
2. 实现 rlst 的逻辑字节游标、head/index 与 A/B 记录槽，先用 FD 替身，再接真实 mover/AXI 随机反压。
3. 实现 L1：记录校验、共享 DSP 初值、z bank/清零、覆盖/颜色、原子提交与三角形屏障。
4. 给 BAND/TEX 增独立端口并跑直接消费者；再实现 L2 的固定延迟采样、credit、色键和调制。
5. 补十三类变异、十万条真实 RTL 流、协议/取消和关闭态；最后做独立 RAM/DSP 综合。

拟新增检查名为 rlst/rast-rtl/rast-ports，避免占用现有 `rast`（R1 软件检查）；
开发时登记到 validate 的唯一清单与依赖。改 owner 需覆盖 cmd/inst/mover/frame，
改 BAND/TEX 需覆盖 band/tex/stripctl 与代表实例/PB 消费者；PB∧RAST 仍非法，
但旧 PB 不能被共用搬运层改坏。新模块先独立综合；若改变已进入整机的 RTL，
按验证流程补受影响代表构型整机综合，不能以 R3 将来会综合抵账。B7 集成和三维板测仍归 R3。
