# 摄像头实时图层

状态：未开工，**顺位最低**。只在基础要求（BitBlt、帧缓冲、双缓冲、帧率对比 Demo）
与高阶要求（Alpha 混合、颜色键控、高负载 Demo）都上板之后，还有余力时才做。
不阻塞任何条目；反过来，它依赖引擎与 E5 的端口分配先定下来。

本条不属设计文档第 7 节的 E1~E8，不占 E 系列编号。

## 1 要解决什么

板卡随附一个 MIPI 摄像头模组（实拍在资料包
`Efinix/05_外设器件手册/摄像头SC431HAI_模组实拍_20260918.jpg`，资料包不入库），
赛题二不要求用它，当前工程也没有接。它是一个现成的创新点来源，但用法要对：
**摄像头给 2D 引擎当素材，不另起一个视觉项目。** 否则在评审眼里会像是跑到了赛题一或赛题三。

想做成的效果：摄像头画面在 DDR3 里是一块每帧自动刷新的源图，引擎读它与读普通贴图没有区别。
在此之上做的创新点按推荐顺序：

| 顺序 | 做什么 | 与赛题的关系 | 额外的硬件 |
| --- | --- | --- | --- |
| 1 | **实时抠像合成**：颜色键控从「一个精确颜色」扩展为「一个颜色范围」，对摄像头画面做绿幕抠像，把人像叠进游戏或 GUI | 高阶要求的颜色键控与 Alpha 混合，从静态贴图推到实时视频源；做法与手机显示控制器的硬件图层合成同类 | 键控比较器加一个范围比较，其余复用引擎 |
| 2 | 摄像头画面当游戏背景，弹幕叠在上面 | 同屏精灵数量的测试照做，只是背景换成活的 | 无 |
| 3 | 体感控制：逐行统计某种颜色标记的重心，CPU 读坐标控制玩家 | 互动演示，不涉及 AI | 一个行流水线的统计单元，挂 APB |
| 4 | 拍一帧抠出来，当作新的精灵素材 | 与 1 技术重叠，演示效果好 | 无 |

1 是主推，3 可以叠在 1 之上，2 与 4 几乎零成本，1 做完顺手就有。

### 1.1 摄像头本身

| 项 | 内容 | 出处 |
| --- | --- | --- |
| 传感器 | 思特威 SC431HAI，400 万像素，有效窗口 2568×1448，最高 2560×1440@60fps | `Efinix/05_外设器件手册/摄像头SC431HAI_数据手册_V1.1.pdf` 第 1 页、概述 |
| 输出 | MIPI CSI-2，1/2/4 路数据线，RAW8 或 RAW10 的原始拜耳数据，要解马赛克才是 RGB | 同上 |
| 可用功能 | 2×2 合并像素、输出窗口调整、镜像与倒置、传感器自带测试图（数据手册 2.9 节） | 同上，第 1 页特性列表与目录 |
| 配置 | I2C，8 位写地址 0x60（由 SID 管脚电平决定，另一档是 0x64） | 数据手册表 1-3；官方例程 `i2c_master_ctrl_top.v` 的 `I2C_DEVICE_ADDR` |

### 1.2 官方参考工程

`Efinix/02_Ti60F225_DemoBoard_v4_赛题1-3/10_Ti60f225_sc431hai2hdmi_demo/` 下有 v1、v3~v6 几个版本，
以下数据取自 v1（`Ti60f225_sc431hai2hdmi_v1/`），接手时先比较各版本差在哪里再选。

通路：传感器 → 芯片内置 D-PHY 与 CSI-2 RX Controller IP → 帧缓冲（DDR3，存 RAW8，每拍 4 像素）
→ 读出时解马赛克 → HDMI 1080p。

- 传感器配置是一张写死的 I2C 寄存器 ROM（`rtl/cam_i2c_ctrl/i2c/i2c_master_reg_rom.v`，约 160 条有效项），
  输出窗口 `0x3208~0x320b` 配成 1920×1080。
- CSI-2 RX IP 参数：4 路数据线、`HS_BYTECLK_MHZ=70`、`PIXEL_FIFO_DEPTH=4096`、连续时钟模式
  （`ip/csi_rx_controller/settings.json`）。
- 帧缓冲存进 DDR3 的是 RAW10 截掉低 2 位后的 8 位（顶层 `vin` 取 `[9:2]` 等四段）。

各模块资源（`outflow/ti60f225_oob.res.csv`，工程整体 191 块片上 RAM）：

| 模块 | FF | LUT | 片上 RAM | 本工程要不要 |
| --- | --- | --- | --- | --- |
| `csi_rx_controller` | 1191 | 2203 | 36，其中像素 FIFO 32 块 | 要；FIFO 深度可以调小，要多少由第 2 节第二步定 |
| `i2c_master_ctrl_top` | 170 | 293 | 2 | 看第 2 节第一步的取舍 |
| `debayer_top_2to1` | 253 | 109 | 4 | 要，或自己写 |
| `frame_buffer` | 1417 | 1730 | 28 | 不要，换成本工程的写 DMA |
| `dsi_tx` 与 `panel_config` | 2028 | 3860 | 80 | 不要，板上没有这块屏 |

| 方面 | 现状 | 结论 |
| --- | --- | --- |
| 管脚 | 摄像头数据线在 `GPIOT_PN_06/07/09/10/11`，I2C 与复位在 `GPIOR_16/18/20`（官方工程 `ti60f225_oob.peri.xml`） | 本工程 `gfx2d_ti60.peri.xml` 一个 GPIOT 都没用，也没用这三个 GPIOR，**无冲突**（2026-09-18 对两份 `peri.xml` 做过比对） |
| 片上 RAM | 现在 65 块，设计文档 2.3 节给引擎的预算 108 块，合计 173 块 | 按官方参数再加约 42 块到 215 块（84%）；像素 FIFO 调小后能压到约 180 块 |

| SoC 的 I2C0 | [`soc资源裁剪.md`](soc资源裁剪.md) 计划关掉 I2C0 | 与第 2 节第一步冲突，见下文 |

## 2 怎么切分

**第零步，确认模组是好的。** 用 JTAG 加载官方工程的比特流（`outflow/ti60f225_oob.bit`，掉电丢失，不动 Flash），
插上摄像头与 HDMI 看有没有画面。不改仓库，随时可做，建议在做其它上板实验时顺手做掉。

**第一步，传感器配置交给 CPU。** 不照抄 ROM 表：I2C 挂到 SoC 上，由 C 程序写寄存器，
曝光、窗口、测试图在运行时可调，演示时也能现场切换。
两种做法：用 SoC 自带的 I2C0，或在 APB 上挂一个 I2C 主机。
**如果那时 `soc资源裁剪.md` 已经把 I2C0 关掉，只能走 APB**；两条都还没做时，
裁剪那次生成要考虑是否保留 I2C0（约 350 XLR）。

**第二步，数据通路。** CSI-2 RX → 解马赛克 → 缩放或裁切到 640×480 → 写 DMA → `Axi_Mux` → DDR3，
两块缓冲区轮换，CPU 从寄存器读当前可读的是哪一块。分辨率的取法：

- 传感器 2×2 合并出 1280×720，FPGA 里再缩到 640×360 或裁到 640×480。视野完整。
- 或者传感器直接开 640×480 窗口。实现最省，视野变窄，画面像拉近了。

哪种可行、帧率多少，要按数据手册 2.7、2.8 节算过再定，本条现在不下结论。
像素格式跟随设计文档 3.5 节的像素规格。

**第三步，引擎把它当源图。** 不给引擎加新命令，摄像头缓冲区就是一个普通的源地址。
在此之上按第 1 节的顺序做创新点：先 1（范围键控），再按余力做 3。

**不做的：** 不做 AI、不做风格化、不做推流，那是赛题一、赛题三的方向；不输出 1080p。

## 3 判据

| 项 | 判据 |
| --- | --- |
| 第零步 | 官方比特流下 HDMI 有实时画面 |
| 配置通路 | 读传感器 ID 寄存器（数据手册 1.5 节）得到手册写的值；写测试图模式寄存器后画面变成测试图 |
| 数据通路 | **先用传感器自带的测试图当判据**：内容是确定的，写进 DDR3 的缓冲区逐像素与期望值比对，不一致的像素数为 0。真实画面不能当判据，只能看 |
| 注错 | 故意把解马赛克的拜耳相位配错一格，比对必须报错，证明判据会红 |
| 带宽 | 实测摄像头写入对扫描输出无影响：扫描 FIFO 不下溢（E5 的水位计数器） |
| 资源与时序 | 编译报告里片上 RAM 与各时钟域 setup、hold 全为正，与接入前逐行对比 |
| 创新点 1 | 绿幕前实拍，抠像结果叠进游戏画面，录屏存进 `Deliverables/Assert/measurements/` |
