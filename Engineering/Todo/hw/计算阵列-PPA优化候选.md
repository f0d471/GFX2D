# 计算阵列的 PPA 优化候选

状态：**未开工（条件启动）**（2026-10-18 立项）。基线：`engine_pix` 单独综合
3886 XLR / 12 RAM / 12 DSP（[engine 第 04 章](../../TechReports/engine/04-计算阵列与片上缓存.md) 3.8），
整机 B0 默认交付档 36780 XLR / 105 RAM / 16 DSP。

启动条件（任一成立才动手）：

- 要把全功能档 B5 的容量往前推（当前 59652 XLR，只余 731）；
- 时序变紧（B0 setup +0.882~1.132 ns，B5 +0.104 ns，hold 恒定 +0.026 ns）；
- 要做只留 COPY/FILL 的极小档，省 RAM 比省 LUT 更值。

不因「看起来能省」而动手。B0 有富余，优化在本轮没有容量收益，只有将来开满功能或
时序变紧时才有意义。

## 1 要解决什么

静态分解（估算，未用综合报告确认）与量化依据：

| 部件 | 位宽/数量 | XLR 估算 | FF 估算 | 说明 |
| --- | --- | --- | --- | --- |
| 12 个 `engine_blend` | 12 × 单通道 | 2500~3200 | 约 760 | 单核 = 级 1 的 9 位三路选择、`base×255` 移位减、级 2 十九位加、级 3 加 128 / 除 255 / 饱和，加 63 个 FF 与 1 个 DSP |
| 旋转 mux 树 | 4 × 32 位 4:1 | 350~400 | 0 | 每输出字三级 2:1 |
| 两块行缓冲与端口 | 512×128 / 512×96 | 约 150 | 224 | 12 块 RAM 之外的地址拼接、`dst_wdata` 字节重排、输出寄存器 |
| 两拍窗口与大寄存器 | `r_cur/r_prev` 256、`r_px` 128、`r_dst/r_dst2` 192、`r_a` 32 | 约 100 | 约 700 | 纯寄存器，几乎不花 LUT |
| 每半上下文 | `h_*` 两半约 70 位 ×2 | 约 120 | 140 | 开行时的 2:1 选择 |
| 掩码、色键与延迟链 | `row_mask()` 两处例化 + 四条延迟像 | 150~220 | 约 30 | `row_mask` 是 4 个 12 位比较器 ×2 |
| 状态机与记账 | `cnt_k/out_count/drain_count/q_count` | 约 120 | 约 50 | — |

由此得到三条结论，后面所有候选都从这三条出发：

1. **LUT 主要在混合核上**（六到八成），所以只动外围最多省个位数百分点；
2. **RAM 块数由位宽决定、深度免费**（256×128 与 512×128 都是 7 块），所以深度不是杠杆；
3. **FF 主要在四大块大寄存器与 12 个核里**，省 FF 不必然省 XLR（XLR 按 LUT 与 FF 的较大者打包）。

## 2 怎么切分

### C1 旋转器改两段 barrel

现状：`px0..px3` 各是 32 位 4:1 选择（三级 2:1），约 384 个 LUT4。
改法：改成 shift-by-1 与 shift-by-2 两段，每段 4 个 32 位 2:1，共约 256 个 LUT4。
预期：省 100~130 XLR（约 3%）。
风险：低，`px[t] = w[st + t]` 的语义不变。
证据：pix 套件（相位 4×4、拆段 4 行、长行 640 像素）足够；token 多重集不再等价，必须靠仿真加同轮综合。

### C2 `row_mask()` 换成小移位器

现状：函数里 4 个槽各做两次 12 位比较，两处例化（首拍、末拍），约 150~220 XLR，
且串联深度落在边带握手那条组合路径上。
改法：首拍掩码按 `(4'hF << ld)` 起，短行再加尾部截断 `~(4'hF << (ld + npx))`；
末拍掩码按 `ld + npx − 4*beat` 截位。两种都只是 4 位变量移位。
预期：省 50~100 XLR，组合深度下降。
风险：中。一拍的行（行尾并入首拍）、`beat = 0` 与 `npx < 4 − ld` 的边界必须逐值等价。
证据：418 行 sweep 已覆盖相位 4×4 与 1~8 像素宽，可做逐槽等价。

### C3 数据通路去同步复位

对象：`r_cur/r_prev/r_px/r_dst/r_dst2/r_a/r_k/r_k2/v_d1~d4/q_src/q_dst`，约 1000 个 FF。
理由：这些寄存器的下游有 `valid` 把关，复位没有功能作用；去掉约 1000 条复位连线可降扇出与拥塞。
预期：XLR 小幅，布线与时序改善不确定，必须实测才知值不值。
风险：仿真出现 X 传播（只在 `valid = 0` 的拍上）。
证据：pix 套件 + 整机四步，重点看 hold。

### C4 `src_k` 寄存器化（时序向）

现状：`cnt_k + rot_off` 直接进块 RAM 地址端口。
改法：`src_cnt` 自己走一个寄存器（行首装 `rot_off`，每拍加 1），把七位加法器从
「`cnt_k` → 地址 → 块 RAM」这条路径摘掉。
代价：8 个 FF 加一个行首装载条件。
前置条件：place 报告的最差 setup 路径起点确实落在这条链上；不在就不做，否则是白花面积。

### C5 按构型裁 RAM 宽度（只对非默认档有效）

- 无 `GFX_KEY` 且无 `GFX_ALPHA`：源的高字节没人用，`src_mem` 128 → 96 位，7 块变 5 块；
- 无 `GFX_ALPHA`：目的从不读，`dst_mem` 整块可去掉，省 5 块；
- 合计 12 → 5 块。

B0 是像素全开（`GFX_EQ_EXT / GFX_ALPHA / GFX_KEY` 都开），用不到这条。
工作量在构型构建与源列表层，不在 pix 内部，落地要按
[验证流程](../../../Main/doc/验证流程.md) 对每个受影响构型重跑能力与功能判据。

### C6 零成本清理

- `ws_key_lanes` 的两处 `ifdef GFX_KEY` 分支完全相同，可合一条（无面积，纯可读性）；
- 把「7 拍延迟」与「8 拍排空」写成派生常量（无面积，防止改级数时忘改排空）。
  这一条与 [计算阵列-三处自定项](计算阵列-三处自定项.md) 2.2 节的可选小改是同一件事，
  落地时只做一次。

### 已否决（静态分析即可判掉，避免重复提案）

| 想法 | 否决理由 |
| --- | --- |
| 行缓冲深度 512 → 256 | 块数由位宽定，256×128 与 512×128 都是 7 块；512 深度还能用地址最高位直接选半 |
| 源块与目的块合并成一块 RAM | 每拍需要 2 读 + 2 写，`EFX_DPRAM10` 只有 1R1W，物理上做不到 |
| 目的块再收窄 | 已是每像素 3 字节（RGB），X 字节本就不进 RAM |
| 4 像素/拍降到 2 像素/拍 | 省 6 个 DSP 与约 1500 XLR，但吞吐减半；DSP 只占 16 里的 12，不是瓶颈 |
| 12 个核时分复用 | 要 2 倍时钟或 2 拍一次，违反「写一开始就每拍一拍」的硬要求 |
| 去掉 `r_dst2`（96 FF） | 清零挪到核输入侧 = 12 个核各加 8 位门 = 96 LUT，与 96 FF 打平 |

## 3 判据

一次改动要收口，按下列顺序取证，缺项按未完成记：

1. 基线复现：单独综合 3886 XLR / 12 RAM / 12 DSP，整机 B0 36780 / 105 / 16 与 setup/hold。
   数不对先查环境与工具参数，不在错的基线上比。
2. 等价性：只挪位置与注释的改动用去注释 token 多重集；涉及结构的改动跑
   `sim/engine/pix/` 套件与 B1~B4 真实通路 512 KiB 逐字比对。
3. 面积：同轮 A/B，报区间不报单点。XLR 同源码重复综合波动 2~3%，且综合器对源码文本敏感
   （`engine_bin` 正文重排曾使整机映射 +1606）。
4. 时序：全域 setup 与 hold 非负；hold 只比同轮（本身就只 +0.026）。
5. 板测：只在改动影响部署对象时做，按验证流程选范围。
