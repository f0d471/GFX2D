分三类。同一类里的实验互不阻塞，可以并行或搭车。

**现在就能做，不被任何东西挡住的：** 目前没有。E6 原在这一类里，2026-09-26 定为不做。

E7 与 E8 已于 2026-09-27 按缩减范围收尾并归档进

E5 的 2.4 节原在这一类里，2026-09-21 完成压力矩阵与回归，2026-09-24 整体验收并归档，
不再列为待办。

E1 已验收（结论见 platform 第 04 章）：**保留 Standard 构型**，
所以 E8 的缓存对照组不再是 Lite。65 块 RAM 是当时的历史基线；
扫描输出接入后的当前主线为 71 块（[主工程 README](../../../Main/README.md)），资源对照要取实验入场前同一 RTL。

E3 已于 2026-09-18 判据修复后上板完成并验收（结论见 platform 第 05 章），条目已于 2026-09-19 删除。
它解开的两个问题：驱动与软件执行器可以在读回共享区之前失效一次就安全使用，
不需要维持「只写不读回」，条件是失效晚于外部写入完成；「同帧 CRC 对比」判据成立，
整帧读回约 13 ms（估算），适合逐帧调试时开启。

E5 原先在这一类里（前半是端口重分配与防饿死，后半等扫描输出）。扫描输出验收后，
2.4 于 2026-09-21 完成，E5 于 2026-09-24 整体验收；真实引擎接入后的复测归引擎工作点。

## 搭车与顺序建议

1. **候选缓存由 platform 第 10 章第六节维护。** 4KB 与 16KB 的 DDR 回归和固定程序选型已完成；
   正式采用 16KB 时单独生成 IP、同步 SDK 并核对资源与时序，按改动影响做必要回归，
   真实游戏与扫描压力由 SW9 验证。8KB 新版及三次矩阵不再是待办。
2. **E5 的端口重分配已经单独完成。** 引擎接入另做一次编译；`core_clk` 的 hold 只有 0.026 ns，
   需在引擎接入后重新核对时序，并按第 08 章复测扫描 FIFO。
3. **E7、E8 已收尾。** 历史实验产物用于对照，软件后续正常开发不受冻结；
   改像素算法时复验受影响的正确性，改缓存、DDR、时钟或总线时验证相关硬件路径。
4. **P4 的最终取舍由真实负载决定。** SW8/SW9 在真实游戏和板上测完整帧及 `N_max` 后再定，
   E8 合成探针仅提供阶段性选型依据。

## 每一份 spec 的共同结构

按 [`README.md`](../README.md) 的单条结构，节序固定：

| 节 | 内容 |
| --- | --- |
| 状态 | 一行，写明未开工 / 进行中 / 待验收，以及它阻塞什么（验收之后文件删除，不存在「已验收」状态） |
| 1 要解决什么 | 现在是什么样，不做会导致什么 |
| 2 怎么切分 | 拆成哪几步，每一步的产物；不做什么也写在这里 |
| 3 判据 | 怎样算做完；可量化的写数字，上板项写清对照组与注错用例 |
| 4 开发日志 | 开工后逐次追加，最新的在最前 |
