# 引擎 P3-G1 片上纹理（TEX）

状态：**待验收**（2026-10-08，RTL、驱动、游戏接入与本条自动验证完成）。
前置：无（B1～B6 已归档）；仍阻塞 G2。研究正文与证据索引见
[engine 第 07 章](../../TechReports/engine/07-片上纹理前期研究.md)。
本批对应总体设计 1.4 节路线表的 P2；范围见 [总览](引擎P3总览.md) D56/D57/D63。
开发日志追加在第七节。

## 1 要解决什么

直通模式每颗 16×16 ALPHA 约 1,183.5 周期（engine 第 06 章板上实测），其中源读
一行一笔事务；简单减去 16 笔源读未计入本地描述符收尾与同步读延迟。
2026-10-07 校准从机实验：P1 为 1,104.25 周期/颗，TEX 读延迟 1／2 拍为
703.25／719.25，源 DDR 事务为 0；该数不含命令取数、SoC 与扫描争用，板测仍待实现。
真实游戏 P1 的 `N_max=1014`，G1 的 1,500～1,700 只保留为早期模型参考。
本批先启用 32 字节 v1 命令的 TEX 能力 profile；ABI v2 实例列表归 G3。

## 2 范围与定案

- D57：TEX=16 KiB scratchpad（128 位读、32 位装载；四个 1024×32 bank
  实测 16 块 RAM），不做 cache、
  不做 BLIT-to-TEX；装载走 APB 窗口 `0xF810_4000～0xF810_7FFF`（Slave0 空闲页，
  guard 页 0xF000 起不受影响），驱动上电写入热集并读回 CRC 自校验。
  窗口属于 APB Slave0 第 4～7 页；`gfx2d_top` 与 `engine_top` 传完整 16 位偏移，
  `engine_top` 分选寄存器和 TEX，`engine_regs` 继续只收第 0 页 12 位地址。
  只允许 4 字节对齐的 32 位访问；读在 SETUP 相发同步请求、ACCESS 相返回，
  写只在 ACCESS 完成沿提交；未对齐访问回 PSLVERR 且不得改 RAM。
- D63：`CAPS.TEX` 置 1；直通模式其余行为不变。表面 `space=1`（TEX）字段
  v1 已预留，本批仅允许 BLIT 源使用；所有目的仍为 DDR，TEX 目的、BAND 与
  space=3 均按 `BAD_SPACE` 报错。方程和格式的 v1 限制继续有效。
- 表面描述符 `base` 在 `space=1` 时解释为 TEX 内字节偏移（16 字节对齐），
  驱动负责热集布局并登记表面表。TEX 结构额外要求
  `base + height * (1 << stride_log2) <= 0x4000`，采用扩展位宽计算；
  无效槽、错对齐、越界先报 `BAD_SURFACE`，保留十步检查优先级。
- 装载期间引擎不得引用未装载完的 TEX 表面：驱动顺序保证（先装载、后登记
  valid 位），硬件不加互锁。装载、读回、重登记均要求引擎空闲且无 pending 表；
  重载先清受影响槽的 valid，CRC 不符时保持无效。禁止运行期 CPU 读写 TEX，
  读回 CRC 的期望来自已通过素材包校验的条目内容，包含行 padding；
  以允许 APB 读回复用 128 位读口。控制软复位保留 RAM 数据、清槽 valid；
  FPGA 重配置后重新装载，RAM 不作全量复位。
- 热集按现行 manifest 为 BUL16/BUL8/SPARK：偏移 `0/0x1000/0x1400`，
  长度 `4096/1024/5120`，共 10,240 字节，余 6,144 字节。
- 软件模型按 `space` 映射 TEX 的 DDR 影子，保持相同命令和相同逻辑表面表对拍；
  `lib/gfx` 不包含 BSP 寄存器头。硬件驱动增加含 space 的表面登记入口，
  旧 DDR API 保留包装；`renderer_prepare` 传递 space，后端切换前 flush。

## 3 前期研究要求（沿 B 批规矩）

- ≥2 个本层参考读到代码级：候选方向——scratchpad 供流与 valid/ready 流的
  延迟匹配（skid buffer 与提前取数两种做法的时序对比）、verilog-axi 读核与
  同步 RAM 的衔接案例。
- ≥1 个出数字的实验：TEX 读延迟（1～2 拍）注入 `sim/engine/mover` 或
  `sim/engine/pix` 校准从机，测对每颗周期模型的影响。
- 关键问题：
  1. I3 的恒 ready 不要求 valid 无空拍。优先在 TEX 内同步延迟 data/valid/tlast，
     几何层继续先发边带；改变消费者反压契约后才研究 skid buffer 的容量；
  2. 第 4～7 页在引擎顶层译码，以 `paddr[15:14]==2'b01` 命中，
     保持寄存器模块比较链与地址宽度；
  3. 描述符「片上」标记的传播路径（几何层→搬运层上下文寄存器）。
  4. I3 保持单个像素流所有者；TEX 流在途时允许 DDR 请求提前发出，返回先停在
     DMA FIFO，TEX 收尾后才送目的流。读状态须携带取数来源，TEX 状态保持到
     ready，碰到 DDR 状态时延后。排空同时等待 TEX 流水与既有 AXI 收尾。
  5. `PERF_RD_BURST/RD_BEAT` 只计 DDR 接受的描述符，TEX 不计；命令取数仍计。

## 5 判据

- 正式 `sim/engine/tex`：4,096 字装载/读回、APB 两相/连续访问/未对齐拒绝、首末地址、相邻字隔离、同步延迟 1/2 拍、
  tlast 与上下文、TEX/DDR 混合及预取同时请求、两种复位排空；所有用例独立比对。
  装载 CRC 错必须拒绝登记；无效槽与越界必须得到准确错误三元组；变异须红在对应判据。
- 既有 `sim/engine/{geom,ctrl,frame,mover,pix}` 回归不红；PERF 对实际 DDR 总线计数。
- 单独与整机综合均登记资源及 WNS/WHS；四 bank 基准 16 块，变更组织须重新核实。
  单独工程 hold 与整机历史 +0.026 ns 分别比较，单独综合不能替代整机收敛。
- 板上：
  1. 同一命令表软硬后缓冲 CRC 一致（TEX 源，覆盖色键与方程 1/5）；
  2. 同一轮、同一负载测 DDR 与 TEX；PERF_BUSY/16 为口径，16×16 ALPHA 每颗
     周期 ≤750（保留原门槛；研究仿真不足以保证板上可达），同时证明源 DDR 事务消失；
  3. `N_max` 16×16 按口径重测并登记台账（模型预期 ~1,500～1,700，作参考不作门槛）。
- 游戏 HW/TEX、HW/DDR、SW 后端能切换且 CRC 一致，热集仅启动/重载时上传，
  不把每帧上传藏在引擎计时之外；8×8 做旧口径对照，但未新增硬门槛。
- spec 第 02 章在实现时增加 v1-TEX 能力 profile；32 字节命令版本不改，
  v2 实例列表归 G3。证据归档 TechReports engine 第 07 章。

## 6 风险

- hold 余量 +0.026 ns：TEX 读路径加级后盯 WNS/WHS，必要时加流水级重收敛。
- APB 32 位写与 128 位读的组织会改变 RAM 块数；13 块估算已被四 bank 实验修正。
- 同步延迟加 1 拍实测使每颗多 16 周期。原约 660 周期简单相减过于乐观，
  ≤750 板上门槛仍有风险，正式实现以描述符收尾与整机争用实测定位。
- 无装载互锁依赖驱动独占与错误登记；busy 中装载必须由 API 拒绝。
