## 1 要解决什么

**现在是什么样。** HDMI 通路与 SoC、DDR3 没有任何数据交互（`../../../Main/rtl/top/gfx2d_top.v` 文件头第 28 行）。
画面来自 `hdmi_tx` 内部厂商模块 `color_bar_rgb` 的八色竖条，时钟是 `hdmi_tx_slow_clk`
（25.2MHz，PLL_BL0，来自 27MHz 晶振）。Axi_Mux 的 S0 口已经留给扫描输出，
目前接的是 E5 用的替身 `rtl/bus/scanout_stub.v`：它按行节拍发 160 拍的读并记录延迟，但读回的数据直接丢掉，不出像素。

**不做会怎样。**

1. 赛题基础要求 1 与 3（「HDMI 输出至少 640×480@60」「双缓冲防撕裂」）在板上没有落点，
   CPU 和引擎画进帧缓冲的东西看不见。
2. E5 的 2.4 节无法做。替身只能给出总线延迟的上界，真实 FIFO 的最低水位
   取决于扫描输出自己的取数节奏，这一条 E5 已写明只能等扫描输出存在。
3. 引擎开工后只能靠串口和 CRC 判断对错。CRC 能说明对不对，说明不了错在哪里；
   一幅错位或颜色反了的画面，一眼就能看出错在哪一层。

**已经定下、本工作点必须遵守的约束**（出处都已验收，不在本条重新讨论）：

| 约束 | 值 | 出处 |
| --- | --- | --- |
| 总线端口 | Axi_Mux S0，只读，写通道不发起 | E5 2.1 节，platform 第 06 章 |
| 在途事务 | 最多一笔：上一笔 `rlast` 握手之前不拉高下一笔 `arvalid` | E5 2.2 节措施一；放宽要重做 E5 全套判据 |
| 帧缓冲 | 帧缓冲 0 `0x0200_0000`，帧缓冲 1 `0x0240_0000`，行跨 4096 字节 | 设计文档 2.1 节 |
| 像素格式 | XRGB8888，像素字 `0x00RRGGBB`，小端；一个 128 位拍 4 个像素，拍内偏移 0 是最左的像素 | 设计文档 3.5 节第 7 条，spec 第 01 章 |
| 一行一笔 | 640 像素 = 160 拍，`arlen = 159`，每行正好在一个 4KB 页里，不跨界 | 设计文档 2.1 节 |
| 视频时序 | 640×480@60，H 16/96/48、V 10/2/33，同步低有效，一行 800 个像素时钟、一场 525 行 | `rtl/hdmi/hdmi_tx.v` 参数 |
| FIFO 预算 | 128 位 × 512 深（约 3 行），7 块片上 RAM | 设计文档 2.3 节 |
| 厂商文件 | `rtl/hdmi/` 下三个官方文件不改，拆像素与对齐之类的适配放扫描输出一侧 | 设计文档 3.5 节 |
| 时序余量 | `core_clk` 的 hold 余量只有 0.026 ns | platform 第 06 章 5.1 节，Todo README 搭车规则第 1 条 |

**在途一笔够不够，用 E5 的板上数算一遍。** 这一条约束是本工作点最容易被怀疑的地方，
所以把账摊开写在这里，以后不必重新推：

| 量 | 值 | 出处 |
| --- | --- | --- |
| 行周期 | 3175 个 `core_clk` 周期（31.75 微秒） | 视频时序 |
| 一笔 160 拍读的最坏整笔时间 | 236 个周期 | E5 板上实测 `MAX_FULL_TXN`（E5 2.3 节） |
| 总线占用率 | 7.4% | 236 / 3175 |
| 像素侧消耗速率 | 1 拍 / 15.9 个周期 | 160 拍摊进可见期 25.4 微秒 |
| 供给与消耗之比 | 10.8 倍 | 1.48 对 15.9 |

在途一笔不是勉强够用，是富余十倍。**本工作点的风险不在带宽，在跨域与每场清空的正确性**（D7）
与像素侧的对齐（2.2 节）。

**两个时钟没有同源关系。** `core_clk` 来自 25MHz 晶振（PLL_TL0），像素时钟来自 27MHz 晶振（PLL_BL0），
两者的频率比不是整数、相位也不固定，这是整个工程**第一个真正有数据穿过的跨时钟域**。
`sdc/gfx2d_ti60.sdc` 里 `core_clk` 自成一组 `-exclusive`，像素时钟一组 `-asynchronous`，
所以跨域路径在 STA 里是被切掉的：**同步器写错了，时序报告不会报任何东西**。
跨域的正确性只能靠结构审查加仿真判据，这一点决定了第 3 节判据的写法。

## 2 怎么切分

### 2.1 开工前要确认的十项取舍（D1~D10，全部已确认）

每一项给出建议与理由，确认之后写进本节，再开工。
D1~D6 是 2026-09-19 写 spec 时列的，D7~D9 是 2026-09-20 对着 RTL 与 E5 实测数据复核时补的，
D10 是同日前研究时补的（建议已给、待定案；它不挡前三个 RTL 文件）。

**D1 寄存器放在哪个 APB 页。**
建议：接管扫描替身的 `0xF810_E000~0xF810_EFFF` 页，`scanout_stub` 从顶层撤下（源文件留在 `rtl/bus/`，
仿真 `sim/axi_mux_guard/` 仍用它当 S0 替身）。替身的量测寄存器（首拍、整笔、拍间隙三项最大值与直方图）
原样搬进新模块，偏移不变，这样 E5 2.3 节的板上程序只改 ID 判断就能继续用。
另一个选择是另开一页（如 `0xD000`），好处是替身与真模块可以并存，代价是 S0 只有一个口，并存也只能二选一接入。

两点必须写进定稿：

- 替身的 `0x00C BASE`、`0x010 LINE_PERIOD`、`0x014 FIELD_LINES` 在新模块里没有意义，
  这三个洞正好给 `FRONT_BASE`、`BACK_BASE`、`SWAP_REQ`，其余量测寄存器的偏移保持不动。
- **和替身时代的数据只有上界可比，直方图的分布不可比。** D3 把取数从行节拍改成按水位，
  场起始会连发三笔把 FIFO 灌满，连发时第二、三笔的首拍等待里含排队时间。
  `MAX_FIRST_WAIT`、`MAX_FULL_TXN` 仍是同一个意义的上界，分桶计数则是另一种负载下的形状。
  同理，E5 2.4 节的数据必须用真模块重新量，替身时代的只能当对照。

**结论（2026-09-20 定案）：接管 `0xF810_E000` 页，上面两点照办。**
`scanout_stub.v` 留在 `rtl/bus/` 不删，`sim/axi_mux_guard/` 继续拿它当 S0 替身；
顶层撤下替身的同时，`ddrBurstProbe`、guard 板上程序里对 S0 的 ID 判断一并改。

**D2 `FRONT` / `SWAP_REQ` 归谁。**
设计文档 3.4 节把它们放在引擎寄存器（`0xF810_0000` 页的 `0x030`、`0x034`），
可引擎还不存在，而切换本身发生在扫描输出里。
建议：扫描输出自己的页里设 `FRONT_BASE`（当前在扫的帧缓冲基址，只读）、`BACK_BASE`（读写）与 `SWAP_REQ`；
引擎接入时，引擎页的 `FRONT`/`SWAP_REQ` 做成转发到这里的别名，或者设计文档 3.4 节改为指向扫描输出页，二选一在引擎工作点定。
软件侧 `sw/bsp/ti60/` 的 `board_present` 只认一个接口，SW9 按这里的寄存器写。
用基址而不是表面号：表面表属于引擎，扫描输出不应该依赖它。

**结论（2026-09-20 定案）：三个寄存器放扫描输出自己的页，用基址不用表面号。**
引擎页的 `FRONT`/`SWAP_REQ` 是做别名转发还是改设计文档 3.4 节，留到引擎工作点定，
本工作点只需保证扫描输出这一侧是唯一真源；SW9 的驱动按本页的寄存器写。

**D3 取数策略：按水位取，不按行节拍取。**
替身按固定行周期发读，真扫描输出不应该这样做。
建议：取数侧（`core_clk`）只看 FIFO 空位：**空位不少于 160 拍、且没有在途读、且本场还有行没取**，就发下一行的读。
场开始时从第 0 行重新取，FIFO 深 512 拍时自然会预取约 3 行。
这样做预取深度由 FIFO 深度决定，不需要知道行时序；一次延迟尖峰只会吃掉水位、不会丢行；
E5 2.4 节「最低水位不低于一行」这条判据的前提（至少提前一行预取）也自动满足。

两条跟着这个选择走的结论，写在这里免得以后当成 bug：

- **总线上的形态从均匀变成突发。** 阈值 160、深度 512，稳态水位在 337~512 之间摆动，
  场起始会连发三笔。对扫描输出自己无害（它有 FIFO），但引擎和 CPU 看到的延迟尖峰会比替身时代密，
  这正是 E5 2.4 节要重新量的原因。若实测发现对 S1、S2 干扰过大，再加一个 `PREFETCH_MAX` 限制连发笔数，本工作点先不加。
- **深度与阈值是一对，以后砍 RAM 必须一起改。** 物理上真正需要的缓冲只有「一笔事务期间消耗掉的量」，
  按上面的账是约 15 拍加阻塞余量；512 深是「空位不少于一行才发读」这条策略推出来的，不是带宽推出来的。
  所以第 3 节「最低水位不低于 160 拍」量的是策略有没有按设计走，不是风险边界。
  真要省 RAM，得同时把一笔改成半行（80 拍）、深度改 256、判据改 80，三样一起动。

**结论（2026-09-20 定案）：按水位取数，阈值 160 拍、深度 512、在途仍不超过一笔，`PREFETCH_MAX` 本工作点不加。**
注意阈值 160 的含义要按 D4 选定的 FIFO 实际水位语义换算（含不含在途、滞后几拍），不要照字面写。
**换算已于 2026-09-20 做完，发行式与判据式写在第 4 节同名条目的结论 3，落地值见 2.2 节的「FIFO 语义」表：**
两个水位都不含在途；写侧用来算空位（偏高，保守），读侧用来量最低水位（偏低，是下界）。

**D4 异步 FIFO 用仓里已有的厂商源码，手写作退路。**
原先的建议是手写，理由是「IP 生成物要登记要恢复、iverilog 跑不了厂商模型、水位要掏内部状态」。
2026-09-20 复核发现这三条理由都不成立：仓里已经有一个现成的异步 FIFO 源码，
`../../../Main/rtl/vendor/ddr3_controller/common/efx_fifo_v2.3/efx_fifo_wrapper.v`，
1376 行明文 Verilog（不是加密块），已经列在 `fpga/gfx2d_ti60/gfx2d_ti60.xml` 第 27 行的设计文件里，
它的参数正好覆盖本工作点的需求：

| 需求 | 该模块对应的参数或端口 |
| --- | --- |
| 跨时钟域 | `SYNC_CLK = 0`，`wr_clk_i` 与 `rd_clk_i` 分开 |
| 128 位 512 深 | `DATA_WIDTH = 128`、`DEPTH = 512` |
| 推断片上 RAM | `FAMILY = "TITANIUM"`、`RAM_STYLE = "block_ram"` |
| 两侧水位 | `wr_datacount_o`、`rd_datacount_o`，D3 的阈值与水位判据直接用 |
| 跨域复位 | `rst_busy` 与 `a_rst_i`（**订正：`a_wr_rst_i`/`a_rd_rst_i` 在 wrapper 里没接到 FIFO**，见下） |
| 结构 | 内部就是格雷码指针加 `bin2gray`/`gray2bin`，同步器带 `async_reg`，`SYNC_STAGE = 2` |

不用跑 IP 生成器（文件已在库里，不产生新的生成物），iverilog 直接能编（纯 RTL，无厂商原语），
水位是现成端口。代价换成了另一样：`datacount_o` 的精确语义（是否含在途、延迟几拍）与 `rst_busy`
期间的行为要自己读代码确认，并在 `sim/display/` 里用判据钉死。

建议：**先按厂商源码接，手写留作退路**。若它的复位或水位语义不满足 D7，再回到手写，
第 3 节为手写准备的同步器结构判据原样保留。两条路都要过「片上 RAM 增量与预算对账」这一条。
不建议照抄同目录的 `simple_dual_port_ram.v`：它是异步读写法，容易被推成 LUT RAM 而不是片上 RAM 块。

**结论（2026-09-20 定案）：按建议办，先接厂商源码，手写作退路。**
开工第一件事是读 `efx_fifo_wrapper.v` 并在 `sim/display/` 里用判据钉死两件事：
`wr_datacount_o` / `rd_datacount_o` 的精确语义（含不含在途、滞后几拍，D3 的阈值按它的实际含义取），
以及 `a_wr_rst_i` / `a_rd_rst_i` / `rst_busy` 在 D7 那六步里的行为。
这两件事不清楚之前不往下写 `display_fetch`。退回手写的触发条件只有两个：
水位或复位语义满足不了 D7，或者综合后没有推断成片上 RAM 块。
从零写异步 FIFO 的教学价值另行安排，不占赛期的关键路径。

> **订正（2026-09-20，探针实测推翻）**：这两件事已在第 4 节 2026-09-20 条里做完，结论与本节假设不同：
> 上面「跨域复位」一行里的 `a_wr_rst_i`/`a_rd_rst_i` **在 wrapper 里根本没有接到 FIFO**（端子悬空），
> 两侧复位由 `a_rst_i` 一处给，`rst_busy` 就是「两个域都退出复位」的回执；
> 复位窗口里 FIFO **不拦写**，`we=0` 必须由主机保证。
> 水位语义与滞后拍数、`FRAME_BEATS` 与像素侧对齐的定值也在那一条里。手写退路**没有启用**。

**D5 场同步中断接不接。**
建议：接到 SoC 的 `userInterruptA`（现在接常量 0，中断号 16，`USER_0_INTR` 已开），但复位后 `IRQ_EN = 0`。
中断线的总分配（0 扫描输出、1 引擎、2 摄像头）由 SoC IP 定型定下（[platform 第 07 章](../../TechReports/platform/07-SoC-IP定型与工具链升级.md) 3.1 节，中断号 16/17/22），它已于 2026-09-19 验收。
这是一条电平中断：使能之后软件若不写清除位，CPU 会一直进中断出不来，整机看起来就是死机。
所以本工作点的上板程序先用轮询 `FRAME_COUNT` 验证，中断作为单独一个用例：
先写好清除中断的处理函数再打开 `IRQ_EN`，并用一次「故意不清除」确认现象符合预期。

**结论（2026-09-20 定案）：接 `userInterruptA`，复位后 `IRQ_EN = 0`，上板先轮询后中断。**
「先写清除函数、再开使能」这条顺序不是建议而是纪律，电平中断少了它整机挂死。

**D6 保留彩条作回退与对照。**
建议：`CTRL.SRC` 一位选择画面来源，0 为现在的彩条、1 为帧缓冲，复位值 0。
好处是上电画面不依赖软件，显示器、线和 TMDS 通路出问题时能和扫描输出的问题分开；
帧缓冲模式画面异常时，切回彩条就能判断是不是扫描输出的锅。
彩条模块本身继续当视频时序发生器用（它的 `hs`、`vs`、`de` 已上板验证过），
像素数据在它后面替换，`de`、`hs`、`vs` 按 FIFO 读出的延迟对齐（对齐的具体拍数见 2.2 节）。

**`EN` 与 `SRC` 是正交的两位。** `EN` 管取不取数，`SRC` 管画面来源。
`EN = 1`、`SRC = 0`（照常取数但屏幕出彩条）是有效组合，用来只量总线不上屏；
`EN = 0`、`SRC = 1` 则是黑屏加欠载计数，属于误用但硬件不禁止。
不写这一句，实现时很容易被做成「`SRC = 0` 就不取数」。

**结论（2026-09-20 定案）：保留彩条，`CTRL.SRC` 复位值 0，`EN` 与 `SRC` 正交。**
彩条继续充当视频时序发生器，上电画面不依赖软件，是排查显示器与 TMDS 通路时的对照组。

**D7 每场清空 FIFO 的完整协议。**
这是本工作点唯一的正确性坑，2.2 节「欠载自愈」那一句展开后有三件事必须定死：

1. **先排空在途读，再复位写指针。** 场起始时若有一笔读还没 `rlast`，直接复位写指针，
   剩下的拍会落进新场 FIFO 的头部，画面整屏横向错位若干个像素组——而这个错位是自愈机制自己造成的。
   时间上完全容得下：消隐有 45 行约 1.43 毫秒，排空最坏 236 个周期即 2.36 微秒。
2. **两侧复位要握手，不能各复位各的。** 场起始事件在像素侧产生、取数侧靠 toggle 同步收到，
   两侧看到「清」的时刻差若干拍，裸复位两个格雷码指针是典型的异步 FIFO 复位竞争。
   用厂商 FIFO（D4）时用 `a_rst_i` 一处给，厂商在两侧各有一套同步器，`rst_busy`
   就是「两个域都退出复位」的回执；手写则要自己补一次 toggle/ack。
   （**订正 2026-09-20**：原文这里写的是 `a_wr_rst_i`、`a_rd_rst_i` 与 `rst_busy` 这一组，
   探针实测证明那两个端子没有接进 FIFO，见第 4 节 2026-09-20 条与 2.2 节的 FIFO 语义表。）
3. **是每场都清，还是只在欠载后清。** 正常场取 480 行、弹 480 行，场末水位本来就是预取状态，
   清空只为欠载准备。建议**仍每场都清**：状态少，不依赖「这一场是正常的」这个前提。

顺序定为：场起始 → 停发新读 → 等 `rlast` 并丢弃该笔数据 → 两侧复位握手 → 锁存本场基址 → 开始预取。

**结论（2026-09-20 定案）：每场都清，按上面六步的固定顺序，三条全部照建议办。**
理由记在这里：正常场与欠载场走同一条路径，这条路径每秒执行 60 次，
不存在「平时不走、真出事那天第一次运行」的清空代码。
六步中的第二步（等 `rlast` 并丢弃）是本工作点最容易漏、漏了最难查的一步，
2.3 节的注错 `inj_no_drain` 就是专门盯它的。

**D8 加不加「多了几拍」的判据寄存器。**
现有的 `FIFO_ZERO_HITS`、`FIFO_UNDERFLOW_BEATS` 只能抓「少了」，抓不到「多了」，
而 D7 那个坑的症状恰恰是多了几拍：画面错位，但所有计数器都是 0，板上无从判断错在哪一层。
建议加两个只读寄存器：`FRAME_BEATS`（本场有效显示区弹出的拍数，应恒为 76800）、
`SNAP_END_LEVEL`（场末残留水位，正常恒为 0，理由见 2.2 节寄存器表）。成本是两个计数器，
收益是把「错位」从肉眼猜变成读一个数。

**结论（2026-09-20 定案）：加。** 两个寄存器已写进 2.2 节的寄存器表，
仿真判据在 2.3 节 `image` 一行，板上判据在第 3 节「拍数」一行。

**D9 哪些寄存器在场起始生效。**
`SWAP_REQ` 已定为场起始生效，但 `SRC`、`EN`、`BACK_BASE` 没说，中途改 `SRC` 就是一个撕裂帧。
建议一句话统一：**所有影响画面的寄存器都在场起始锁存生效，与 `SWAP_REQ` 同一拍**；
`CLEAR` 与 `IRQ_EN`、`IRQ_STAT` 不影响画面，立即生效。
不写死，实现时会一个寄存器一个样。

**结论（2026-09-20 定案）：统一在场起始生效。**
对软件只有一条规则：**写完等一场就生效**，SW9 的驱动按这一条写，不必逐个寄存器记。
读回时 `FRONT_BASE` 反映的是已经生效的那一场，可以用它确认生效与否。

**D10 视频侧怎么组合（前期研究新增，2026-09-20）。**
现状与冲突：`hdmi_tx` 是密封的——`color_bar_rgb`、`dvi_encoder`、P/N 取反与 `pll_locked` 复位同步
都在它里面，顶层没有把像素送进编码器的入口。本节 2.2 的文件表说 `display_top`「对顶层只露 TMDS」，
而 `Main/rtl/README.md` 说「编码器与 `hdmi_tx` 的对外接口不动」，两句话不能同时按字面成立，必须选一个。

建议 **A′：`hdmi_tx` 一行不改，作为独立的彩条通路留着；`display_top` 自带一个 `color_bar_rgb`
（只当视频时序发生器）、延迟与像素选择、`dvi_encoder` 与 P/N 取反，输出 TMDS；顶层把 `hdmi_tx` 的
TMDS 送进 `display_top`，由它按 `CTRL.SRC`（场起始锁存、在像素域重新打拍）做 2:1 选择后驱动 LVDS TX。**
代价已实测（`outflow/gfx2d_ti60.hier_util.rpt`）：`u_hdmi_tx` 整模块 318 XLR，其中 `u_color_bar` 89.5、
`u_dvi_encoder` 213.5；再加 40 位 2:1 选择约 0.6%，顶层当前 21653 / 60780 = 35.6%，余量足够。
好处：已验证的 TMDS 侧一个字符都不动，`sim/hdmi` 继续有效且仍在网表里；D6 的彩条对照是**真正独立**的
第二条通路（不共用编码器，出问题时能把「扫描输出的锅」和「TMDS 通路的锅」分开）；顶层端口不变，
`peri.xml` 不用改。

备选 **B**：给 `hdmi_tx` 加 `ext_rgb`/`ext_de`/`ext_hs`/`ext_vs`/`ext_sel` 五个端口，编码器共用，
省掉重复的 318 XLR；代价是改一个已上板验证过的模块、`sim/hdmi` 的测试台要跟着改，
彩条与帧缓冲两条通路共用编码器，对照不再是独立的。
不取 **C**（`hdmi_tx` 退休、`display_top` 独占 TMDS）：已验证的 TMDS 侧代码变成死代码，`sim/hdmi` 失去对象。

**影响面：D10 只决定 `display_top.v` 与顶层例化的最后一步。`display_fifo.v`、`display_fetch.v`、
`display_out.v` 三个文件与它无关，可以先生效。**

**结论（2026-09-20 复核后确认）：取 B′——把 `color_bar_rgb` 从 `hdmi_tx` 里搬到 `display_out`，
`hdmi_tx` 变成纯编码封装。** 不取 A′，也不取原样的 B。三条理由：

1. **A′ 会造出第二个视频时序发生器，而「场」是全设计的同步基准。** 场起始驱动取数、切换、中断、
   帧快照与 `FRAME_COUNT`。A′ 里 `display_out` 自带一个彩条当时序发生器，而 `SRC = 0` 时屏幕上的画面
   由 `hdmi_tx` 里另一个彩条驱动：两份同样的状态机在同一个时钟下当然会同步，但「本场是第几场」
   从此有两个真源。这与仓库一贯的单一真源做法相反，也让「彩条模式下 `FRAME_COUNT` 指的是哪一场」
   变成一个需要解释的问题。
2. **共用编码器的对照其实更强，不是更弱。** A′ 的理由是「不共用编码器才能把扫描输出的锅和 TMDS 的锅分开」，
   但真实的诊断场景是「彩条正常、帧缓冲花屏」：共用编码器时两条通路的唯一差别就是像素来源，
   锅 100% 在取数侧；各用一个编码器时，差别里多了一份编码器副本、一个时序发生器和一个 40 位选择，
   能排除的东西反而少了。另一种场景「两种模式都黑屏」在两个方案下诊断力相同。
3. **B′ 要写的代码比 A′ 少，而且不碰官方文件。** `rtl/README.md` 的表写明 `hdmi/` 是
   「封装可改，官方文件不改」，`hdmi_tx.v` 是本项目写的封装，三个官方文件（`color_bar_rgb`、
   `dvi_encoder`、`encode`）一个字节都不动，MD5 仍然对得上。A′ 则要在 `display_top` 里重新例化
   编码器与 P/N 取反（`assign tmds_* = ~enc_*`，板上 P/N 对调那一步最容易抄错），并重复 318 XLR。

B′ 的具体改法：

| 文件 | 改什么 |
| --- | --- |
| `rtl/hdmi/hdmi_tx.v` | 删掉 `u_color_bar` 例化；新增输入 `vid_rgb[23:0]`、`vid_hs`、`vid_vs`、`vid_de`，新增输出 `vid_rst_n`（现有 `rst_sync` 的结果，给像素侧共用一个复位源）。其余（`dvi_encoder` 例化、P/N 取反、参数表）一行不动 |

新建 `rtl/display/`。三个官方文件（`color_bar_rgb.v`、`dvi_encoder.v`、`encode.v`）一个字节不动；
按 D10 取 B′，本项目写的封装 `hdmi_tx.v` 改成纯编码封装（删掉彩条例化、加像素输入与复位输出）：

几处必须写清楚的行为：

- **切换时机。** 取数侧在「场起始」事件（像素侧场同步经 toggle 同步过来）锁存本场的基址：
  若 `SWAP_REQ` 已置位，就把 `BACK_BASE` 变成本场基址并清 `SWAP_REQ`，`SWAP_COUNT` 加一。
  一场的 480 行都从同一个基址取，所以不会撕裂。「场起始」必须早于本场第一行开始取数，
  取在场消隐开始、预取之前。
- **欠载自愈。** 有效显示区里 FIFO 读空时输出黑色并计数，不能停住等数据；
  场同步时按 D7 的六步清空 FIFO，下一场从第 0 行重新取。
  这样一次欠载最多坏一场，不会让之后的每一行都错位
  （**坏一场的具体形态**：漏弹一拍之后，本场余下的行都会比显示晚一个像素组，
  由下一场的第 0 行与下一场清空复位，这一点在 `starve` 用例里要写清楚）。
  **清空本身是有顺序的**：必须先等在途那笔读的 `rlast`、丢掉它的数据，再复位两侧指针，
  否则残留的拍会进入新场的队头，错位由自愈动作亲手造成。
  2026-09-20 的实测给这一步加四条落地约定：清空由取数侧（`core_clk`）执行；
  执行期间 `wr_en=0`，**FIFO 自己不会拦**（复位窗口里 `full_o` 为 0、`wr_en_int = we & ~wr_full` 仍为 1，
  写进去的字会盖掉 `ram[0]` 而指针钉在 0——这一条由源码判定，探针只能证明它不被计入水位）；
  复位保持至少 2 个 `core_clk` 周期；
  **`rst_busy` 不能在 `core_clk` 里直接判**——它是 `wr_rst_int | rd_rst_int` 的组合，
  其中 `rd_rst_int` 是像素域的寄存器，直接采样就是一条没有同步器的跨域路径，而 SDC 又把它切掉了、STA 不会报。
  做法：把 `rst_busy` 在 `core_clk` 里过两级同步器，判到它连续为低再等 4 拍，才恢复写入；
  实测最坏撤销延迟是 +100 ns（rd 域，T10），约 10 个 `core_clk` 周期，消隐期 1.43 毫秒绰绰有余。
  排空等在途 `rlast` **不带超时**：从机挂死时这一场会坏，但那种条件下整条 DDR 通路本来也不可用。

- **像素侧的对齐写死到拍（2026-09-20 定值）。** 彩条模块的 `de` 与 `o_vid_data` 是同拍的寄存器输出，
  但它的 `h_cnt`、`v_cnt` 是状态机计数器、每进一个状态清零、比 `de` 早一拍，
  **不能拿 `v_cnt` 当行号用**（行号用像素侧自己的行计数器：`de` 上升沿加一，场起始归零）。
  又因为 `de` 是寄存器输出、看不到未来，对齐只能往后做。定值如下：

  - **延迟 `D = 1`**：FIFO 的 `OUTPUT_REG = 0`，实测读延迟恰为 1 个 rd 周期（`rd_en` 在沿 N 采样且
    `empty=0`，`rdata` 与 `rd_valid_o` 在沿 N+1 有效）。像素输出**不加自己的寄存级**，
    `rgb = mux(rdata, psel_d1)` 组合给出；`dvi_encoder` 的输入本来就是寄存的，25.2MHz 下够。
  - `psel`（0~3）只在 `de0 = 1` 时计数，`de0` 为低时冻结；`psel_d1` 是 `psel` 延迟一拍。
  - **`rd_en = de0 & (psel == 2'd0) & ~empty`：在每组的第一个像素周期弹这一组要用的那拍。**
    数据在下一拍（也就是延迟后的 `de` 的第一个像素周期）到达，与 `psel_d1 = 0` 同时。
    每行恰好 160 次弹出，每场恰好 76800 拍，与从机供给的拍数一样多，**既不用预弹、也不用在最后一行末组压掉一次**
    （这两样都试过：`psel == 3` 的相位要预弹第一拍，而且最后一行末组会多弹一拍，
    76801 次弹出对 76800 拍供给，末尾必然假欠载一次）。
  - `hs1/vs1/de1 = hs0/vs0/de0 延迟一拍`，输出像素与它们同拍；`de1` 为低时输出黑色。
    空读（`empty`）时不出数、输出黑色并计 `FIFO_UNDERFLOW_BEATS`（每拍 4 个像素）。
  - 时序参数（`H_ACTIVE`/`V_ACTIVE` 等）要能从测试台覆盖：3 场逐像素仿真若按 640×480 跑是
    15.2ms/场，缩到几行才跑得动。
  - 位段：一拍的 `[31:0]` 与 `[63:32]`… 依次是第 0~3 个像素，像素内 `[23:16]` R、`[15:8]` G、`[7:0]` B，
    拆像素只按低位在前翻 `psel`，不交换字节。
- **跨域的多位量一律不直接同步。** 帧号、本场最低水位与欠载计数在像素侧场同步时锁存成一组，
  用 toggle/ack 握手送回 `core_clk`，接收侧确认之前源侧保持不变（E5 2.4 节已规定这种做法）。
  跨域的单个脉冲一律用 toggle 加两级同步，不用电平直接打拍。
- **字节顺序：不需要重排，这一条已经判定。** 推导是闭合的：内存里像素字为 `0x00RRGGBB`，
  小端下字节 0 是 B、1 是 G、2 是 R；AXI 的字节通道同样是小端，所以一拍的 `[31:0]` 就是这个字，
  `[23:16]` 是 R、`[15:8]` 是 G、`[7:0]` 是 B。而 `rtl/hdmi/hdmi_tx.v` 里
  `blue_din = vid_rgb[7:0]`、`green_din = vid_rgb[15:8]`、红取 `[23:16]`。两边位段完全同序。
  所以只需要把拍内的 4 个像素按低位在前的顺序拆开，不做任何字节交换。
  设计文档 3.5 节「扫描输出在接帧缓冲时要按本表做一次字节重排」是错的，
  错因是把「内存里的字节位置」与「字内的位段」当成了一回事——字节表本身没错，由它推出要重排是错的。
  第 3 节的上板图案判据不再是用来裁决这个推导，而是去验证 DDR3 控制器与 upsizer 没有额外搅动字节通道；
  结论已于 2026-09-20 回写设计文档 3.5 节第 7 条与 TechReports 的 spec 第 01 章 3.7 节，两处副本都已订正。

寄存器表（D1、D2、D8、D9 按建议确认的前提下，**偏移 2026-09-20 定稿**）。
APB 窗口 `0xF810_E000~0xF810_EFFF`，表内偏移即窗口内偏移（12 位）。
除下面这些外的偏移读回 0 并置 `PSLVERROR`；写只允许写到 `CTRL`、`BACK_BASE`、`SWAP_REQ`、`IRQ_EN`、`IRQ_STAT`，
写别处置 `PSLVERROR` 且不改状态。
**一个例外：`FRONT_BASE`（`0x00C`）的写做成「忽略且不报错」。** 替身时代它是可写的 `BASE`，
`ddrBurstProbe` 会往这里写；报 `PSLVERROR` 有触发 SoC 总线异常的风险，而那个位对程序没有用，
所以按「静默忽略」处理，让老程序不必改这一句。其余只读寄存器的非法写照常报错。
按 D9，`EN`、`SRC`、`BACK_BASE`、`SWAP_REQ` 写进去之后在下一个场起始才生效，
`CLEAR`、`IRQ_EN`、`IRQ_STAT` 立即生效：

| 偏移 | 名称 | 读写 | 复位值 | 内容 |
| --- | --- | --- | --- | --- |
| `0x000` | `ID` | 只读 | `32'h4449_5350`（"DISP"） | 替身是 `"SCAN"`，判据要改 |
| `0x004` | `VERSION` | 只读 | 1 | |
| `0x008` | `CTRL` | 读写 | 0 | bit0 `EN`（开始取数），bit1 `SRC`（0 彩条、1 帧缓冲），bit2 `CLEAR`（**清两侧统计**：core 侧直接清，像素侧的 `FIFO_ZERO_HITS`/`FIFO_UNDERFLOW_BEATS` 靠 toggle 送过去清，2026-09-21 上板补）。替身的 bit1 是 `CLEAR`，新表的 `CLEAR` 挪到 bit2 |
| `0x00C` | `FRONT_BASE` | 只读 | `0x0200_0000` | 本场在扫的基址（替身的 `BASE`，只读化了，复位值不变） |
| `0x010` | `BACK_BASE` | 读写 | `0x0240_0000` | 下一次切换的目标（替身的 `LINE_PERIOD`） |
| `0x014` | `SWAP_REQ` | 读写 | 0 | 写 1 请求在下一个场起始切换，切换完成后硬件清零（替身的 `FIELD_LINES`） |
| `0x018` | `MAX_FIRST_WAIT` | 只读 | 0 | 与替身同义 |
| `0x01C` | `MAX_FULL_TXN` | 只读 | 0 | 同上 |
| `0x020` | `MAX_R_GAP` | 只读 | 0 | 同上 |
| `0x024` | `TXN_COUNT` | 只读 | 0 | 完成的读事务数 |
| `0x028` | `LINE_COUNT` | 只读 | 0 | 场内行序号 0~479 |
| `0x02C` | `R_BEAT_COUNT` | 只读 | 0 | 收到的 R 拍数（含排空丢弃的） |
| `0x030` | `SKIP_COUNT` | 只读 | 0 | 保留偏移，按水位取数不「跳行」，恒读 0（`ddrBurstProbe` 的 `skip=0` 仍成立） |
| `0x034` | `RESPERR_COUNT` | 只读 | 0 | 非 OKAY 读响应计数 |
| `0x038` | `STATUS` | 只读 | 0 | bit0 `BUSY`（一笔在途）、bit1 `AR_PENDING`、bit2 `STARTED`（本场已开始取数） |
| `0x03C`~`0x068` | `HIST_FIRST[12]` | 只读 | 0 | 分桶同替身 |
| `0x06C`~`0x098` | `HIST_FULL[12]` | 只读 | 0 | 同上 |
| `0x09C`~`0x0C8` | `HIST_GAP[12]` | 只读 | 0 | 同上 |

| `0x0D4` | `IRQ_STAT` | 读写 | 0 | bit0 场起始；写 1 清除 |
| `0x0D8` | `FRAME_COUNT` | 只读 | 0 | 场计数（`core_clk` 域） |
| `0x0DC` | `SWAP_COUNT` | 只读 | 0 | 完成的切换次数 |

**FIFO 语义（2026-09-20 实测，D3/D4 的落地值）。** 探针源码与命令见第 4 节附录。

| 量 | 实测 | 对设计的影响 |
| --- | --- | --- |
| 读延迟 | `rd_en` 在沿 N 采样且 `empty=0` → `rdata`/`rd_valid_o` 在沿 N+1 有效 = **1 个 rd 周期** | 对齐取 `D=1`（上面「像素侧的对齐」） |
| 水位是否含在途 | **不含**，两个水位都是 RAM 里的指针差；`wr_datacount_o` 满值 512（10 位） | 「空位 ≥ 160」加上「在途 ≤ 160」才等于不溢出 |
| 写入 → `rd_datacount_o` | 写入拍之后第 3 个 rd 沿更新（本域监视器在第 4 个沿看到）；= 1 个 wr 周期 + 3 个 rd 周期 | 读侧水位**偏低**（写指针滞后） |
| 读出 → `wr_datacount_o` | 读出拍之后 1 个 rd 周期 + 3 个 wr 周期（实测 61 ns）；本域监视器最坏再晚 1 个 wr 沿 | 写侧水位**偏高**（读指针滞后）→ 「空位 ≥ 160」是保守判据，不会溢出；稳态偏高只有 1~2 拍 |
| `a_rst_i` | 撤销后 `rst_busy` 落下的时刻按事件分：上电长复位撤销 +65 ns（wr 域）/ +99 ns（rd 域）；10 ns 脉冲 +45 / +82 ns；40 ns 脉冲 +60 / +100 ns。**最坏 +100 ns，约 10 个 `core_clk` 周期**。三种情况都两域一起复位、水位归零、`empty=1`、收发正常 | 复位保持 ≥2 个 `core_clk` 周期；`rst_busy` 过两级同步器再判（它含像素域寄存器，见上面「欠载自愈」） |
| `BYPASS_RESET_SYNC` | 必须保持 0（默认）。置 1 时 `wr_rst_int`/`rd_rst_int` 会接到 wrapper 没有连线的 `a_wr_rst_i`/`a_rd_rst_i`，且 `rst_busy` 被写死为 0 | 例化时显式写 `BYPASS_RESET_SYNC(0)`，别用默认值碰运气 |
| `a_wr_rst_i`/`a_rd_rst_i` | **在 wrapper 里没有接到 FIFO**（两个端子常置 1，FIFO 照常收发 160 拍且顺序全对） | 不要照 spec 旧文去接它们；D7 的两侧复位由 `a_rst_i` 一处给 |
| 复位窗口里的写 | FIFO **不拦**：`wr_en_int = we & ~wr_full`，`full_o` 在复位期间为 0，写进去的字会盖掉 `ram[0]` 而指针钉在 0 | 必须由主机保证复位窗口 `we=0`；「等 `rlast` 再复位」这条纪律不能省 |
| 满/空标志 | 写满后继续写 → `overflow_o` 单拍脉冲；空时读 → `underflow_o` 单拍脉冲 | 计数时要排除复位窗口与消隐期 |
| 顺序 | 160 拍连写连读逐拍相同；复位后写 4 拍读 4 拍逐拍相同 | 没有额外重排 |

**`FRAME_BEATS` 定值 76800（= 480 行 × 160 拍）。** 相位取「每组第一个像素周期弹这一组的拍」之后，
每场弹出与从机供给一样多，不多不少。**抓 D7 那个坑的是 `SNAP_END_LEVEL`（比定值多出残留的拍数），不是拍数**：
残留的拍数会让场末水位偏离定值，而逐像素比对同时整幅横移。

### 2.3 仿真

新建 `sim/display/`，按 `sim/README.md` 的规则每个判据配一个注错。
从机用 `sim/axi_probe/axi_ram_model.v`（带随机反压，`hold_ar` 用来造 `starve` 的那个场），

确认结论不依赖某个固定的相位关系。`efx_fifo_wrapper.v` 是明文、不例化厂商原语，iverilog 直接能编

| 用例 | 做什么 | 判据 |
| --- | --- | --- |
| `fifo` | 只测 `rtl/display/display_fifo.v`：单拍写、单拍读、连写连读 160 拍、复位一次 | 读延迟 1 个 rd 周期；写入到读侧水位 = 1 wr + 3 rd 周期；读出到写侧水位最坏 1 rd + 3 wr 周期；复位后两侧归零且 `empty=1`；160 拍顺序逐拍相同。注错 `inj_no_reset`（不驱动 `a_rst_i`）时「复位后归零」一条必须 FAIL |

| `level` | 正常反压 | 预装完成后每场最低水位不低于 160 拍，`FIFO_ZERO_HITS` 与 `FIFO_UNDERFLOW_BEATS` 为 0 |

**一条工具教训（2026-09-20 踩到）：** 用整数变量做 128 位数据的位选（`i[127:0]`，`i` 是 `integer`）
在 iverilog 里取到的是 `x`，而 `x !== x` 为真，逐拍比对会**静默通过**——探针第一次跑就因此
报出假的 `order_err=0`。数据图案一律用 128 位寄存器自增，不要用整数位选。

### 2.4 编译与时序

单独一次编译，不和别的网表改动搭车（搭车规则第 1 条）：

### 2.5 上板

新程序 `sw/apps/test/displayTest`，骨架照已有的 probe 程序，串口输出每项一行、末尾 `fail N` 与 `done`。

两条软件侧的前提：帧缓冲的 CPU 侧访问走 `sw/bsp/include/memmap.h` 的 `REGION_FB0`、`REGION_FB1`
与 `board.h` 里取帧缓冲指针的接口，不在程序里写裸地址；
**写方向不需要考虑缓存**（这颗 CPU 没有写缓冲，`dBus_Bridge_withoutWriteBuffer`，E3 已实测，
写返回时已落 DDR），只有读回帧缓冲做校验时才要先失效，按设计文档 2.1 节的三条约定做。

1. **上电画面。** 不跑程序时仍是彩条（`SRC` 复位值 0）。
2. **图案。** CPU 往帧缓冲 0 写一幅定位图案后切 `SRC = 1`：四角各一个不同颜色的方块、
   最左 4 列分别为纯红、纯绿、纯蓝、白、一条 1 像素宽的水平线与垂直线。
   用来判断字节顺序、拍内像素顺序、行跨与边界有没有差一。**这一条的判据是看屏幕**，
   同时读回寄存器，不能只靠肉眼。
3. **双缓冲。** 帧缓冲 1 写另一幅图，连续切换 600 次（10 秒），
   `SWAP_COUNT` 与写入的请求次数相等，`FRAME_COUNT` 每秒涨 60；
   屏幕上是两幅图交替，没有上下两半不一样的帧。
4. **CPU 写图的帧率。** 软件在后缓冲画一个移动的方块、每场切换一次，把帧率打到串口（里程碑 M1 的判据）。
5. **水位与欠载。** 帧缓冲模式下连续 120 场读快照，得出最低水位、中位值与最低值帧号；
   同时在探针主机（S1）满负载读、写各一轮下再做一遍。这就是 E5 的 2.4 节，数据同时记进 E5。
6. **中断。** 按 D5：先写好处理函数再使能，计 1 秒内的中断次数应为 60；再做一次「不清除」，确认现象与预期一致后关回。
7. **回归。** memTest、`ddrAliasTest`、`ddrBurstProbe`、E5 的 guard 板上程序全部 `fail 0`；
   后两个里对 S0 替身的假设要随 D1 一起改。

### 2026-09-21 软件层接上：board_present / board_wait_frame 与 displayTest

**`board_present(index)`**：把 `index` 那一面写进 `BACK_BASE`，置 `SWAP_REQ`，
**等切换真的发生再返回**——返回之后另一面已经不在扫描，调用方可以安全地画下一帧。
第一次调用时连同 `CLEAR` 一起打开 `EN | SRC`：core 复位不会复位像素域，

屏幕这一条是整条链路的端到端判据：内存里的 `0x00FF0000` 一路经 DDR3 控制器、upsizer、
异步 FIFO、拆像素、编码器、TMDS、线缆到显示器仍然是红的。2.2 节「不需要字节重排」
与对设计文档 3.5 节的订正到此有了板上证据，不再只是推导。

**双缓冲也验了。** 帧缓冲 1 灌成反序色带，写 `SWAP_REQ=1`：`SWAP_COUNT` 0 → 1、
`SWAP_REQ` 被硬件自清回 0、`FRONT_BASE` 从 `0x0200_0000` 变成 `0x0240_0000`，
屏幕变成 白、蓝、绿、红，**没有上下两半不一样的帧**。D2、D9 与「双缓冲」判据成立。

**缺陷一：欠载时每组的第 0 个像素不是黑色（`display_out.v`）。**
`missed` 取的是 `miss_d1[sel]`，比正确的 `miss_sh[sel]` 晚一拍。后三个像素照样对
（移位把标志铺满了），但第 0 个像素取到的是上一组移剩的 0，于是那一组的第一个像素
不黑化，输出的是 FIFO 上一拍的残留值。
判别性实验（临时测试台，不入库）：`rd_empty` 恒 1、`SRC=1`、`rd_data` 低 32 位填 `0x00AABBCC`，
有效区 928 个像素里有 232 个读出 `aabbcc`，**每 4 个像素一次**，正好是每组的第 0 个；
改回 `miss_sh[sel]` 之后 `nonblack=0`。
`starve` 用例测不出来：它只判「这一场有错、下一场全对」，从来没判过欠载时输出是不是黑的。
影响面只在欠载期间（判据本来要求欠载为 0），但规格写的是「空读时输出黑色」，实现没做到。

**缺陷二：场起始与发行同一拍时会绕过排空（`display_fetch.v`）。**
`case` 是用**旧的** `in_flight` / `ar_valid` 判断要不要进 `S_DRAIN` 的。若同一拍既
`fs_event` 又 `can_issue`，就会一边把 `ar_valid` 拉起、一边因为「当时既没有在途也没有挂起」
直接跳过 `S_DRAIN` 去复位 FIFO；那笔 AR 随后才被接走，它的拍落在 `S_RUN` 恢复之后，
进新场的队头——**正是 D7 要防的那件事，由清空动作自己造出来**。
触发要同时满足「本场还有行没取」与「恰好在 `fs_event` 那一拍空闲」，窗口只有一个 `core_clk` 周期，
但那正是欠载自愈的场景（正常场在场起始时取数侧早就取完了）。
修法：`can_issue` 加 `!fs_event`。
同时给测试台补了一条不变量判据——**复位 FIFO 的那一拍不能有在途读、也不能有挂起的 AR**，
它不依赖「恰好撞上」，`inj_no_drain` 现在也多红一条（2 → 3 个错）。

**缺陷三：`CTRL.CLEAR` 清不掉像素侧的累计值（上板才暴露）。**
双缓冲那一轮读到 `FIFO_ZERO_HITS=1`、`FIFO_UNDERFLOW_BEATS=77266`——约等于**一整场**。
根因是两个域的复位不对称：core 复位（每次 `reset halt`）不会复位像素域（它的复位来自 `pll_locked`），
于是像素侧的 `src_eff` 还留着上一次会话的 1，从 core 复位到下一个场起始之间一直在帧缓冲模式下
读空 FIFO，把整场的空读记进欠载计数。设计本身在一个场之内会自己纠正（`src_sel` 在 core 复位时为 0，
下一个场起始就锁存回 0），**真正的问题是软件清不掉**：`CLEAR` 原先只清 core 侧，
而像素侧的累计值只认像素域复位。判据要求这两个数恒为 0，那就永远判不过——
而标准上板流程每次加载程序前都要 `reset halt`。
寄存器表里 bit2 写的本来就是「清统计」，没写「只清 core 侧」，所以是实现收窄了规格。
修法：`display_fetch` 在写 `CLEAR` 时翻一个 `clear_toggle`，像素侧两级同步后边沿清零；
`starve` 用例补了对应判据（写 `CLEAR` 之后两个计数器必须读回 0）。

**另外补了一条与缺陷无关的复位纪律。** `lat_en`/`lat_src`/`lat_back`/`lat_swap` 原先没有复位值，
而上电那次 `S_RESET → S_WAIT` 发生在第一个 `fs_event` 之前，那时会拿它们去写
`en_eff`/`src_eff`/`started`，还会用 `lat_swap` 选分支：仿真里是 X，板上是上电值，两边对不上。

**改完之后重跑。** `sim/display/` 正常 9 项全 PASS（`starve` 从 7 项判据涨到 10 项）、
注错 7 项全 FAIL 在对应判据上、`fifo/inject_no_reset` FAIL，`SIM OK`；
`FULL=1` 的整帧 640×480 逐像素用例 PASS。

**还没做的事：三个修复只过了仿真，没过板子。** 板上跑的仍是修复前的比特流
（上面那批上板数据也是在它上面取的；缺陷一、二不影响这些读数，缺陷三正是被它暴露出来的）。

`base` 读回正确。新模块在板上的读通道（按水位发行、在途 ≤1、跨 4KB 行）由此得到独立验证。

**一个未了结的上板现象（属 E5 回归，不属本条）。** `ddrBurstProbe` 三次运行都在
`INJECT age64_rd` 那一行之后停住，串口不再输出；第三次之后不再用 `reset halt`，直接挂 OpenOCD 读回现场：
`PC=0x00001068`（CPU 卡在 `while (!(R_STATUS & ST_DONE))` 这个**无超时**轮询里）、
探针主机 `0xF810_1000` 区：`STATUS=0x2`、`ADDR=0x0d000000`、`LEN=0xff`、`COUNT=0x1000`、`MODE=1`（写）、
`0x2C` 错误计数 0 ——**探针替身卡在写突发的中间**，不是 CPU 挂在 DDR 上。
写方向上本模块一个字节都不发（只读主机），所以这一条大概率是替身自己的写通路在
「AW 被 guard 掩码挡住、而写数据已经在途」时进的死锁，触发与否取决于 S2 等待的时序
（platform 第 06 章记过周期数有约 2% 的板间波动；同一次运行里 `AGE_LIMIT=1` 的写轮是过的，
只有 `AGE_LIMIT=64` 的这一轮卡住）。**待查**：要么改 `ddrBurstProbe`（它本来就要按 2.6 节改 ID
与两处 ≥20 ms 等待），要么修探针替身的写通路。这一条不挡彩条，也不挡 display 的判据。

**留板状态。** 比特流烧在 SRAM（掉电丢失，Flash 未动），CPU 停在 `reset halt`，
`CTRL=0`。屏幕上是 `display_out` 里那个 `color_bar_rgb` 经 `hdmi_tx` 与 LVDS TX 出的八色竖条 ——
按 D10 的 B′，这条通路与帧缓冲模式共用同一个编码器和同一个时序发生器。

**仿真里定下来的两件事（都改了判据的写法）。**

1. **「最低水位」的计量窗口要排除每场最后 4 行。** 一场取 480 行、弹 480 行，起始水位是 0（场起始清空过），
   所以**场末水位必然排到 0——这是守恒，不是故障**：取数侧发完最后一行（`row` 到 480）就停发，
   剩下的水位只够约 3 行（512 / 160）。3 节的「水位」一条与 E5 2.4 据此改写。
   仿真（640×8 小帧）里窗口内的最低水位实测 **351 拍**，正好是发行阈值那一侧（512−160）的补数，
   与设计预期一致；把排水段算进去的话任何正确设计都会被判失败。
2. **D7 的「等 `rlast` 再复位」只在一种情况下有实活干。** 正常场里最后一行早就取完，
   场起始时取数侧是闲着的（`in_flight=0`、`ar_valid=0`），所以 `inj_no_drain` 与 `image` 配对
   **测不出任何差别**（第一版就是 PASS）。它只能与 `starve` 配对：停住取数一直停到场起始，
   取数侧是「还欠着账」进场的，这时跳过排空 —— 残留的拍落进新场、它的 `rlast` 还把行号推进一格
   （跳行），下一场整场错位（实测 5119/5120 个像素错，行地址也整体偏一行）。
   `run.sh` 里的注错配对已经照这个改。

**仿真里修掉的四个设计错（都是 RTL 的错，不是判据的错）。**

- `can_issue` 少了 `!ar_valid`：`ar_fire` 那一拍照样满足 `!in_flight`（寄存器还是旧值），
  于是同一拍「先清 `ar_valid` 又立刻拉起」，一笔没完就发下一笔——在途超一笔、行地址跳格。
- 场起始时若有「地址已拉高、还没被接走」的那一笔，旧码直接进复位：它迟早会被接走，
  拍子随后流进新场的队头。现在按 `(in_flight || ar_valid)` 决定要不要先排空。
- 上电没有清 FIFO：厂商 FIFO 的指针在第一次 `a_rst_i` 之前是 X，APB 读回一堆 X
  （而 `x < 0` 与 `x > 0` 都是假，判据差点静默通过——测试台的 `chk` 现在把 `^got === 1'bx` 判失败）。
  现在复位后 FSM 从 `S_RESET` 起，先清一次再进 `S_RUN`。
- 快照 ack 用同一拍的 `snap_sync[1]`：那是旧值，ack 永远追不上 toggle，源侧一直占着不更新
  （表现是 APB 里永远是第一场的快照）。事件检测延后一拍再取同步值。

**另外两条设计纪律。** 上电到软件使能之间 `SRC=0`（彩条），FIFO 本来就是空的，
把那一场算进欠载会白记 1280 拍；水位、触底、欠载只在 `de1 && src_eff` 时统计。
六个注错要改内部行为，做成 `parameter integer INJECT`（默认 0，综合时是常量、分支被优化掉），

### 2026-09-20 复核：探针逐字复现，订正四处，D10 定为 B′

把附录的探针原样抽出来重跑了一遍（`iverilog -g2012` + `vvp`，只加 `efx_fifo_wrapper.v` 一个文件），
所有 `T1`~`T10` 的输出与本节记录**逐字相同**，`order_err=0`、`RESULT: PROBE DONE`，
原始数据可信。在此之上订正四处：

1. **`rst_busy` 不能在 `core_clk` 里直接判（唯一一处会进网表的错）。** 它是
   `wr_rst_int | rd_rst_int` 的组合，`rd_rst_int` 在像素域，直接采样就是一条没有同步器、
   SDC 又切掉了的跨域路径。改法写进 2.2 节「欠载自愈」第四条：过两级同步器再判，连续为低后再等 4 拍。
2. **复位撤销时刻的两处数字串了事件。** 原文把上电长复位的 `+65/+99 ns` 与 10 ns 脉冲的 `+45/+82 ns`
   混着写。按原始输出分成三行：上电 +65/+99，10 ns 脉冲 +45/+82，40 ns 脉冲 +60/+100，
   **最坏 +100 ns ≈ 10 个 `core_clk` 周期**。
3. **`SNAP_END_LEVEL` 的定值是 0，不是「某个固定值」。** 一场取满 480 行 76800 拍、弹出也是 76800 拍，
   `row` 到 480 就停发，最后一个可见行弹完时 FIFO 必然空。写死 0 才抓得住系统性偏差——
   写「恒为同一个值」的话，一个一直稳定偏着的错误会照样通过。
4. **D9 撞到了 `ddrBurstProbe` 的测量窗口。** `EN` 改成场起始生效之后，写 `S_CTRL=1` 要等最多 16.7 毫秒
   才开始取数，收尾的 `wait_ms(1)` 也停不住它。两处都要等 ≥20 毫秒，已写进 2.6 节的交接清单。

另外补了一条例化纪律：`BYPASS_RESET_SYNC` 必须显式写 0，置 1 会把 `wr_rst_int`/`rd_rst_int`
接到 wrapper 根本没连线的那两个端子上，同时把 `rst_busy` 写死成 0。

**D10 定为 B′**（把 `color_bar_rgb` 搬进 `display_out`，`hdmi_tx` 变成纯编码封装），
不取原研究建议的 A′。理由三条写在 2.1 节 D10 里，核心是：A′ 会造出第二个视频时序发生器，
而「场」是取数、切换、中断、快照共同的同步基准，不该有两个真源；共用编码器的对照其实更强
（两条通路唯一的差别就是像素来源）；B′ 要写的代码更少，且三个官方文件仍然一字不动。

### 2026-09-20 前期研究：FIFO 语义实测、像素侧对齐定值、视频侧组合方式

**这一轮做了什么。** D4 写明「开工第一件事是读 `efx_fifo_wrapper.v` 并在 `sim/display/` 里用判据钉死两件事」，
所以先把这两件事做掉：**FIFO 的水位语义与复位语义用仿真实测钉死**。
顺带对着 RTL 复核像素侧的对齐相位与视频侧的组合方式，并把寄存器表与偏移定稿。

**结论 1（订正 D4）：`a_wr_rst_i` / `a_rd_rst_i` 在 wrapper 里根本没有接到 FIFO。**
`efx_fifo_wrapper.v` 第 124~144 行例化 `efx_fifo_top` 时只连了 `a_rst_i`，两个辅助复位端子悬空
（`BYPASS_RESET_SYNC=1` 时它们也不会生效，因为传下去的是悬空值）。
探针把这两个端子**全程置 1**，FIFO 照常连写连读 160 拍、顺序全对、复位正常——这是判别性实验：
真接上了的话 FIFO 会一直停在复位，一次收发都不会成功。
所以 D4 结论里「用厂商 FIFO 时就是 `a_wr_rst_i`、`a_rd_rst_i` 与 `rst_busy` 这一组」这句话要改成：
**两侧复位由 `a_rst_i` 一个信号给**，厂商在内部对每个域各有一套 2 级同步器（`wr_rst`/`rd_rst`），
`rst_busy = wr_rst[1] | rd_rst[1]` 就是「两个域都已经退出复位」的回执，D7 的「两侧复位要握手」不用自己补 toggle/ack。
**但这个回执本身是跨域的**：`rd_rst[1]` 在像素域，`core_clk` 直接采样它就是一条没有同步器、
STA 又看不见的跨域路径。取数侧要判它，必须先过两级同步器（见 2.2 节「欠载自愈」的第四条约定）。
**但复位窗口里 FIFO 不拦写**：`wr_en_int = we & ~wr_full`，而复位期间 `waddr_cntr` 被钉在 0、
`raddr_int` 是旧值，`full_o` 读出来是 0，所以写进来的字会直接盖掉 `ram[0]`，`wr_ack_o` 被复位压住不响应。
`we=0` 必须由主机保证，「等 `rlast` 再复位」这条纪律因此不能省。

**结论 2（实测）：水位语义与滞后。** 探针参数就是目标配置（`SYNC_CLK=0`、`DEPTH=512`、`DATA_WIDTH=128`、
`OUTPUT_REG=0`、`ASYM_WIDTH_RATIO=4`、`FAMILY="TITANIUM"`），两个时钟取板上名义值 10 ns 与 39.683 ns：

| 项 | 实测 | 判读 |
| --- | --- | --- |
| 单拍写 → `rd_datacount_o` | 写沿 t=345 ns，水位在之后第 3 个 rd 沿（456 ns）更新，本域监视器在第 4 个沿（496 ns）才看到 | 1 个 wr 周期 + 3 个 rd 周期；**读侧水位偏低** |
| 单拍读 → `wr_datacount_o` | 读沿 t=694 ns，水位在 755 ns 更新（+61 ns），本域监视器 765 ns 看到 | 1 个 rd 周期 + 3 个 wr 周期；**写侧水位偏高** |
| 读延迟 | `rd_en` 在沿 N 采样且 `empty=0` → `rdata` 与 `rd_valid_o` 在沿 N+1 有效（694 ns → 734 ns） | 1 个 rd 周期，对齐取 `D=1` 的依据 |
| 水位含不含在途 | **不含**：两个水位都是 RAM 里的指针差；`wr_datacount_o` 满值到 512（10 位够） | 「空位 ≥ 160」+「在途 ≤ 160」才等于不溢出 |
| 连写 160 拍 → 连读 160 拍 | `n_out=160`，逐拍相同，`empty` 正确回到 1 | 顺序与容量都对 |
| 写满 512 后再写 | `overflow_o` 单拍脉冲 | 写侧要自己防溢出 |
| 空时读 | `underflow_o` 单拍脉冲，指针不动 | 读侧要自己用 `empty` 压 `rd_en` |
| 上电长复位撤销 | `rst_busy` 在 +65 ns（wr 域采样）与 +99 ns（rd 域采样）落下 | 两侧一起复位 |
| `a_rst_i` 10 ns 脉冲（T7） | +45 ns / +82 ns；两侧水位归零、`empty=1` | 一个 wr 周期的脉冲就够 |
| `a_rst_i` 40 ns 脉冲（T10） | +60 ns / +100 ns，同样两域都复位 | **最坏 +100 ns ≈ 10 个 `core_clk` 周期**；设计取复位保持 ≥2 个 `core_clk` 周期，恢复写入前把 `rst_busy` 过两级同步器再判 |
| 复位后写 4 拍读 4 拍 | 逐拍相同 | 复位不损坏通路 |

**结论 3（D3 的落地式）：发行条件与判据的准确写法。**

```
发行（core_clk，每拍判一次）：!in_flight && (row < 480) && EN && (512 - wr_datacount_o >= 160)
判据（像素侧本域）：最低水位 = de1 期间 rd_datacount_o 的最小值
```

「空位 ≥ 160」用**写侧**水位：它在读指针滞后时偏高，也就是把空位算小，判据因此保守；
稳态偏高只有 1~2 拍（读出到写侧水位的滞后约 1 个 rd + 3 个 wr 周期）。在途的 160 拍不计入水位，
所以只有「空位 ≥ 160 && 在途 ≤ 160」同时成立才等价于「不会溢出」——这也是在途不超过一笔这条约束的另一半理由。
判据侧的读数用**读侧**水位：它偏低，所以「每场最低水位 ≥ 160」量到的是真实水位的下界；
偏低只发生在突发灌入期间（滞后窗口 1 个 wr + 3 个 rd 周期约 129 ns，按实测一笔 160 拍 236 个周期算，
最多十来拍看不见），最低点附近写指针已经稳定，可以忽略。
D3 那条「稳态水位在 337~512 之间摆动」的推算不变，阈值与深度仍是一对。

**结论 4（定值）：像素侧对齐 `D = 1`，弹出相位取「每组的第一个像素周期」（不用预弹）。**
`psel`（0~3）只在 `de0 = 1` 时计数，`psel_d1` 是它延迟一拍；`hs1/vs1/de1 = hs0/vs0/de0 延迟一拍`；
`rgb = mux(rdata, psel_d1)` 组合给出（`dvi_encoder` 的输入本来就是寄存的，不加输出寄存级）：

```
rd 沿          t_j       t_j+1    t_j+2    t_j+3    t_j+4 (= t_{j+1})
de0             1         1        1        1          1
psel            0         1        2        3          0
rd_en           1                                      1        ← psel==0 时弹这一组的拍
rdata        beat_{j-1}  beat_j   beat_j   beat_j    beat_j      ← 新拍在 t_j+5 到达
psel_d1         x         0        1        2          3
de1             0         1        1        1          1
输出            黑       4j+0     4j+1     4j+2       4j+3
```

`rd_en = de0 & (psel == 2'd0) & ~empty`：每行 160 次、每场 76800 次，与从机供给的拍数一样多。
**先写的相位不是这个。** 第一版按「`psel == 3` 时弹下一组的拍」推，那要求每场额外预弹一次第一拍
（否则每场第一行的第 0~3 像素是上一场的残留），而且最后一行末组还会多弹一拍：
76801 次弹出对 76800 拍供给，场末必然假欠载一次、`SNAP_END_LEVEL` 也对不上定值。
改成 `psel == 0` 之后两个问题一起消失：数据在下一拍到达，正好是延迟后的 `de` 的第一个像素周期。
本场余下的行在发生一次欠载后都会整体晚一个像素组，靠下一场清空复位——`starve` 用例里要写清这个形态。
时序参数要从测试台能覆盖（`H_ACTIVE`/`V_ACTIVE` 透传），否则 640×480 一场就是 15.2 ms 仿真时间。

**结论 5（订正 D8）：`FRAME_BEATS` 的定值仍是 76800，抓「多了几拍」的是 `SNAP_END_LEVEL`。**
按结论 4 的相位，每场弹出与供给一样多，`FRAME_BEATS` 恒为 76800；
D7 那个坑的症状是**场末残留水位偏离定值**（在途的那几拍进了新场的队头，多出来的拍留在 FIFO 里），
逐像素比对同时整幅横移。拍数只抓「少了」（欠载）。

**结论 6（定稿）：寄存器表与偏移写进 2.2 节。** 做法照 D1：接管替身的 `0xF810_E000` 窗口，
量测寄存器的偏移与语义原样搬过来（含三组直方图），
替身的 `0x00C BASE` / `0x010 LINE_PERIOD` / `0x014 FIELD_LINES` 三个洞给
`FRONT_BASE` / `BACK_BASE` / `SWAP_REQ`；新寄存器接在直方图之后，从 `0x0D0` 起。
两处细节：`ID` 从 `"SCAN"`（`0x5343_414E`）改成 `"DISP"`（`0x4449_5350`）；
`CTRL` 的 `CLEAR` 从 bit1 挪到 bit2（bit1 让给 `SRC`），`EN` 仍是 bit0——`ddrBurstProbe` 只写 0/1，不受影响。

**结论 7（新增 D10，已于当日复核后定为 B′）：视频侧怎么组合。** 见 2.1 节 D10（那里记的是最终结论与理由）。
本轮研究当时的分析要点：
`hdmi_tx` 是密封的，spec 2.2「`display_top` 对顶层露 TMDS」与 `rtl/README.md`「`hdmi_tx` 对外接口不动」
不能同时按字面成立。建议 A′（`hdmi_tx` 一行不改当彩条通路，`display_top` 自带彩条/编码器/P&N 取反，
从 `hdmi_tx` 收 TMDS 做 2:1 选择），实测代价 `u_hdmi_tx` = 318 XLR（`u_color_bar` 89.5 + `u_dvi_encoder` 213.5）
再加 40 位选择，约 +0.6%，顶层当前 21653 / 60780 = 35.6%。备选 B 是给 `hdmi_tx` 加五个端口省掉这份重复，
代价是改一个已上板验证的模块并让两条通路共用编码器。**它只影响最后一个文件，前三个可以先写。**

**结论 8（D1 的交接面）：撤替身之后要动的只有两处。**
① `sw/apps/probe/ddrBurstProbe`：只需改 ID 判断（`0x5343_414E` → `0x4449_5350`）；
它往 `S_BASE`（`0x00C`）写的那一句在新模块里按「忽略且不报错」处理（见 2.2 节的例外），
随后读回的恒等检查仍成立（`FRONT_BASE` 复位值仍是 `0x0200_0000`）；
`S_CTRL` bit0 仍是 `EN`；`S_SKIP` 保留偏移恒读 0，`skip=0` 仍成立。
**但 TRI 阶段的负载倍数要重测**：替身是行节拍均匀发读，新模块是按水位突发，不能拿替身时代的数字当对照。
② `sw/bsp/ti60/board.c` 里 `board_present`/`board_wait_frame` 两个空实现接上（`board.h` 的注释已写「等 display 系列」）。

**结论 9（工具教训）：整数位选会让比对静默通过。** 探针第一版用 `i[127:0]`（`i` 是 `integer`）
造 128 位图案，iverilog 取到的是 `x`，而 `x !== x` 为真，连读 160 拍的逐拍比对**报出假的 `order_err=0`**。
数据图案一律用 128 位寄存器自增。判据脚本里凡是「比对」都要意识到这一点（E5 那次假绿的同类问题）。

```verilog
// 探针（不入库）：efx_fifo_wrapper 的水位与复位语义
//
// 目的（D4 开工前提）：
//   1. wr_datacount_o / rd_datacount_o 的精确语义：含不含在途、滞后几拍
//   2. a_rst_i / a_wr_rst_i / a_rd_rst_i / rst_busy 的行为
//
// 参数取扫描输出的目标配置：128 位 x 512 深、异步、TITANIUM、block_ram、OUTPUT_REG=0
// a_wr_rst_i / a_rd_rst_i 全程置 1：若它们真的被接进 FIFO，FIFO 会一直停在复位，
// 探针里任何一次收发都不会成功。这是「wrapper 没接这两个端口」的判别性实验。
`timescale 1ns/1ps

module tb_fifo_semantics;

    // 板上名义值：core_clk 10ns、像素时钟 39.683ns
    reg wr_clk = 1'b0;
    reg rd_clk = 1'b0;
    always #5.0    wr_clk = ~wr_clk;
    always #19.8415 rd_clk = ~rd_clk;

    reg         a_rst    = 1'b1;
    reg         a_wr_rst = 1'b1;      // 常置 1，判别性
    reg         a_rd_rst = 1'b1;      // 常置 1，判别性
    reg         wr_en    = 1'b0;
    reg         rd_en    = 1'b0;
    reg  [127:0] wdata   = 128'h0;

    wire         almost_full, prog_full, full, overflow, wr_ack;
    wire         empty, almost_empty, prog_empty, underflow, rd_valid, rst_busy;
    wire [9:0]   datacount, wr_dc, rd_dc;
    wire [127:0] rdata;

    efx_fifo_wrapper #(
        .FAMILY            ("TITANIUM"),
        .SYNC_CLK          (0),
        .BYPASS_RESET_SYNC (0),
        .SYNC_STAGE        (2),
        .MODE              ("STANDARD"),
        .DEPTH             (512),
        .DATA_WIDTH        (128),
        .PIPELINE_REG      (1),
        .OUTPUT_REG        (0),
        .ASYM_WIDTH_RATIO  (4),
        .RAM_STYLE         ("block_ram")
    ) dut (
        .a_rst_i        (a_rst),
        .a_wr_rst_i     (a_wr_rst),
        .a_rd_rst_i     (a_rd_rst),
        .clk_i          (1'b0),
        .wr_clk_i       (wr_clk),
        .rd_clk_i       (rd_clk),
        .wr_en_i        (wr_en),
        .rd_en_i        (rd_en),
        .wdata          (wdata),
        .almost_full_o  (almost_full),
        .prog_full_o    (prog_full),
        .full_o         (full),
        .overflow_o     (overflow),
        .wr_ack_o       (wr_ack),
        .datacount_o    (datacount),
        .wr_datacount_o (wr_dc),
        .empty_o        (empty),
        .almost_empty_o (almost_empty),
        .prog_empty_o   (prog_empty),
        .underflow_o    (underflow),
        .rd_valid_o     (rd_valid),
        .rdata          (rdata),
        .rd_datacount_o (rd_dc),
        .rst_busy       (rst_busy)
    );

    integer i;
    reg     log_wr = 1'b0;
    reg     log_rd = 1'b0;

    // rst_busy 落下时刻（每个域各记一次），复位撤销时刻由激励记录
    time t_rst_off = 0;
    time t_low_wr  = 0;
    time t_low_rd  = 0;
    reg  seen_low_wr = 1'b0;
    reg  seen_low_rd = 1'b0;

    always @(posedge wr_clk) if (t_rst_off != 0 && !seen_low_wr && !rst_busy) begin
        seen_low_wr = 1'b1; t_low_wr = $time;
    end
    always @(posedge rd_clk) if (t_rst_off != 0 && !seen_low_rd && !rst_busy) begin
        seen_low_rd = 1'b1; t_low_rd = $time;
    end

    // 只打印，不做判断，避免测试台自己的逻辑掩盖 DUT 行为
    always @(posedge wr_clk)
        if (log_wr)
            $display("W t=%0t en=%b wr_dc=%0d rd_dc=%0d full=%b ack=%b ovf=%b busy=%b",
                     $time, wr_en, wr_dc, rd_dc, full, wr_ack, overflow, rst_busy);

    always @(posedge rd_clk)
        if (log_rd)
            $display("R t=%0t en=%b rd_dc=%0d wr_dc=%0d empty=%b dv=%b data=%h busy=%b unf=%b",
                     $time, rd_en, rd_dc, wr_dc, empty, rd_valid, rdata, rst_busy, underflow);

    // 读出一拍：以 rd_valid_o 为准，记录同一拍的总线数据
    reg [127:0] fifo_out [0:511];
    integer     n_out = 0;
    always @(posedge rd_clk)
        if (rd_valid) begin
            fifo_out[n_out] = rdata;
            n_out = n_out + 1;
        end

    integer rd_err = 0;
    reg [127:0] wpat = 128'h0;
    reg [127:0] t8_exp [0:3];

    initial begin
        $dumpfile("tb_fifo_semantics.vcd");
        $dumpvars(0, tb_fifo_semantics);

        // ---- 上电复位 ----
        repeat (4) @(posedge wr_clk);
        @(negedge wr_clk);
        seen_low_wr = 1'b0; seen_low_rd = 1'b0; t_rst_off = 0;
        a_rst = 1'b0;
        t_rst_off = $time;
        repeat (8) @(posedge rd_clk);
        $display("RESET release t_off=%0t rst_busy_low_wr=%0t (+%0d ns) rst_busy_low_rd=%0t (+%0d ns) empty=%b wr_dc=%0d rd_dc=%0d",
                 t_rst_off, t_low_wr, t_low_wr - t_rst_off, t_low_rd, t_low_rd - t_rst_off,
                 empty, wr_dc, rd_dc);

        log_wr = 1'b1;
        log_rd = 1'b1;

        // ---- T1 单拍写：看 rd 侧水位滞后 ----
        $display("T1 begin single-write t=%0t", $time);
        @(negedge wr_clk); wr_en = 1'b1; wdata = 128'h0000_0000_0000_0000_0000_0000_0000_00A1;
        @(negedge wr_clk); wr_en = 1'b0;
        repeat (8) @(posedge rd_clk);
        $display("T1 end t=%0t wr_dc=%0d rd_dc=%0d empty=%b", $time, wr_dc, rd_dc, empty);

        // ---- T2 单拍读：看 rdata / rd_valid 的延迟与 wr 侧水位滞后 ----
        $display("T2 begin single-read t=%0t", $time);
        @(negedge rd_clk); rd_en = 1'b1;
        @(negedge rd_clk); rd_en = 1'b0;
        repeat (10) @(posedge wr_clk);
        $display("T2 end t=%0t wr_dc=%0d rd_dc=%0d empty=%b unf=%b data=%h n_out=%0d",
                 $time, wr_dc, rd_dc, empty, underflow, fifo_out[0], n_out);

        // ---- T3 连写 160 拍（预装一行的样子） ----
        // 用 128 位计数器造图案：整数 i 的位选 i[127:0] 在 iverilog 里是 x，
        // 用它做数据比对会让 x !== x 变成「相等」，判据静默失效。
        $display("T3 begin burst-write 160 t=%0t", $time);
        for (i = 0; i < 160; i = i + 1) begin
            @(negedge wr_clk); wr_en = 1'b1; wpat = wpat + 128'h1; wdata = wpat;
        end
        @(negedge wr_clk); wr_en = 1'b0;
        repeat (12) @(posedge rd_clk);
        $display("T3 end t=%0t wr_dc=%0d rd_dc=%0d empty=%b", $time, wr_dc, rd_dc, empty);

        // ---- T4 连读 160 拍：看 wr 侧水位跟随与顺序 ----
        n_out = 0;
        $display("T4 begin burst-read 160 t=%0t", $time);
        for (i = 0; i < 160; i = i + 1) begin
            @(negedge rd_clk); rd_en = 1'b1;
        end
        @(negedge rd_clk); rd_en = 1'b0;
        repeat (14) @(posedge wr_clk);
        for (i = 0; i < 160; i = i + 1)
            if (fifo_out[i] !== (i + 1)) begin
                rd_err = rd_err + 1;
                if (rd_err <= 4) $display("T4 MISMATCH idx=%0d got=%h exp=%h", i, fifo_out[i], i + 1);
            end
        $display("T4 end t=%0t wr_dc=%0d rd_dc=%0d empty=%b n_out=%0d order_err=%0d",
                 $time, wr_dc, rd_dc, empty, n_out, rd_err);

        // ---- T5 空读：欠载标志 ----
        $display("T5 begin read-while-empty t=%0t empty=%b", $time, empty);
        @(negedge rd_clk); rd_en = 1'b1;
        repeat (2) @(posedge rd_clk);
        $display("T5 unf=%b rd_dc=%0d", underflow, rd_dc);
        @(negedge rd_clk); rd_en = 1'b0;

        // ---- T6 写满 512 + 溢出 ----
        $display("T6 begin fill-to-full t=%0t wr_dc=%0d rd_dc=%0d", $time, wr_dc, rd_dc);
        @(negedge wr_clk); wr_en = 1'b1;
        while (!full) @(negedge wr_clk);
        $display("T6 full at t=%0t wr_dc=%0d rd_dc=%0d", $time, wr_dc, rd_dc);
        repeat (3) @(negedge wr_clk);
        $display("T6 write-while-full: ovf=%b wr_dc=%0d", overflow, wr_dc);
        @(negedge wr_clk); wr_en = 1'b0;
        repeat (4) @(posedge wr_clk);

        // ---- T7 复位：1 个 wr 周期（10ns）的 a_rst_i ----
        $display("T7 begin reset pulse 10ns t=%0t wr_dc=%0d rd_dc=%0d", $time, wr_dc, rd_dc);
        seen_low_wr = 1'b0; seen_low_rd = 1'b0; t_rst_off = 0;
        @(negedge wr_clk); a_rst = 1'b1;
        @(negedge wr_clk); a_rst = 1'b0; t_rst_off = $time;
        repeat (8) @(posedge rd_clk);
        $display("T7 end t=%0t rst_busy=%b busy_low_wr=+%0d ns busy_low_rd=+%0d ns wr_dc=%0d rd_dc=%0d empty=%b",
                 $time, rst_busy, t_low_wr - t_rst_off, t_low_rd - t_rst_off, wr_dc, rd_dc, empty);

        // ---- T8 复位后恢复：写 4 拍读 4 拍，核对数据 ----
        n_out = 0; rd_err = 0;
        for (i = 0; i < 4; i = i + 1) begin
            @(negedge wr_clk); wr_en = 1'b1; wpat = wpat + 128'h1; wdata = wpat; t8_exp[i] = wpat;
        end
        @(negedge wr_clk); wr_en = 1'b0;
        repeat (12) @(posedge rd_clk);
        for (i = 0; i < 4; i = i + 1) begin
            @(negedge rd_clk); rd_en = 1'b1;
        end
        @(negedge rd_clk); rd_en = 1'b0;
        repeat (4) @(posedge rd_clk);
        for (i = 0; i < 4; i = i + 1)
            if (fifo_out[i] !== t8_exp[i]) begin
                rd_err = rd_err + 1;
                $display("T8 MISMATCH idx=%0d got=%h exp=%h", i, fifo_out[i], t8_exp[i]);
            end
        $display("T8 end t=%0t n_out=%0d rd_err=%0d out0=%h out1=%h out2=%h out3=%h",
                 $time, n_out, rd_err, fifo_out[0], fifo_out[1], fifo_out[2], fifo_out[3]);

        // ---- T9 复位窗口里继续写：会不会被确认、会不会落进 RAM ----
        // 场起始若不等在途 rlast 就复位写指针，剩下的拍正是这样进来的。
        $display("T9 begin write-during-reset t=%0t wr_dc=%0d", $time, wr_dc);
        @(negedge wr_clk); wr_en = 1'b1; wdata = 128'hBAD0_0000_0000_0000;
        @(negedge wr_clk); a_rst = 1'b1;                          // 复位期间 wr_en 仍为 1
        repeat (3) @(posedge wr_clk);
        $display("T9 during reset: ack=%b full=%b wr_dc=%0d rd_dc=%0d empty=%b busy=%b",
                 wr_ack, full, wr_dc, rd_dc, empty, rst_busy);
        @(negedge wr_clk); a_rst = 1'b0;
        repeat (2) @(posedge wr_clk);
        @(negedge wr_clk); wr_en = 1'b0;
        repeat (8) @(posedge rd_clk);
        $display("T9 end t=%0t wr_dc=%0d rd_dc=%0d empty=%b (复位期间写进去的字留在 RAM 里)",
                 $time, wr_dc, rd_dc, empty);

        // ---- T10 一拍的复位脉冲（39.7ns）也能复位 ----
        @(negedge wr_clk); wr_en = 1'b1;
        repeat (20) @(negedge wr_clk);
        @(negedge wr_clk); wr_en = 1'b0;
        repeat (12) @(posedge rd_clk);
        seen_low_wr = 1'b0; seen_low_rd = 1'b0; t_rst_off = 0;
        $display("T10 begin reset pulse 40ns t=%0t wr_dc=%0d", $time, wr_dc);
        @(negedge rd_clk); a_rst = 1'b1;
        @(negedge rd_clk); a_rst = 1'b0; t_rst_off = $time;
        repeat (8) @(posedge rd_clk);
        $display("T10 end t=%0t busy_low_wr=+%0d ns busy_low_rd=+%0d ns wr_dc=%0d rd_dc=%0d empty=%b",
                 $time, t_low_wr - t_rst_off, t_low_rd - t_rst_off, wr_dc, rd_dc, empty);

        $display("RESULT: PROBE DONE rd_err=%0d", rd_err);
        $finish;
    end

    // 看门狗
    initial begin
        #500_000;
        $display("RESULT: PROBE TIMEOUT at t=%0t", $time);
        $finish;
    end

endmodule
```
