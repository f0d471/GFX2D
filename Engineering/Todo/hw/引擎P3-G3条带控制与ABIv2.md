# 引擎 P3-G3 条带控制、命令 ABI v2 与软件分桶

状态：**未开工**（2026-10-06 建条）。前置：G2 验收。
本批把 G2 的数据面接成帧级执行：控制层按条带走命令子表、软件按条带分桶、
软硬件对同一份条带表逐像素一致。开发日志追加在第七节。

## 1 要解决什么

条带模式改变了命令的组织方式（全帧平表→30 个条带子表）与执行顺序
（全局序→条带内序）。「加速但不改画」性质必须在这一批以可执行判据重建：
同一份绘制需求，条带模式与直通模式逐像素一致。这是 spec 第 02 章 v2
实例列表、引擎条带循环、软件分桶与执行器三方的共同验收边界。

## 2 范围与定案

- **D60 SET_CLIP**：条带模式下仅允许作为条带 0 命令区首条，全帧生效
  （v1「持续生效」跨条带自然延续，无需每条带复位）；其余位置按 `BAD_FIELD`
  报错。依据：游戏本体当前无 `SET_CLIP` 调用（`Main/sw/apps/game` 无命中）。
- **D61 命令表布局**：定长条带区——表 A/B 各 1 MB 切 30 区×1024 条×32 B
  （960 KB），区基址=表基址+区号×32 KB；30 字计数数组放表头（120 字节，
  一次取数批可读入）。区溢出时构造层报错并拒绝提交；是否自动分帧在本批内定。
- **寄存器**：`LSTRIPS`（条带数，复位 30）与 `STRIP_H`（条带高 log2，复位 4）
  经 `regs_gen.py` 真源表加入（DOORBELL 0x028 与 SURF0 0x040 之间的空档）；
  CTRL 模式位（直通/条带）启用；`CAPS.BAND` 置 1。DOORBELL 语义不变
  （每帧一次），引擎自动走完全部条带后置 `LIST_DONE`。
- **错误语义**：`ERROR_INDEX` 重建加条带维（条带号×区容量+区内索引）；
  `ERROR_TAG`（w7）不变；构造层默认填的调试标签改为条带号+区内索引的合成。
- **空条带快路径**：0 条命令的条带跳过取数，只做 fill/flush（或连续条带
  合并 fill/flush，作为优化项本批评估）。
- 跨条带弹：构造层按裁剪后的矩形分别入两桶；零面积桶不出命令；
  OVERLAP 与越界检查按裁剪后矩形执行（与 v1「零面积跳过像素但检查一步不少」一致）。

## 3 前期研究要求

- ≥2 个参考：候选方向——移动 GPU TBDR 的 binning/命令排序公开资料
  （PowerVR/Adreno 文档）、开源 2D 引擎的 tile 命令组织。
- ≥1 个出数字的实验：条带循环 TB 的取数批节奏与命令缓冲乒乓（16 条/批）
  在条带场景下的利用率，对照直通模式。
- 关键问题：
  1. 条带表头（计数数组）取数批与现有 FE 状态机（F_IDLE/F_ISSUE/F_POLL/F_PULSE）
     的衔接；空条带跳取数的状态迁移；
  2. 桶内序与全局画序的等价性论证（不同条带的 y 区间不相交 ⇒ 任意两命令
     的像素交集只可能在同一条带内 ⇒ 条带内保持相对序即足够）——写进 spec；
  3. 每条带 flush 握手与 S_ACTIVE/S_TERM 的组装（G2 提供通路，本批接线）。

## 5 判据

- 既有 159 向量（直通回归）全过；新增条带向量全过（覆盖：跨条带弹、色键、
  方程 0～5、零面积、越界、SET_CLIP 表头合法/非法、区溢出、空条带、错误注入）。
- PC 模糊测试：随机条带表 ≥1 万张（规模开工时写死）与直通模式逐像素 0 差；
  错误三元组（错误码/INDEX/TAG）在两模式下一一对应。
- 软件执行器条带模式与分桶入库，`tools/check/check_sw_layers.sh` 仍过。
- 单独综合：WNS/WHS 记录且 hold 不劣于现状。
- 板级证据归 G4；本批验收边界=仿真+软件+综合。
- 证据归档 TechReports engine 第 09 章。

## 6 风险

- 等价性论证的漏洞（如 SET_CLIP 与裁剪框跨表继承在条带模式下的交互）：
  以模糊测试兜底，反例即 spec 缺陷，修 spec 再修实现。
- 构造层分桶的 CPU 开销把 G4 的 N_max 压低于预期：分桶按每弹 O(1) 设计，
  G4 用 SW9 分段口径实测；不足再立优化条目，不并进本批。
