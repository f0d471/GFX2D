# 绘制前端 F4 通用实例命令

状态：**研究完成，待开发**（2026-10-10）。前置 F1 已验收归档，见
[engine 第 12 章](../../TechReports/engine/12-绘制前端成本分解.md)；开工前
研究已收口于 [engine 第 13 章](../../TechReports/engine/13-绘制前端实例命令研究.md)：
编码空间无冲突、17 组真实状态展开等价、板上确认批入口构造收益
（−38%~−61%，BLIT 段口径）。F2/F3 不阻塞。本批交付直通实例 profile，
作为 F5 的输入。共同契约见 [总览](../sw/绘制前端总览.md)。

决策依据：engine 第 11 章 D65、D70、D72、D73；实例属于通用绘制输入。

## 1 要解决什么

32 B 标量 BLIT 重复携带源/目的表面、方程、尺寸和色键。当前 CPU 模板复用节省了
部分计算，但仍要为每个实例输出完整记录。将共享状态与实例属性分开，可以降低
CPU 打包与传输量；几何和像素工作仍随实例数发生。

本批提供一般矩形 BLIT 的实例化，不接受弹种、速度、寿命、关卡参数或纹理内容。
它对重复图像、图集动画、字形和 UI 矩形均可用。工业对应为 instancing 的共享
geometry/state 与 per-instance attributes，来源见 engine 第 11 章。

## 2 怎么切分

### 2.1 编码契约：v1-I profile

保留 v1/v2 原布局、旧 ID 主版本与旧九项 PERF 偏移。增加 `CAPS.INST` 位 12，
操作码 `0x05=BLIT_INST`；首次实现只在直通模式支持，v2 原始桶中的该操作按
BAD_OPCODE 拒绝。软件先查 CAPS，未支持时在提交前展开成原标量表，不提交后回退。

一包固定 32 B，复用现有取数对齐；下表是新操作的独立字段定义：

| 字 | 字段 | 约束 |
| --- | --- | --- |
| w0 | op=5；eq/key/src/dst/c 与 BLIT 同位；其它位按原保留规则 | 方程/格式校验沿原十步语义 |
| w1 | instances_base，设备字节地址 | 16 B 对齐，DMA 只读 |
| w2 | instance_count | 0..65535；上界防止无界工作占用，软件拆连续包时保序 |
| w3 | width:u16，height:u16 | 所有实例共享；零面积仍完成字段/表面/范围检查 |
| w4 | key 值 | key_en=0 时必须为 0；与旧 BLIT 的 w5 位置不同 |
| w5 | [15:0] stride_bytes；[17:16] layout；[31:18]=0 | stride 为 4 的倍数、entry_bytes..256 |
| w6 | layout=0 时固定 sx:i16/sy:i16；layout=1 时必须 0 | 支持负源位置，按原规则裁出 |
| w7 | packet_tag | 整包标签；出错实例另报 ERROR_INSTANCE |

实例数组为小端：layout=0/XY4 的 word0 为 dx:i16/dy:i16；layout=1/XYUV8 的
word0 为 dx/dy、word1 为 sx/sy。前者 4 B/实例，后者 8 B/实例。布局 2/3 按
BAD_FIELD 拒绝，不借用未定义字段；米弹方向变化和字形图集使用 XYUV8。
数组长度按 64 位计算：`count==0 ? 0 : (count-1)*stride+entry_bytes`；
基址加长度不得回卷，实际 DMA 向 16 B 边界取整的末拍需位于分配的 padding 内。

软件类型与入口定为：

```c
typedef struct {
    uint8_t *host;
    uint32_t dev_base, bytes, used, generation;
} gfx_instance_arena;
typedef struct {
    gfx_blit_tmpl shared;
    uint32_t layout;
    int32_t fixed_sx, fixed_sy;
} gfx_instance_desc;
int gfx_instances_append(gfx_list *list, const gfx_instance_desc *desc,
                         const gfx_blit_pos *pos, uint32_t count,
                         gfx_instance_arena *arena);
```

新 API 采用整包构造原子性：先检查参数/坐标可编码、CLOSED、packet 容量、共享
语义与 arena 容量，再写数组和包；失败不改变表或 arena.used，rejected 加一、
first_error sticky，只有容量错误加 overflow。它与旧 `gfx_blit_run` 的逐项返回
契约分开，旧入口保持原义。count=0 允许 pos=NULL，不分配 arena，仍检查共享
字段并可发合法零实例包。XY4 要求逐项源坐标等于 fixed_sx/fixed_sy；XYUV8 的
fixed 字段为 0。C 构造器只生成紧凑 stride=4/8，原始 ABI 另支持上述较大 stride。

新增软件入口接收 int32 坐标与显式容量，先验证可无损转成 int16；不能靠截断
制造可提交的错误坐标。输入可从应用数组逐批拷入实例 arena，arena 属本帧 lease。
共享状态相同且连续才合包；src/dst/eq/c/key/尺寸/clip 变化立即结束当前包。
标量 fallback 保留展开后的 packet/instance 索引映射，错误报告可还原逻辑身份。

宿主执行/普查新增显式只读数组 view（host、dev_base、bytes），以设备地址减
dev_base 后检查长度，再取宿主指针。当前 `gfx_mem` 从素材区起覆盖帧/离屏面，
不覆盖更低地址的共享区，不能直接用于实例 arena，也不能在 PC 上解引用设备地址。
新增执行入口接收这些 views，旧 `exec_sw_run` 与旧 `gfx_mem` 布局保持。

### 2.2 执行通路与顺序

```text
现 FE 取一个 packet -> 原字段/表面检查 + 实例范围检查
    -> engine_inst 取实例 -> {共享状态, sx/sy, dx/dy, clip, packet_index, instance_id}
    -> 原 I1/engine_geom -> 原 mover/pix -> 完成当前实例 -> 下一实例
```

实例取数使用现 DMA 读核心的受控入口；不能让数组数据进入命令 cbuf 后被当作
下一条命令解释。`engine_inst` 保存 packet/clip/表面上下文，在消费端 ready 前
保持整个 bundle 稳定。初版按实例执行完成后推进，可预取后续坐标，但不能越过
当前 draw 的像素完成关系。批中共享状态不可被下一 packet 覆盖。

实例读突发 ≤192 拍、不跨 4 KiB、处理首尾有效字与 16 B padding，首尾及响应
长度按当前取数规则检查。DMA owner 区分 command/instance/像素/背景，状态回送
显式携带 owner 与 packet/instance 上下文；不能复用低 4 位 cidx 代替完整错误定位。

### 2.3 检查、错误与完成

包级检查顺序：opcode → 保留位/布局/stride/count/地址 → equation → surface →
space → format → 共享字段；然后逐实例按原 BLIT 规则检查并提交几何。
N=0 或尺寸=0 不跳过包级合法性检查；合法零实例包不发实例 DMA、不写像素。
本批直通保留源=目的时逐实例重叠检查，后续依赖仍按原画序；F5 单独执行更严格
的条带反馈拒绝规则。

增加 RO `ERROR_INSTANCE=0x038`：复位/新门铃为 0xFFFFFFFF；实例错误为包内
零基索引，包级/标量错误为 0xFFFFFFFF，与其它错误字段同拍锁存。
ERROR_INDEX 仍为输入编码 packet 的零基索引，ERROR_TAG=w7。
数组取数失败在首个不能可靠取得的实例处报 FETCH/BUS_READ；已执行前缀不回滚，
停止新几何提交、抑制失败写并排空，再统一 ERR 完成，禁止呈现失败帧。
不因某实例坏而继续显示剩余实例；新 CPU API 的构造失败在发布前报告。

DOORBELL 仍是一张表一次；LIST_DONE 在最后实例及全部像素写响应完成后产生。
软复位与超时先取消新请求，再收尾所有已接受 DMA；DONE/ERR 对外可见时资源才可回收。

### 2.4 计数与实施文件

旧 PERF_CMD 保持编码记录的既有计数点，一包只计一次；新增 PERF_INSTANCE
在合法实例送入几何时递增，含几何最终裁空的实例。PERF_PIXEL/KEY_SKIP 不变；
数组读计真实 RD_BURST/RD_BEAT，TEX 像素读仍不计 DDR。新增计数追加在旧九项之后，
`PERF_COUNT` 与驱动按能力取数；不能令旧读九项函数越界。

| 层 | 文件与动作 |
| --- | --- |
| ABI | spec 第 02 章与 `gfx_abi.h` 增加 v1-I；C 打包/解码与检查器镜像 |
| CPU | `lib/gfx` 实例 arena/构造；renderer 与游戏连续批次适配，保留标量 fallback |
| 执行与统计 | `exec_sw.c`、`census.c` 增加 profile 入口与显式数组 view；独立标量展开金标准不复用该解析器 |
| 控制 | `engine_cmd.v` 增加包分派与错误定位；新增 `engine_inst.v` |
| 搬运 | `engine_mover.v` 增加实例读 owner 与状态，不增加游戏 AXI 端口 |
| 寄存器 | `regs_gen.py` 生成能力、错误索引和新增计数；旧位/偏移保持 |
| 验证 | `sim/engine/frontend` 的独立标量展开、AXI 反压与整帧 fixture |

单独综合预算为新增 ≤4 RAM、不新增像素乘法器；这是筛选预算，非已测资源。
若明显超预算，先评估取数缓存深度与复用 FE，不接受依赖固定纹理才能缩小的实现。

## 3 判据

- ≥10000 张实例/标量独立像素差分；六方程、key、DDR/TEX、多尺寸、变化 sx/sy、
  N=0/1/15/16/17/65535、零面积、负坐标、clip epoch、地址 4 KiB 边界均覆盖。
- 逐项核对包字段、实例定位、顺序、PERF 与 padding；覆盖源/目的同槽及非法别名。
- stride 取错、XYUV 字序调换、状态提前覆盖、实例跳号、owner 错路、末写未完成
  即 DONE 六类注错至少各有定向见红；原 v1/TEX/v2 回归全过。
- 随机反压和 DMA 错误/复位/超时/批次交界通过；独立综合与整机时序通过。
- 同状态测 CPU 打包/提交与 GPU 实例 DMA/展开/像素周期。4 B 只适用固定源坐标，
  8 B/复杂状态切换的实际占比必须报告；不把 32→4 B 直接当 8 倍整机加速。
- 本批正确验收不要求条带构造已消失；F5 才负责实例到空间列表的下沉。
  是否单独采用直通实例后端仍由同轮净收益判定。

## 4 开发日志

2026-10-10（研究轮）：开工前研究收口，过程与数据在
[engine 第 13 章](../../TechReports/engine/13-绘制前端实例命令研究.md)。
结论：编码空间（CAPS 位 12、操作码 0x05、ERROR_INSTANCE=0x038、PERF 下标 9）
全部可用；17 组 F1 冻结输入全部落在连续同状态区间，编码字节压到 16.1%
（K1984 档 14.3%，敌弹池单段 2313 颗 XY4 与第 12 章 9252 B 下界吻合；
Boss 战 XYUV8 占 46%）；宿主对拍 17 组全过＋拆包/坐标/坏包边界样例通过；
板上同状态三路径测量（G4 4KB 主线 bit，纯构造）：生产 blit_run 分段重放
对批入口 43953→17005、320378→168506、367635→227503 周期/帧，
**批入口形态 −39%~−61%，逐实例调用形态反向慢 1.6~1.9 倍**。
定案建议：`gfx_instances_append` 必须保持 spec 的批入口形态（共享检查段级
一次），renderer 适配按（共享状态、layout）分组直调批入口；arena 写入按
4 B 对齐整字存储；本 spec 的接口与判据继续作为开发轮依据，另需把
"研究原型的 f4_core 与生产实现的边界"写成 2.4 的实施注记。

2026-10-10：建立通用实例 profile、数组与错误完成契约；接口仍为计划，未改 ABI/RTL。
