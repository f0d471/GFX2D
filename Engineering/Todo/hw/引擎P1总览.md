## 1 要解决什么

**现在是什么样。** B1～B4 分层 RTL 已验收；控制层和顶层尚未接入。
`Axi_Mux` 留给引擎的 S1 口由探针主机
`rtl/bus/axi_probe_master.v` 占着（APB 第 1 页 `0xF810_1000`）；设计文档 3.4 节给引擎的寄存器页
`0xF810_0000~0xF810_0FFF` 目前落在 `rtl/bus/apb_probe.v` 上（顶层按 `paddr[15:12]` 分页，第 0 页是默认分支）；
SoC 给引擎预留的中断 B 在 `rtl/top/gfx2d_top.v` 里接的是 `1'b0`。
软件这一侧已经全部就位：命令 ABI v1 定稿（spec 第 02 章），逐像素规格定稿（spec 第 01 章），
软件执行器与 159 条一致性向量、十一个整帧用例都在 `sw/lib/gfx/`，SW6 的基础 Demo 已在板上用软件执行器跑通。

**不做会怎样。**

1. 赛题的六项要求里有五项落在引擎上：基础 1 的指令解析、块拷贝与纯色填充，基础 2 的突发与 FIFO，
   基础 3 里「硬件加速帧率」那一半，高阶 1 的 DSP Alpha 混合，高阶 2 的色键。
2. 软件执行器画一帧场景 S1 要约 805 ms（E7，platform 第 09 章），SW8 已写明软件后端下 `N_max` 不存在；
   高阶 3 的 `N_max` 只能来自硬件。
3. E5 的 FIFO 水位与 SoC 等待只在探针负载下量过，platform 第 08 章写明换成真实引擎要按同一判据复测。

**已经定下、各批都必须遵守的约束**（出处都已验收，不在引擎条目里重新讨论）：

| 约束 | 值 | 出处 |
| --- | --- | --- |
| 总线端口 | `Axi_Mux` 的 S1，读写都用 | E5，platform 第 06 章 |
| 在途事务 | 每个方向最多一笔：读方向上一笔 `rlast` 握手之前不拉高下一笔 `arvalid`；写方向上一笔 `bvalid` 握手之前不拉高下一笔 `awvalid`。写方向没有 guard 兜底 | platform 第 06 章 3.2 节措施一；放宽要重做 E5 全套判据 |
| 地址 | CPU 地址就是控制器地址，有效范围 `0x0000_1000~0x0FFF_FFFF`；AXI ID 截成 4 位 | E2，platform 第 02 章 |
| 突发 | 上限 256 拍；读 `t_tx = 27.41`、`k = 1.086`，写 `t_tx = 7.25`、`k = 1.183`（周期，N 为拍数） | E4，platform 第 03 章 |
| 帧缓冲 | 两面 `0x0200_0000`、`0x0240_0000`，行跨 4096 字节；缓冲切换只归扫描输出（`BACK_BASE`/`SWAP_REQ`） | 设计文档 2.1 节；扫描输出 D2 |
| 像素规格 | 六个方程、除以 255 的舍入、饱和、通道范围、色键、裁剪与坐标、字节序 | spec 第 01 章，设计文档 3.5 节 |
| 命令语义 | 32 字节记录、表面表、十步检查的顺序、首错停止、错误三元组 | spec 第 02 章，设计文档 3.4 节 |
| 缓存一致性 | CPU 读回引擎写过的区域之前必须失效，失效晚于写入完成 | E3，platform 第 05 章 |
| 时钟 | 引擎挂 `core_clk`（100MHz），与 SoC、DDR3 控制器的 AXI 同域，没有跨时钟 | 设计文档 2.5 节 |
| 时序余量 | `core_clk` 的 hold 余量只有 0.026 ns（4KB 与 16KB 缓存两种构型相同） | platform 第 06、10 章 |
| 片上 RAM | 现用 71 块（4KB 缓存）或 89 块（16KB 缓存），总共 256 块 | platform 第 10 章 |

**每颗弹幕要多少周期，用 E4 的板上数先算一遍**（估算，引擎上板后用计数器替换）。
标准弹是 16×16、预乘 ALPHA（SW8 的 K2）；目的 x 不按 4 像素对齐时一行 5 拍，按最坏情况算：

| 量 | 算式 | 周期 |
| --- | --- | --: |
| 读源一行 | 27.41 + 1.086 × 5 | 32.8 |
| 读目的一行 | 同上 | 32.8 |
| 写目的一行 | 7.25 + 1.183 × 5，与下一行的读分属两个方向，可以重叠 | 13.2（不计入） |
| 每行 | 读源加读目的 | 65.6 |
| 每颗弹幕 | 16 行，加命令取数分摊与流水线填充 | 约 1100 |
| 每帧固定开销 | 游戏区 400 宽加 HUD 240 宽的整屏 FILL：480 × (125.6 + 78.2) | 约 9.8 万 |
| 扫描输出占用 | 480 笔 × 最坏整笔 236（E5 实测 `MAX_FULL_TXN`） | 约 11.3 万 |
| 可用 | 166.7 万减去上面两项 | 约 145 万 |
| 硬件侧上限 | 145 万 ÷ 1100 | **约 1300 颗** |

前期研究在校准到 E4 板上数的事务模型上用真实的两个 DMA 核与 `Axi_Mux` 复算（engine 第 02 章 3.8 节）：
每颗 1092~1124 周期，取决于源、目的 x 是否按 4 像素对齐；整屏 FILL 的 400 像素一行 126.0 周期；硬件侧上限约 1310 颗。

这个数没有计入 CPU 写命令时对 DDR 的争用。它说明两件事：瓶颈是每行两笔读事务的固定开销
（每行 65.6 周期里有 54.8 是固定开销），而不是带宽；P2 把纹理放到片上、去掉「读源」那一笔，
每行降到约 32.8 周期，硬件侧上限约翻一倍。这是 D1 把 P2 排在 P3 前面的依据。

## 2 怎么切分

### 2.1 为什么按层分批，每批做到什么程度

原条目把 spec、取舍与研究都写在一个文件里，前期研究十个问题有四个（第 1、2、6、10 问）落在搬运层，
其余四层只有定案、没有研究：计算核心只有 D9 一句「先让综合推断 DSP，时序不够再按厂商原语例化」，
几何层的求交与十步检查的硬件结构都没有研究过。反过来，给每层都先写满 spec 与研究再开工，
开发之前就要堆出几百行文字，拖慢节奏。

折中的做法：

1. **接口先冻结，内部逐批深挖。** 层与层之间的八个接口写在 2.4 节，各批只能细化自己输出一侧的字段，
   改动回写 2.4 节并在本文件开发日志记一行。有了这张表，每批都能用测试台单独仿真，不必等上下游。
2. **每批的研究有最低要求：**
   针对本层至少读两个开源实现或论文，读到代码或手册级，列进本批的借鉴表（来源、许可、借鉴什么、用在哪、不借鉴什么）；
   至少一个能出数字的小实验（Efinity 2026.1 单独综合本层，或 iverilog 微型仿真）；
   本层的待定项带着数据列出，定案后编号 D24 起。
3. **篇幅有上限。** 每批条目开工前控制在 150~200 行；研究的过程、数据与解释在批次完成时写进 TechReports `engine/` 系列的对应章节正文，
   条目的开发日志只留时间流水。
4. **每批的流程：** 研究 → 定案 → RTL 与单元仿真（判据注错见红）→ 单独综合登记资源与时序 →
   TechReport `engine/` 第 0N 章 → 状态改待验收 → 验收后删条目，下一批开工。

时间：D1 给 P3 定的条件是「P1 在 10 月中旬之前上板」，从 2026-09-28 算约 17 天做六批，
所以每批的研究控制在半天到一天。

### 2.2 路线与分层（D1、D2）

**D1 路线：P1 → P2 → P3（有条件）。** 本条只做 P1：命令 ABI v1 的全部操作（NOP、FILL、BLIT、SET_CLIP、END），
源表面三种格式，目的只有 XRGB8888，`space` 只有 DDR。
P2 是「直通模式加片上纹理」：只把 SW7 的标准圆弹、小圆弹与火花（合计不到 16 KiB）放进片上，
米弹（约 100 KiB）与 Boss（约 432 KiB）仍从 DDR 读；它在 P1 上板之后另开条目。
P3 条带模式以「P1 在 10 月中旬之前上板」为条件，做的话与 ABI v2 的实例列表一起做
（每颗弹幕的提交从 32 字节降到约 8 字节；sw 第 06 章 3.6 节的批量提交接口 `gfx_blit_run()` 就是它的入口，
接口的输入保持「一串目的坐标与源帧」，换成 v2 时调用处不用改）。
P4 弹幕运动卸载不做：E8 的阶段性建议是 N=2000 时运动只占一帧的 5.6%。

**D2 引擎的分层。** 五层，从上到下：

| 层 | 内容 | 文件 | 批 |
| --- | --- | --- | --- |
| 控制层 | APB 寄存器、命令表取数、十步检查、首错定位、`SET_CLIP` 状态、中断、性能计数器、软复位请求；引擎对外的顶层 | `engine_regs.v`、`engine_cmd.v`、`engine_top.v` | B5 |
| 几何层 | 目的矩形、游戏区、裁剪框、目的表面、源表面五者求交；矩形拆成行；每行拆成按 16 字节对齐、不跨 4KB 的读写描述符 | `engine_geom.v` | B3 |
| 搬运层（AXI 事务层） | 一个 AXI 主机：读写两个厂商无关的 DMA 核、读侧多个请求方的仲裁、在途门控、W 通道带内掩码、排空与超时 | `engine_mover.v` | B2 |
| 计算阵列与片上缓冲 | 源行缓冲、目的行缓冲（各放两行乒乓）；像素旋转器；一条像素通路，每拍 4 像素；色键 | `engine_pix.v` | B4 |
| 计算核心 | 单通道混合（乘、除以 255 舍入、饱和） | `engine_blend.v` | B1 |

五者里的源表面一项来自 spec 第 01 章 3.6 节第 5 步：「源越界只跳过该像素」等价于再交一个矩形
`[dst_x − src_x, dst_x − src_x + src_w − 1] × [dst_y − src_y, dst_y − src_y + src_h − 1]`，
在矩形级做掉，像素通路不逐像素判源越界；整帧用例 `blit-clip-partial` 的第三条就是这种情形。
FILL 没有源，只交前四个（前期研究订正，首稿写四者）。

像素通路的输入输出一律是流接口，不直接连 AXI；输出里「这个像素不写」用 X 字节的带内标记表示（D16），
不用流的 `tkeep`（首稿写「数据加有效字节掩码」，写核中间拍不看 `tkeep`，前期研究订正）。
P2、P3 只换搬运层与片上缓冲（DDR 行缓冲换成纹理缓存或条带缓冲）和几何层的迭代顺序，像素通路与计算核心不动。

拆分时的两处调整：命令缓冲（D18 的 128 位 RAM）原先写在 `engine_pix.v`，改归控制层，
因为读写它的都是命令取数与十步检查；`engine_top.v` 原先没有归层，改归控制层，
因为 APB 从口与寄存器在控制层，B5 的 159 条向量要经它的 APB 口喂进去。

描述符完成的判定、零面积命令（裁剪后没有一行）怎么告诉控制层这条命令已经做完，在 B3 与 B5 开工时一起定，定了回写 I1、I2。
**B3 前期研究给的推荐项（D38，engine 第 03 章 3.6 节）**：几何层对空命令不回任何描述符，
与控制层之间加一条独立的「命令完成」单拍脉冲（带命令索引），控制层凭它推进命令索引与完成计数；
非空命令的完成仍由最后一个写描述符的「是否本命令最后一行」带出。B5 确认后回写 I1、I2 与 I8。
两种完成的先后不保证：空命令的脉冲可能早于它前面那条非空命令最后一笔写的状态，控制层按「完成计数等于已下发的 FILL/BLIT 条数」判断整张表做完，不能按到达顺序推进（2026-10-01 复核补）。

**I5 的反向**：B4 给几何层一个电平输入 `row_free[1:0]`，每一半一位，`row_free[h]` 高表示源、目的两块行缓冲
（各放两行乒乓）的第 h 半都空着；几何层在**每一行**（含每条命令的第 0 行）发边带之前查这一行那一半
`row_free[行号最低位]`，B4 只在第 h 半的边带握手之后才把 `row_free[h]` 拉低（**D41**，engine 第 03 章 3.6 节）。
原定一位、只在命令内部的行推进时查，B3 验收时发现命令边界上第 0 行会盖掉上一条命令还没写完的那一半，改成现在这样。
B4 已确认（D45）：`row_free[h]` 在第 h 半的边带握手之后拉低，该半的写流末拍被写核收走那一拍拉高。

**I5 的源格式只对 BLIT 有意义**（B4 验收，2026-10-01）：FILL 没有源表面，计算阵列按规范条款 §4.2 一律取 `w4[31:24]` 作 a，
不看边带的 `sfmt`，所以 B5 不必给 FILL 填一个特定的源格式。

**跨命令的写后读（B4 验收查出，待 B5 定）**：几何层发完一条命令的最后一个写描述符就空闲，那一行的像素可能还在流水里、
写响应更没回来；读、写是两个独立的核，下一条命令的读描述符照常发出。下一条命令读到上一条命令最后一行的区域时，
读的可能是旧值（engine 第 04 章第四节，`sim/engine/pix` 的 `path_hazard_nowait` 必须见红）。B1~B4 不挡这种冲突，
要由命令下发处理，三种做法：控制层等上一条命令的末行写状态再发下一条（16 颗 16×16 ALPHA 实测多 2.1%）；
几何层每条命令开头等写方向空闲（同价）；只在新命令的矩形与上一条的目的矩形相交时才等（省下大部分 2.1%，多一组矩形比较）。
推荐第一种；取第一种时 `row_free` 在命令开始时恒为空闲，D49 估的边界等待也不再存在。
**B5 定案 D52（2026-10-02）：取第一种。** 等待挡住下一条命令的语义提交与几何层 `start`，
下一批取数预取照常推进；十步检查可以先算候选结果但不得提前上报——上一条完成前，
后一条的检查错误不能抢成首错。已测路径每颗 1104.3 周期（上限约 1313 颗）不含 B5 开销，B6 须整机复测。

（`a = 0` 时 `Fd = 255`），16 位模截断在 ALPHA 上有 4113532 处出错；
D26 的理由也按复核改成「换代入能省到 6 块，但会加长关键级，DSP 余量充足，不换」。
