## 1 先恢复逐包源表面校验

CFG_BG 仅检查背景，其他包的源由 `packet[19:16]` 选择。整帧表面冻结不能证明所有被用源合法。
先以恢复源/目的结构谓词建立正确性基线；按 surface id/代际缓存验证结果只能作为另一个候选。

必须覆盖：

- valid=0、零宽、未对齐 base、stride 小于宽度×4；被裁空的非法源仍拒绝。
- 未使用非法槽不误拒；被使用的每个 id 都得到检查。
- 前一包已有绘制时，整帧预检失败仍不得改写目标。
- BAD_SURFACE 的 stage/index/tag/instance、首错顺序、模式返回与物理排空。

修复后运行普通 PB/命令消费者及对应外部变异，重新综合 B5 并按影响完成板测。
历史 B5 只余 8 XLR，不能据此保证恢复检查后仍可建；不得以修改期望标签掩盖拒绝语义变化。

## 2 建立可归因的 PPA 基线

冻结真实输入摘要、工具、模式、种子、目录条件与时钟，先做无设计改动的重复对照。
每个候选先验证原语推断，再做同参数整机 A/B；记录 map、层级自持资源、Routing、
最终 XLR、RAM/DSP 类型、最差路径及吞吐。父子层级不能累加；静态位宽和 FF 数不换算为净面积承诺。
批量修改无法逐条归因；保留失败和资源增长，禁止沿用“2～3% 噪声底”豁免小变化。

## 3 选定需求后启动的结构候选

| 对象 | 原型要回答的问题 | 采用前的边界 |
| --- | --- | --- |
| SURF 表（原 R-1） | 比较组合多读口、同步读+源/目的快照、配置/代际验证描述符；实际推断几份 RAM | APB SETUP/ACCESS、忙态写策略、复位、无效槽读回、首错与每命令新增拍数 |
| 公共运算器/实例读取器（原 K2/I1） | 显式输入 mux、运算通路、调用者上下文、取消与仲裁；源码 task 不证明物理共享 | 最坏混合流、FD/FS 所有权、错误排空、扫描等待和净 Routing 成本 |
| 精简 PB | 比较现 PB、紧凑引用/描述符、受约束批绘制和 B3；核算 COUNT/SCATTER/回放全部读写 | 保序像素、空场/小图元/跨带/透明重叠/高实例数、容量与错误身份；ABI 改动单独版本化 |
| TEX/BAND 存储映射（原 T1/B1） | 容量下界之外，逐 lane 写使能、实际端口、同步读延迟和 RMW 吞吐能否满足 | 128 位总线与四像素提交、读所有者和停顿；BAND 背景/呈现流量不能从整帧账中省略 |
| RAST 累计/初始化（原 RA3） | 活动 acc/ar 的 42 位界是否覆盖全部更新；初始化右移前乘积单独证明 | 符号、舍入、停顿、末行不可见更新和颜色/z 原子提交；不得直接截短初始化中间量 |
| setup/记录复用/覆盖剔除 | 先量 CPU 独占阶段、跨带引用、唯一记录、bbox 候选/覆盖/提交，再选加速对象 | 精确数值、缓存失效、匹配工作量和三角深度屏障；submit 已含 raster 时不再相加 |

TEX 的容量下界 13 RAM、BAND 的 32 RAM 只用于排查空间，不能直接承诺由实际 16/36 降到该数。
B7 含 INST、不含 PB；当前 Standard SoC 已具备 M 扩展，MULDIV_EXT 的 Lite 开关不作为腾面积目标。
硬件配置、像素语义、顺序混合、事务 owner、排空与扫描实时性必须显式保留或提供等效机制。

## 4 计算阵列的未实施候选

| 编号 | 机制与约束 |
| --- | --- |
| C1 | 旋转改 shift-by-1/2 两段 barrel；先证明四相位逐像素等价，再看整机映射，不承诺静态 LUT 节省 |
| C2 | row_mask 用四位移位器形成首尾掩码；覆盖一拍行、beat=0、短行与两侧相位 |
| C3 | 去除 valid 屏蔽的数据寄存器复位；先确认无效拍 X 不会污染地址、握手和可见输出，再评估布线 |
| C4 | src_k 行首装载后逐拍计数；只有最差路径确在 cnt_k→地址→RAM 链上才启动，核对两半行/停顿 |
| C5 | 无 KEY/ALPHA 构型裁 source RAM 宽度，无 ALPHA 时裁目的 RAM；实际块数与流水消费者一起验证 |

流水延迟常量的单一真源与 [计算阵列三处自定项](计算阵列-三处自定项.md) 共用一个工作点。
重复条件分支、排版与源码组织清理静默处理，不作为面积收益或新技术点。
原像素算术、行缓冲深度、四像素吞吐与复位/排空契约不因候选表自动改变。

## 5 采用与验证门槛

只有产品容量、时序或吞吐需求触发才启动候选，不以最高利用率为目标。
每批选定受影响普通测试、外部变异和直接消费者；RTL 改动补整机综合、全时钟余量，
性能声明用同输入、同负载、同参数的正式测量，部署变化按影响补板测。
未采用候选保持原默认后端，应用继续只使用平台 API；玩法帧率和美术不作为本条目的固定验收任务。
