## 0 分析方法与噪声底（全章候选共用，先读）

综合器（Synplify）行为决定候选怎么提、结论怎么取（[manual §6](../../../Main/rtl/engine/engine-manual.md)）：

- 同一源码重复综合 XLR 波动 **2~3%**（59K 档约 ±1100~1800 XLR），**RAM 与 DSP 跨轮完全一致**。
  推论：**RAM/DSP 类候选的归因是干净的，一切 <300 XLR 的逻辑微优化单独做都低于噪声底**，
  只能攒批、同轮 A/B 取区间。
- 源码文本敏感：token 等价的排版重排也能改映射（`engine_bin` 正文曾 +1606 XLR）。
  「重写得更整齐」不是候选；涉及正文的改动必须整机同轮复核。`engine_bin` 与
  `engine_band` 属文本敏感族，正文不动是硬约束。
- XLR 按 LUT 与 FF 的较大者成对打包：**省 FF 不必然省 XLR**（FF 富余时单删 FF 收益为 0），
  LUT 单删必然省。估算口径：32 位加/减/比较 ≈ 16 XLR，18 位 ≈ 9，2:1 mux ≈ 1 XLR/bit。
- 实测锚点（引用时注明轮次）：单份 `ec_struct_ok` 例化 386~400 XLR（B0 hier_util u_ssrc/u_sdst）；
  `engine_tex` 整模块 116 XLR / 16 RAM；128 位宽 RAM 口按宽度规则 7 块/512 深。

## 2 计算阵列（engine_pix + engine_blend，2026-10-18 原条目收编）

### 2.1 要解决什么

静态分解（估算，未用综合报告确认）与量化依据：

| 部件 | 位宽/数量 | XLR 估算 | FF 估算 | 说明 |
| --- | --- | --- | --- | --- |
| 12 个 `engine_blend` | 12 × 单通道 | 2500~3200 | 约 760 | 单核 = 级 1 的 9 位三路选择、`base×255` 移位减、级 2 十九位加、级 3 加 128 / 除 255 / 饱和，加 63 个 FF 与 1 个 DSP |
| 旋转 mux 树 | 4 × 32 位 4:1 | 350~400 | 0 | 每输出字三级 2:1 |
| 两块行缓冲与端口 | 512×128 / 512×96 | 约 150 | 224 | 12 块 RAM 之外的地址拼接、`dst_wdata` 字节重排、输出寄存器 |
| 两拍窗口与大寄存器 | `r_cur/r_prev` 256、`r_px` 128、`r_dst/r_dst2` 192、`r_a` 32 | 约 100 | 约 700 | 纯寄存器，几乎不花 LUT |
| 每半上下文 | `h_*` 两半约 70 位 ×2 | 约 120 | 140 | 开行时的 2:1 选择 |
| 掩码、色键与延迟链 | `row_mask()` 两处例化 + 四条延迟像 | 150~220 | 约 30 | `row_mask` 是 4 个 12 位比较器 ×2 |
| 状态机与记账 | `cnt_k/out_count/drain_count/q_count` | 约 120 | 约 50 | — |

三条结论（后面所有候选从这三条出发）：

1. **LUT 主要在混合核上**（六到八成），所以只动外围最多省个位数百分点；
2. **RAM 块数由位宽决定、深度免费**（256×128 与 512×128 都是 7 块），所以深度不是杠杆；
3. **FF 主要在四大块大寄存器与 12 个核里**，省 FF 不必然省 XLR。

### 2.2 候选 C1~C6

**C1 旋转器改两段 barrel** — 现状：`px0..px3` 各是 32 位 4:1 选择（三级 2:1），约 384 个 LUT4。
改法：shift-by-1 与 shift-by-2 两段，共约 256 个 LUT4。预期省 100~130 XLR（约 3%）。
风险低（`px[t] = w[st + t]` 语义不变）；token 多重集不再等价，必须仿真加同轮综合。

**C2 `row_mask()` 换成小移位器** — 现状：4 槽各两次 12 位比较、两处例化，约 150~220 XLR，
串联深度落在边带握手组合路径。改法：首拍 `(4'hF << ld)` 起掩码+短行尾部截断；末拍按
`ld + npx − 4*beat` 截位，都是 4 位变量移位。预期省 50~100 XLR 且组合深度下降。
风险中：一拍的行、`beat=0`、`npx < 4−ld` 边界逐值等价。418 行 sweep 已覆盖相位。

**C3 数据通路去同步复位** — 对象 `r_cur/r_prev/r_px/r_dst/r_dst2/r_a/r_k/r_k2/v_d1~d4/q_src/q_dst`
约 1000 FF（下游 valid 把门，复位无功能作用）。预期 XLR 小幅、布线改善不确定，实测才知值不值。
风险：`valid=0` 拍出现 X 传播（本库规避 X 的纪律要评估）。

**C4 `src_k` 寄存器化（时序向）** — 把 `cnt_k + rot_off` 的七位加法器从「计数器→地址→块 RAM」
路径摘掉（行首装 `rot_off` 每拍自增）。代价 8 FF。**前置条件：place 报告最差 setup 起点确实
在这条链上，不在就不做。**

**C5 按构型裁 RAM 宽度（只对非默认档）** — 无 `GFX_KEY` 且无 `GFX_ALPHA`：`src_mem` 128→96 位
（7→5 块）；无 `GFX_ALPHA`：`dst_mem` 整块去掉（省 5 块）。B0 像素全开用不到。

**C6 零成本清理** — `ws_key_lanes` 两处相同 `ifdef GFX_KEY` 分支合一；「7 拍延迟/8 拍排空」
写成派生常量（与[计算阵列-三处自定项](计算阵列-三处自定项.md) 2.2 是同一件事，落地只做一次）。

### 2.3 已否决（pix 范围）

| 想法 | 否决理由 |
| --- | --- |
| 行缓冲深度 512→256 | 块数由位宽定；512 深还能用地址最高位选半 |
| 源块与目的块合并 | 每拍 2 读+2 写，`EFX_DPRAM10` 只有 1R1W，物理做不到 |
| 目的块再收窄 | 已是每像素 3 字节，X 字节本就不进 RAM |
| 4 像素/拍降到 2 | 吞吐减半；DSP 不是瓶颈 |
| 12 核时分复用 | 违反「一行每拍一写」硬要求 |
| 去掉 `r_dst2` | 清零挪到核输入 = 12×8 位门 96 LUT，与 96 FF 打平 |

## 3 常驻层（全部档编译）

### 3.1 engine_top（778 行）：无合格候选

纯结构互连：APB 页分选（L411~437）、PB 前端二选一 mux 网（L208~245，仅 B5）、错误/PERF 事件
构型选择（L450~495）。自身时序逻辑仅 3 个 FF，整档量级 B0 约 100~200 XLR。逐类排查：位宽与
下游端口一一对应；无 PB/无 TEX 分支已全部用常量 `assign` 接死（L169~188、L261~271）被常量
折叠吸收；重复子表达式综合器自行共享。**对互连层做任何排版重排期望值为负**（<1% 整机 XLR
贡献 vs 文本敏感风险）。

### 3.2 engine_regs（434 行）

资源画像：表面表 `surf_w0/w1/w2w` 3×16×32 = **1536 FF**（L212~214）是最大块，且两个组合读口
（L216~221，16:1 mux 树）估 800~1900 LUT——本文件第一大 LUT 消耗很可能在读 mux 而非 FF 本身；
PERF 14×32=448 FF；配置/错误/控制约 400 FF。B5 档整文件估 1500~2500 XLR。

**R-1（存疑/高风险，本文件唯一上量级候选）表面表 FF 堆 → 块 RAM。** 现状 L212~221：三字
×16 槽寄存器阵列 + 2 组合读口（`surf_ra_id/rb_id` 供 cmd 十步检查同拍组合消费）+ APB 读回。
改法：16×96（或 3×16×32）DPRAM，1 写口 APB + 3 读口（ra/rb/读回）每阵列 3 份拷贝写口同播，
约 12~18 块 BSRAM；cmd 侧检查数据流改一拍同步读（命令检查速率低，+1 拍无性能影响）；APB 读
用 SETUP→ACCESS 天然一拍。预期 **−1000~1500 XLR**，代价 +12~18/256 RAM。风险：跨文件改
engine_cmd 检查路径；软复位清 valid 位从 16 槽并行 AND 变 16 拍读改写 FSM（须嵌进排空期并保
`soft_rst_done` 前完成）；BRAM 未写槽读回 X ≠ 现状 0，仿真基建要加 RAM 初始化。**先做单独
试点综合拿同轮 A/B 与 RAM 余量读数再立项**（B7 档 RAM 已用 187/256，+18 后仍余 51，量够）。

**R-2（低优先，只对 B0 有效）条带共享参数死重。** L268~270 读回 case 臂无 `ifdef`（对照
pb_base 组 L258~265 有），无 STRIP/PB 档 96 FF 寄存器大概率保留。改法：三臂照 pb 组写法包
`ifdef`。收益 B0 −96 FF（XLR 0~48）；B5/B7 有 STRIP，零收益。

不建议动：PERF 数量×位宽（偏移布局是契约、软件全宽读差分）；配置寄存器窄化（「写什么读什么」
契约）；`err_*` 窄化（来源全 32 位且读回契约绑定）；`pc4` 三加法器写法（综合后是 2 位 popcount，
免费）；SURF 译码改除 3（成本同量级）。附带登记：L204 `(surf_diff >= 0)` 对无符号恒真，
零成本冗余文本。

### 3.3 engine_cmd（1329 行）+ engine_packet_check（100 行）

cmd 资源画像：`cbuf` 64×128 位两批乒乓命令缓冲（一批 ≤16 条=32 拍贴满，L242~259）≈ 7 块
RAM；FF 大头 = `counts[0:31]` 32×32=1024（条带表，STRIP 门控，L436）、`inst_packet` 256、
`w0/w1` 256、`i1_*` 输出组 ~330、`bi/k/base_r/count_r/n_*` ~160、错误四元组 ~128、
clip 64、rq/fe/n 控制组 ~150；组合大块 = `ec_struct_ok`×2（u_ssrc/u_sdst，实测锚点各
386~400 XLR）+ `ec_fields`×1 + 优先链 + `calc_n` 38 位函数按**不同输入**展开约 4 份
（每份 38 位加/减 + 33 位减 + 比较链 ≈150~250 XLR）。packet_check 只被 engine_bin 例化
（cmd 不例化），其分析见 4.5。

**K1 `counts` 寄存器堆 RAM 化（B5/B7 档，STRIP 门控内）。** 现状 L436 `reg [31:0] counts
[0:31]`：表头 4 拍每拍写 4 字（L1219），读只取 `counts[strip_id]`（L1229/1238）——单写口
（128 位/拍=4 字段）+ 单变址读的存储，却用 FF 堆 + 32:1 变址 mux 实现。改法：4 bank 交织
（每 bank 8 深×32 位，`i%4` 归 bank，每拍各写一字；读按 `strip_id[1:0]` 选 bank、`[4:2]`
做 bank 内地址 + 4:1 输出选择），推断 4 小块 RAM 或 1 块宽口；同步读多的一拍在
S_HREAD 末拍→S_BNEXT 的空隙里消化（strip_id 在上一带 S_BWAIT 已知，可提前驱动地址）。
预期 **−300~500 XLR**（1024 FF=512 XLR 容量 + ~200~400 变址 mux LUT，扣 RAM 化新增选择）。
风险：S_HADDR/S_HWAIT/S_HREAD 节拍微调 + cmd 正文重排须整机同轮复核。验证：条带表头
逐字回读、30 带循环、`INJ_STRIP_HEADER_OFFSET` 注错轮、STRIP 档 feature-function。

**K2 S_FETCH 与 S_SWITCH 的「预取下一批」重复块合并。** 现状：L840~859（S_FETCH 内）与
L1111~1130（S_SWITCH N_OK 分支内）两段几乎同构——同一套 `calc_n` + 38 位地址加法 +
`n_bi/n_bn/n_half/nst/rq_*` 赋值 + `pf_armed` 触发，差异仅在输入索引（`bi+bn` vs
`n_bi+n_bn`）与两处寄存器复位细节。同输入的 `calc_n` 多次调用会被 CSE 合并，但这两段是
**不同输入的两份**。改法：抽公共组合块（输入 = 批首索引，输出 = 预取请求五元组）+ 两处
调用，或合并为一个预取子状态机。预期 **−150~300 XLR**。风险：状态机正文重排（cmd 不在
冻结清单，但同轮整机复核必须）；两段复位细节差异要逐句对齐（`nst<=N_INFL` 时机）。
验证：批边界推进用例（16/17 条跨批、地址截断批）、预取 SLVERR 不上报、`INJ_NO_FB` 轮。

**K3（存疑，先对照权威再动）无 TEX 构型的 `tex_ok` 项恒 1。** 现状：`ec_struct_ok`
L49~52 的 TEX 结构检查（`{31'd0,h}<<sl` 47 位移位 + 48 位加法 + 16KiB 界比较，每份
≈100~150 XLR）**无条件编译**，无 `GFX_HAS_TEX` 档（如 B0）也在编译输入里。语义疑点：
space=1 且结构非法的表面，现状 `ok=0` 走 BAD_SURFACE，而手册 7.2 说无 TEX 时
「space=1 归 BAD_SPACE」——两说并存，**须先对照 `sw/lib/gfx/check.c` 的权威顺序**：
若权威就是 BAD_SURFACE 优先则不能恒 1；若权威是 BAD_SPACE 则恒 1 反而是改对（顺带省
2×(100~150)≈**200~300 XLR**，B0 档）。验证：feature-contract 全档轮询读回 + space=1
负例的三档构型 A/B。**先查证后立项。**

**K4（攒批）`w0/w1/inst_packet` 去复位。** L704/L770/L908 等处 544 FF 数据通路带同步
复位，下游 S_RUN/S_DISPATCH 状态机把关（w0/w1 只在 S_RUN 消费）。省 544 条复位连线，
XLR 收益存疑（Efinix 复位走 LUT 输入侧）。与 pix C3 同批评估。风险：X 传播纪律。

微项（攒批池）：`strips_r` 6→5 位（lstrips≤30）、`fe_d` 2→1 位、`rq_first` 比较的
9 位扩展可收。`global_nbi`（L453）正常编译无消费者（只在 `INJ_NO_FB` 分支用），常量
传播已剪，零成本登记。

不建议动：`cbuf` 形状（两批乒乓是预取契约，64 拍贴满）；`k/bi/global_*` 32 位与
`k<<5` 38 位运算（list_count 全宽契约，输入各异难共享）；S_RUN 单拍十步检查的流水化
（无 place 证据的时序路径不动，同 pix C4 纪律）；`inst_fields_bad` 与 packet_check 的
同口径重复（数据来源与时机不同，共享=跨模块耦合，同 bounds/geom 结论）；`err_stage`/
ras_* 组（RAST 门控契约）；`fe_bd_exp/rcv` 6 位（满批 32 拍贴域）；R-1（regs 表面表
BRAM 化）对 cmd 的联动改一拍同步读已计入 R-1 风险。

### 3.4 engine_geom（452 行）

资源画像：FF 约 326（数据通路 225 + 命令锁存 95）；组合三块——五者求交网络约 26 个 32 位
运算（L129~198，估 400 XLR）、起拍地址通路两个 32 位桶形移位+6 个加法器（L401~407）、
段计算 dst/src 对称两份（L234~311）。整模块估 900~1100 XLR。

**G1 求交与坐标中间量 32→18 位有符号。** 现状：`t_x0/t_y0/t_x1/t_y1/dx1/dy1/s_hi_x/s_hi_y/
sx_off` 全 32 位，26 个 32 位运算。改法：中间量与比较全改 18 位有符号（入口符号/零扩展），
求交结果进地址通路处再扩回 32 位（`dst_cur/src_cur/nb/stride` 不动）。预期 **−150~200 XLR**
（每个 32 位运算 16 XLR → 18 位 9）。值域已核算：最坏 `s_hi_x = (32767−(−32767)) + 65535 − 1
= 131068 < 2^17`，18 位恰好够、**不能压到 17 位**；`band_y0+STRIP_H−1 = 65550` 在界内。
`engine_bounds` 已是 18 位同款（本模块就是 geom 应对齐的参照）。风险：符号/零扩展边界错；
`i_empty` 与 `INJ_BAND_CLIP/INJ_SKIP_SURF` 注错分支逐句等价保留。验证：全量回归 +
geom_model.py 期望序逐笔比对；重点用例 = 65535 宽高、负 `dst_x/dst_y`、反向 clip、
`band_y0=65520` 邻域、源表面刚好压界。

**G2 计数器位宽裁剪（攒批）。** `row_i/nrows` 16 位但 ≤480、`py` 16 位但 ≤479、`nb` 32 位但
= npx×4 ≤ 2560：改 9/9/9/12 位，省 41 FF，LUT ≈ 0，**XLR 收益存疑**（FF 富余时为 0）。
与 G1 同轮做，值域语义不变（`sb_row/sb_py` 16 位端口高位补零）。

不建议动：段计算 dst/src 对称两份（同拍并发，时分复用改握手节拍；`alen ≠ s_len` 无公共子
表达式）；`dst_stride/src_stride` 改存 `slog2`（桶形移位器搬进每行路径，LUT 换 FF 负收益）；

## 4 可选层（B5 类全功能档编译；B7 编译 tex/band，不编译 PB 簇与 inst）

构型归属：tex←`GFX_HAS_TEX`；band←`GFX_HAS_BAND_HW`；inst←`GFX_HAS_INST`；
pb/pb_dma/bin/bounds/packet_check←`GFX_HAS_PB`。整模块裁剪已由 feature_config.py 管理，
本章只登记**模块内部**的省法。

**前置门槛实验（tex/band 候选共同的第一步）**：Efinity/Synplify 能否把「带字节/lane 写使能
的宽阵列」推断进块 RAM，全仓无先例（mover 的 wstrb 施加在总线层、pix 行缓冲是全宽写）。
推断失败会回退分布式 LUT（灾难性）。先花一次试综合验证，失败则本章 RAM 类候选全部搁置。
RAM 类候选的块数归因跨轮零波动，是最干净的一类。

### 4.1 engine_tex（236 行）

资源画像：4×(1024×32) 1R1W = **16 块 RAM** + 整模块仅 **116 XLR**（实测；`READ_LATENCY=1`
常量折叠已剪除 L2 级寄存器）。

**T1 四 bank 合并单阵列 1024×128、32 位 lane 写使能。** 现状 L185~195 每 bank 独立
`mem[0:1023]`，写使能本就逐 bank（`paddr[3:2]==b`），读口四 bank 同行并联。改法：单阵列
`mem[0:1023][127:0]`，写口字段写（标准字节使能推断写法），读 mux 原样。收益 **16→13~14 块
（−2~3 RAM）**。行为零改变（逐 bank 写 ≡ 逐 lane WE，地址同构）。验证：试综合看 RAM 计数与
LUTRAM 告警；tex 装载/回读、读流 CRC、B7 采样延迟拍数回归。

不建议动：`q1/v1/l1/sv2/sd2`（常量折叠已剪，实测 116 XLR 反证）；数据通路复位（省孤立 FF
不省 XLR）；`prdata` 的 `:32'd0` mux（APB 契约）。

### 4.2 engine_band（546 行）

资源画像：4 lane×(2048×32 + 512×32) ≈ **36~40 块 RAM**（容量下限 32 块 = 640×16×128b，
纯纵横比浪费 4~8 块）；XLR ≈2.5~3.5K；九相 FSM。🔴 正文文本敏感族（同 bin）。

**B1 RAM 换形。** 小段 4×(512×32) 合并 512×128 lane-WE：**−1 块（两端实测锚点，确定）**；
大段 4×(2048×32) 合并 2048×128：模型估 −0~4 块（2048 深块内纵横比无锚点，存疑）。
风险：同 lane-WE 推断门槛 + 正文重排须整机同轮复核。

**B2 `desc_ok` 单点求值（存疑，攒批）。** 6 处展开（L232/233、L346/347、L373/374）每次内联
32 位减法+5 位桶形移位+掩码+三组比较。改一处求值六用。预期 0~300 XLR——操作数全是寄存器
纯函数，Synplify 大概率已做 CSE；若已共享则是纯文本扰动（负收益）。做之前先看 map 报告。

**B3 `cfg_ok` 检查拆两拍（低优先）。** L155~163 两条 48 位「加+变量移位+加」链只在 start_fire
一拍消费。EMPTY 后加 CHECK 态分两拍。−80~120 XLR，代价每条带 LOAD 前置 +2 拍（带宽无感）。

**B4 死代码登记（零面积，纯清理）。** `r_bg`（L135 声明、L398 复位、L424 写入，**全文件无
读取**）32 FF 死寄存器（综合已剪，删登记防误读）；`FLUSH_WAIT` 态（L124 定义、L176/L505 引用，
**无任何进入该态的赋值**）不可达，`flushing` 输出里的 `|| phase==FLUSH_WAIT` 为恒 0 项。

不建议动：2048+512 二次幂两段切分（防 2560 深取整到 4096 变 64 块）；rd/wr 描述符检查器共享
（两口可同时在途，共享需仲裁，ready 时序是契约）；`ws_ready` 同址退让与 `ras_hold`（1R1W
冲突护栏）；FLUSH 输出保持机制（契约）；位宽微项（`row[15:0]` 实际 4 位等，范围传播大概率
已裁）。

### 4.4 engine_pb（579 行）

资源画像：无块 RAM（`ref_cache/coord_cache` 是 128 位单拍缓存）；31 态 FSM（binary 源码编码）；
FF 约 1100~1200（`packet` 256、双 cache 256、snapshot/xy/uv 128、地址/错误组 ~350）；
子例化 engine_bin/pb_dma/`ec_struct_ok`×2（L178-179）。

**P1 `u_surface`/`u_target` 合一。** 两份 `ec_struct_ok` 严格分时（bg_ok 只在 CFG_BG、dst_ok
只在 CFG_DST）。三组 96 位二选一后接单实例。预期 **−290 XLR**（−390 锚点 + 96 mux）。
风险：谓词前加一级 mux 的时序复核。验证：非法 src/dst 表面报 code 4/stage 1 且错误身份不变。

**P2 `overlap()` 48→33 位。** L181-184 端口 48 位但 5 个调用点实参都 ≤33 位有效
（`input_end` 38 位但其 >2^32 时 L395 同表达式首项已独立触发 fault，截断不改变判决——该
证明写进注释）。10 个比较器 ×(48−33)/2 ≈ **−70 XLR**。验证：末端恰在 2^32、跨 2^32 回卷
的区间负例。

**P3 `cfg_bg_end/cfg_dst_end` 与 P1 共用 mux。** L170-171 两份 33 位「加+变量移位+加」，
两态分时且操作数与 P1 同源。复用后单份运算，**−100~150 XLR**。与 P1 捆绑同轮。

不建议动：pb/bin 双 `packet` 256 位寄存器与 L155 的 256 位 mux（构建/回放共享检查器的架构
代价，拆开复制检查器净亏 500+ XLR 且必动 bin 正文）；`command_packet` 重排 mux（uv/xy 到
COORD 阶段才确定）；31 态合并（填充态是时序流水，合并省 0 XLR 伤时序）；`bytes_r/list_r/
pb_r` 32 位（大地址配置是行为红线）；复位（已最小）。

### 4.5 engine_packet_check（100 行）+ engine_bin（379 行）

**PC1（B5 头条，已由主审复核数据流）删 `u_s`/`u_d` 帧级冗余谓词，约 −780 XLR。**
packet_check L43-44 例化两份 `ec_struct_ok`，其 `src_*/dst_*` 输入是**帧常数**：pb L223-224
把帧级端口直通 bin，bin L150-153 锁存后 L155 原样喂入；而 pb L178-179 在帧配置阶段
（CFG_BG L372 / CFG_DST L381）已用**同一谓词、同一组信号**检查过，不过则整帧 ERROR_DRAIN，
且配置从 go 到 busy 撤下保持不变——构建与回放全程 `src_ok=dst_ok=1`，L89 的 error=4 分支
不可达。改法：`wire src_ok = 1'b1, dst_ok = 1'b1;` 加证明注释；bin 侧锁存链
（check_src_*/check_dst_* 唯一下游就是 u_check）被常量传播自动剪除，**bin 正文一字不动，
无重排风险**。预期 **−780 XLR 左右**（386+400 锚点，即使打折 −600 以上），单条覆盖 B5
缺口 731 的大部。风险：packet_check 独立单测若直接喂非法表面会期望 error=4，用例需同步修正
（喂帧级前置条件合法的输入）。验证：PB 全量回归 + `INJ_BIN_*` 注错轮 + 帧级 CFG 负例仍报
code4/stage1 且错误身份（index=0、instance=FFFFFFFF）不变。

**bin 侧登记项：bucket RAM 形状先查证再定。** `bucket_ram` 32 深×96 宽（有效 89 位），若已
是 BRAM 则 5 块且 XLR 无关；**若实为 LUTRAM（32 深有此可能），加 `syn_ramstyle="block"`
反而是 −300~500 XLR 的赢法**。第一步 = 查 B5 档 hier_util `u_bin` 行 mem 列定方向。
换形（两桶一字 64×48=3 块 / 串行 20 位×5 拍=1 块）都要大动 L195-214 读写时序 = 大动正文，
🔴 仅在确认 LUTRAM 且块数紧张时考虑。

不建议动：FSM `syn_encoding` 属性（动正文，收益方向未知，先查 map 报告）；`next_clip`
与 bounds 合并（bounds 缺夹紧端点输出口，改共享模块端口牵连 bin 喂入，🔴）；CLEAR 态逐桶

## 5 三维层（B7 编译：r3/rlst/rast；rast 实测 L1 形态 9921 XLR / 20 RAM / 4 DSP）

数值语义（48 位边、19×18 乘、/16 舍入、严格 LESS、`(texel*c+127)/255`）是
[三维数值契约](../../../Main/doc/三维数值契约.md) 冻结契约，本章候选全部限定在「实现资源」
层面（乘法器映射、寄存器复用），逐值等价是底线。

**活证据（时序敏感度）**：rast 同源码仅 `TEX_LATENCY` 1→2，XLR 9921→12055（+21%）、DSP 4→7
——L2 形态三个调制乘法器自动进 DSP 而 L1 留在 LUT。Synplify 文本敏感在三维簇有最直接的
量级证据，任何候选必须同轮 A/B。

### 5.1 engine_r3（190 行）/ engine_rlst（507 行）：不动

r3：寄存器语义/cfg_bad/PERF 全部 CSR 冻结契约，FF-only 无 XLR 收益。rlst：`fifo_mem` 64×16
实测已进 1 块 RAM（此前担心的 64:1 异步读 mux 没有发生）；18 态 FSM 状态数由 AXI owner
排空语义决定（协议契约）；协议/越界检查组合冻结。卫生项（零收益）：`count_lo/rsvd_acc`
死声明、`S_CNT1/S_RSVD1` 无 case 分支，可顺手删。

### 5.2 engine_rast（791 行）

资源画像（实测 L1）：乘法器 = 19×18 有符号 ×4 **已进 DSP** + TEX 调制 8×8 ×3 **留在 LUT**；
RAM = z 四 bank 4×(2048×16 + 512×16) = 20 块；FF 大头 = 参数槽 2×32×32=2048、M_INIT 暂存
（pxh/pxl/pyh/pyl 732 + ep_en/ep_ed 156 + c_a1/c_a2 576 + c_sum 288）、扫描 acc/ar 576、
退休队列 8×88=704；数据通路复位本就不带（干净）。

**RA1（次选，几乎零数值风险）调制三乘法强制进 DSP。** L481-483 三个 8×8 无符号乘
（`head[57:50]*head[25:18]` 等）被 Synplify 判小乘法落 LUT（L1 实测 4 DSP 证明；L2 形态 7 DSP
证明工具能映射）。改法：操作数显式写成 18 位有符号宽操作数（零扩展后 `$signed` 乘），数值
恒等（同一整数积）；必要时查 Efinity 手书的 DSP 映射属性。预期 **−200~350 XLR**，DSP 26→29
（134 富余）。风险：零扩展高位可能被前端常量折叠仍回 LUT（存疑点），同轮 A/B。
验证：r2-synthesis L1 看 DSP=7 且 XLR 降；rast-ports + rast-rtl L1/L2 全量数值回归逐位不变。

**RA2（首选，收益最大）M_INIT 部分积捕获与归并融合。** 现状 L674-689 捕获级把 DSP 乘积切片
存入 pxh/pxl/pyh/pyl（732 FF）与 ep_en/ep_ed（156 FF），L690-706（4'd9）才归并成
c_es/c_a1/c_a2。改法：捕获拍直接写归并结果（如 `c_a1[0] <= (dsp_p[2][29:0] <<< 16) +
dsp_p[3][30:0]`），删 4'd9 整级与四组寄存器。这是**同一表达式前移 7 拍**，寄存位置变化、
消费点（4'd10/11）仍在后，逐值等价；附带每三角形 M_INIT 少 2 拍。收益：删 888 FF，估
**−400~800 XLR**（这些寄存器多落 FF-only 单元）。风险：DSP 组合乘输出→47 位加法链→FF 的
单拍路径变长，100MHz 边缘可行须 STA 确认；文本重排扰动。验证：rast-rtl 十万记录全量逐值、
r2-synthesis 同轮 A/B（面积+M_INIT 路径时序）。**保守备选**（时序超限时）：只融合
ep_en/ed→c_es（−156 FF）。

**RA3（大手术，后备）参数槽 RAM 化。** slot0/slot1 寄存器堆 2048 FF + `act_sel` 双槽读 mux
（~450 XLR）改 2 块 32×32 DPRAM，M_VALID/M_INIT 改顺序读出锁入工作寄存器（+~960 FF），
净 −600~1100 XLR + 2 RAM。M_VALID 拉长 ~25 拍（值序不变，脉冲类判据要复查）。**仅在
RA1+RA2 不够凑 `MULDIV_EXT` 预算时考虑。**

不建议动：z bank 形状（合并 2560 深块数不变仍 5 块/bank，非 2 幂深度有展开回 FF 风险；
RAM 预算不紧张）；48 位三套边/属性寄存器（行首值 `e_row` 换行语义要求独立保存，
`acc<=ar+gy` 同理，步数回推不可行因 fire0 可停顿）；8 项退休队列字段（88b 已紧致，
texel 全 32 位是 KEY 比较契约，深度 8 由 credit 契约锁定）；`clamp_uv`/宽度检查
（r3 侧常数绑定，常量传播已塌缩）。

## 10 负作用盘点与取舍分档（2026-10-28 追加）

判定口径（与立项人对齐）：**用富余资源换稀缺资源不算负作用**（DSP 余 134、RAM 余 51~151，
换 XLR 是本条目的目的）；**算负作用的是三类——拍数/延迟变化、模块间接口交付变化、吞吐与
N_max 类指标下降**。

### 10.1 有负作用的候选（7 条 + 2 条冻结）

| 候选 | 负作用类型 | 量级与性质 | 可否缓解 |
| --- | --- | --- | --- |
| R-1 表面表 BRAM 化 | ①拍数 ②接口 ③时序 | 每条命令检查路径 +1 拍（命令处理吞吐约 −5~10%；整帧影响待实测，240fps 余量下大概率无感，但极限 N_max 帧里是否可见必须板测）；软复位完成 +16 拍（清 valid 位的 FSM）；regs→cmd 表面读口从组合变同步=**模块间接口协议变化**（cmd 状态机加拍适配） | 不可消除，是方案固有代价；试点综合阶段连时序一起取证 |
| RA3 参数槽 RAM 化 | ①拍数 | 每三角形 M_VALID 校验 +25 拍（双槽流水能隐藏大部分；**最坏短三角序列裸奔，三角形吞吐下降**）；err 检出延迟 +25 拍 | 多数场景被流水隐藏；作为后备手段本身就限定「仅 RA1+RA2 不够时」 |
| I1 inst 双例化去重 | ②接口 | 两处例化重组为共享一份 + mode mux，cancel/go 源合并——**例化关系与控制汇合点都变**，是模块间 bug 温床；无吞吐负作用 | 独立工作包 + PB 构建与 v1-I 旧路径双全量回归；运行互斥已有帧层屏障背书 |
| B3 cfg_ok 拆两拍 | ①拍数 | 每条带 LOAD 前置 +2 拍；30 带/帧合计 +60 拍 ≈ 0.6μs，占 16.7ms 帧预算 0.004%，帧率无感 | 本身可忽略；收益也小，攒批顺带 |
| K1 counts 堆 RAM 化 | ①拍数 | 设计目标零节拍（strip_id 在上一带结束即已知，提前驱动读地址）；做不好最坏 +1 拍/带（帧级无感） | 零节拍写进验收条件 |
| K3 无 TEX 的 tex_ok 恒 1 | 行为变化 | 潜在改变 space=1+结构非法时的错误码归类（BAD_SURFACE↔BAD_SPACE）——**对外可见行为变化**，非资源问题 | **冻结待查证**：对照 sw/lib/gfx/check.c 权威 + 三档构型负例 |
| bin bucket 串行换形（20 位×5 拍） | ③吞吐 | 每桶读写 1 拍变 5 拍，PB 构建周期直接拉长 | **已排除**：换形只保留「两桶一字 64×48」无节拍变体 |

边缘两项（列验证项不算负作用）：RA2 的单拍路径变长是**时序收敛可行性**问题（不是延迟
负作用；成了反而是每三角形 −2 拍的正作用），STA 不收即启用分级备选；P1/P3 的谓词输入
mux 前移是时序余量微耗，同轮 setup 复核。

### 10.2 零负作用清单

同拍恒等或恒等变换，除工程纪律外无代价：**PC1、P2、PD1、RA1、RA2（行为上）、T1、B1、
B4、I2、G1、G2、M1、M2、K2（行为上）、R-2、pix C1/C2/C4/C6、微项池**。其中 RA1 是
「富余换稀缺」的正面样本（LUT→DSP，数值恒等、延迟更稳）；G1/C2 组合深度还变浅（时序
向正作用）。

### 10.3 吞吐与 N_max 零影响

第 7 章否决表当初已挡掉**全部**砍吞吐方案（4 像素/拍降 2、12 核时分复用、行缓冲深度
减半、band 两段切分改深取整、inst 串行化器改宽缓存），保留候选没有一条降低每拍像素或
三角形吞吐。N_max（SW9 口径，由命令表容量 32768 条、共享池 10MB、每帧拍预算共同限定）
对这些候选零影响；唯一待实测项是 R-1 的 +1 拍/命令在极限 N_max 帧里是否可见——收口判据
加一条「同轮板测 N_max 不降」。三角形/帧指标只升不降（RA2 −2 拍/三角形）。

### 10.4 RAM 净账（富余互换的边界，多项叠加后仍为正余量）

B7（现 187/256，余 69）：R-1 +12~18、RA3 +2、K1 +1~2，T1 −2~3、B1 −1~5 → 净 +8~17，
落到 ~195~204，仍余 52+ ✓。B5 同构比例更松（105 起步）。**结论：RAM 侧承接得起全部换
RAM 候选**；但省块的 T1/B1 应先做或与 R-1 同轮，避免中途出现 RAM 峰值。

### 10.5 取舍分档（推荐路径）

- **A 档（直接做：零负作用且单条/捆绑过噪声底）**：PC1 → P2 → PD1 → P1+P3（捆绑）→
  RA1 → G1。B5 起步约 −1370~1610，B7 起步约 −350~550。全量回归 + 同轮 A/B 收口即可。
- **B 档（值得做，按风险控制）**：RA2（先 STA 探路，时序不收即降级为只融合 ep 级）；
  I1（独立工作包，接口重组类，双全量回归）；K1（零节拍设计写进验收）；K2（重排纪律）。
- **C 档（条件触发，不主动）**：R-1——**负作用最重但单独收益最大，是「A+B 都不够」时的
  王牌**（先试点综合拿真实 XLR/RAM/时序三联数据再决定）；RA3（仅当 RA1+RA2 凑不齐
  MULDIV_EXT 预算）；B3 与 bin 两桶一字换形（各自前置条件满足才动）。
- **D 档（冻结）**：K3（查证前）；bucket 串行变体（吞吐负作用，永久排除）。

一句话路径：**A 档全做拿走确定收益 → 实测看缺口 → 缺 B5 容量上 I1，缺 MULDIV_EXT 预算上
RA2→RA3，R-1 永远最后。**
