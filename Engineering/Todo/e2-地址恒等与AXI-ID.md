# E2：CPU 地址与 DDR3 物理地址是否恒等，SoC 发出的 AXI ID 有多宽

状态：未开工。阻塞帧缓冲布局与引擎的地址通路，是设计文档第 7 节里排在最前的两项之一。
只需要现有比特流加一段程序，加一个探针寄存器需要重新编译一次。

## 1 要解决什么

顶层 `rtl/top/gfx2d_top.v` 在 SoC 与 DDR3 控制器之间做了两处位宽截断：

```
SoC io_ddrA                  ddr3_top
  awaddr[31:0]  ----+-----> s_axi_awaddr[27:0]      高 4 位丢弃
                    |
  awid[7:0]     ----+-----> s_axi_awid[3:0]         高 4 位丢弃
  b_payload_id[7:0] <------ {4'b0, bid[3:0]}        回来时补 0
```

两处都照抄官方参考设计，但官方设计只跑 memTest，没有第二个主机，也没有引擎按物理地址访问同一块内存。

地址这一侧要回答的是：软件写 `0x0100_0000` 时，数据落在颗粒的哪个物理地址上。
如果 CPU 地址与控制器地址恒等，驱动里下发给引擎的指针可以直接用 C 指针的值；
如果不恒等，驱动要做一次换算，所有涉及地址的寄存器都要跟着改。
CPU 看到的 DDR 窗口比颗粒大（`DDRSize` 是 `0xE000_0000`，颗粒只有 256MB），
超出 256MB 的地址会回绕到低地址，回绕的边界与方式要测出来，否则帧缓冲布局可能踩到自己。

ID 这一侧要回答的是：SoC 实际发出的 `awid` / `arid` 会不会超过 15。
超过 15 时高 4 位被丢掉，控制器返回的响应 ID 与 SoC 期待的对不上，
SoC 会把响应交给另一笔事务。这类错误在 memTest 这种单线程顺序访问下不一定暴露，
接入第二个主机之后才会变成随机的数据错误。

## 2 怎么切分

**第一步，地址恒等。** 用 OpenOCD 在 CPU 停住的状态下往 DDR 写特征值，
再用 JTAG 读回同一地址，确认调试通路与 CPU 看到的是同一份数据。
然后写一段程序，在 `0x0000_1000`、`0x0800_0000`、`0x0FFF_FFF0` 三处写入各不相同的特征字，
逐个读回。产物是一张 CPU 地址到实际存储位置的对照表。

**第二步，回绕边界。** 在 `0x1000_0000`（256MB 处）写特征字，读 `0x0000_1000` 起的那一段，
确认是否被改写。往上按 2 的幂逐个试到窗口上界。产物是回绕周期与可用地址区间。

**第三步，ID 位宽。** 在顶层加一个 sticky 寄存器，把每一拍的 `soc_ddr_awid[7:4]`
和 `soc_ddr_arid[7:4]` 按位或进去，从 `apb_probe` 新增的一个只读地址读出来。
跑 memTest 与一段带大量 cache miss 的程序，读这个寄存器。
读到 0 说明 ID 没有超过 15，当前截断安全；读到非 0 要记下是哪几位，
再决定是把控制器的 `AXI_ID_WIDTH` 改宽，还是在顶层加一层 ID 映射。

三步的顺序不能换：第三步要改顶层并重新编译，前两步不用，先做便宜的。

## 3 判据

| 项 | 判据 |
| --- | --- |
| 地址恒等 | 三处特征字逐个读回一致，且 JTAG 读回的值与 CPU 读到的一致 |
| 注错见红 | 故意读相邻地址，读回的值必须与特征字不同，证明判据能分辨 |
| 回绕 | 找到第一个使低地址被改写的地址，写明回绕周期 |
| ID | sticky 寄存器的值，以及产生这个值的程序名与运行时长 |
| 结论落地 | 结论写进 `doc/赛题二总体设计.md` 2.1 节与顶层注释，替换现在的「还没有查证」 |

sticky 寄存器读到 0 时要注明它只覆盖了测过的那几段程序，不是证明。
