# SoC 资源裁剪

状态：未开工。不阻塞引擎开工。晚做的代价是引擎成形之后再重新生成 IP，
`sdk/` 的登记项要再恢复一次，整套回归要再跑一次。

## 1 要解决什么

当前工程占 14517 个 XLR（23.9%）与 65 块片上 RAM（25.4%）。逻辑单元宽裕，
**稀缺的是片上 RAM**：全片 256 块，设计文档 2.3 节给引擎的预算是 108 块，
加上现在的 65 块是 173 块（67.6%）。余量够，但没有富余到可以白扔。

SoC IP 里生成了三样当前用不到的东西：

| 项 | 占用 | 怎么关 |
| --- | --- | --- |
| I2C0 | 约 350 XLR | IP 配置里关掉，重新生成 |
| `axiA` 16MB 从口窗口 | 约 20 XLR 与一部分地址解码 | 同上。控制寄存器走 APB 就够 |
| DDR 跨时钟 FIFO | **17 块片上 RAM** | 只有 Lite 版 SoC 能选统一时钟，要先做 E1 |

三项里只有第三项值得花力气，17 块占全片 6.6%。前两项顺手一起做。

关 I2C0 之前先看 [`摄像头实时图层.md`](摄像头实时图层.md)：那条如果还打算做，
传感器配置可以走 I2C0；关掉之后就只能在 APB 上另挂 I2C 主机。那一条顺位最低，
默认照关，但生成前要确认一次（2026-09-18 补）。

`io_ddrMasters_0` 那条外部主机通路（约 600 XLR 与 5 块 RAM）已经因为顶层不给它接时钟
而被优化掉了，彻底删除同样要重新生成 IP，可以搭这一次的车。

另外，Efinity 2026.1 自带 efx_soc 3.4.0，工程里是 3.3.0 生成的，
GUI 打开会提示升级。升级同样覆盖 `ip/soc/` 与软件包，与裁剪是同一件事，一并做。

## 2 怎么切分

**第一步，E1。** 生成一个 Lite 版 SoC，与现在的 Standard 版对比 CoreMark、RAM 块数、XLR。
统一时钟省下 17 块 RAM，代价是外设与 CPU 同频带来的性能差异，差多少要量出来。
这一步只比较，不改主线工程。

**第二步，定构型。** 根据 E1 的结果决定 Standard 还是 Lite，一并关掉 I2C0 与 `axiA`，
删掉 `io_ddrMasters_0`，升级到 3.4.0。一次生成，一次改。

**第三步，恢复登记项。** 按 `sdk/README.md` 的「已登记的修改」逐条改回：
bootloader 的 `USER_SOFTWARE_SIZE` 改 `0x080000`、链接脚本的程序区改 4092K、
镜像超限断言、重新编译 bootloader 并同步 8 个片上 RAM 初始文件。

**第四步，顶层跟进。** 关掉的端口从顶层例化里删掉，同步改 `peri.xml`，
`rtl/README.md` 与 `fpga/README.md` 的表跟着改。

**第五步，软件跟进。** 3.4.0 的软件包模板 `-march` 带 `_zicsr_zifencei`，
同步之后可以改用 IDE 自带的 gcc 13.4，`../../Main/doc/开发环境.md` 第 2、7 节与 `../../Main/sw/README.md` 的编译命令要一起改。
改完之后 `sw/apps/test/bootSizeTest` 的两个 CRC 期望值要重新计算，因为工具链变了。

## 3 判据

| 项 | 判据 |
| --- | --- |
| 生成前 | 工程已提交或备份，否则覆盖不可逆 |
| 登记项 | `sdk/README.md` 的表逐条核对，bootloader bin 的 SHA256 与片上 RAM 初始文件一致 |
| 编译 | 四步 PASS，约束告警 0，位宽截断告警仍只有厂商加密文件里那 2 条 |
| 资源 | 与 `../TechReports/platform/01-从零搭起可上板的硬件基线.md` 5.1 节的表逐行对比，写明每一项的变化来自哪一个改动 |
| 归因 | 当前基线相对官方工程有约 506 个 XLR 是差额反推出来的，没有逐项归因。这一刀要重新生成 IP、重跑布局，正好借层次报告把这部分认领掉，不要让它一直挂在表里 |
| 时序 | `core_clk` 与 `sdram_clk` 的 setup 与 hold 全为正，hold 与改前对比 |
| 上板 | APB 探针四项、memTest PASS、HDMI 八色竖条，三项都过 |
| 启动 | `bootSizeTest` 的两个 CRC 与新工具链下重新计算的期望值一致，官方 124KB 比特流作对照组仍然不一致 |

最后一条的对照组不能省。它是唯一能区分「512KB bootloader 生效」与
「程序恰好短到 124KB 也能跑」的判据。
