# 绘制前端 F3 保序分桶与模板复用

状态：**待验收（候选未采用）**。前置：[F1](绘制前端F1-成本分解与基线.md)；可独立于 F2 实现与对照。
范围：保留 ABI v2 的纯软件构造候选。共同契约见 [总览](绘制前端总览.md)。

决策依据：engine 第 11 章 D68、D69、D72；稳定引用与模板分别消融，原语义保持。

## 1 要解决什么

当前每颗按覆盖桶复制完整记录；固定 32 KiB 桶距离和交叉访存可能造成成本。
目标是改变构造期间的数据组织，最终提交的 v2 表与原实现逐字节一致。
现有 `gfx_blit_run` 已复用模板检查，本批评估剩余几何与输出工作。

## 2 怎么切分

### 2.1 延迟物化的稳定分桶候选

新入口 `gfx_list_begin_strips_planned` 显式接收调用方提供的 plan/ref 工作区，
后续仍通过原绘制 API；原 `gfx_list_begin_strips` 的立即写入行为保持。
planned 模式的物理表仅在 `gfx_list_end` 成功 seal 后可消费；调用方不得在 seal
前读表。逻辑 used/错误记账在追加时更新，表头发布在 seal 成功后完成。

```text
1. 按原输入序规范化、检查、裁剪 -> Plan[U]，同时得到 counts[S]
2. exclusive_scan(counts) -> offsets[S+1]
   按 Plan 原序把 plan_id 放进 refs[offsets[s]+cursor[s]++]
3. 按 s=0..S-1 读 refs 区间 -> 连续生成该桶的完整 32 B 记录 -> 发布表头
```

第 2 步仍散写小引用；第 3 步才连续写 32 B 记录，包含按引用读取 Plan 的成本。
复杂度 O(U+M+S)，禁止默认逐桶重扫 U 份输入。参考为 Blelloch scan 与工业 PB
组织，具体来源见 engine 第 11 章；不因用了 scan 就假设能快于单遍实现。

### 2.2 数据与容量

每个 plan 项定为 48 B、16 B 对齐：前 32 B 为全局裁后的普通命令，随后
`first_strip:u16, last_strip:u16, logical_index:u32, reserved[2]:u32`。
保留必要的源偏移与全局目的坐标，物化时再裁成局部 y、重建 w7。
零面积/完全裁出不进入 plan；NOP 保持原来的桶 0 行为；SET_CLIP 更新构造状态。

引用为 `plan_id:u32`，按桶紧凑排列；counts/offsets/cursors 各 32 个 u32，
不以 32 KiB 步长隔开元数据。工作区容量由调用方提供并先检查地址/长度。
上界 U=32768 时 Plan 为 1.5 MiB；M≤30×1024 时引用为 120 KiB，双在途帧
工作区分别拥有，或明确只能一帧计划在途。不能复用 CPU 正在改写的 plan。

本批不改变提交的 1 MiB v2 区、首段表头、1024/桶、计数数组与硬件取数公式。
工作区由共享区显式划分，不占用 A/B 命令区、素材或 framebuffer。

### 2.3 原子性、错误与发布

追加时先完成旧 API 的参数/关闭/字段检查与反馈检查；预检本次覆盖的所有桶，
任一满则本次不增加任何 counts/plan/ref，不占逻辑或物理索引，后续调用仍按旧
记账处理。已裁出与零面积仍保持原字段检查顺序。

工作区不足是新入口的显式构造错误：在写 plan 前预检，sticky 首错阻止提交。
seal 不可在末尾才发现预先可知的容量不足；任何 seal 失败都不能发布有效表头。
成功 seal 后只允许原 CLOSED 语义；二次 end、故意打开关闭表及错误后的追加做差分。

物化按桶和原序生成：w1 的源裁剪偏移、w2 的局部 y、w3 的片段尺寸、w7 的
s×1024+j 均与原构造相同。未经 END/seal 的计划不得提交；renderer 对新模式
加入 sealed 检查，原路径检查不放松。

### 2.4 几何模板候选

在稳定分桶独立验证之后，再做可单独开关的模板对照。键只包含共享绘制字段、
尺寸、源位置/描述符 generation、strip_log2、裁剪 epoch 与相位 `dy mod H`。
首版只对完全位于源/目的/clip 内的矩形缓存 leading/interior/trailing 片段模式；
边界、负坐标和源越界退回完整求交，不能弱化检查。

模板缓存由构造上下文持有，设置明确容量与替换策略；失效、未命中时走普通算法。
宽高、源图集位置或 epoch 变化必须改变键。实例跨带后桶位置和 w7 会变化，
没有稳定槽位证明时仍完整写 32 B；本批不采用跨帧“只改两个字”的隐含旧内容复用。
模板的生成、查找、miss、代码体积与缓存影响全部记入成本。

### 2.5 实施与消融

| 候选 | 对照 | 目的 |
| --- | --- | --- |
| P0 原单次追加 | 原生产 v2 | 固定基线 |
| P1 planned/ref/连续物化 | P0，同状态同地址 | 只改变访存组织 |
| P2 几何模板 | P0，共同模板检查保持 | 只改变重复几何计算 |
| P3 两者组合 | P0/P1/P2 | 验证收益可组合，不能直接相加 |

修改集中在 `lib/gfx/strip.c`、内部计划模块、`gfx.h` 的新入口与 renderer seal
检查；游戏只通过后端选择启用，不在弹种表中编码优化。检查器与计量复用 F1。

## 3 判据

- ≥10000 张确定性随机场景，seal 后整张 v2 表逐字节对原生产实现；返回值、
  used、first_error、rejected、overflow、ended 一致，计划区越界由 sanitizer 检出。
- 溢出发生在中间桶时整次不追加；后续合法调用的 tag 仍一致。模板键遗漏源位置/
  epoch、引用顺序颠倒、尾片裁源少一行、seal 提前发布四类变异必须见红。
- 非游戏矩形、六方程、图集不同源位置、合法 H/高度组合、动态 clip 和别名全覆盖。
- 独立像素对照与完整宿主回放沿总览；byte 一致只能证明构造兼容，不替代板上性能。
- P1/P2/P3 分别报告周期、额外字节、workspace、代码体积和 cache 对照。
  无净收益时默认保留 P0；不为“连续写”这一名称强行采用三阶段实现。
