# SW17 可选应用集合与快照固件

## 状态

待验收（2026-10-30，已完成选定软件、四档 JTAG、原生 PC 两版本及交付核对，等待用户试玩）。

## 1 要解决什么

B0/B3/B5 无 RAST，却随附与 B7 相同的完整 BIN。产品源码、菜单、PC 参数、面板和
验证器仍有固定四应用假设。交付仅含 demo/stg/press 的 2D 固件与含 R4 的完整固件，
应用数量由清单决定；系统菜单/about 不计入内容数量。保留现有稳定 ID 和输入协议。

## 2 怎么切分

1. 单一应用目录与产品配置：生成注册/元数据/构建依赖，2d/full 和自定义集合；配置进入
   构建身份与独立输出目录；裁掉 R4 内容、atlas、启动引用及无消费者的专用库。
2. 目录元数据驱动能力检查与快捷入口；菜单隐藏不可用项，滚动与空内容；PC ID/name 查询。
3. 面板消费版本化目录，未知应用仍可显示和通过菜单导航；不扩展按键位图。
4. 交付工具按清单核对 PC/BIN 内容集合、位流能力和素材预算；固件身份与硬件身份分开。
5. 检查按所选集合判定，增加稀疏 ID、多页、多个三维应用、坏配置和真实裁剪反例。
6. B0/B3/B5 绑定同一 2D BIN；B7 完整 BIN。PC 两个版本及实板验证、文档和试玩交付。

## 3 判据与范围

- 不改 RTL、厂商 SDK、Flash 布局或素材像素；现有位流摘要必须不变。不写 Flash。
- 2D 包仅 demo/stg/press 加系统功能；ELF/MAP 不含 R4 内容/atlas；full 保留三维。
- 运行时以实际能力保护所有入口，分类不等于硬件能力。ID/名字唯一，非连续 ID 可启动。
- 0/1/3/多页条目导航、缺能力、重复/未知应用和配置切换不混入旧对象。
- 构建检查核算程序镜像 512 KiB、运行内存、素材 4 MiB；表面槽按活动应用复用。
- 初期定向 quick；冻结后 acceptance 选择 console、应用集合专项、platform-sdk、layers、
  pack 与受影响的游戏/统计消费者。Windows 原生两版本构建与窗口目检。
- 实板按 B0/B3/B5/B7 实际部署，绑定 bit/BIN/素材与原始日志；前三档不要求 R4 出帧，
  full/B7 必须有三维完成帧。人工 HDMI/实体输入与自动检查分开记录。
- TechReport 与证据归档后状态改待验收，用户验收前保留本文件。
