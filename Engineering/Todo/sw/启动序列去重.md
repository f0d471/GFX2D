# SW14：启动序列去重（gfx2dGame → stg_runtime 能力整合）

## 状态

未开工（2026-10-28 立项，原「SW10 收尾的去重」经盘点升级为能力整合工作包）。
不阻塞任何判据；产品线第二迭代（摄像头）开工前完成即可。

## 1 要解决什么

`apps/common/stg_runtime.c` 与 `gfx2dGame/main.c` 是同一段启动序列的两份实现
（内存窗口、素材包装载对账、TEX 热集、后端覆盖层、r4 钩子）。2026-10-28 盘点
发现**这不是机械去重**：main.c 的本地版本携带 stg_runtime 缺少的判据能力——

- `INJECT_TEX_CRC` 注错钩子（TEX 读回 CRC 注错）；
- `G1_TEX_COMPARE` / `G4_STRIP_COMPARE` 的影子缓冲与 `s_mem.tex_host` 接线
  （DDR/TEX 对拍构建的比对基准）；
- `backend_apply` 的 mode 感知（演示/r4 独占 TEX 的排除逻辑在 console 版里
  是写死的另一套语义）；
- boot_asset 走 `sw6_log_pak`（golden 格式）而 stg_runtime 打自己的
  `pak len …` 格式——统一前 console 判据脚本的 marker 依赖两种格式并存。

直接换用会把对拍/注错能力删掉。去重的正确形态是**把能力先并入 stg_runtime，
再让两个消费者共用**。

## 2 怎么切分

1. stg_runtime 吸收能力：TEX 装载加注错钩子与影子比较（`#if` 门控，缺省关）；
   `backend_apply` 加 mode 参数（调用方声明自己的 TEX 独占语义）；
   `say_pak_line` 统一为 golden 格式（console 判据 marker 同步改）。
2. main.c 换用：静态实例收敛为 `stg_runtime s_rt`（引用量 ~160 处，用
   `#define s_pak (s_rt.pak)` 系宏零改动落地），删除 boot_mem/boot_asset/
   boot_fail_report/boot_tex/tex_overlay/backend_apply/r4 钩子本地版；
   boot_surfaces（sw6 演示表）与 boot_precompose 保留（单一消费者）。
3. 验证：host 双构建零告警 → **sw6 期望日志按 21 项包再生**（前置欠账）→
   sw6 quick/全量判据逐字节 → 板上 240 帧回归（HW 后端 60fps drop=0）→
   console 判据复跑 PASS。

## 3 判据

- `stg_runtime.c` 与 `main.c` 不再有同名的 boot/tex/backend 重复段；
- sw6 判据（全量+quick，新包期望日志）与迁移前逐行相同（pak 行起）；
- console 判据全链 PASS 复跑；
- 板上回归 240 帧 HW 后端 60fps drop=0。
