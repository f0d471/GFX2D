# 绘制前端总览：构造、实例与空间分桶

状态：**F1～F4 已验收归档（F1～F3 于 2026-10-10、F4 于 2026-10-11，条目已删除），F1～F3 候选未采用；F4 交付直通实例 profile（开关默认关）；F5/F6 未实施**。P3/G4 已验收，接续依据为
[engine 第 10 章](../../TechReports/engine/10-整机与Nmax实测.md)的整机结果；
本轮 D64～D76 的制定依据、候选取舍、实证与归档结论集中在
[engine 第 11 章](../../TechReports/engine/11-绘制前端方案研究.md)。

本系列交付可复用于一般矩形合成的绘制前端。游戏继续在 CPU 上完成运动、发射、
碰撞和规则；前端只接收绘制状态、几何属性与资源描述。当前 4KB/1 路、100MHz、
16 行 BAND 保持主线；16KB/4 路仍为候选，不用扩大缓存代替结构优化。

## 1 要解决什么

### 1.1 基线与目标

| 同轮 G4 构型 | 16×16 N_max / K | 8×8 N_max / K | 资源与证据 |
| --- | ---: | ---: | --- |
| 4KB TEX 直通 | 1891 / 1648 | 2237 / 1984 | 同位流基准，不以历史 P1 的 1014/1365 充当及格线 |
| 4KB STRIP | 424 / 384 | 505 / 464 | 41476 XLR / 163 RAM / 16 DSP；3600 场确认 |
| 16KB STRIP 候选 | 479 / 432 | 597 / 544 | 40795 XLR / 181 RAM / 16 DSP；3600 场确认 |

目标：在保持画面与负载的前提下，消除条带构造造成的整机退化；采用的最终路径应
在同轮、同构型、同程序的两种弹型搜索中均超过 TEX 直通。1891/2237 是已登记基线，
新批次以同轮 TEX 实测为比较对象，不把某个预期 N_max 写成已知收益。

每批分别记录“规格/模型验证”“实现正确”“净收益”“采用”四种结果。
正确但无净收益的候选可保留研究结论，默认后端维持上一已验证路径；不能把候选
自动转正，也不能将研究结束记作优化成功。

### 1.2 两笔成本与一笔固定项

定义 U=输入绘制/状态包数，I=实例包内元素数，M=跨带后的引用/片段数，S=条带数。
标量路径没有实例包；实际逻辑矩形数为标量 FILL/BLIT 数加 I，不能直接用 U 或 M 代替。

```text
CPU：游戏逻辑 -> 状态/实例生成 -> 裁剪/计数 -> 分桶 -> 物化 -> 发布
GPU：预合成(可选) -> binning(可选) -> LOAD -> EXEC -> FLUSH -> 完成
扫描：                                 已完成帧 -> 请求交换 -> 场边界
```

当前观测模型的 CPU build 固定项约 0.93M，边际约 635/563 周期/可见敌弹；
相应物理记录边际约 1.92/1.41。固定项、M/I 放大、每片段成本分开测量。
计数实验的高负载背景/HUD 占比约 13%~22%，低负载可接近一半；不能用记录数减少
比例代替 CPU 或帧时间减少比例。

流水帧预算按实际依赖算：

```text
C_cpu = C_logic + C_state + C_instance + C_bin + C_emit + C_publish + C_other
C_gpu = C_prepass + C_hw_bin + C_load + C_exec + C_flush
C_critical >= max(C_cpu, C_gpu)，另计依赖空泡、交换与统计/日志的实际时间
```

同一引擎上的预合成、binning 和渲染依次占用硬件；这些项不能从预算中消失。
`cyc_exec` 含收尾墙钟时间，GPU 忙时间看 PERF_BUSY；计数前后保持原日志和确认周期。

### 2.2 共同架构契约

决策编号沿用 engine 第 11 章的 D64～D76；这里列出各实施规格共同遵守的约束。

**顺序（D72）。** 输入是已经确定的绘制序列。共享状态相同只允许合并连续区间；
不额外按弹种/材质排序。每桶是原输入的稳定子序列，实例内部按数组索引递增。
两个条带的目的像素不相交；同一条带仍保持原相对次序。ALPHA/ADD/CONST/MUL
一律按原方程和舍入执行，不假定可交换。

**状态（D72）。** 裁剪框、源/目的描述符和格式构成 draw 状态。SET_CLIP 产生
状态 epoch；旧 v2 仍在 CPU 吸收。新前端必须在该 draw 被接受时保存其裁剪语义，
不能让执行时的末次 SET_CLIP 追溯覆盖以前的 draw。

**内容依赖（D67/D72）。** 目的反馈、跨 pass 读写和重叠别名先分类。条带/PB 路径继续
拒绝 DDR 源与目的 backing 区间相交；支持的直通同槽路径保留原检查。背景面是
本次 pass 的完整初值，动态直通 prepass 的完成先于 BAND LOAD。

**通用边界（D65）。** 库和 RTL 接口只包含矩形、表面、方程、裁剪、数组、容量、
地址和完成信息。STG kind、纹理内容、图集固定地址、K 值、游戏状态只出现在
应用适配与测试夹具。必须验证非游戏矩形、变化的图集源坐标和多种尺寸/方程。

**编码分层（D70/D71/D72）。** F2/F3 保持现 v1/v2 字节接口。F4 新增能力可查询的 v1-I
实例 profile；F5 使用独立版本的内部 PB。旧 v2 的表头首段、1024 条/桶、
ERROR_INDEX=s×1024+j 保持原义；PB 的总引用容量和逻辑错误索引另行定义。

**所有权（D73）。** 帧上下文拥有输入、实例、计划区、PB 与背景页；发布到 DONE/ERR
且排空完成前不可改写。A/B 双表各有完整资源集合或明确的串行租约；不能只双缓冲
命令指针却复用仍被 GPU 读取的实例数组/背景/PB。切后端前显式 flush。

**错误（D72/D76）。** 失败表不呈现；不自动拆帧、跳过出错实例继续显示，或在已有像素
写入后静默切软件重画。CPU 参数错、容量错、DMA 错与像素错分别登记。旧 API
的 FULL/CLOSED/字段优先级和逐次调用原子性由差分保持；新 API 明确发布失败边界。

**计数（D64/D76）。** 逻辑 draw、实例、片段/引用、编码包数分别报告。旧九项 PERF
原偏移不变；实例/PB 路径增量计数追加，不把“编码命令减少”解释为绘制工作减少。
多阶段读写字节必须包括预合成、metadata、引用、重复实例取数和 padding。

**资源（D66/D73/D74）。** 不修改 SDK 生成物实现前端。新增寄存器从 `regs_gen.py` 生成。
F4/F5 增量分别先按 ≤4/≤8 RAM 作研究预算，实际以独立综合和整机为准；
两缓冲 BAND 额外约 36 RAM，4KB 总量约 199 加前端增量，16KB 约 217 加前端增量。
三套 BAND 相对当前额外约 72 RAM，分别约 235/253 加前端增量，列为资源高风险候选。

### 2.3 复用到后续图形路线

| 本系列技术点 | 后续复用边界 | 当前不扩大的范围 |
| --- | --- | --- |
| pass、attachment 初值、完成与租约 | 二维 UI、离屏合成、显示/视频多层 | 多层硬件 overlay、脏区显示协议 |

未来扩展需要新的 geometry kind、版本和验证；不能声称现有 BLIT 编码已经能无损
承载任意三角形或着色器。

## 3 判据

### 3.1 每批共同的正确性门槛

1. 独立直通软件执行器为像素基准；F3 另与原 v2 做字节/错误差分。F4/F5 用
   独立展开模型生成标量 draw，不能拿同一错误展开器互相证明正确。
2. 至少 10000 张确定性随机场景，固定种子；覆盖六方程、色键、负坐标、源越界、
   零面积、跨带、裁剪 epoch、反馈别名、容量边界、地址回卷和关闭/复位；ASan/UBSan。
3. 每项新关键不变量有定向反例和注错；错误版本必须在指明的消费者处失败。
   RTL 注错使用条件编译，正常输入不包含注错逻辑。
4. 涉及 RTL 的批次采用真实模块、变量输入和随机反压；已有 v1/TEX/v2 回归保持。
   综合必须记录全域与 core_clk setup/hold，负 slack 不采用，报告与 +0.026 ns 基线的差异。
5. 最终候选宿主完整 9208 帧与直通逐行一致；新板测至少跨关卡 17 帧同帧 CRC/PERF，
   采用前完整硬件 9208 帧对拍。旧 G4 回放证明基线，不能代替新候选结果。

### 3.2 性能与采用门槛

- 单项实验采用同状态、同地址、同预热、同显示争用的 A/B；每配置三次，记录
  原值、p50/p99/最大值和噪声。差异小于 2% 或重复性差于 2% 时先查机理，不宣称收益。
- 单项采用至少有关键路径周期下降且输出工作相同；收益必须包含新增准备、传输、
  验证外溢及依赖空泡。研究探针计时外消费输出，发布性能沿生产统计频率。
- 最终同程序同位流保留 TEX 与候选后端，按当前 `core/nmax.c` 的原参数自动搜索；
  两型各最终 3600 场零掉帧，zero/under/faults=0；同轮 TEX 也完整确认。
- `N_max` 同时报 K、实际活动数、CPU/GPU 分段、物理流量和 FIFO 水位。
  只有候选两型均超过同轮 TEX、正确性与资源门槛均过，才能宣称消除 P3 整机退化。
- 不能通过降低活动数、改图、停背景、冻结 HUD、减少统计、缩短确认、关扫描输出、
  降低时钟口径或改变游戏状态推进来取得“优化”。

### 3.3 交付与证据

每批产物包括源码/接口、独立判据、原始日志、摘要与 TechReports 正文。
临时构建进各自忽略 build/；参考实现的来源/版本与实际借鉴边界写进报告。
部署产物的身份登记复用唯一清单，仅跨构建/传输边界重新检查。

F1～F3 交付软件实现、研究判据与板端证据，保持现有生产 ABI；F4～F6 仍按
各自前置启动。候选是否采用由同状态成本与整机门槛决定，未采用的研究不更新
作品性能数字。采用后才联动总体设计、台账、作品报告与幻灯片。
