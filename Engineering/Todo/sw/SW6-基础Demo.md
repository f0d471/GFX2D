# SW6 基础 Demo

状态：未开工。前置 SW3、SW4 都已就位（2026-09-21，构造层与执行器在 `sw/lib/gfx/`，PC 侧的窗口与帧节拍在 [sw 第 03 章](../../TechReports/sw/03-PC平台层与帧节拍.md)）；SW5 未完成时用占位图。对应赛题基础要求 3。

## 1 要解决什么

赛题基础要求 3 原话是「大量方块随机移动」与「多张大图快速切换」，并且屏幕上**实时对比软件与硬件渲染的帧率**
（设计文档 4.3 节「基础 Demo」一行）。这是评审最先看的东西，也是整条渲染链路第一次被真实负载驱动。
它比游戏简单，适合先把「逻辑 → 命令表 → 执行器 → 显示」这条链路的每一环跑通。

## 2 怎么切分

### 2.1 场景 A：方块随机移动

- N 个方块，位置与速度用 Q12.4，碰边反弹；颜色、尺寸（8~32）、方程（COPY / ALPHA / ADD）随机。
- 上下键调 N（步长 100），HUD 显示当前 N。
- 每帧：更新 → 生成命令表（背景一条 FILL + N 条 FILL 或 BLIT）→ 交执行器。

### 2.2 场景 B：大图切换

**首版场景方案**：保留 3~4 个视觉上不同的 640×480 大图场景及快速切换，
首版用可复用图块/图集或程序生成画面合成，不要求素材包存 3~4 张独立的未压缩整图；
SW5 v1 不为此增加 INDEX8 或 RLE。正式美术主题等游戏路线确定后再替换。

- 每 k 帧切一个场景（k 可调，最小 1），切换时可选淡入淡出（CONST 方程叠一层）。
- 素材包 Flash 分区上限是 4 MiB。绘图接口的行跨必须为 2 的幂，
  640×480×32 位整图实占 480×4096 = 1,966,080 字节（1.875 MiB），
  不能按紧凑存放的约 1.17 MiB 估算。复用图块时由同一个图集表面加子矩形引用，
  程序生成的占位画面不必进入素材包；所有实际入包素材都由 SW5 按真实布局核算。

### 2.3 HUD

- 右上角显示：软件帧率、硬件帧率、N、命令数、像素数。
- 文字经 8×16 字库 BLIT + 色键画出，走同一条命令表，不直接写像素（总览约束 4）。
- PC 上硬件帧率一栏显示 `--`；板上接入引擎后由 SW9 填。
- 帧率的口径：一秒内完成交换的帧数；另显示最近一帧的逻辑、构造命令、执行三段耗时。

本条**不含**：游戏内容、硬件帧率的实测（SW9）。

## 3 判据

| 项 | 判据 |
| --- | --- |
| 场景 A | PC 上 N 从 100 调到 5000，画面无错位、无越界写（ASan 无报告）；方块出屏部分被正确裁掉 |
| 场景 B | 3~4 个场景全屏覆盖且画面互不相同；每帧切换一次时不撕裂（每一帧整帧来自同一场景，无窗口回放下对每帧 CRC 与该场景单独渲染的 CRC 比对） |
| HUD | 字符逐个与字库比对正确；N、命令数、像素数与执行器统计一致 |
| 统计 | 每秒一行 CSV（格式见 SW8），字段齐全 |
| 录像 | 场景 A、B 各录一段，回放两次 CRC 序列相同 |
