# R1-定点三维数学、setup 与参考光栅器

状态:**未开工**(spec 成稿 2026-10-22;2026-10-22 静态评审后修订:数值契约冻结到公式级,
setup 定案由 CPU 完成,S3L 出口前移)。阻塞 R2(硬件对拍的金标准与 setup ABI)与 R4(PC 侧)。
总览见 [../hw/三维光栅总览.md](../hw/三维光栅总览.md)。

## 1 要解决什么

三维光栅先行需要三层软件基础,现有资产都不能直接替代:

- **像素级精确的数值契约与参考光栅器**。R2 的硬件光栅核按「软件执行器=金标准」方法学验收
  (doc/赛题二总体设计.md 3.8),必须先有一份与硬件位精确一致的 C 参考实现。small3dlib
  是软件渲染器但有自己的定点约定与质量取舍,不能当金标准。
- **CPU 侧几何与 setup 管线**。定案(2026-10-22 评审):**三角形 setup 由 CPU 完成**——
  属性梯度需要面积归一化(除法或倒数乘),硬件做就要定义多周期除法/倒数的算法、误差、延迟
  与资源,工期不允许;且同一三角形跨多条带时 CPU setup 只算一次。硬件只收 setup 参数
  (边缘系数/梯度/包围盒)并做增量扫描。RasterIX 软件侧同样预计算边缘方程与插值增量。
- **无 FPU 的 3D 数学**。CPU 是 rv32im(settings.json:65 FPU=0)。现有 fixmath 是 Q.8 游戏
  定点+三角函数,没有 Q16.16 矩阵/投影/除法。

## 2 怎么切分

### 2.1 数值契约(唯一规格源,冻结后 R2 硬件与 2.4/2.5 参考实现都按此实现)

**网格与采样点。** 屏幕 x 向右、y 向下、原点左上。像素 (i,j) 的采样点取 Q12.4 网格上的
**(16i, 16j)**,即整数网格点即采样点。与 D3D 的「+0.5 像素中心」不同——这是本管线自定义约定,
理由是省掉半像素常数与进位,三方(硬件/参考/fuzz)自洽即可;top-left 破平概念仍以 D3D
栅格化规则为背书。

**绕序与面积。** 顶点按屏幕视觉顺时针(y 向下)提交:

```
area2_raw = (x1−x0)·(y2−y0) − (x2−x0)·(y1−y0)     全部 Q12.4 raw 单位
area2_raw ≤ 0 的三角形不得提交(CPU 背面/退化剔除,硬件不收)
```

**边函数。** 三条边按 v0→v1、v1→v2、v2→v0:

```
E_raw(p) = (x_b−x_a)·(p_y−y_a) − (y_b−y_a)·(p_x−x_a)
内部 ⟺ 三条 E_raw(p) ≥ 0
```

**top-left 破平(精确式)。** 对边 a→b,记 dx=x_b−x_a、dy=y_b−y_a(本绕序下内部位于行进方向右侧):

```
top  ⟺ dy == 0 && dx > 0        水平边向右行进
left ⟺ dy < 0                   向上行进(西侧边)
E==0 的采样点算内部 ⟺ 该边是 top 或 left
```

整数判定式(硬件与参考实现统一用它):每边偏置 `bias = (top||left) ? 0 : −1`,
判内条件改为 **E + bias ≥ 0**。bias 由硬件在 setup 从 (dx,dy) 符号推导,不占 ABI 位。

**发射系数(回应「16A」问题)。** 像素 (i,j) 处 E = A_px·i + B_px·j + C0,其中
**A_px = 16·A_raw、B_px = 16·B_raw**(发射值已含 ×16,内环每步 +A_px/+B_px),
C0 = C_raw(采样点 (0,0) 处的值)。

**Guard band 与溢出契约。** CPU 在提交前把三角形屏幕多边形 Sutherland–Hodgman 裁到
guard band:**x∈[−256, 896)、y∈[−256, 736)**(像素,Q12.4 raw ∈ ±2^14 内)。由此可证
(写进契约,参考实现配断言):

- 坐标分量与差值 |Δ| ≤ 2^15,A_px/B_px ≤ 2^19;
- |C0| ≤ 2^19·2^10 = 2^29,步进全程 E ≤ 2^29.2,**全 s32 不溢出**;
- |area2_raw| ≤ 2^29.7,s32 安全(完整 s16 坐标域不裁剪会到 2^32,这就是必须 guard band 的原因);
- 裁剪在屏幕空间、透视除法之后做(近面裁剪在除法之前,见 2.3);裁剪产生的扇形拆分按
  v0 锚定三角化。

**包围盒。** `i_min = ceil_div(x_min_raw, 16)`、`i_max = floor_div(x_max_raw, 16)`
(有符号整除:floor 向 −∞,ceil = −floor(−x);j 同理),再与 x∈[0,639]、条带
y∈[16s, 16s+15] 求交。空交即跳过。bbox 存像素整数闭区间。

**深度。** 每顶点 z_window 由 CPU 按固定管线透视投影算出(z_ndc=(f+n)/(n−f)+2fn/((n−f)·z_view),
再线性映射 [0,1];OpenGL 规范深度坐标变换,窗口空间线性),存 **u16 = round(z_window·65535)**。
插值:CPU 发 z0(u16)与 DZDX/DZDY(**s16.16**);累加器 s32 = z0<<16,提交时
`clamp((acc + 32768) >> 16, 0, 65535)`。测试 LESS(严格小于才写),z-clear=0xFFFF。

**UV。** u0/v0 存 u16 Q12.4;梯度 DUDX/DUDY/DVDX/DVDY 存 **s16.16**;累加器 s32 = u0<<16
(Q16.16 域),提交 `(acc + 32768) >> 16` 后 **CLAMP 到 [0, tex_size−1]**(v1 定案,REPEAT 不做)。

**细条剔除(sliver)。** CPU 剔除任一 |梯度| ≥ 2^30 的三角形(单位像素内属性跨度过半,
防梯度域溢出;视觉上不可分辨,记 PERF 计数)。

**顶点色与调制。** ARGB8888×3;FLAGS.VCOLOR_EN=1 时 texel×vcolor 按 3.5 节 V 顺序
÷255 舍入(VCOLOR_EN=0 时等价 vcolor=白);FLAGS.TEX_EN=0 时直接用 vcolor(平涂)。
输出 XRGB8888,[31:24] 强制 0(与 2D 引擎同一纪律)。

**setup 记录 ABI(96 字节,小端,字节表冻结;C 侧用 offset 宏+_Static_assert,不用 struct 布局)。**

| 偏移 | 宽 | 字段 | 格式 |
| ---: | --: | --- | --- |
| 0 | 4 | FLAGS | [0]TEX_EN [1]VCOLOR_EN [2]KEY_EN(采样 texel==RAS_KEY 时该像素色与 z 均不写,语义对齐 2D 引擎色键;色键值在 3D 页寄存器,不进记录) 其余 0 |
| 4 | 12 | E0 = A_px, B_px, C0 | s32×3 |
| 16 | 12 | E1 = A_px, B_px, C0 | s32×3 |
| 28 | 12 | E2 = A_px, B_px, C0 | s32×3 |
| 40 | 2 | Z0 | u16 |

### 2.2 fixmath 扩展(sw/lib/core/fixmath.c/h)

- Q16.16:mul(`mul`+`mulh`)、div(长除)、recip(1024 项倒数表+牛顿一次修正;
  libfixmath(MIT)只作算法参照);mat4×vec4、透视投影(near/far/fov 参数化)、
  视口变换(输出 Q12.4)。
- 与既有 Q.8/二进制角工具共存,前缀 `fx16_`,不改既有函数。

### 2.3 几何管线与 small3dlib 边界(出口前移)

- **S3L 只用到视图空间为止**:场景/模型数据、模型矩阵与视图变换。评审证实
  `S3L_mapProjectionPlaneToScreen`(small3dlib.h:1923)整数除法直出整数像素——**不经过它**,
  亚像素无从恢复;其近面策略(`S3L_NEAR_CROSS_STRATEGY` 默认 0)不做正确裁剪——**不用它**。
- 我方管线接管视图空间之后:近面 Sutherland–Hodgman 裁剪(裁剪空间,z>near)→
  透视除法 → Q12.4 视口映射 → 屏幕 guard-band 裁剪(2.1)→ **setup**(按 2.1 产 96B 记录)
  → 条带子表分桶。全部定点,裁剪与除法的舍入式进 2.1 契约。
- 两套数学的关系:S3L 定点约定只存在于视图空间之前;`fx16_` 服务于我方管线;
  转换点唯一(视图空间出口),配边界值穷举小测试。

### 2.4 参考实现(sw/lib/gfx/rast_ref.c/h + rast_setup.c/h)

- `rast_setup`:几何管线尾段(2.3),输入屏幕空间多边形,输出 96B 记录+条带子表。
- `rast_ref`:按 2.1 契约逐像素实现(消费 setup 记录,与硬件同输入同输出);
  接口风格对齐命令层(条带局部 y)。PC 单测、板上对拍、R4 软件对照三种用法。
- 独立第二实现 `rast_ref2`(ref_exec 模式:不同代码组织,同一契约),三方对拍防规格误读。

### 2.5 向量与 fuzz(两层)

- **光栅层**:手算向量(平顶/平底/任意朝向、共享边不重不漏、跨条带、退化 area2=0、
  E=0 恰落在 top/left/right/bottom 四种边、guard band 边界 ±256/±896、z 相等 LESS 不写、
  UV CLAMP 两端)+ xorshift32 定种子随机记录流 N≥10 万,三实现交叉。
- **几何层**:矩阵/投影/裁剪端到端向量(含近面跨越、guard band 恰触发、扇形拆分),
  对拍 rast_setup 输出的记录字段。
- golden CRC 入库 sw/lib/test/(对齐 golden.txt 模式),R2/R3 直接取用。

## 3 判据

1. 2.5 两层手算向量在三份实现(rast_ref/rast_ref2/穷举脚本)上逐位一致;每条向量注明
   钉住的契约条款;每条舍入式配 16 位域穷举脚本(check_round255 先例)。
2. fuzz:光栅层 N=100,000 记录、几何层 N=10,000 三角形,三实现 CRC 相同;
   至少三类注错见红(破平改非 top-left、A_px 漏 ×16、guard band 裁剪关掉后 s32 溢出可复现)。
3. `offsetof`/`sizeof` 静态断言(2.1 字节表)在 64 位与 -m32 下都过;S3L 出口边界测试过。
4. PC(host.mk)零告警;板上(target.mk)编过(板上运行归 R3)。
5. 契约文本(2.1)按评审意见二次复核一遍:公式、单位、位宽、边界例子四要素逐条齐全。
