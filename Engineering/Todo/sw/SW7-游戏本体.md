# SW7 游戏本体

状态：未开工。前置 SW3、SW4；实体与弹型部分只要 SW1 就能开始（先不出画面，用单元测试验证）。
SW5 未完成时用占位图。对应赛题高阶要求 3。

## 1 要解决什么

设计文档 4.1、4.3 节定的是竖版弹幕射击：左侧 400×480 游戏区、右侧 240×480 HUD，
一个关卡「杂兵段 → Boss 多阶段」，自机自动射击、方向键移动、低速模式显示判定点。
资料包里没有可移植的游戏（4.2 节已检索），要自己写，估计纯 C 2000~3000 行。

它同时是压力测试（SW8）的负载来源，所以实现约束（4.4 节）不是风格要求，而是性能要求：
SoA、不在每个弹幕上调函数指针、发射时算好参数、更新循环只做加法、离屏立即回收、不用 `malloc`。

## 2 怎么切分

### 2.1 数值与数据结构（只要 SW1）

- `sw/lib/core/`：Q12.4 定点、1024 项正弦表（生成脚本入库，表本身由脚本生成）、xorshift32、整数平方根。
- 游戏代码放应用 `sw/apps/game/gfx2dGame/src/game/`，通用数值放 `sw/lib/core/`。
- 实体池：敌弹、自机子弹、敌机、粒子各一个固定大小的池，SoA 布局。
  AoS 还是 SoA 以 [E8](../hw/E8-CPU每弹幕开销与缓存大小.md) 的实测为准；E8 未出结论前按设计文档先用 SoA。
- 回收：每帧末做一次压缩（把存活的挪到前面），不用空闲链表，更新循环里没有分支跳过死实体。

### 2.2 弹型

设计文档 4.1 节的五种，全部数据驱动，一种弹型是一张参数表，不是一个函数：

| 弹型 | 参数 |
| --- | --- |
| 圆环 | 发数、初始角、速度 |
| 螺旋 | 每帧发数、角速度、速度 |
| 自机狙 | 发数、扇角、速度（发射瞬间取自机方向） |
| 扇形 | 发数、中心角、张角、速度 |
| 随机雨 | 每帧发数、x 范围、速度范围（xorshift32） |

发射器（挂在敌机或 Boss 上）按时间表调用弹型；分类方法参考 BulletML，不移植解析器。

### 2.3 自机、碰撞与规则

- 自机：8 方向移动，低速时速度减半并显示判定点；自动射击；炸弹清屏并短暂无敌。
- 碰撞：「自机判定点 vs 敌弹」「自机子弹 vs 敌机」两类，圆对圆，平方距离比较，全是整数（4.1 节）。
  判定点半径、擦弹半径做成常量。
- 残机、分数、擦弹计数；被击中时 CONST 方程的受击闪白（设计文档第 5 节）。

### 2.4 关卡

- 关卡脚本是一张按帧号排序的事件表（出现杂兵、切 Boss 阶段、切背景），不写成代码分支。
- 杂兵段 3~4 波；Boss 3 个阶段，每阶段一种弹型组合，血量耗尽或超时进入下一阶段。
- 背景：两层 COPY + 色键的视差滚动（第 5 节「免费」一档）。

### 2.5 画面组装

每帧命令表的顺序：背景 → 敌机 → 自机 → 自机子弹（ADD）→ 敌弹（ALPHA）→ 粒子（ADD）→ HUD。
游戏区的裁剪用一条 `SET_CLIP` 限制在 400×480，HUD 前再发一条恢复全屏（spec 第 01 章：裁剪框不随帧复位）。

本条**不含**：演示模式切换与压力测试（SW8）、P4 弹幕运动卸载（M5，是否做看 E8）、音效。

## 3 判据

| 项 | 判据 |
| --- | --- |
| 定点与数表 | 正弦表 1024 项与双精度参考值的最大误差登记；`sin² + cos²` 在全表上的偏差登记（主机测试里算，不进游戏代码） |
| 弹型 | 每种弹型固定种子发射一次，前 120 帧的全部弹幕坐标与存档的期望文件逐帧一致 |
| 碰撞 | 构造边界用例：距离恰好等于半径和、差 1、重叠，三种结果与定义一致 |
| 池与回收 | 池满时不再发射且溢出计数加一；压缩后存活实体的相对顺序不变（绘制顺序稳定） |
| 可玩 | PC 上从开始打到 Boss 结束，全程无崩溃；一段完整通关录像入库，回放两次 CRC 序列相同 |
| 规模 | 场景 S1 规模（2000 个敌弹）在 PC 上正常显示，统计里的像素数与设计文档 4.5 节的估算对比并登记差异 |
| 实现约束 | 更新循环里无函数指针调用、无除法（`objdump` 检查板上构建的对应函数），离屏弹幕当帧回收 |
