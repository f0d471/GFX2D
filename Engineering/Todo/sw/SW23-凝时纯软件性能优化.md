# SW23 凝时纯软件性能优化

状态：未开工。2026-11-06按用户要求登记剩余优化，明确不改RTL；本次仅记录，不启动开发或板测。
SW22继续保持待用户试玩验收，本条不改变其交付和验收状态。

## 1 目标与边界

- 保持现有切面人物、枪手、材质、分辨率、敌人数量和玩法；优先减少重复计算、记录扫描及CPU/FPGA串行等待。
- 沿用冻结B7、现有两段独立武器深度和Q16.16/Q12.4/128B记录契约；不改RTL、SoC、寄存器/记录ABI或Flash。
- 资源所有权与跨帧调度放在渲染运行时/服务层，不向玩法层暴露驱动寄存器。
- 改善固定视角与持续移动射击的实际帧率及p99/max长帧；稳定30FPS仍是目标，不预先承诺达到。

基线为[SW22第26章](../../TechReports/sw/26-凝时切面建模与精确单色setup.md)及其[板测指标](../../TechReports/sw/evidence/26-sh-facets-20261105/board/logs/sh-board/timing.json)：

固定视角124条R4TIME抽样：geometry约41.7ms、bin约5.2ms、submit约22.4ms；submit已包含约16.8ms的raster，不能相加。
活动97条抽样的geometry最大约174.8ms。原始抽样见[固定视角日志](../../TechReports/sw/evidence/26-sh-facets-20261105/board/logs/sh-board/normal.serial.log)和[活动日志](../../TechReports/sw/evidence/26-sh-facets-20261105/board/logs/sh-board/active.serial.log)，不能作为逐帧均值或分位数。
正式开工时重新核对源码、固件、参数与设备身份；这些数字保留SW22版本边界。

## 3 剩余事项与顺序

| 优先级 | 待做事项 | 机制与要求 |
| --- | --- | --- |
| P1 | 扩展精确单色setup快路径 | 从人物/枪械扩展到房间、家具中符合条件的面片；保持原拆分顺序和舍入，超出条件时走通用路径。先核对单色四边形拆分、裁剪和容量原子性 |
| P2 | 复用投影与相机无关数据 | sh_poly已投影的面在背面翻绕重试时复用屏幕顶点，避免再次投影/裁剪；研究房间共享顶点、静态面数据，以及转视角时仍有效的对象数据缓存。缓存须覆盖相机、姿态、位置、投影和viewport的真实依赖 |
| P3 | 缓存条带范围与分桶信息 | 对未变化记录复用bbox/条带范围，减少反复扫描128B记录；保留顺序、索引偏移、容量、合法空段与错误判据，不能直接删除校验来换取数字 |
| P4 | CPU/FPGA跨帧流水 | 在现有B7接口上，让CPU准备下一帧的记录/子表/HUD，同时FPGA绘制当前帧；设计双缓冲、帧号/逻辑快照及资源所有权，评估额外内存和输入延迟 |

P1～P3先分别取样，确认收益后再组合；P4单独设计、验收。现有单色setup仍有成本，缓存命中、失效和近面裁剪必须分别计时，不能沿用优化前探针的阶段比例。
当前CPU准备约48ms、硬件提交约22ms，理想重叠仍受约48ms限制；冲30FPS需要同时压低CPU准备时间和长尾，流水本身不保证达标。

P4的必要边界：记录、子表和HUD直到整帧世界/武器两段均完成才能复用；帧缓冲直到显示换帧确认才能重用。
退出、应用切换、故障恢复须排空在途任务；不写front，不跨帧混用输入、相机或逻辑状态，不把重复呈现算作新绘制帧。

## 4 开发时的验证范围

- 本次登记仅检查文档链接与空白，不运行编译、仿真、综合、部署或性能测试。
- 开发时按验证流程和validate.py --list复核范围；局部先quick，采用候选时完成选定acceptance。
- 几何/setup/缓存：补通用与快路径记录字节/像素对照、32/64位、sanitizer、近裁剪/宽屏/贴墙/满池/合法空段及定向变异；若改共享库，扩大至rast和实际消费者。
- 分桶：保持相同输入的子表字节、顺序和容量结果；覆盖缓存失效、索引错位、空段和溢出反例。
- 跨帧：验证在途表不可覆盖、代际/帧号匹配、错误取消、切换排空、显示所有权和输入延迟。
- 板端继续JTAG验证硬软像素、贴墙开火/装填、故障判据与显示健康；固定视角/连续移动射击各至少1800实际应用帧，报告FPS、p50/p99/max和late/over，不以平均值掩盖长尾。
- 同输入、参数和构建下比较前后；冻结证据、记录实际收益与未达目标，完成后另写TechReport并交用户验收。
