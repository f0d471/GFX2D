# SW9 板上移植

状态：未开工。分两半：
**前半**（板上软件执行器跑游戏、串口逐帧 CRC 与 PC 比对）只要 SW3、SW4 的录像回放与 SW7 的部分逻辑，不等硬件；
**后半**（上屏显示、场同步、硬件引擎驱动、软硬件帧率对比）等 display 与 engine 两个系列，
这两个系列在 `Todo/` 里还没有条目。本系列里只有这一条有硬件前置。

## 1 要解决什么

PC 版证明的是逻辑与画面正确，板上要回答三件事：同一份代码在 RV32 上结果是否逐位相同、
软件渲染在板上有多快、切到硬件后快多少。第三件是赛题基础要求 3 的「实时对比」，
也是 `N_max` 的来源。

## 2 怎么切分

### 2.1 前半：无显示运行（现在就能做到的部分）

- 补全 `sw/bsp/ti60/`：输入（KEY0~3 + 串口）、素材区（`board_region` 指向 DDR 素材区，素材由 JTAG 或 Flash 预先放入，解析用 `sw/lib/core` 的素材包代码）。计时与日志在 SW1 已有。
- 录像回放：把 PC 录的一段按键序列编进程序（或经串口送入），板上跑同样的帧数，
  每帧用软件执行器画进 DDR 帧缓冲 0（`0x0200_0000`），算整帧 CRC32 打到串口。
- 与 PC 无窗口回放的 CRC 序列逐帧比对。这一步验证的是 ILP32 与 LP64、gcc 8.3 与 gcc 15 之间没有行为差异。
- 顺带测出板上软件渲染每帧的三段耗时（逻辑、构造命令、执行），这是软件基线帧率的第一个真实数字；
  执行段的细分吞吐以 E7 为准。

### 2.2 后半：上屏与硬件引擎（等 display、engine）

- display 就绪后：`sw/bsp/ti60/` 的 `board_present` 改为写 `FRONT`/`SWAP_REQ`，场同步中断驱动帧节拍，画面上屏。
- engine 就绪后：引擎驱动放 `sw/bsp/ti60/`，按设计文档 3.4 节的寄存器表提交命令表（`LIST_BASE`/`LIST_COUNT`/`DOORBELL`），
  完成中断后请求交换；按 sw 系列 README 的一致性规则，读回共享区之前失效。
- Tab 切软硬件，HUD 两个帧率都填实数；硬件计数器（`PERF_*`）并入 SW8 的 CSV。
- 同帧软硬件 CRC 对比：同一张命令表，软件执行器画一份、引擎画一份，CRC 必须相同；
  注错：跳过读回前的失效，CRC 必须不同（设计文档 3.8 节）。
- 在板上跑 SW8 的压力测试，软件与硬件各得一个 `N_max`。

驱动代码在 engine 就绪之前就可以按寄存器表写好并编过，只是无法验证。

## 3 判据

| 项 | 判据 |
| --- | --- |
| 前半：逐帧一致 | 一段不少于 600 帧的录像，板上每帧 CRC 与 PC 逐帧相同；注错：板上把某个方程的注错宏打开，从第一次用到该方程的那一帧起 CRC 开始不同 |
| 前半：耗时 | 三段耗时每秒一行打到串口，原始日志入 `sw/apps/game/gfx2dGame/logs/` |
| 前半：体积 | bin 小于 512KB，登记 SHA256 与编译命令 |
| 后半：上屏 | 三种模式在 HDMI 上显示，交换无撕裂 |
| 后半：同帧 CRC | 软硬件同帧 CRC 一致，跳过失效的注错版必须不一致 |
| 后半：对比 | 软件与硬件的帧率、`N_max` 同屏显示，并写进 CSV |
